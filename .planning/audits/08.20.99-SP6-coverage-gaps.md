## Priorisierte Lücken für Block L Spec

Sortiert nach Risiko (größte unsichtbare Bug-Gefahr zuerst):

### 🔴 KRITISCH-1: D.2 — EWB-Prompt Fallback-Trap
**Lücke:** `streame_manual_ewb_variante()` hat `try/except build_profile_context()` → Fallback. Kein Test prüft dass der Profil-Kontext tatsächlich im Claude-System-Prompt landet.
**Unsichtbarer Bug:** EWB-Button liefert generische Antworten ohne Profil-Personalisierung. UI funktioniert, Backend liefert, aber Qualität ist degradiert.
**Spec-Anforderung:** Test der `streame_manual_ewb_variante()` mit gemocktem `build_profile_context` aufruft und prüft dass der System-Prompt nicht der Fallback-String ist.

### 🔴 KRITISCH-2: D.1 — `_load_profile_cache()` ungetestet
**Lücke:** Die Cache-Befüllung bei `start_live_session` ist vollständig ungetestet. Wenn `_load_profile_cache()` ausfällt (Exception), liefert `build_profile_context()` leere Sektionen.
**Unsichtbarer Bug:** `## PreCall-Briefing` zeigt `(noch nicht erstellt)`, `## Lead-Kontext` zeigt `Vorwissen-Level: nicht angegeben` — obwohl der User alles ausgefüllt hat.
**Spec-Anforderung:** Test von `_load_profile_cache()` mit DB-Fixture: nach Aufruf sind `opener_content`, `faqs`, `profile_branche` in `_session_state[sid]['_profile_cache']`.

### 🔴 KRITISCH-3: A.1 — Vorwissen-Level → Prompt-Injection-Chain
**Lücke:** Kein Test prüft den Pfad `vorwissen_level` → `_session_state` → `build_profile_context()` → Prompt enthält `Vorwissen-Level: mittel`.
**Unsichtbarer Bug:** User wählt "Kennt uns gut" (hoch), Pipeline ignoriert es, Claude gibt falschen Pitch-Level.
**Spec-Anforderung:** Unit-Test: `_session_state[sid]['vorwissen_level'] = 'hoch'` setzen, `build_profile_context(sid=...)` aufrufen, `'Vorwissen-Level: hoch'` im Output assertieren.

### 🟡 MITTEL-1: B.2 — EWB-Slot-1 Handler ungetestet
**Lücke:** `handle_manual_ewb()` WS-Handler hat null Test-Coverage.
**Unsichtbarer Bug:** Profil-Einwand-Match schlägt fehl (z.B. kurzlabel-Mismatch nach Schema-Migration), `standard_ga` bleibt leer, Claude bekommt kein Profil-Gegenargument.
**Spec-Anforderung:** Test mit gemocktem `streame_manual_ewb_variante` der prüft dass `profile_einwand` nicht `{}` ist wenn ein passender Einwand im Profil existiert.

### 🟡 MITTEL-2: A.2 — Anrede WS-Handler nicht getestet
**Lücke:** `handle_set_anrede()` in `deepgram_service.py` hat keinen direkten Test — nur die gespiegelte Hilfsfunktion in `test_ewb_rate_api.py`.
**Unsichtbarer Bug:** `set_anrede`-Event trifft ein, Handler schreibt in falschen State-Key, `build_profile_context(sid=...)` liest vom anderen Key.
**Spec-Anforderung:** Test der echten `handle_set_anrede`-Funktion mit Mock-SID.

### 🟡 MITTEL-3: A.3 — Branchen-Selector → `recherche_firma()` Parameter-Pass
**Lücke:** Kein Test für `/api/precall/research` mit `branche`-Parameter.
**Unsichtbarer Bug:** `branche=None` wird an `recherche_firma()` übergeben obwohl User eine Branche gewählt hat → generisches Briefing.
**Spec-Anforderung:** HTTP-Test: POST `/api/precall/research` mit `branche='Finanzdienstleistung'` → mock `recherche_firma` → assert `branche='Finanzdienstleistung'` im Call.
