# Phase 08.23.2.A Plan 05: Migration Scripts Summary

**One-liner:** 33-table SQLite-to-Postgres migration script with FK-ordered batch inserts, circular FK two-pass strategy, and inline row-count + sample validation after each table.

## What Was Built

**scripts/validate_postgres_migration.py**
- `MIGRATE_TABLES`: 33-entry list of all tables to migrate
- `validate_row_count(table, sqlite_session, pg_session)`: compares row counts, exits 1 on mismatch
- `validate_sample_rows(table, sqlite_session, pg_session, n=5)`: samples up to 5 IDs from SQLite, checks presence in Postgres, exits 1 on missing row
- Standalone `__main__` runner exits with clean error message when DATABASE_URL missing (not a Python exception)

**scripts/migrate_to_postgres.py**
- `MIGRATION_ORDER`: 33 tables in FK-dependency order (no-FK tables first, then organisations/users with circular FK nulled, profiles, profile children, user+org children, conversation_logs, conversation_log children)
- `BATCH_SIZE = 500` rows per insert batch
- `CIRCULAR_FK_NULLS`: organisations.coach_id and users.active_profile_id inserted as NULL in pass 1
- `migrate_table()`: reads from SQLite, inserts via raw SQL parameterized INSERT in batches
- `restore_circular_fks()`: second pass to UPDATE coach_id and active_profile_id from SQLite values
- `main()`: calls migrate_table + validate_row_count + validate_sample_rows inline after each table
- `DRY_RUN=1` mode: reads all 33 tables from SQLite, skips all Postgres writes — verified working

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Plan table count was 32 but models.py has 33 migratable tables**
- **Found during:** Task 1 — counting `__tablename__` values in database/models.py
- **Issue:** Plan's MIGRATE_TABLES listed 33 entries (organisations through crm_notes) but had `assert len == 32`. The plan note said "MIGRATE_TABLES must have exactly 32 entries" — inconsistent with the actual model count. models.py has 35 tables total: 33 legacy tables + calls + call_events. ft_call_sessions and ft_assistant_events were already deleted in plans 03/04.
- **Fix:** Used 33 as the correct count. assert updated to 33. MIGRATION_ORDER also has 33 entries.
- **Files modified:** scripts/validate_postgres_migration.py, scripts/migrate_to_postgres.py

**2. [Rule 3 - Blocking] sys.path not set for standalone script execution**
- **Found during:** Task 2 dry-run verification
- **Issue:** `from scripts.validate_postgres_migration import ...` failed with ModuleNotFoundError when script run as `python scripts/migrate_to_postgres.py` (not as module)
- **Fix:** Added `sys.path.insert(0, project_root)` at script top using `os.path.dirname(os.path.abspath(__file__))`
- **Files modified:** scripts/migrate_to_postgres.py

**3. [Rule 3 - Blocking] Unicode box-drawing chars caused UnicodeEncodeError on Windows**
- **Found during:** Task 2 dry-run verification
- **Issue:** `──` characters in print statements caused `cp1252` encoding error on Windows console
- **Fix:** Replaced `──` with `---` in print strings
- **Files modified:** scripts/migrate_to_postgres.py
