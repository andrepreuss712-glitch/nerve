<decisions>
## Implementation Decisions

### Migrations-Skript-Ansatz

- **D-01:** Migrations-Logik in `scripts/migrate_to_postgres.py` via SQLAlchemy-Modelle. Für jede der 32 Tabellen: SQLite-Rows lesen → SQLAlchemy-Modell instanziieren → `bulk_save_objects()` in Postgres-Session → committen. Tabellen in FK-Dependency-Reihenfolge (Parents vor Children).
- **D-02:** Validierungs-Logik wohnt in `scripts/validate_postgres_migration.py` als Modul mit wiederverwendbaren Funktionen (`validate_row_count(table)`, `validate_sample_rows(table, n=5)`). Das Modul hat einen `if __name__ == '__main__'`-Block damit es eigenständig ausführbar bleibt. `migrate_to_postgres.py` importiert und ruft diese Funktionen nach jedem Tabellen-Insert auf (inline, nicht erst am Ende). Bei Abweichung: Abbruch mit Fehlermeldung welche Tabelle und welche Validierung gescheitert ist.

### Call/CallEvent SQLAlchemy-Modelle

- **D-03:** `Call` und `CallEvent` als neue Sektion am Ende von `database/models.py`, abgegrenzt durch Kommentar `# --- Neue Architektur-Tabellen (Phase 08.23.2.A+) ---`. Keine eigene Datei — CLAUDE.md-Vault-Regel "Bestehende Dateien erweitern, nicht splitten". Zukünftige neue Tabellen aus 08.23.2.F/G/H kommen in dieselbe Sektion.
- **D-04:** Deferred-FK-Spalten (`tenant_id`, `account_id`, `contact_id`) als `Column(UUID(as_uuid=True), nullable=True)` **ohne** `ForeignKey()` bis die Ziel-Tabellen in 08.23.2.F/G existieren. Jede Spalte bekommt einen Pflicht-Kommentar der erklärt warum kein FK und welche Phase ihn ergänzt:
  ```python
  # FK-Verknüpfung wird in Phase 08.23.2.F nachgereicht (tenant_orgs existiert dort)
  tenant_id = Column(UUID(as_uuid=True), nullable=True)
  # FK-Verknüpfung wird in Phase 08.23.2.G nachgereicht (accounts existiert dort)
  account_id = Column(UUID(as_uuid=True), nullable=True)
  # FK-Verknüpfung wird in Phase 08.23.2.G nachgereicht (contacts existiert dort)
  contact_id = Column(UUID(as_uuid=True), nullable=True)
  # user_id bleibt Integer-kompatibel mit users.id bis UUID-Migration in 08.23.2.F
  user_id = Column(Integer, ForeignKey('users.id'), nullable=False)
  ```
- **D-05:** CHECK-Constraints und Indizes via `__table_args__` im Modell — Single Source of Truth, Alembic erkennt sie beim Autogenerate:
  ```python
  # Call.__table_args__
  (
      CheckConstraint("call_mode IN ('cold_call', 'meeting_consented')", name='ck_calls_call_mode'),
      CheckConstraint("transcript_storage IN ('none', 'ephemeral', 'consented_full')", name='ck_calls_transcript_storage'),
      CheckConstraint("outcome IN ('meeting_booked', 'callback', 'no_interest', 'wrong_person', 'contract_signed', 'unknown') OR outcome IS NULL", name='ck_calls_outcome'),
      Index('idx_calls_account_time', 'account_id', 'started_at'),
      Index('idx_calls_user_time', 'user_id', 'started_at'),
      Index('idx_calls_mode_outcome', 'call_mode', 'outcome', postgresql_where=text('outcome IS NOT NULL')),
  )

  # CallEvent.__table_args__
  (
      CheckConstraint("event_type IN ('transcript_chunk', 'suggestion_shown', 'reaction', 'phase_change', 'audio_health', 'objection_detected', 'consent_optin')", name='ck_call_events_event_type'),
      Index('idx_call_events_call_time', 'call_id', 'event_ts_ms'),
      Index('idx_call_events_type', 'call_id', 'event_type'),
      Index('idx_call_events_payload_gin', 'payload', postgresql_using='gin'),
  )
  ```

### Test-Strategie

- **D-10:** 3 FT-Test-Dateien **komplett löschen:** `test_ft_lifecycle.py`, `test_ft_models.py`, `test_ft_write_hooks.py`. Ausschließlich FT-spezifisch, ohne FtCallSession/FtAssistantEvent kein Inhalt.
- **D-11:** `test_per_sid_migration.py` **chirurgisch bearbeiten:** Nur Funktion `test_write_ft_event_isolation_per_sid` (ca. Z. 134-198) löschen + zugehörige FtCallSession/FtAssistantEvent-Import-Zeile entfernen. Die anderen 5 Funktionen (DSGVO-kritischer Multi-User-Profil-Session-Schutz aus Phase 08.20) bleiben unverändert.
- **D-12:** Test-Isolation Hybrid-Modell:
  - **Lokal:** Tests laufen weiter auf SQLite/bestehender Test-DB-Konfiguration. Null Setup-Änderung auf Andres Laptop.
  - **Server-seitig:** Separate `nerve_test`-DB auf Hetzner, eigener `nerve_test_user` (eingeschränkte Rechte, nur auf `nerve_test`). Deploy-Skript führt `pytest` mit `TEST_DATABASE_URL=postgresql://nerve_test_user@/nerve_test` als Pflicht-Schritt aus. Wenn rot: Deploy-Abbruch + Code-Rollback.
  - **@pytest.mark.postgres:** Tests die spezifisch Postgres-Verhalten prüfen (CHECK-Constraints, JSONB-Queries, UUID-Generierung, GIN-Indizes) bekommen diese Markierung. Lokal: `pytest -m "not postgres"` überspringt sie. Auf Server: Pflicht-Lauf ohne Ausnahme.

### Postgres-Setup auf Hetzner

- **D-13:** Postgres 16 (EOL Nov 2028, bessere JSONB-GIN-Performance). DB-Name `nerve` (Production), `nerve_test` (Tests). Beide DBs mit UTF-8 + `de_DE.UTF-8` Collation, `TEMPLATE template0`:
  ```sql
  CREATE DATABASE nerve WITH ENCODING 'UTF8' LC_COLLATE='de_DE.UTF-8' LC_CTYPE='de_DE.UTF-8' TEMPLATE template0;
  CREATE DATABASE nerve_test WITH ENCODING 'UTF8' LC_COLLATE='de_DE.UTF-8' LC_CTYPE='de_DE.UTF-8' TEMPLATE template0;
  ```
- **D-14:** Eingeschränkter `nerve_app`-DB-User (kein DROP/CREATE/ALTER/TRUNCATE). `ALTER DEFAULT PRIVILEGES` damit Rechte automatisch für zukünftige Tabellen aus 08.23.2.F/G/H gelten. Analog `nerve_test_user` für Test-DB.
- **D-15:** Unix-Socket-Verbindung (`postgresql://nerve_app@/nerve`). `postgresql.conf`: `listen_addresses=''` (kein TCP). `pg_hba.conf`: `peer`-Authentifizierung für `nerve_app` → `nerve` und `nerve_test_user` → `nerve_test`.
- **D-16:** Postgres-Installation mindestens 3-5 Tage **vor** Cutover-Sonntag. Trocken-Übung: Migrations-Skript gegen Kopie der SQLite-Datei ausführen, Zeilen-Count vergleichen, Stichproben prüfen, dann Test-DB leerschießen. Cutover-Sonntag-Fenster damit auf 10-15 Minuten reduziert.

### Backup-Cronjob

- **D-17:** systemd-Timer (nicht cron). Drei Dateien:
  - `/etc/systemd/system/nerve-backup.service` (Type=oneshot, User=postgres, OnFailure=nerve-backup-alert.service)
  - `/etc/systemd/system/nerve-backup.timer` (OnCalendar=`*-*-* 03:30:00`, Persistent=true, RandomizedDelaySec=15min)
  - `/opt/nerve/scripts/backup_postgres.sh`: `pg_dump | gzip` nach `/opt/nerve/backups/postgres/nerve-YYYY-MM-DD_HHMMSS.sql.gz`, Rolling-Retention `find -mtime +30 -delete`, Größen-Check (< 1KB = Fehler + exit 1).
- **D-18:** Backup-Alert via Dashboard-Streifen + `/api/health`-Erweiterung:
  - `/api/health` prüft jüngste Backup-Datei: `backup_status: 'ok'|'stale'|'missing'` + `age_hours`.
  - Dashboard zeigt gelben Warnung-Streifen wenn `backup_status != 'ok'`.
  - `nerve-backup-alert.service` schreibt bei Fehler in journald (kein SMTP nötig).

<code_context>
## Existing Code Insights

### Reusable Assets
- `database/models.py`: Alle 32 1:1-Migrations-Tabellen bereits als SQLAlchemy-Modelle definiert — Migrations-Skript kann sie direkt importieren und für bulk_save_objects() nutzen.
- `database/db.py`: Bestehende Session-Factory und Base — Postgres-Umstellung über `DATABASE_URL` ENV-Variable, kein Code-Change an db.py nötig (SQLAlchemy engine ist DB-agnostisch).
- `config.py:32`: Aktuelle SQLite-URL — wird durch ENV-Variable `DATABASE_URL` ersetzt (Postgres). Lokal bleibt SQLite als Default wenn `DATABASE_URL` nicht gesetzt.
- Bestehendes `deploy.sh` — wird um Server-side pytest-Schritt erweitert.

### Established Patterns
- ENV-Variable-Konfiguration: `config.py` liest bereits aus `os.environ` für Secrets — `DATABASE_URL` folgt diesem Pattern.
- systemd-Service: `nerve.service` existiert bereits — `nerve-backup.service/timer` folgt gleicher Struktur.
- Bestehende Health-Route: `/api/health` existiert — Erweiterung um `backup_status`-Feld folgt bestehendem Pattern.

### Integration Points
- `database/db.py` Engine-Init: Einzige Stelle wo die DB-URL gesetzt wird — hier wird `DATABASE_URL` ENV-Variable eingelesen.
- `deploy.sh`: Pflicht-Schritt `pytest -m "not postgres"` (lokal) bzw. voller Pytest-Lauf auf Server mit `TEST_DATABASE_URL`.
- Dashboard-Template: Backup-Warnung-Streifen wird oben im bestehenden Dashboard-Template eingefügt.

</code_context>

## Specific Ideas

- `nerve-backup-alert.service` erst als journald-Logger; später (post-EA) einfach um Webhook oder msmtp erweiterbar.
- Trocken-Übung der Migration (Tage vor Cutover) verhindert Überraschungen am Sonntag 23:00.
- `ALTER DEFAULT PRIVILEGES` beim nerve_app-User-Setup sichert automatisch Rechte für alle zukünftigen Tabellen aus 08.23.2.F/G/H — kein nachträgliches GRANT pro Folge-Phase.
- Backup-Datei-Größen-Check (< 1KB = Fehler) fängt lautlose pg_dump-Abbrüche ab.
