# Phase 04.13: PreCall Intelligence - Context

**Gathered:** 2026-04-13
**Status:** Ready for planning

<domain>
## Phase Boundary

Automatische Firmen-Recherche vor dem Call. Vertriebler gibt Firmenname + optional Ansprechpartner ein, NERVE erstellt kompaktes Call-Briefing in ~30 Sekunden, Briefing erscheint vor Call-Start im Live-View.

**Nicht in Scope:** Screen Intelligence / Bildschirm-Analyse (eigene Phase), PIP-Integration (Phase 04.17), Pricing-Integration (separater Schritt).

</domain>

<decisions>
## Implementation Decisions

### Datenquellen-Ansatz
- **D-01:** MVP nutzt Web-Search (z.B. Brave Search API oder Google Custom Search) + Claude-Summary statt spezialisierter APIs wie Clearbit/Proxycurl. Guenstigste Option, kein zusaetzliches API-Key-Management, sofort verfuegbar.
- **D-02:** Claude Haiku fuer Briefing-Generierung (Kosten-Constraint aus CLAUDE.md: "Sonnet MUSS raus aus dem Live-Loop — nur Haiku fuer alles Live"). Sonnet nur wenn explizit Post-Call.
- **D-03:** Keine dauerhafte Speicherung der Recherche-Rohdaten (DSGVO). Nur das generierte Briefing wird temporaer in der Session gehalten. Nach Session-Ende wird Briefing verworfen oder optional als Teil des ConversationLog archiviert.

### Ausloese-Modus
- **D-04:** Button-gesteuert (Option B aus Briefing). Vertriebler drueckt bewusst "Recherche starten" wenn er es fuer einen wichtigen Call braucht. Kein automatisches Briefing bei jedem Call — spart Kosten, gibt dem User Kontrolle.
- **D-05:** Eingabefelder: Firmenname (Pflicht), Ansprechpartner (Optional), Branche/Kontext (Optional). Minimaler Input fuer maximalen Output.

### Briefing-Darstellung
- **D-06:** Briefing erscheint als eigener Block im Live-View VOR Call-Start (nicht im PIP — PIP kommt erst in Phase 04.17). Aehnlich einem Info-Panel oberhalb der Transkription.
- **D-07:** Kompaktes Format: 3-5 Bullet-Points mit Firmen-Insights + 2-3 Gespraechs-Empfehlungen. Kein langer Text — Vertriebler muss es in 10 Sekunden erfassen koennen.
- **D-08:** Briefing bleibt waehrend des gesamten Calls sichtbar (einklappbar), damit der Vertriebler jederzeit nachschauen kann.

### Scope-Abgrenzung
- **D-09:** Screen Intelligence (Bildschirm-Analyse im Meeting) ist NICHT Teil dieser Phase. Das ist ein separates Feature mit eigener Komplexitaet (Screen Capture API, Claude Vision, etc.).
- **D-10:** Kein Kontingent-Modell im MVP. Feature ist fuer alle User verfuegbar. Kostenmonitoring wird beobachtet, Kontingente werden ggf. spaeter eingefuehrt.

### Claude's Discretion
- Genaues Layout/Styling des Briefing-Blocks — konsistent mit bestehendem Design
- Error-Handling bei fehlgeschlagener Recherche (Timeout, keine Daten gefunden)
- Caching-Strategie fuer wiederholte Recherchen zur gleichen Firma

</decisions>
