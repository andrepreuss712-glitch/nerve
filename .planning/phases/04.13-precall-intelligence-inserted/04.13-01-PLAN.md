<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client -> /api/precall/research | User-provided firmenname crosses into server-side API calls |
| Server -> Brave Search API | Server sends user input as search query to external API |
| Server -> Claude Haiku | Server sends search results as context to Claude API |
| Brave API response -> Claude prompt | External API data becomes LLM input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04.13-01 | Tampering | precall_service._brave_search | mitigate | Validate firmenname length (3-200 chars), strip control characters before passing to Brave API. Brave handles URL construction -- no direct URL fetch from user input. |
| T-04.13-02 | Information Disclosure | config.py | mitigate | BRAVE_SEARCH_API_KEY stays server-side in .env, never returned in API responses or rendered in templates |
| T-04.13-03 | Tampering | precall_service._generiere_briefing | accept | Search results are data to Claude, not instructions. System prompt is separate and server-controlled. Prompt injection via search results is low risk since output is display-only briefing text. |
| T-04.13-04 | Denial of Service | precall_service.recherche_firma | mitigate | In-memory cache with 5-min TTL prevents repeated API calls for same company. Timeout=15s on Brave request prevents hanging. |
| T-04.13-05 | Information Disclosure | precall_service._generiere_briefing | mitigate | System prompt explicitly forbids personal data beyond professional role. Raw search results are not stored in DB (per D-03). |
</threat_model>
