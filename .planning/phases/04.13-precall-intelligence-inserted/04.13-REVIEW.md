## Summary

Phase 04.13 adds PreCall Intelligence: a Brave Search + Claude Haiku pipeline that generates a company briefing before a sales call. The implementation is clean overall -- good input validation, DSGVO-compliant design (no raw search data stored), proper use of Haiku (not Sonnet) for the live path, and safe DOM manipulation via `.textContent` (no XSS). However, there is one critical issue where unsanitized client-supplied text is stored directly into the database, and a few warnings around validation mismatches, unbounded cache growth, and a missing model identifier.

## Critical Issues

### CR-01: Client-supplied precall_briefing stored without validation or size limit

**File:** `routes/app_routes.py:256,414`
**Issue:** The `api_beenden` endpoint reads `precall_briefing` directly from the JSON request body and stores it into `ConversationLog.precall_briefing` (a TEXT column) without any validation, sanitization, or size limit. While the normal flow sends the Claude-generated briefing text, a malicious or broken client could send arbitrary content of any size. This is a data integrity and potential storage abuse issue. Since this value could later be rendered in dashboard views, it also creates a stored XSS risk if any future template renders it with `|safe` or `innerHTML`.
**Fix:**
```python
# In api_beenden, after line 256:
precall_briefing = req_data.get('precall_briefing', None)
if precall_briefing is not None:
    if not isinstance(precall_briefing, str):
        precall_briefing = None
    elif len(precall_briefing) > 2000:
        precall_briefing = precall_briefing[:2000]
```

## Warnings

### WR-01: Input validation mismatch between route and service (min length 2 vs 3)

**File:** `routes/app_routes.py:872` and `services/precall_service.py:54`
**Issue:** The route handler `api_precall_research` validates `len(firmenname) < 2` (minimum 2 chars), but `precall_service.recherche_firma` validates `len(firmenname) < 3` (minimum 3 chars). A 2-character company name passes the route but is rejected by the service, returning a confusing error message via 502 status instead of a 400 validation error.
**Fix:** Align both to the same minimum. Since the service enforces 3, the route should match:
```python
# routes/app_routes.py line 872
if not firmenname or len(firmenname) < 3 or len(firmenname) > 200:
    return jsonify({'error': 'Firmenname ist Pflicht (3-200 Zeichen)'}), 400
```

### WR-02: Unbounded in-memory cache in precall_service can grow without limit

**File:** `services/precall_service.py:17`
**Issue:** `_briefing_cache` is a plain dict that grows unboundedly. Expired entries are never evicted -- they only stop being returned. Over a long-running server process, this dictionary will accumulate stale entries for every unique company name ever searched, consuming memory proportional to total unique queries.
**Fix:** Add periodic eviction or use an LRU cache:
```python
# Option A: Simple eviction on each lookup (add to recherche_firma before cache check)
now = time.time()
stale_keys = [k for k, (_, ts) in _briefing_cache.items() if now - ts >= _CACHE_TTL_S]
for k in stale_keys:
    del _briefing_cache[k]

# Option B: Use functools.lru_cache or a bounded dict with max size
```

### WR-03: Service error returns 502 for all failures including client-caused ones

**File:** `routes/app_routes.py:880`
**Issue:** When `recherche_firma` returns an error, the route always responds with HTTP 502 (Bad Gateway). However, some errors are client-caused (e.g., "Firmenname muss zwischen 3 und 200 Zeichen lang sein") and should return 400. Using 502 for validation errors misrepresents the failure to the client and could confuse error monitoring.
**Fix:**
```python
briefing, error = recherche_firma(firmenname, ansprechpartner, branche)
if error:
    # Distinguish upstream failures from input validation
    if 'Pflicht' in error or 'Zeichen' in error or 'konfiguriert' in error:
        return jsonify({'error': error}), 400
    return jsonify({'error': error}), 502
```

### IN-02: Claude model identifier uses snapshot date that will become stale

**File:** `services/precall_service.py:136`
**Issue:** The model string `"claude-haiku-4-5-20251001"` hardcodes a specific snapshot date. This is not a bug, but worth noting for future maintenance: when Anthropic releases a newer Haiku version, this will need manual updating. Consider extracting model identifiers to `config.py` for centralized management.
**Fix:** Move to config.py:
```python
# config.py
PRECALL_MODEL = os.environ.get('PRECALL_MODEL', 'claude-haiku-4-5-20251001')
```
