# Phase 04.13: PreCall Intelligence - Research

**Researched:** 2026-04-13
**Domain:** Web Search API + Claude Haiku Briefing Generation + Flask UI Integration
**Confidence:** HIGH

## Summary

Phase 04.13 adds a button-triggered company research feature to the Live-View. The user enters a company name (required) and optionally a contact person and industry context. The backend performs a web search via Brave Search API, feeds results to Claude Haiku for summarization, and returns a compact 3-5 bullet-point briefing with 2-3 conversation recommendations. The briefing appears as a collapsible block in the Live-View before and during the call.

The technical approach is straightforward: a new `precall_service.py` module handles the Brave Search API call and Claude Haiku summarization. A new Flask route (`/api/precall/research`) accepts the input and returns the briefing as JSON. The frontend adds input fields and a "Recherche starten" button to the existing mode-selection overlay flow, and a persistent collapsible briefing panel in the Live-View body.

**Primary recommendation:** Use Brave Search API ($5/1000 queries, free tier available) with plain `requests` HTTP calls (already in requirements.txt) -- no additional Python packages needed. Claude Haiku 4.5 for summarization at $1/M input + $5/M output tokens. Total cost per briefing: approximately $0.003-0.008 (search + LLM).

claude_client = anthropic.Anthropic(api_key=ANTHROPIC_API_KEY)

BRAVE_SEARCH_URL = "https://api.search.brave.com/res/v1/web/search"

def recherche_firma(firmenname, ansprechpartner=None, branche=None):
    """Web-Recherche + Claude-Briefing fuer eine Firma.
    Returns: (briefing_dict, error_msg)
    """
    # 1. Brave Search
    suchergebnisse = _brave_search(firmenname, ansprechpartner, branche)
    if not suchergebnisse:
        return None, "Keine Suchergebnisse gefunden"
    
    # 2. Claude Haiku Briefing
    briefing = _generiere_briefing(firmenname, ansprechpartner, branche, suchergebnisse)
    if not briefing:
        return None, "Briefing-Generierung fehlgeschlagen"
    
    return briefing, None

    query = firmenname
    if ansprechpartner:
        query += f" {ansprechpartner}"
    if branche:
        query += f" {branche}"
    
    headers = {
        "Accept": "application/json",
        "Accept-Encoding": "gzip",
        "X-Subscription-Token": BRAVE_SEARCH_API_KEY,
    }
    params = {"q": query, "count": 10, "search_lang": "de", "country": "DE"}
    
    try:
        resp = requests.get(BRAVE_SEARCH_URL, headers=headers, params=params, timeout=15)

                "title": r.get("title", ""),
                "description": r.get("description", ""),
                "url": r.get("url", ""),
            })
        return results if results else None

    data = request.get_json(force=True)
    firmenname = (data.get('firmenname') or '').strip()
    if not firmenname:
        return jsonify({'error': 'Firmenname ist Pflicht'}), 400
    
    ansprechpartner = (data.get('ansprechpartner') or '').strip() or None
    branche = (data.get('branche') or '').strip() or None

        return jsonify({'error': error}), 502

**What:** Simple dict cache for repeated research on same company

**Example:**
```python
# Module-level cache in precall_service.py
_briefing_cache = {}  # firmenname_lower -> (briefing, timestamp)
_CACHE_TTL_S = 300    # 5 minutes

def recherche_firma(firmenname, ...):
    cache_key = firmenname.strip().lower()
    cached = _briefing_cache.get(cache_key)
    if cached and (time.time() - cached[1]) < _CACHE_TTL_S:
        print(f"[PreCall] Cache hit: {firmenname}")
        return cached[0], None
    # ... do research ...
    _briefing_cache[cache_key] = (briefing, time.time())
```

## Common Pitfalls

### Pitfall 1: Brave Search API Timeout
**What goes wrong:** Brave Search takes >15 seconds, user stares at spinner
**Why it happens:** Network latency, API overload, large result sets
**How to avoid:** Set `timeout=15` on requests.get(), show clear loading state with timeout message
**Warning signs:** Response times consistently >10s

### Pitfall 2: Poor Search Results for Small Companies
**What goes wrong:** Kleine Handwerksbetriebe have almost no web presence, briefing is empty/useless
**Why it happens:** Limited public data for small DACH companies
**How to avoid:** Handle gracefully -- show "Wenig oeffentliche Daten gefunden" with whatever is available. Never show empty briefing.
**Warning signs:** Search returns <3 results

### Pitfall 3: Claude Haiku Hallucinating Company Details
**What goes wrong:** Haiku invents facts about the company not present in search results
**Why it happens:** LLM tendency to fill gaps with plausible-sounding information
**How to avoid:** Strong system prompt: "Verwende NUR Informationen aus den Suchergebnissen. Erfinde KEINE Fakten. Wenn wenig Daten vorhanden, sage das ehrlich."
**Warning signs:** Briefing contains specific numbers not in search results

### Pitfall 4: DSGVO -- Personal Data in Search Results
**What goes wrong:** Search results contain personal data about the contact person
**Why it happens:** Public LinkedIn/XING profiles, news articles with names
**How to avoid:** Only aggregate publicly available business-relevant data. No personal details beyond professional role. System prompt must enforce this. Raw search results are not stored (D-03).
**Warning signs:** Briefing mentions private addresses, phone numbers, personal social media

### Pitfall 5: Blocking the activateSession() Flow
**What goes wrong:** PreCall UI breaks the existing mode-selection -> session-start flow
**Why it happens:** Inserting new UI step between mode selection and mic activation
**How to avoid:** Keep "Ueberspringen" always visible and prominent. PreCall is optional -- never blocks session start.
**Warning signs:** Users can't start a call without completing research

### Pitfall 6: Missing Brave API Key in Production
**What goes wrong:** Feature silently fails on Hetzner server because .env lacks BRAVE_SEARCH_API_KEY
**Why it happens:** New env var not added to server
**How to avoid:** Graceful degradation -- if key is empty, hide the research button entirely and log `[PreCall] BRAVE_SEARCH_API_KEY nicht konfiguriert`
**Warning signs:** Feature works locally but not in production

### Claude Haiku Briefing Generation
```python
# Source: Existing pattern from services/claude_service.py [VERIFIED: codebase]
PRECALL_SYSTEM_PROMPT = """Du bist ein Vertriebsassistent der kompakte Call-Briefings erstellt.

Du erhaeltst Web-Suchergebnisse zu einer Firma. Erstelle daraus ein Briefing fuer einen Vertriebler.

Format:
## Firmen-Insights (3-5 Bullet-Points)
- [Konkrete, relevante Information]

## Gespraechs-Empfehlungen (2-3 Punkte)
- [Konkreter Tipp fuer den Call]

Regeln:
- Verwende NUR Informationen aus den Suchergebnissen
- Erfinde KEINE Fakten. Wenn wenig Daten vorhanden, sage das ehrlich
- Maximal 150 Woerter gesamt
- Auf Deutsch
- Fokus auf vertriebsrelevante Informationen: Groesse, Branche, aktuelle News, Wachstum, Tech-Stack
- Keine persoenlichen Daten ausser berufliche Rolle des Ansprechpartners
"""

def _generiere_briefing(firmenname, ansprechpartner, branche, suchergebnisse):
    search_text = "\n\n".join([
        f"**{r['title']}**\n{r['description']}\nURL: {r['url']}"
        for r in suchergebnisse
    ])
    
    user_msg = f"Firma: {firmenname}"
    if ansprechpartner:
        user_msg += f"\nAnsprechpartner: {ansprechpartner}"
    if branche:
        user_msg += f"\nBranche: {branche}"
    user_msg += f"\n\nSuchergebnisse:\n{search_text}"
    
    try:
        msg = claude_client.messages.create(
            model="claude-haiku-4-5-20251001",
            max_tokens=400,
            system=PRECALL_SYSTEM_PROMPT,
            messages=[{"role": "user", "content": user_msg}],
        )
        return {
            "text": msg.content[0].text,
            "firmenname": firmenname,
            "ansprechpartner": ansprechpartner,
            "quellen_count": len(suchergebnisse),
        }
    except Exception as e:
        print(f"[PreCall] Claude Briefing Fehler: {e}")
        return None
```
