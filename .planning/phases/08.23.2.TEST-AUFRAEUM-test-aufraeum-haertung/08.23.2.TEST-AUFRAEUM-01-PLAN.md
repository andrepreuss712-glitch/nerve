## Kern-Korrektur der Diagnose (Fable+Gemini-Konsens, live-verifiziert)

Die reale Gate-Warnung (audit_log **+ organisations + users**) ist **NICHT** ein FK-Order-Problem,
sondern eine **audit_log-TRIGGER-KASKADE**:
- `audit_log.user_id -> users.id` (models.py:395, NO ACTION — live `audit_log_user_id_fkey confdeltype=a`)
- `audit_log.org_id -> organisations.id` (models.py:396, NO ACTION — live `audit_log_org_id_fkey confdeltype=a`)

Der Immutability-Trigger verhindert den audit_log-Delete → die audit_log-Rows bleiben liegen und
**halten per FK die users/orgs-Rows fest** → deren Delete stallt → BASELINE-AUTO-FIX-Warnung fuer alle
drei. Der Savepoint-Retry-Loeser (`_fk_safe_delete_rows`, conftest.py:155-235) heilt jede **azyklische**
Order-Verwechslung selbst → ein reiner Order-Fehler kann **prinzipiell keinen Hard-Stall** erzeugen.
**→ Task 1 (Trigger-Bypass) loest die reale Warnung fuer audit_log + users + organisations ALLEIN.**
