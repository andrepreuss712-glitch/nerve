## A — DB-Layout für Transcript-Persistenz

| Option | Description | Selected |

## B — Backend Bug B + Confidence-Schwellen

## D — DSGVO + Cascade-Delete

### Sub-Frage: Aufbewahrungsfrist transcript_segments

| Option | Description | Selected |
|--------|-------------|----------|
| An transcript_storage-ENUM koppeln | ephemeral=30 Tage, consented_full=dauerhaft. Konsistent mit DSGVO-Architektur. | teilweise ✓ |
| Immer dauerhaft bis User-Löschantrag | Keine Cron-Jobs, aber DSGVO-Risiko für EU-Nutzer. | |
| Immer 30 Tage automatisch | Maximale Sicherheit, aber Phase E DPO-Daten gehen verloren. | |

**User's choice:** Angepasste Variante (Cross-AI Gemini 2026-05-28): Zwei-Tabellen-Architektur. `public.transcript_segments` mit FK: 90 Tage Frist (ephemeral), User-Opt-in zu consented_full. `training.transcript_archive` (D.UX.0, kein FK, kryptographisch anonymisiert): dauerhaft. Timestamp-Korrelations-Angriff-Schutz via kryptographisch randomisierten `ts_offset_ms`.

**Notes:** Gemini hat Variante B (Identitäts-Verfall in einer Tabelle) ausgeschlossen — Timestamp-Korrelations-Angriff möglich via `ts_ms + calls.started_at`. Deshalb strikte Zwei-Tabellen-Trennung.
