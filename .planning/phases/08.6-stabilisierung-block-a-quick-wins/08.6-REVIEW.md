## Warnings

### WR-01: `ValueError` crash on non-numeric form input in PlanningListView

**File:** `routes/admin_views.py:144`
**Issue:** `int(request.form.get('id') or 0)` is called without exception handling. If a POST arrives with a non-numeric `id` value (e.g. `"abc"`), `int()` raises `ValueError` and Flask returns an unhandled 500. The admin panel is superadmin-only, so exploitability is low, but it is still an unhandled crash path.
**Fix:**
```python
try:
    link_id = int(request.form.get('id') or 0)
except (ValueError, TypeError):
    link_id = 0
```

### WR-02: Jinja2 HTML entity double-escaping in analytics.html

**File:** `templates/analytics.html:22`
**Issue:** `{{ s.session_mode or '&mdash;' }}` — when `session_mode` is falsy, Jinja2's autoescaping encodes the `&` in the literal string `'&mdash;'` to `&amp;mdash;`, so the browser renders the literal text `&mdash;` instead of an em dash character. The same pattern applies to `s.result or '&mdash;'` on line 26.
**Fix:** Use Jinja2's `| safe` filter on a known-safe literal, or use the unicode character directly:
```jinja2
{{ s.session_mode or '—' }}
{# or #}
{{ s.session_mode or '&mdash;' | safe }}
```
The `| safe` approach is fine here because the literal string is hardcoded, not user-supplied. Alternatively, render the `&mdash;` as raw HTML outside the expression and conditionally show it:
```jinja2
{% if s.session_mode %}{{ s.session_mode }}{% else %}&mdash;{% endif %}
```

### WR-03: Conflicting `display` declarations on `perf-empty-chart` element

**File:** `templates/dashboard.html:143`
**Issue:** The element has `style="display:none;position:absolute;inset:0;display:flex;..."` — two `display` properties in the same inline style. The second declaration (`display:flex`) wins unconditionally in all browsers, making the empty-state overlay always visible, even when there is chart data. The JavaScript at line 572 sets `emptyEl.style.display = 'flex'` but never sets `display:none` to hide it initially, relying on the inline style that doesn't work.
**Fix:** Remove the first `display:none` from the inline style (it has no effect with the second `display:flex` present) and instead initialize the element as hidden via a separate CSS class or by ensuring the JS hides it on render:
```html
<!-- Option A: move initial hide to JS -->
<div id="perf-empty-chart" style="display:none;position:absolute;inset:0;...">

<!-- Remove the duplicate display:flex from the same attribute -->
```
In `renderPerformance()`:
```javascript
if (emptyEl) emptyEl.style.display = 'none';   // reset before check
if (!p.hat_daten && emptyEl) {
    emptyEl.style.display = 'flex';
    ...
}
```

### IN-01: Weak `SECRET_KEY` default is insecure if env var not set

**File:** `config.py:12`
**Issue:** `SECRET_KEY` defaults to `'dev-secret-change-me'`. If deployed without setting the env var, Flask sessions are cryptographically worthless. This is a pre-existing concern, not introduced by phase 08.6.
**Fix:** Either assert the env var is present at startup, or generate a random fallback that is logged as a warning. Best practice: fail fast in non-debug environments:
```python
SECRET_KEY = os.environ.get('SECRET_KEY')
if not SECRET_KEY:
    import secrets as _s
    SECRET_KEY = _s.token_hex(32)
    print("[Config] WARNING: SECRET_KEY not set — using ephemeral key. Sessions will break on restart.")
```
