## Test-DB-Provisionierung

| Option | Description | Selected |
|--------|-------------|----------|
| Eigene DB auf Prod-Instanz | CREATE DATABASE nerve_test als postgres → alembic upgrade → DROP. Nutzt cluster-globale Rollen, kein Docker, schnellster Deploy. | ✓ |
| Docker-Container (postgres:N) | Voll isolierte Instanz, aber Rollen+Policies nachbauen, Docker-Dependency, langsamer. | |
| Ephemerer Temp-Cluster (pg_tmp/initdb) | Frischer Cluster in tmpdir, ohne Docker, aber fragil + ungewöhnlich. | |

**User's choice:** Eigene DB auf Prod-Instanz
**Notes:** André ergänzte eine HARTE Sicherheits-Schranke (→ D-02): CREATE/DROP DATABASE + alle Test-DSNs zielen ausschließlich auf `nerve_test`; Whitelist-Guard verweigert CREATE/DROP bei abweichendem Namen und bricht ab statt zu raten. Begründung: Tippfehler bei DROP DATABASE auf der Prod-Instanz = Totalverlust der Prod-DB.

## Test-Isolation

| Option | Description | Selected |
|--------|-------------|----------|
| DB 1× pro Lauf + Rollback pro Test | 1× alembic upgrade, pro Test Transaktion+Rollback (bestehendes nerve_app_pg_conn-Muster). Schnell + sauber. | ✓ |
| Drop+Recreate Schema pro Test | Maximale Sauberkeit, aber Gate zu langsam. | |
| Shared DB ohne per-Test-Reset | Schnellste, aber Reihenfolge-Kopplung + Leakage. | |

**User's choice:** DB 1× pro Lauf + Rollback pro Test
**Notes:** André ergänzte eine HARTE Ausnahme (→ D-04): RLS-Isolations- + Anonymizer-Worker-Tests dürfen NICHT auf dem Rollback-Pfad laufen — Cross-Tenant braucht echte Commits über getrennte Connections, sonst False-Green (rollback-only = nichts committet = zweite Connection sieht ohnehin nichts = trivial grün ohne RLS je zu prüfen). Lösung: dediziertes Real-Commit-Fixture mit deterministischem Daten-Teardown; generische Tests bleiben Rollback.

## Gate-Robustheit & Deploy-Tempo

| Option | Description | Selected |
|--------|-------------|----------|
| Teardown: trap EXIT + Pre-Run-Cleanup | DROP garantiert auch bei Fehler/SIGTERM; verwaiste nerve_test vor Lauf droppen. | ✓ |
| Teardown: nur am Skript-Ende | Einfacher, aber hartes kill lässt Rest zurück. | |

**User's choice:** trap EXIT + Pre-Run-Cleanup · jeder Schritt einzeln mit Grund · Korrektheit vor Tempo (~+30s OK)
