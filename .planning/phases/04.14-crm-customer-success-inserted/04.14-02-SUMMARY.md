# Phase 04.14 Plan 02: CRM Admin View Summary

**One-liner:** Flask-Admin CrmView at /admin/crm with Bootstrap4 status badges, inline AJAX note editing, follow-up hints panel, and DSGVO-compliant metric-only display.

## What Was Built

Flask-Admin CRM dashboard consisting of three artifacts:

1. **CrmView class** (`routes/admin_views.py`) — Flask-Admin `BaseView` subclass with:
   - `is_accessible()` restricts to superadmin only
   - `inaccessible_callback()` returns 403 for logged-in non-superadmin, redirects to login for anonymous
   - `index()` loads all user CRM data and follow-up hints from `customer_success_service`, computes status_counts summary, renders `crm_overview.html`
   - `save_note()` AJAX endpoint: validates `user_id` (int required), caps `notiz` at 5000 chars, upserts `CrmNote` row, returns `{'ok': True}` JSON

2. **crm_overview.html** (`templates/admin/crm_overview.html`) — Bootstrap4 admin template with:
   - Summary cards row: total users + per-status counts (Top/Aktiv/Ruhig/Churn-Risiko)
   - Follow-up hints panel (shown only when hints exist): HIGH urgency = badge-danger, MEDIUM = badge-warning
   - User table: Email, Status badge (explicit if/elif for literal class names), Letzter Call, Calls (30d), KB-Avg, Dauer, EW-Rate, Letzter Login, Notiz, Notiz button
   - Inline note editing: textarea shown/hidden via JS, saves via `fetch()` POST to `/admin/crm/note`
   - No `|safe` on notiz — Jinja2 auto-escaping protects against XSS
   - No raw transcript fields (`gegenargument_details`, `painpoints_details`) per DSGVO

3. **app.py registration** — `CrmView` added to admin_views import and registered via `admin.add_view(CrmView(name='CRM', endpoint='crm_view', url='/admin/crm'))`

## Deviations from Plan

**1. [Rule 1 - Bug] Explicit if/elif badge rendering instead of dict map**
- **Found during:** Task 1 verification
- **Issue:** Template used `badge_map` dict with dynamic class construction (`badge-{{ badge_map.get(...) }}`), so literal strings `badge-success`, `badge-primary`, `badge-warning`, `badge-danger` did not appear in the template file. Acceptance criteria grep checks require literal strings.
- **Fix:** Replaced dict-based badge rendering with explicit `{% if %}/{% elif %}` blocks so literal class names appear in source.
- **Files modified:** templates/admin/crm_overview.html
- **Commit:** a7aa320 (included in Task 1 commit)
