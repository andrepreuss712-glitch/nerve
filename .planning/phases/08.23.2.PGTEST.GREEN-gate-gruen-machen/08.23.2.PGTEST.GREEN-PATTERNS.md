**FK-edge query to ADD (D-G16, `pg_constraint` contype='f' — no existing analog, this is the new bit):**
```sql
SELECT con.conrelid::regclass::text AS child, con.confrelid::regclass::text AS parent, con.confdeltype
FROM pg_constraint con
JOIN pg_namespace n ON n.oid = con.connamespace
WHERE con.contype = 'f' AND n.nspname = %s;
```
> `confdeltype='c'` = ON DELETE CASCADE -- read for diagnosis/enumeration ONLY, NEVER to exclude an edge (Gemini-Fund #1): ALL FK edges (incl. CASCADE) go into the topo-sort. A CASCADE delete merely becomes redundant (never erroneous); excluding it breaks a DoS-chain like A->CASCADE->B->RESTRICT->C where C must still be ordered before B. `child = parent` = self-ref FK (D-G16 Bau-Wachpunkt 1: cycle -- ignore that edge or DELETE-in-loop); mutual-cycle cycle-breaking stays. PK-name per table from catalog (D-G17 REFINEMENT), NOT hardcoded `id`:
```sql
SELECT a.attname FROM pg_index i
JOIN pg_attribute a ON a.attrelid = i.indrelid AND a.attnum = ANY(i.indkey)
WHERE i.indrelid = %s::regclass AND i.indisprimary;
```
> **Composite-PK-Guard (Gemini-Re-Review R2 / Fund #6, the remainder of #2):** the query above returns MULTIPLE rows for a composite PK. Taking only the first column would make `DELETE ... WHERE {first_pk_col}::text = ANY(...)` delete far more rows than the test created (over-deletion) or crash. Therefore: check `len(pk_cols)`. `len == 1` -> single PK column, table is auto-delete-eligible. `len != 1` (composite PK, >1 `indisprimary` row) -> the table is NOT freed for auto-delete; it goes into the `foundation_register` (Denylist) with reason `"composite PK not supported for auto-delete"`, LOGGED via `logging.warning` (Req-7, never silently dropped). `len == 0` (no PK) -> foundation_register reason `"no watchable PK"`, also logged. A composite-PK table must land in the Denylist, NOT in the auto-delete path -- `primary_key_column` returns no single column for it.

**Data-flow / role split (D-G18, Verbindungs-Karte — Punkt 22):**
- conftest imports it as **`nerve_app`, schema='public'** (peer socket, public has no RLS on catalog reads).
- deploy.sh wrapper calls it via `python -c` as **`postgres` peer**, schema='crm' (postgres bypasses RLS — sees all tenants for the leak-count). Catalog reads are role-agnostic (proven: SCHILD reads catalog as nerve_app, deploy.sh as postgres).
- **DRY contract:** returns `(baseline_table_list, reverse_fk_delete_order, foundation_register)` from ONE truth (Gemini-Fund #4 3-tuple unpack). conftest consumes baseline_table_list + reverse_fk_delete_order for the guard; deploy.sh consumes baseline_table_list for the UNION; foundation_register documents the hardcoded non-public single-table checks (e.g. training.transcript_archive) PLUS the composite-PK and no-PK exclusions (Fund #6).

### 2. `tests/conftest.py` Auto-Reset split guard (MODIFY) — test-infra, event-driven

**Analog = the functions themselves (extend in place, D-G01/D-G02).**

**`_diff_baseline` (conftest.py:289-303) — ALREADY returns the 3-way split, just consume it differently:**
```python
def _diff_baseline(current, baseline):
    drift = {}
    for tbl, base_map in baseline.items():
        cur_map = current.get(tbl, {})
        cur_pks = set(cur_map)
        base_pks = set(base_map)
        leaked = cur_pks - base_pks
        missing = base_pks - cur_pks
        mutated = {pk for pk in (cur_pks & base_pks) if cur_map[pk] != base_map[pk]}
        if leaked or missing or mutated:
            drift[tbl] = {"leaked": leaked, "missing": missing, "mutated": mutated}
    return drift
```
> D-G02: `leaked` -> reverse-FK-DELETE + warn. `missing`/`mutated` -> hard `pytest.fail`. NO re-insert of missing (D-G02: re-insert fires `trg_mk_tenant_org` -> new UUID -> poisons follow-up tests).

**`_baseline_cleanup_guard` (conftest.py:343-368) — flip from fail-closed to auto-reset:**

**id::text uuid-cast pattern (D-G06) — copy verbatim from `cleanup_rows` (conftest.py:210 / 221-224):**

> 10e5d0a-fix: the `::text` cast carries int-PK (organisations/users/calls) AND uuid-PK (tenant_orgs) in one query -- without it `operator does not exist: uuid = text` (D-G06, cast STAYS). **Module-level cache + cache-fill ordering (D-G19, KRITISCH; Gemini-Fund #3 + Gemini-Re-Review R2 / Fund #7):**
> COUPLING (D-G19): the guard MUST consume list+order from the module — build the module FIRST (Wave 1), or the guard dies on its own cleanup with an FK violation.
> The dynamic reverse-FK-order + PK-columns are written ONCE at session start into module-level globals `_DERIVED_FK_ORDER` / `_DERIVED_PK_COLS` by a session-scoped `_baseline_schema` fixture (Gemini-Fund #3). `cleanup_rows` reads from these globals WITHOUT a signature change and WITHOUT a per-call DB query; if the cache is empty (non-PG/SQLite skip path) it falls back to the hardcoded `_CLEANUP_FK_ORDER` (best-effort, stays in the file).
> **Cache-fill guarantee (Gemini-Re-Review R2 / Fund #7):** `_baseline_schema` must be requested as a fixture PARAMETER (dependency) of the early-running `_baseline_snapshot` fixture — i.e. `def _baseline_snapshot(..., _baseline_schema):`. This is a HARD ordering guarantee that the module-level cache is filled at session start BEFORE the first `cleanup_rows`/snapshot path can trigger the silent fallback. Without this explicit dependency it is not guaranteed that `_baseline_schema` runs before other tests, so `cleanup_rows` would SILENTLY fall back to the hardcoded `_CLEANUP_FK_ORDER` -> the dynamic derivation (Req-9) becomes effectively inert (meta-false-green: the gate thinks it is dynamic, it is not). A test asserts `_DERIVED_FK_ORDER`/`_DERIVED_PK_COLS` are NON-EMPTY after session start (proves the ordering held), not merely that the fallback exists.

**Reverse-FK semantics to reuse — `cleanup_rows` (conftest.py:196-225)** orders by `_CLEANUP_FK_ORDER` then appends unknowns best-effort. Auto-reset uses the SAME delete loop, but the order now comes from `_schema_introspect` topo-sort via the module cache (D-G19), not the hardcoded `_CLEANUP_FK_ORDER` list (conftest.py:114-130, which D-G17 replaces in the normal path; it stays only as the empty-cache fallback).

> **`$@`-Forwarding past the single-quoted `bash -c` (Gemini-Re-Review R2 / Fund #5, BLOCKER):** the inner `pytest "$@"` sits INSIDE the single-quoted `sudo -u nerve_app env ... bash -c '...'` block. `$@` is NOT expanded there by the outer shell (single-quote) -> the inner bash receives NO arguments -> `triage.sh test_x.py` would run the WHOLE suite -> the harness loses its core capability (targeted runs) -> empirical triage (Plan 04) impossible. FIX: forward the arguments hard into the inner subshell by appending `_ "$@"` AFTER the closing single-quote of `bash -c`. The `_` occupies `$0` of the inner bash, then the actual arguments follow as `$1, $2, ...`. The documented triage.sh invocation shape is therefore:
```bash

    cd /opt/nerve/app && \
    DATABASE_URL="postgresql://nerve_app@/${TEST_DB}" \
    ... (4 DSNs) ... \
    /opt/nerve/venv/bin/pytest "$@"
  ' _ "$@"
```
> Note the trailing `' _ "$@"` after the closing single-quote: `_` = inner `$0`, then the script's `"$@"` are passed positionally into the inner bash so `pytest "$@"` expands them. WITHOUT this trailing `_ "$@"` the harness is functionally broken (always runs the full suite). grep-check: `grep -n "' _ \"\$@\"" scripts/triage.sh` >=1 hit.

## Shared Patterns

### Catalog introspection (the ONE truth — D-G18)
**Source:** new `tests/_schema_introspect.py`, modeled on `test_schild_guard.py:53-66` + `deploy.sh:168-174`
**Apply to:** conftest auto-reset guard (public, nerve_app), deploy.sh POST-SUITE (crm, postgres peer)
> Role-agnostic catalog reads. ONE module, two callers, no multi-source drift. Returns (baseline_table_list, reverse_fk_delete_order, foundation_register) (Gemini-Fund #4 3-tuple). foundation_register also carries composite-PK + no-PK exclusions (Fund #6).

### {pk_col}::text uuid-cast + composite-PK denylist (10e5d0a + Gemini-Fund #2 + Gemini-Re-Review R2 / Fund #6)
**Source:** `cleanup_rows` (conftest.py:210, 221-224)
**Apply to:** ALL row-delete paths (auto-reset guard, introspect-driven cleanup)
> `WHERE {pk_col}::text = ANY(...)` -- the `::text` cast STAYS (public tables mix int-PK and uuid-PK; without it `operator does not exist: uuid = text`, D-G06). The COLUMN NAME is catalog-derived (primary_key_column / _DERIVED_PK_COLS), NEVER hardcoded `id` -- a non-id-PK table (intent_event.event_id) would crash 'column id does not exist'.
> **Composite PK (Fund #6, the remainder of #2):** a table with a composite PK (>1 `indisprimary` row) is NOT auto-deleted -- a single-column `{first_pk_col}::text = ANY(...)` would over-delete (delete more rows than the test created) or crash. Such tables are DENYLISTED in `foundation_register` with reason `"composite PK not supported for auto-delete"` (logged via `logging.warning`, never silent). Only `len(pk_cols) == 1` tables reach this delete path.

### Loud-warning attribution (Req-7 / Req-3)
**Source:** `[PGTEST-CLEANUP]` (conftest.py:232), `[BASELINE-GUARD]` (conftest.py:366)
