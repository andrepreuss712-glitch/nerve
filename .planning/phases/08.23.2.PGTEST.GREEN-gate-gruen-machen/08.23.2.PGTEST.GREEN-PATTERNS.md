**FK-edge query to ADD (D-G16, `pg_constraint` contype='f' — no existing analog, this is the new bit):**
```sql
SELECT con.conrelid::regclass::text AS child, con.confrelid::regclass::text AS parent, con.confdeltype
FROM pg_constraint con
JOIN pg_namespace n ON n.oid = con.connamespace
WHERE con.contype = 'f' AND n.nspname = %s;
```
> `confdeltype='c'` = ON DELETE CASCADE (D-G16 Bau-Wachpunkt 2: skip cascade-children in topo-sort). `child = parent` = self-ref FK (D-G16 Bau-Wachpunkt 1: cycle — ignore that edge or DELETE-in-loop). PK-name per table from catalog (D-G17 REFINEMENT), NOT hardcoded `id`:
```sql
SELECT a.attname FROM pg_index i
JOIN pg_attribute a ON a.attrelid = i.indrelid AND a.attnum = ANY(i.indkey)
WHERE i.indrelid = %s::regclass AND i.indisprimary;
```

**Data-flow / role split (D-G18, Verbindungs-Karte — Punkt 22):**
- conftest imports it as **`nerve_app`, schema='public'** (peer socket, public has no RLS on catalog reads).
- deploy.sh wrapper calls it via `python -c` as **`postgres` peer**, schema='crm' (postgres bypasses RLS — sees all tenants for the leak-count). Catalog reads are role-agnostic (proven: SCHILD reads catalog as nerve_app, deploy.sh as postgres).

### 2. `tests/conftest.py` Auto-Reset split guard (MODIFY) — test-infra, event-driven

**Analog = the functions themselves (extend in place, D-G01/D-G02).**

**`_diff_baseline` (conftest.py:289-303) — ALREADY returns the 3-way split, just consume it differently:**
```python
def _diff_baseline(current, baseline):
    drift = {}
    for tbl, base_map in baseline.items():
        cur_map = current.get(tbl, {})
        cur_pks = set(cur_map)
        base_pks = set(base_map)
        leaked = cur_pks - base_pks
        missing = base_pks - cur_pks
        mutated = {pk for pk in (cur_pks & base_pks) if cur_map[pk] != base_map[pk]}
        if leaked or missing or mutated:
            drift[tbl] = {"leaked": leaked, "missing": missing, "mutated": mutated}
    return drift
```
> D-G02: `leaked` -> reverse-FK-DELETE + warn. `missing`/`mutated` -> hard `pytest.fail`. NO re-insert of missing (D-G02: re-insert fires `trg_mk_tenant_org` -> new UUID -> poisons follow-up tests).

**`_baseline_cleanup_guard` (conftest.py:343-368) — flip from fail-closed to auto-reset:**
```python
@pytest.fixture(autouse=True)
def _baseline_cleanup_guard(request, _baseline_snapshot, _baseline_guard_engine):
    yield
    if _baseline_snapshot is None or _baseline_guard_engine is None:
        return
    current = _snapshot_public_tables(_baseline_guard_engine)
    drift = _diff_baseline(current, _baseline_snapshot)
    if drift:
        parts = []
        for tbl, d in drift.items():
            parts.append(
                f"{tbl}: leaked={sorted(d['leaked'])}, missing={sorted(d['missing'])}, "
                f"mutated={sorted(d['mutated'])}"
            )
        pytest.fail(
            f"[BASELINE-GUARD] {request.node.nodeid}: PUBLIC-Baseline drifted -> "
            + " | ".join(parts)
        )
```
> NEW shape: split `drift` into `leaked` (auto-delete) vs `missing|mutated` (still `pytest.fail`). On leaked: log `[BASELINE-AUTO-FIX] {nodeid} leaked rows in {tbl}: {ids}` (D-G03), then DELETE via the order from `_schema_introspect`. D-G04: PUBLIC ONLY (crm stays POST-SUITE in deploy.sh).

**`_baseline_guard_engine` (conftest.py:306-321) — extend from read-only to read+write (D-G05 TX-hygiene):**
```python
@pytest.fixture(scope="session")
def _baseline_guard_engine():
    dsn = os.environ.get('TEST_DATABASE_URL')
    if not dsn:
        yield None
        return
    engine = create_engine(dsn)
    try:
        yield engine
    finally:
        engine.dispose()
```
> D-G05: auto-delete must run inside explicit `with engine.begin() as conn:` (commit-on-exit) so deleted rows are gone for the NEXT test. This is nerve_app peer, public-only, NOT a BYPASSRLS role (comment line 312).

**id::text uuid-cast pattern (D-G06) — copy verbatim from `cleanup_rows` (conftest.py:210 / 221-224):**
```python
cur.execute(f"DELETE FROM {tbl} WHERE id::text = ANY(%s)", ([str(x) for x in ids],))
# SQLAlchemy variant:
conn_or_session.execute(
    text(f"DELETE FROM {tbl} WHERE id::text = ANY(:ids)"),
    {"ids": [str(x) for x in ids]},
)
```
> 10e5d0a-fix: `id::text` carries int-PK (organisations/users/calls) AND uuid-PK (tenant_orgs) in one query — without it `operator does not exist: uuid = text`. Auto-reset replicates this exactly.

**Reverse-FK semantics to reuse — `cleanup_rows` (conftest.py:196-225)** orders by `_CLEANUP_FK_ORDER` then appends unknowns best-effort. Auto-reset uses the SAME delete loop, but the order now comes from `_schema_introspect` topo-sort (D-G19), not the hardcoded `_CLEANUP_FK_ORDER` list (conftest.py:114-130, which D-G17 replaces).

**COUPLING (D-G19, KRITISCH):** guard MUST consume list+order from the module — build the module FIRST (Wave 1), or the guard dies on its own cleanup with an FK violation.
