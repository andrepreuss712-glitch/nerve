# Phase 08.23.2.PGTEST.GREEN Plan 03: Triage-Harness — SUMMARY

**One-liner:** `scripts/triage.sh` provisioniert nerve_test per pg_dump-Restore 1:1 wie deploy.sh und laeuft targeted pytest via `bash -c '... pytest "$@"' _ "$@"` (Fund #5 Argument-Forwarding) ohne je zu deployen.

---

## Was wurde gebaut

`scripts/triage.sh` ist ein bleibendes Server-Triage-Werkzeug (Ratchet, Andre-Direktive 15.06.). Es:

1. Provisioniert eine Wegwerf-`nerve_test`-DB 1:1 wie der deploy.sh-Gate-Block:
   - (1) Whitelist-Guard `TEST_DB="nerve_test"` (Prod-Schutz D-02, Req-5/10)
   - (2) `trap cleanup EXIT` -> `DROP DATABASE IF EXISTS nerve_test` rueckstandsfrei
   - (3) Pre-Run-DROP (verwaiste nerve_test wegraeumen)
   - (4) `CREATE DATABASE nerve_test OWNER postgres` (NICHT nerve_app — crm-RLS-Treue)
   - (5) Schema-Dump `pg_dump --schema-only nerve | psql` MIT `set -o pipefail` (False-Green-Schutz)
   - (6) Stamp-Row-Dump `alembic_version` MIT `set -o pipefail`
   - (7) `alembic upgrade head` gegen nerve_test
   - (8) Dump-Treue-Katalog-Gate (crm-RLS-Policies >= 7, FORCE >= 5, anon-GRANTs >= 5)

2. Laeuft **nur die uebergebenen Tests** via:
   ```bash
   sudo -u nerve_app env ANON_PW="$ANON_PW" TEST_DB="$TEST_DB" bash -c '
     cd /opt/nerve/app && \
     DATABASE_URL="postgresql://nerve_app@/${TEST_DB}" \
     TEST_DATABASE_URL="postgresql://nerve_app@/${TEST_DB}" \
     NERVE_APP_TEST_DSN="postgresql://nerve_app@/${TEST_DB}" \
     NERVE_SCHILD_TEST_DSN="postgresql://nerve_app@/${TEST_DB}" \
     ANON_WORKER_TEST_DSN="postgresql://nerve_anon_worker:${ANON_PW}@127.0.0.1:5432/${TEST_DB}" \
     /opt/nerve/venv/bin/pytest "$@"
   ' _ "$@"
   ```
   Das `' _ "$@"` nach dem schliessenden single-quote reicht die aeusseren Argumente HART in die innere bash: `_` belegt `$0`, dann folgen `$1, $2, ...`. OHNE dieses Forwarding wuerde jeder Aufruf `bash scripts/triage.sh tests/test_x.py` die gesamte Suite laufen (Fund #5 Gemini-Re-Review R2).

3. **Deployt NIE**: kein `systemctl restart`, kein Deploy-Meta-Write, kein POST-SUITE-Check.
