## Background

PGTEST (Option-3-Schnitt, André 2026-06-16) lieferte das ehrliche PG-Tor + Infrastruktur (deploy.sh-Gate-Block mit pg_dump-Restore→Katalog-Treue-Gate→pytest→POST-SUITE→trap-Teardown, conftest-PG-Fixtures, Baseline-Wächter, SQLite-Entfernung) plus 2 echte Bug-Fixes (`6253676` Seed-Tenant-Leak, `10e5d0a` cleanup_rows uuid-PK). Das Tor blieb bewusst KNOWN-RED (Req-7 — NICHT maskiert), kein grüner Deploy, kein Restart, `nerve` auf Migration 0015.

Empirische Wurzel der verbleibenden Roten (Quelle: `08.23.2.PGTEST-CLOSEOUT-SUMMARY.md`):

1. **Suite-weite Baseline-Leak-Dimension** (Kern): **61 Test-Files** leaken über **11 public-Tabellen** (organisations, users, tenant_orgs, ewb_ratings, conversation_logs, revenue_log, api_cost_log, fixed_costs, prompt_versions, exchange_rates, profiles) → der globale fail-closed Baseline-Wächter (`_baseline_cleanup_guard`, conftest.py) verlangt, dass JEDER der ~600 Tests die GANZE public-Baseline pristine lässt. Die über viele Phasen gegen Wegwerf-SQLite (ohne Wächter) geschriebene Suite war nie so gebaut → ~507 errors. Das ist eine Architektur-/Design-Entscheidung (Plan-01), kein lokaler Fix.
2. **~22 phasen-eigene Port-Assertion-Fails** (Plan-03/04-Dateien: anonymizer_worker, postcall_split, postcall_outcome_route, eur_calculator, cost_tracker, ewb_pipeline, exchange_rates, dashboard_outcome_reminder) — Mischung aus echten App-Bugs und veralteten Tests (Triage hat bei statischem Raten 2× danebengelegen).
3. **~29 env-abhängige Tests** (real-Haiku-Integration, p95/Perf-Latenz, Re-ID-Rate) — gehören nicht in ein Deploy-Tor.
4. **Wächter-Tabellenlisten hardcoded** (André-Fund 2026-06-16, am Code verifiziert): `_BASELINE_PUBLIC_TABLES` (conftest.py:263-266), die reverse-FK-Cleanup-Liste (conftest.py:118-130) und der deploy.sh POST-SUITE crm-UNION (deploy.sh:195) sind hand-getippt → kennen `intent_event` (TAXO1) nicht und übersehen evtl. schon bestehende Tabellen (calls/objection_event/transcript_segments) → False-Green-Blindspot vor jedem TAXO-Deploy.

**Primäres Deliverable (existiert heute NICHT):** ein Mechanismus, der die suite-weite Leak-Dimension löst (Leaks sichtbar, Isolation erhalten), plus eine empirisch triagierte + policy-konforme Test-Suite und schema-abgeleitete Wächterlisten — sodass `deploy.sh production` exit 0 erreicht.

## Requirements

1. **Tor grün (Kern-Ergebnis)**: `deploy.sh production` läuft durch und führt den Restart aus.
   - Current: 4× brach `deploy.sh production` am pytest-Schritt ab (`51 failed, … 555 errors`) → kein `systemctl restart` → Prod-Service auf altem Code, `nerve` auf 0015.
   - Target: Ein vollständiger `deploy.sh production`-Lauf endet exit 0; der pytest-Schritt ist grün (modulo policy-erlaubter xfail, Req-6); der `systemctl`-Restart passiert; neuer Code wird live.
   - Acceptance: Ein `deploy.sh production`-Lauf endet exit 0; im Log erscheint der `systemctl restart` nach dem Gate; der trap-Teardown droppt `nerve_test`; die Prod-`nerve`-DB ist Schema-/Daten-unverändert.

2. **Suite-weite Baseline-Leak-Dimension gelöst (Ergebnis gelockt, Mechanismus offen)**: Der Lauf zeigt keine Baseline-Wächter-Leak-Reds/Errors mehr.
   - Current: 61 Files / 11 public-Tabellen / ~600 Tests → `_baseline_cleanup_guard` rot + POST-SUITE-Risiko → ~507 errors.
   - Target: Der globale fail-closed Baseline-Wächter wird so ersetzt/ergänzt, dass im Gate-Lauf 0 Baseline-Leak-Errors auftreten; nur noch echte Assertion-Fails sind das Tor-Kriterium. Der konkrete Mechanismus (Auto-Reset-Wächter vs. per-Test-Delta-Snapshot vs. Hybrid) ist bewusst NICHT hier festgelegt — er ist Plan-/Discuss-Stoff (siehe Req-4).
   - Acceptance: Im Gate-Log erscheinen 0 `_baseline_cleanup_guard`-Fails; der deploy.sh POST-SUITE-Check (crm.* == 0, training.transcript_archive == 0) ist grün; kein `error`-Eintrag stammt aus dem Baseline-Wächter-Pfad.

3. **Leak-Sichtbarkeit + Per-Test-Isolation erhalten (Req-7)**: Leaks werden laut gemeldet, nie stumm geschluckt; Tests vergiften sich nicht gegenseitig.
   - Current: Der Baseline-Wächter macht Leaks via fail-closed-Block sichtbar (laut, aber tor-blockierend).
   - Target: Welcher Test welche Extra-Rows hinterlässt, wird geloggt/gewarnt (z.B. `[PGTEST-…]`-Warnung mit Test-Identität); ein hinterlassener State eines Tests beeinflusst keinen anderen Test (keine Cross-Test-Vergiftung).
   - Acceptance: Ein absichtlich eingebauter Leak erzeugt eine sichtbare Warnung MIT Test-Identität im Log (nicht still); ein gezielter Beleg zeigt, dass zwei Tests, die dieselbe Tabelle nutzen, sich nicht beeinflussen.

4. **Isolations-Mechanismus Gemini-gegengelesen VOR Bau (Plan-01-Reversal)**: Die Mechanismus-Wahl wird Cross-AI geprüft, bevor sie gebaut wird.
   - Current: Plan-01s globaler fail-closed Baseline-Wächter ist Pro-verifiziert; die Umkehr dieser Entscheidung ist noch nicht reviewt.
   - Target: Die im Plan gewählte Isolations-Bauart wird von Gemini gegengelesen, BEVOR sie umgesetzt wird (kehrt eine Pro-verifizierte Plan-01-„fail-closed"-Entscheidung um → Punkt-24-Pflicht).
   - Acceptance: Ein Cross-AI/Gemini-Review-Artefakt zur Isolations-Mechanismus-Wahl existiert, ist im Plan referenziert und datiert VOR dem ersten Execute-Commit der Isolations-Änderung.

5. **~22 Port-Assertion-Fails empirisch triagiert**: Jeder Fail ist klassifiziert (nicht statisch geraten).
   - Current: ~22 Plan-03/04-Port-Assertion-Fails undifferenziert rot; statisches Raten lag hier 2× daneben.
   - Target: Jeder der ~22 Fails ist EMPIRISCH klassifiziert (Test ausgeführt/instrumentiert, nicht aus dem Code-Lesen geraten) als: (i) veralteter Test → gefixt, (ii) echter unkritischer Bug → xfail(strict)+Ticket (Req-6), oder (iii) echter kritischer Bug → BLOCK (Req-6).
   - Acceptance: Eine Triage-Tabelle (pro Test: Klassifikation + empirischer Beleg) existiert im Phasen-Verzeichnis; jeder als „veraltet" klassifizierte Test ist gefixt und grün; kein Fail bleibt unklassifiziert.

HARTE AUSNAHME — diese Klassen werden NIE ge-xfailed/ge-skippt, sie BLOCKEN das Tor rot bis gefixt (eigene Sofort-Phase): Sicherheit / DSGVO / Mandantentrennung (RLS Cross-Tenant) / Anonymisierungs-Leck / Datenverlust oder -korruption.
