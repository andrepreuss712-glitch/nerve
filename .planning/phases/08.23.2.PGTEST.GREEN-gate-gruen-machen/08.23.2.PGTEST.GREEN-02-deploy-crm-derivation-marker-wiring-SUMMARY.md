# Phase 08.23.2.PGTEST.GREEN Plan 02: deploy.sh crm-Derivation + Marker-Wiring Summary

## Was gebaut wurde

### Task 1: `scripts/_crm_leak_count.py` (NEU) + `deploy.sh` crm-Check dynamisiert

**`scripts/_crm_leak_count.py`** — postgres-peer-Wrapper (D-G16/D-G17/D-G18, Req-9 crm-Haelfte):

- Fuegt `_APP_ROOT` in `sys.path` ein (wie conftest.py:9-13) damit `tests._schema_introspect` aufgeloest wird
- Ruft `derive_baseline_tables(dsn, schemas=('crm',))` auf (Multi-Schema-Signatur aus Plan 01, Gemini-Re-Review R3 / Fund #8)
- Entpackt das Tupel vollstaendig: `table_list, _reverse_fk_delete_order, _foundation_register = derive_baseline_tables(...)` (Gemini-Fund #4 — nur `table_list` wird benoetigt, Rest intentionally ignored)
- Summiert **iterativ** `SELECT count(*) FROM {qualified_table}` pro crm-Tabelle in der katalog-abgeleiteten `table_list` (Gemini-Fund #4: eine Total-Zahl, kein UNION)
- Identifier ausschliesslich aus der katalog-abgeleiteten `table_list` (pg_tables `schemaname='crm'`) — NIE aus interpoliertem User-Input
- DSN via `DATABASE_URL`-Env (postgres peer: `postgresql://postgres@/$TEST_DB`)
- Gibt `print(total)` auf stdout aus (deploy.sh liest via `$(...)`)

**`deploy.sh` Aenderung (POST-SUITE-Block):**

- Zeile 195 ersetzt: hand-getippte `SELECT ... UNION ALL SELECT count(*) FROM crm.user_preferences ...` durch:
  `CRM_LEFTOVER=$(sudo -u postgres bash -c "cd /opt/nerve/app && DATABASE_URL=postgresql://postgres@/$TEST_DB /opt/nerve/venv/bin/python scripts/_crm_leak_count.py")`
- `[ "$CRM_LEFTOVER" = "0" ]`-fail-closed-Pruefung: **unveraendert erhalten** (D-G04: harter BLOCK bei crm != 0, KEIN Auto-Clean)
- `training.transcript_archive`-Check: **bleibt explizit single-table** (D-G04, ORM-los, non-public). Kommentar ergaenzt mit Begruendung (foundation_register, Req-7 — nicht still)
- KEIN bestehender Guard geschwaecht: Whitelist-Guard (TEST_DB=nerve_test), trap-DROP, pipefail, Dump-Treue-Katalog-Gate unveraendert

**Req-9-Beleg:** Eine frisch angelegte crm-Tabelle wuerde automatisch mit-gezaehlt — `derive_baseline_tables` liest dynamisch aus `pg_tables WHERE schemaname='crm'` -> `table_list` -> iterativer count. Kein deploy.sh-Hand-Edit noetig.
