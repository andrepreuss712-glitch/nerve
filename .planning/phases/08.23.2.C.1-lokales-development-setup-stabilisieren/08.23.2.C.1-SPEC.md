## Goal

Das lokale Development-Setup wird wieder vollstaendig benutzbar: Server startet, Alembic-Migrationen laufen automatisch, Login funktioniert ohne CSRF-Fehler, alle Hauptmenue-Punkte oeffnen ohne Crash, Live-Assistent und PiP starten ohne Server-Error.

## Background

**Heutiger Zustand (gescoutet 2026-05-19):**

Phase 08.23.2.A hat `_migrate()` dauerhaft deaktiviert fuer Postgres — lokal laeuft SQLite und bekommt keine Alembic-Migrationen mehr. Lokale `phrases`-Tabelle hat nur `['id', 'user_id', 'session_id', 'text', 'objection_type', 'created_at']` — `quality_tier` (Migration 0002) und `mode` (Migration 0003) fehlen. `alembic current` lokal: kein Stand. `alembic heads`: `0003`. Jeder Code-Pfad der diese Spalten liest, loest SQL-Error → Werkzeug-Server-Crash.

Weitere Baustellen (2026-05-15 Live-Beobachtung):
- `app.py` Z.54-58: CSRF-Abschaltung via Custom-ENV `WTF_CSRF_ENABLED=False` — provisorisch, nicht Flask-Standard
- `templates/marketing/landing.html`: 5 hardcoded `https://app.getnerve.app/`-Links (Login, 2x Google OAuth, 2x Microsoft OAuth)
- Live-Assistent lokal unzuverlaessig — Root-Cause undiagnostiziert
- Kein `docs/local-dev.md`

**Bereits gefixt (kein Handlungsbedarf):**
- `gliner>=0.2.24` in `requirements.txt` (Phase C)
- Postgres-Backup-Warning lokal: `/api/health` gibt `'ok'` wenn kein postgresql (C-6b-Fix)
- DB-Datei-Drift: nur `database/nerve.db` existiert

**Andre-Quote 2026-05-15:** "wie wollen wir einen vernuenftigen code schreiben wenn wir das nichtmal local ans laufen bekommen?"

## Requirements

1. **Auto-Alembic beim App-Start (SQLite)**: `alembic upgrade head` laeuft automatisch wenn die App mit SQLite startet.
   - Current: `_migrate()` macht `return` wenn DATABASE_URL mit `postgresql` startet — lokal laeuft kein Alembic; `phrases` fehlt `quality_tier` und `mode`
   - Target: `app.py` fuehrt `alembic upgrade head` aus wenn DATABASE_URL mit `sqlite://` startet. Idempotenz via Alembic-interner `alembic_version`-Tabelle. Skip auf Postgres unveraendert. Log: `[DB] Alembic SQLite upgrade head`
   - Acceptance: `python app.py` → `SELECT mode FROM phrases LIMIT 1` kein SQL-Error; `SELECT quality_tier FROM phrases LIMIT 1` kein SQL-Error; Server-Log enthaelt `[DB] Alembic SQLite`

2. **CSRF-Pattern auf FLASK_ENV=development**: Flask-Standard statt Custom-ENV-Variable.
   - Current: `app.py` Z.54-58 liest `WTF_CSRF_ENABLED` Custom-ENV-Variable
   - Target: Block ersetzt durch `if os.environ.get('FLASK_ENV') == 'development': app.config['WTF_CSRF_ENABLED'] = False`. `.env.example` dokumentiert `FLASK_ENV=development`. Production hat kein `FLASK_ENV=development` → CSRF aktiv.
   - Acceptance: `FLASK_ENV=development` in `.env` → Login-POST HTTP 200/302, kein 400; `.env.example` enthaelt Eintrag

3. **Landing.html Login-Links auf relative URLs**: 5 hardcoded Produktions-Links → relative Pfade.
   - Current: `templates/marketing/landing.html` Z.257, 601, 610, 655, 664 — alle `https://app.getnerve.app/...`
   - Target: Alle 5 Links: `/?modal=login`, `/auth/google`, `/auth/microsoft`
   - Acceptance: `localhost:5000` → "Einloggen"-Button oeffnet lokales Modal (kein Redirect auf app.getnerve.app)

4. **DB-Datei-Drift-Warnung beim App-Start**: Warnung wenn mehr als eine `*.db`-Datei in `database/`.
   - Current: Kein Check ob mehrere DB-Dateien parallel existieren
   - Target: `app.py` beim Start: `glob.glob('database/*.db')` → wenn >1: `print('[DB] WARNUNG: Mehrere .db-Dateien gefunden: ...')`. Kein Abbruch.
   - Acceptance: Zwei `*.db`-Dateien → Server startet, Log enthaelt `[DB] WARNUNG: Mehrere .db-Dateien`; Eine Datei → keine Warnung

5. **Live-Assistent oeffnet ohne Server-Crash lokal**: `/live` laedt, PiP startet ohne unhandled Exception.
   - Current: Klick auf Live-Assistent lokal unzuverlaessig, undiagnostiziert (durch Schema-Crashes bisher nicht reproduzierbar)
   - Target: Nach Req-1-Fix (Schema-Drift beseitigt): `/live` HTTP 200; "Anruf starten" → PiP oeffnet sich; kein Traceback im Server-Log. Diagnose-First gemaess CLAUDE.md Punkt 15 (Logging-Pass vor Fix-Code).
   - Acceptance: Login → `/live` → "Anruf starten" → PiP oeffnet sich; Server-Log kein Traceback/500

6. **`docs/local-dev.md` Setup-Dokument**: Setup-Anleitung + Cache-Hinweis + Pre-Deploy-Regel.
   - Current: Datei existiert nicht
   - Target: `docs/local-dev.md` mit drei Abschnitten: (1) Setup: `pip install -r requirements.txt`, `FLASK_ENV=development` in `.env`, Alembic laeuft automatisch beim Start; (2) Cache-Hinweis: "bei Asset-404 nach Server-Neustart → Strg+Shift+R oder Inkognito-Tab"; (3) Pre-Deploy-Pflicht: "vor deploy.sh min. 10 Min lokal ohne Crash testen"
   - Acceptance: `docs/local-dev.md` existiert mit allen drei Abschnitten

7. **Pre-Deploy-Pflicht-Hinweis in deploy.sh**: Kommentar der 10-Min-Local-Test-Pflicht dokumentiert.
   - Current: Kein Hinweis in `deploy.sh`
   - Target: `deploy.sh` Anfang enthaelt Kommentar: `# PFLICHT vor diesem Deploy: python app.py lokal min. 10 Min ohne Crash getestet`
   - Acceptance: `head -20 deploy.sh` enthaelt Hinweis mit "PFLICHT" und "lokal" und "10 Min"

- **CLAUDE.md Punkt 15 (Logging-First):** Live-Assistent-Diagnose MUSS mit Logging-Pass starten, kein Fix-Code ohne Diagnose-Output.
