# Phase 08.19.5.6.3: PiP-Briefing-Tab Cheat-Sheet-Format — Specification

**Created:** 2026-05-07
**Ambiguity score:** 0.088 (gate: ≤ 0.20)
**Requirements:** 5 locked

## Goal

Der PiP-Briefing-Tab rendert statt dem reinen `mdToHtml(text)`-Fließtext ein strukturiertes Cheat-Sheet: Eckdaten-Block (Kurz-Labels aus `fields`), Empfehlungen-Block (via `mdToHtml(empfehlungen)`), und den bisherigen Fließtext kollabiert hinter einem "Analyse aufklappen"-Toggle.

## Background

**Aktueller Zustand:** `pip-launcher.js:1930` setzt `contentEl.innerHTML = mdToHtml(state.precallBriefing.text || '')` — der gesamte Briefing-Tab zeigt nur den Schicht-2-Fließtext. Im Live-Call ist dieser Fließtext (bis 250 Wörter) schwer zu scannen; wichtige Daten (GF, Branche, Empfehlungen) sind nicht auf einen Blick sichtbar.

**Gap:** Kein strukturierter Eckdaten-Block, keine separate Empfehlungen-Sektion, kein kollabierter Fließtext.

**precallBriefing-Objekt-Schema (Backend, `precall_service.py`):**
- `firmenname` — string (bereits für Tab-Titel genutzt)
- `fields` — dict mit Pflichtfeldern `geschaeftsfuehrer`, `branche`, `mitarbeiterzahl`, `hauptprodukt` (je `{value, source_url, confidence}`); optionale Felder `standorte`, `gruendungsjahr`, `usp_positionierung`, `aktuelle_news` nur wenn confidence != `not_found`
- `empfehlungen` — string (Claude-generierte Markdown-Bullet-Liste, z. B. `"- Opener anpassen...\n- Schmerz ist Gold..."`) oder `''`
- `text` — string (Schicht-2-Fließtext, max ~250 Wörter)
- `ansprechpartner`, `quellen_count` (nicht im Cheat-Sheet genutzt)

**Expand/Collapse-Pattern:** Bereits vorhanden — `_expandBriefingTab()`/`_collapseBriefingTab()` via `pip-briefing-tab-body.style.maxHeight`. Das neue "Analyse"-Toggle nutzt dieses Pattern analog (eigene Sektion im `pip-briefing-tab-body`).

**Einziger Render-Pfad:** PiP-Tab wird nur in `_startCall()` (`pip-launcher.js:1918–1951`) befüllt — keine Multi-Pfad-Gefahr.

## Requirements

1. **Eckdaten-Block**: Die 4 Pflichtfelder aus `fields` werden als Kurz-Label:Wert-Zeilen gerendert, sofern confidence != `not_found`.
   - Current: Kein Eckdaten-Block — `fields` wird in der Tab-Render-Logik nicht ausgelesen
   - Target: `contentEl` zeigt zuerst einen Eckdaten-Block mit den Feldern `geschaeftsfuehrer → "GF"`, `branche → "Branche"`, `mitarbeiterzahl → "MA"`, `hauptprodukt → "Produkt"` in fester Reihenfolge. Felder mit `confidence === 'not_found'` werden komplett weggelassen (keine Leerzeile, kein "—").
   - Acceptance: Wenn `fields.geschaeftsfuehrer.confidence === 'not_found'`, erscheint kein "GF:"-Label im gerenderten HTML. Wenn `confidence !== 'not_found'`, erscheint `"GF: <value>"`.

2. **Empfehlungen-Block**: `empfehlungen`-String wird via `mdToHtml()` als eigene Sektion gerendert.
   - Current: `empfehlungen` wird in der Tab-Render-Logik nicht genutzt
   - Target: Wenn `empfehlungen.trim()` nicht leer ist: Sektion mit Überschrift "Empfehlungen" und `mdToHtml(empfehlungen)` als Inhalt. Wenn leer (`''` oder Whitespace): Empfehlungen-Sektion komplett weggelassen (keine leere Überschrift).
   - Acceptance: Bei `empfehlungen = ''` enthält `pip-briefing-tab-content` keinen Text/Element mit "Empfehlung". Bei `empfehlungen = "- Tip A\n- Tip B"` enthält `pip-briefing-tab-content` ein Element mit dem gerenderten Bullet-Text.

3. **Fließtext kollabiert**: Der bisherige Schicht-2-Fließtext (`text`) bleibt erhalten, aber hinter einem aufklappbaren Toggle.
   - Current: `mdToHtml(text)` wird direkt als `contentEl.innerHTML` gesetzt — immer sichtbar
   - Target: Fließtext ist initial unsichtbar (max-height: 0 oder display:none), ein "Analyse aufklappen ▼"-Button/Toggle macht ihn sichtbar. Das Toggle-Element nutzt das vorhandene maxHeight-CSS-Pattern analog zu `_expandBriefingTab()`/`_collapseBriefingTab()`.
   - Acceptance: Nach `_startCall()` ist der Fließtext im DOM vorhanden aber nicht sichtbar. Nach Klick auf den Toggle ist er sichtbar. Nach erneutem Klick wieder unsichtbar.

4. **nerve.css-Tokens**: Alle neuen Styles nutzen CSS-Variablen aus nerve.css — keine hardcodierten Farben.
   - Current: `pip-briefing-tab-header` hat `border-bottom:1px solid rgba(255,255,255,0.08)` als Inline-Style (Bestand — nicht anfassen)
   - Target: Neue Elemente (Trenner zwischen Sektionen, Toggle-Button-Styling) verwenden `var(--glass-border)` oder bestehende nerve.css-Klassen. Kein `color: #...` oder `background: rgba(...)` in neuem Code.
   - Acceptance: `grep -n "color:#\|background:#\|rgba(" pip-launcher.js` zeigt keine neuen Treffer in den neu hinzugefügten Zeilen dieses Render-Blocks.

5. **Kein Backend-Eingriff**: Die Phase ändert ausschließlich Frontend-Code.
   - Current: Backend liefert `fields`, `text`, `empfehlungen`, `firmenname` — vollständig
   - Target: Keine Änderung an `precall_service.py`, `app.py`, oder Routes
   - Acceptance: `git diff --name-only` nach Ausführung der Phase zeigt keine Python-Dateien als geändert.

## Boundaries

**In scope:**
- `static/pip-launcher.js` — Render-Logik in `_startCall()` für `pip-briefing-tab-content` (ca. Zeilen 1928–1932 ersetzen/erweitern)
- `templates/base.html` — ggf. neue HTML-Struktur für Fließtext-Toggle innerhalb `pip-briefing-tab-body` (wenn JS-only nicht ausreicht)
- `static/nerve.css` — neue Klassen für Eckdaten-Block / Empfehlungen-Sektion / Toggle-Button (falls noch nicht vorhanden)

**Out of scope:**
- Backend (`precall_service.py`, `app.py`, Routes) — Backend liefert alle nötigen Felder bereits
- Optionale `fields`-Felder (`standorte`, `gruendungsjahr`, `usp_positionierung`, `aktuelle_news`) — nicht im Cheat-Sheet (kein "nice-to-have" aus André-Hinweis: pragmatisch bauen)
- `ansprechpartner`-Feld im Cheat-Sheet — nicht im Phase-Design spezifiziert
- Visual-Polish (Farben, Spacing-Feintuning, Icons) — kommt in Block O Teil 2
- `pip-briefing-tab-header`-Bestand-Styles — nicht anfassen
- Neue Tests für die Render-Logik — die Render-Logik ist reines DOM-Manipulation-JS, kein Backend-Verhalten; UAT durch André nach Launch

## Constraints

- nerve.css-Tokens Pflicht für neue Styles (CLAUDE.md Anti-Hardcoded-Farben-Regel)
- Fließtext-Toggle-Pattern muss das vorhandene `maxHeight`-Muster nutzen (kein neues `<details>`/`<summary>` — das würde das bestehende Tab-Expand-Pattern inkonsistent machen)
- Keine Änderung am Tab-Header-Bestand (`pip-briefing-tab-header`, `pip-briefing-tab-icon`) — der bestehende Tab-Open/Close-Toggle bleibt wie er ist
- `empfehlungen` ist ein String, kein Array — kein `.forEach()`, kein `.length`-Check; Leer-Check via `!empfehlungen || !empfehlungen.trim()`

## Acceptance Criteria

- [ ] `pip-briefing-tab-content` zeigt GF/Branche/MA/Produkt als Kurz-Label:Wert-Zeilen wenn confidence !== 'not_found'
- [ ] Felder mit `confidence === 'not_found'` erscheinen nicht im gerenderten HTML (kein Leer-Label)
- [ ] Empfehlungen-Sektion erscheint wenn `empfehlungen.trim()` nicht leer ist; zeigt `mdToHtml(empfehlungen)` als Inhalt
- [ ] Empfehlungen-Sektion fehlt komplett wenn `empfehlungen` leer oder Whitespace
- [ ] Fließtext (`text`) ist initial nicht sichtbar (maxHeight: 0 oder display:none)
- [ ] Toggle-Button macht Fließtext sichtbar; zweiter Klick kollabiert ihn wieder
- [ ] Keine neu eingeführten hardcodierten Farben in den geänderten Zeilen (`var(--...)` oder Bestand-Inline-Styles)
- [ ] Keine Python-Dateien in `git diff --name-only` nach Ausführung der Phase
