## Implemented

### app.py — `_migrate_profile_json()` (85 neue Zeilen)

- **Advisory-Lock (Multi-Worker-Safety):**
  - SQLite: `conn.execute(text("BEGIN EXCLUSIVE"))` — verhindert Multi-Worker-Race beim Gunicorn-Start
  - PostgreSQL: `SELECT pg_advisory_xact_lock(819)` — sperrt bis Commit
- **Aufrufposition:** Nach `_seed_demo_profiles()` (Zeile 1877) — Profile existieren bevor migriert wird
- **Idempotenz:** `(daten.get('schema_version') or 1) >= 2` — None-safe, ueberspringt bereits migrierte Profile
- **ProfileOpener-Sync:** SELECT-vor-INSERT fuer opener/pitch (D-01, idempotent)
- **consent_text dual-write:** `_db_consent or ''` — NULL aus DB wird als leerer String geschrieben (D-04, Finding 4)

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] SQLite execution_options EXCLUSIVE nicht unterstuetzt**
- **Gefunden bei:** Task 1, erster Test-Lauf
- **Problem:** `engine.connect().execution_options(isolation_level='EXCLUSIVE')` wirft `ArgumentError` — SQLite akzeptiert nur `READ UNCOMMITTED`, `SERIALIZABLE`, `AUTOCOMMIT`
- **Fix:** `conn.execute(text("BEGIN EXCLUSIVE"))` direkt als SQL-Statement
- **Dateien:** app.py

**2. [Rule 1 - Bug] schema_version=None wirft TypeError bei >= Vergleich**
- **Gefunden bei:** Task 1, Integrations-Test auf echter DB
- **Problem:** Echte Profile haben `schema_version: null` (JSON None) — `daten.get('schema_version', 1)` gibt `None` zurueck (Key existiert, Default ignoriert), `None >= 2` wirft `TypeError`, bricht `for`-Loop lautlos ab
- **Fix:** `(daten.get('schema_version') or 1) >= 2` in app.py + `daten.get('schema_version') or 1` in `_migrate_profile_data`
- **Dateien:** app.py (Zeile 1287), services/profile_schema.py (Zeile 251)

**3. [Rule 1 - Bug] ProfileReadSchema schlaegt fehl auf echten Produktionsdaten durch Typ-Drift**
- **Gefunden bei:** Task 1, Verifikations-Assertion D-05
- **Problem:** Echte Profile (Profil 1 — NERVE Vertrieb) haben `nogos: List[dict]` (mit `kriterium`/`beschreibung` Keys), `ki.antwortlaenge`/`ki.sensitivitaet` (Extra-Felder), `zielgruppe.beruflicher_hintergrund: List[str]` statt `str` — alles Typ-Drift aus aelteren Profil-Versionen. `ProfileReadSchema(ProfileSchema)` erbt Write-Sub-Schemas mit `extra='forbid'`, ValidationError auf echten Daten.
- **Fix:** Eigenstaendige Read-Sub-Schemas mit `extra='ignore'` und `Any`-Typen; `ProfileReadSchema` als `BaseModel` (nicht Vererbung)
- **Dateien:** services/profile_schema.py

**4. [Rule 1 - Bug] _migrate_profile_json() Aufruf zu frueh (vor _seed_demo_profiles)**
- **Gefunden bei:** Task 1, DB-Zustand nach App-Import
- **Problem:** Urspruenglicher Plan sah Aufruf nach `_data_migrate()` vor (Zeile 1234) — zu diesem Zeitpunkt existieren Profile 1-4 noch nicht (werden erst von `_seed()` und `_seed_demo_profiles()` angelegt). Migration laeuft auf 0 Profilen, dann werden Profile ohne Migration angelegt.
- **Fix:** Kommentar an alter Stelle (Zeile 1336), tatsaechlicher Aufruf nach `_seed_demo_profiles()` (Zeile 1877)
- **Dateien:** app.py
