**Created:** 2026-05-21

## Goal

Das Gatekeeper-Modul wird von konzeptuell unmöglicher Auto-Erkennung (Single-Speaker-DSGVO-Constraint) auf einen klickbaren PiP-Toggle-Button umgebaut: Default beim PiP-Öffnen ist Sekretär-Modus, jeder Wechsel erzeugt einen `call_events`-Zeitstempel für Post-Call-Analyse.

## Background

**Architektur-Fehler aus Live-Test 2026-05-20:**
Phase 08.23.2.C implementierte automatische Gatekeeper-Erkennung via Stimm-Klassifikator (`classify_contact()`, `detect_trigger_phrases()`, `apply_hysteresis()`). Der Live-Test auf staging.getnerve.app deckte auf: NERVE Cold-Call ist Single-Speaker (DSGVO-Pflicht) — nur die Berater-Stimme wird erfasst. Der Klassifikator hört den Sekretär nie. Auto-Erkennung in den ersten 5 Sekunden ist konzeptuell unmöglich. Trigger-Phrasen-Erkennung greift nie (Sekretärs-Audio nie bei NERVE). CLAUDE.md Punkt 11 Modul-Rewrite-Trigger erfüllt (3+ Pflaster + Architektur-Drift).

## Requirements

1. **Auto-Erkennung löschen**: Alle automatischen Gatekeeper-Erkennungs-Aufrufe werden aus dem Live-Loop entfernt.
   - Current: `services/deepgram_service.py` ruft `detect_trigger_phrases()` und (`classify_contact()` via `gatekeeper.py`) automatisch bei jedem Transkript-Chunk auf. `services/gatekeeper.py` enthält `classify_contact()`, `apply_hysteresis()`, `detect_trigger_phrases()`.
   - Target: `deepgram_service.py` enthält keine Aufrufe von `detect_trigger_phrases()`, `classify_contact()`, `apply_hysteresis()`. Die Funktionen werden aus `services/gatekeeper.py` gelöscht. `gatekeeper.py` kann verbleiben oder entfernt werden wenn keine Restfunktionen genutzt werden.
   - Acceptance: `grep -rn "detect_trigger_phrases\|classify_contact\|apply_hysteresis" services/deepgram_service.py services/claude_service.py` → 0 Treffer im Live-Pfad.

2. **UWG-Hard-Block vollständig entfernen**: Erkennung, Banner, DOM und call_events-Handler werden gelöscht.
   - Current: `detect_uwg_hard_block()` in `gatekeeper.py` + Aufruf in `deepgram_service.py`. `pip-uwg-banner` DOM-Element in `base.html`. `_showUwgBanner()`, `_wireUwgBannerClose()` in `pip-launcher.js`. Entsprechender CSS-Block in `nerve.css`.
   - Target: `detect_uwg_hard_block()` gelöscht. `pip-uwg-banner` DOM, CSS und JS-Handler gelöscht. `call_events`-UWG-Handler in `deepgram_service.py` gelöscht.
   - Acceptance: `grep -rn "uwg\|UWG\|pip-uwg" static/pip-launcher.js templates/base.html services/deepgram_service.py static/nerve.css` → 0 Treffer (außer Kommentare in Planungsdateien).

3. **Ctrl+G / Ctrl+E Keyboard-Shortcuts entfernen**: Durch klickbaren Toggle-Button ersetzt.
   - Current: `document.addEventListener('keydown', ...)` Handler für Ctrl+G (gatekeeper) und Ctrl+E (target) in `pip-launcher.js:3492`.
   - Target: Keydown-Handler vollständig entfernt. Kein Tastatur-Kürzel für Modus-Wechsel.
   - Acceptance: `grep -n "ctrlKey\|Ctrl+G\|Ctrl+E\|keydown.*gatekeeper" static/pip-launcher.js` → 0 Treffer (für Modus-Toggle-Handler).

4. **Klickbarer Toggle-Button neben pip-mode-indicator**: Primäre Interaktion für Modus-Wechsel.
   - Current: `pip-mode-indicator` ist ein nicht-klickbares `<span>`. Modus-Wechsel nur via Ctrl+G/E.
   - Target: Ein `<button id="pip-mode-toggle-btn">` direkt neben `pip-mode-indicator` in `base.html`. Klick → `socket.emit('manual_mode_toggle', {category: ...})`. Anzeige wechselt zwischen "Sekretär ↔ Entscheider". Button-Stil via CSS-Token (kein Inline-Hex).
   - Acceptance: PiP zeigt Toggle-Button neben Modus-Indikator. Klick auf Button sendet `manual_mode_toggle`-Socket-Event. Kein zweiter Klick auf `pip-mode-indicator` selbst nötig.

5. **Default = Sekretär-Modus beim PiP-Öffnen**: Initaler State ist `gatekeeper`, nicht `cold_call`.
   - Current: `init_session_state()` in `live_session.py` setzt `contact_category='target'` oder kein Default. `base.html:562`: `data-mode="cold_call"`, Text "Cold-Call". PiP zeigt beim Öffnen Standard-EWB-Buttons.
   - Target: `init_session_state()` setzt `contact_category='gatekeeper'`, `current_mode='gatekeeper'`. `base.html` `pip-mode-indicator` initial: `data-mode="gatekeeper"`, Text "Sekretär". `_updateContactCategory()` wird beim PiP-Start mit `gatekeeper` aufgerufen → `_renderGatekeeperButtons()` direkt beim Öffnen.
   - Acceptance: (1) `pytest`: `init_session_state()['contact_category'] == 'gatekeeper'` AND `['current_mode'] == 'gatekeeper'`. (2) `pytest`: `/api/gatekeeper/phrases`-Aufruf mit Default-Session-State liefert 4 Gatekeeper-Buttons. (3) Manueller Browser-Test auf Staging: PiP ohne vorherigen Toggle öffnen → Indikator "Sekretär", Button-Row 4 Gatekeeper-Buttons. Screenshot in SUMMARY anhängen.

6. **Mode-Switch-Timestamp in call_events**: Jeder Toggle-Klick erzeugt einen persistierten Zeitstempel.
   - Current: `manual_mode_toggle`-Handler in `deepgram_service.py:723` setzt State und emittet Socket-Events, persistiert aber nichts in `call_events`.
   - Target: Bei jedem `manual_mode_toggle`-Event: `call_events`-Eintrag mit `event_type='mode_switch'`, `payload={'old_mode': str, 'new_mode': str, 'old_category': str, 'new_category': str, 'timestamp': monotonic()}` + `call_id` aus aktiver Session. Ermöglicht Post-Call-Phasen-Trennung und Trainings-Korpus-Aufbau.
   - Acceptance: `pytest`: nach simuliertem `manual_mode_toggle`-Event existiert ein `call_events`-Eintrag mit `event_type='mode_switch'` und allen 4 payload-Feldern.

7. **CSS-Token: pip-gatekeeper-bg / pip-gatekeeper-text**: Semantisch korrekter Token für Sekretär-Indikator.
   - Current: `.pip-mode-indicator[data-mode="gatekeeper"]` nutzt `var(--pipeline-warning-bg)` → `var(--warning-bg)` → `#f59e0b` (Amber). Inhaltlich falscher Token — Amber ist für Pipeline-Fehler-Warnings reserviert, nicht für Modus-Indikatoren.
   - Target: Neue Tokens in `nerve.css` `:root`: `--pip-gatekeeper-bg` + `--pip-gatekeeper-text` (Light-Mode-konform, nicht Amber). `.pip-mode-indicator[data-mode="gatekeeper"]` nutzt ausschließlich diese Tokens.
   - Acceptance: `grep "pip-gatekeeper" static/nerve.css` → ≥2 Treffer (Token-Definition + Klassen-Verwendung). `grep "pipeline-warning" static/nerve.css` → 0 Treffer im `pip-mode-indicator`-Block.

8. **pip-launcher.js Hex-Sweep (Dark-Mode-Reste)**: Alle identifizierten hardcoded Hex-Farben in pip-launcher.js werden durch CSS-Token ersetzt.
   - Current: Drei Dark-Mode-Reste + ein Light-Mode-Hardcode in `pip-launcher.js`: Z.1226 `color:#06060a` (button text), Z.2582 `rgba(255,255,255,0.1);color:#c5c9d4` (default badge — auf light background unsichtbar/falsch), Z.1710 `body.style.background = '#F8FAFC'` (PiP body background). SVG-inline-strokes (`#00D4AA`) bleiben — SVG-CSS-Cascade greift nicht.
   - Target: Z.1226: `color:var(--btn-primary-text)`. Z.2582: `var(--badge-default-bg)` + `var(--badge-default-text)` (neue Tokens in nerve.css). Z.1710: `var(--pip-bg)` (neuer Token in nerve.css). Alle drei neuen Tokens in nerve.css `:root` definiert (Light-Mode-konform).
   - Acceptance: `grep -n "#06060a\|rgba(255,255,255,0.1)\|#F8FAFC" static/pip-launcher.js` → 0 Treffer. `grep "pip-bg\|badge-default" static/nerve.css` → ≥2 Treffer.

   - Current: `_updateContactCategory()` in `pip-launcher.js:2446` gibt `'Vorzimmer'` als Label für gatekeeper-mode aus. `pip-mode-indicator` DOM-Text kann "Vorzimmer" anzeigen.

- **CSS-Pflicht:** Ausschließlich `var(--...)` Tokens in neu geänderten oder hinzugefügten Stil-Regeln — keine hardcoded Hex in Komponenten-Klassen oder JS-style-Assignments

- **DSGVO Single-Speaker:** Kein Code der davon ausgeht Sekretärs-Audio zu empfangen — diese Constraint muss auch in Kommentaren/Docs sichtbar bleiben als Begründung für den manuellen Toggle.
- **Haiku Live-Loop:** Kein Claude-Modell-Aufruf für Modus-Erkennung in Phase C.R — Toggle ist rein clientseitig + Socket.
- **Alembic-Chain:** Migration 0003 bleibt unverändert. Kein Schema-Bump durch C.R. Falls `mode_switch` ein neuer `event_type` sein muss der im CHECK-Constraint steht: prüfen ob bereits abgedeckt (aktueller Stand: `call_events.event_type` hat CHECK-Constraint aus Phase 08.23.2.C).
