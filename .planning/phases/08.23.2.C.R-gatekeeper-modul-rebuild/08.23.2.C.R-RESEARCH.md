## Summary

Phase 08.23.2.C.R ist ein Code-Prune + Umbau ohne externe Abhängigkeiten. Die Codebase wurde vollständig analysiert — alle zu löschenden Stellen, alle zu ändernden Stellen und alle neuen Stellen sind mit exakten Zeilen identifiziert.

**Zentrale Erkenntnis:** Die Auto-Erkennung ist an ZWEI Stellen verdrahtet — `deepgram_service.py` (detect_trigger_phrases + detect_uwg_hard_block pro Transkript-Chunk, Z.118-191) und `claude_service.py` (classify_contact + apply_hysteresis im Analyse-Loop, Z.1082-1183). Beide Stellen müssen bereinigt werden, um den Acceptance-Grep sauber zu machen. Die SPEC.md nennt nur deepgram_service.py explizit, aber der Acceptance-Grep schließt auch claude_service.py ein.

**Migration 0004:** Der aktuelle CHECK-Constraint lautet `event_type IN ('transcript_chunk', 'suggestion_shown', 'reaction', 'phase_change', 'audio_health', 'objection_detected', 'consent_optin')` (models.py Z.688). Weder `mode_switch` noch `mode_initial` sind enthalten. PostgreSQL wird INSERTs mit diesen event_types blockieren — SQLite schweigt. Migration 0004 muss den Constraint droppen und neu anlegen.

**Test-Cleanup ist obligatorisch:** Zwei Testdateien importieren direkt aus services.gatekeeper: `tests/test_gatekeeper_classifier.py` (classify_contact, detect_trigger_phrases, detect_uwg_hard_block) und `tests/test_hysteresis.py` (apply_hysteresis). Beide Testdateien testen Funktionen die gelöscht werden — sie müssen komplett entfernt oder radikal umgeschrieben werden. Eine dritte Datei `tests/test_phase_classifier.py` importiert apply_hysteresis für einen State-Mutation-Test.

**Primäre Empfehlung:** Löschen zuerst (Tasks 1-4), dann Hinzufügen (Tasks 5-9). Begründung: Sauberer diff, Acceptance-Greps laufen nach Löschen bereits grün, Hinzufügen auf bereinigter Basis.

**Chain-Stand:** 0001 (no-op marker) → 0002 (quality_tier) → 0003 (phrases.mode) → 0004 (call_events CHECK)

**render_as_batch=True bereits aktiv** in env.py (Z.30 + Z.47) — SQLite-safe.

**Migration 0004 — Soll-Inhalt:**
```python
"""add mode_switch and mode_initial to call_events event_type check constraint

Revision ID: 0004
Revises: 0003
Create Date: 2026-05-21

Phase 08.23.2.C.R: Gatekeeper-Modus-Toggle ersetzt Auto-Erkennung.
mode_switch: Manueller Toggle durch Berater (manual_mode_toggle Socket-Handler).
mode_initial: Startmodus bei Call-Anlage (create_call_for_sid).
"""
from alembic import op

revision = '0004'
down_revision = '0003'
branch_labels = None
depends_on = None


def upgrade() -> None:
    # PostgreSQL: DROP + RECREATE (einzige Methode für CHECK-Constraint-Änderung)
    # SQLite: render_as_batch=True in env.py übernimmt CREATE+COPY+DROP automatisch
    op.execute("ALTER TABLE call_events DROP CONSTRAINT IF EXISTS ck_call_events_event_type")
    op.execute(
        "ALTER TABLE call_events ADD CONSTRAINT ck_call_events_event_type "
        "CHECK (event_type IN ("
        "'transcript_chunk', 'suggestion_shown', 'reaction', 'phase_change', "
        "'audio_health', 'objection_detected', 'consent_optin', "
        "'mode_switch', 'mode_initial'"
        "))"
    )


def downgrade() -> None:
    op.execute("ALTER TABLE call_events DROP CONSTRAINT IF EXISTS ck_call_events_event_type")
    op.execute(
        "ALTER TABLE call_events ADD CONSTRAINT ck_call_events_event_type "
        "CHECK (event_type IN ("
        "'transcript_chunk', 'suggestion_shown', 'reaction', 'phase_change', "
        "'audio_health', 'objection_detected', 'consent_optin'"
        "))"
    )
```

**Achtung SQLite:** `DROP CONSTRAINT IF EXISTS` ist kein gültiges SQLite-SQL. Mit `render_as_batch=True` wandelt Alembic `op.execute()` NICHT um — nur Alembic-eigene Operationen wie `op.drop_constraint()` / `op.add_constraint()` werden durch batch-mode umgewandelt. Die Migration muss daher Alembic-Operationen verwenden, NICHT raw SQL für den Constraint-Teil:

```python
def upgrade() -> None:
    with op.batch_alter_table('call_events') as batch_op:
        batch_op.drop_constraint('ck_call_events_event_type', type_='check')
        batch_op.create_check_constraint(
            'ck_call_events_event_type',
            "event_type IN ("
            "'transcript_chunk', 'suggestion_shown', 'reaction', 'phase_change', "
            "'audio_health', 'objection_detected', 'consent_optin', "
            "'mode_switch', 'mode_initial'"
            ")"
        )
```

Diese Form funktioniert sowohl auf PostgreSQL (direkt) als auch SQLite (via render_as_batch).

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| CHECK-Constraint auf SQLite ändern | Raw ALTER TABLE SQL | Alembic batch_alter_table mit drop_constraint + create_check_constraint | render_as_batch=True transformiert Alembic-Ops automatisch, raw SQL wird nicht transformiert |
| Button-Reset für span→button Migration | Eigene CSS-Reset-Regeln erfinden | Standard-CSS button-Resets (border:none, background:inherit, font-family:inherit) | Browser-Defaults für button sind komplex (border, background, font) — ohne Reset sieht der Button falsch aus |
| PostgreSQL CHECK-Constraint-Änderung | ALTER TABLE MODIFY (existiert nicht in PostgreSQL) | DROP CONSTRAINT + ADD CONSTRAINT | PostgreSQL hat kein MODIFY CONSTRAINT |

## Common Pitfalls

### Pitfall 1: render_as_batch greift nicht auf op.execute()
**Was schiefläuft:** Migration schreibt `op.execute("ALTER TABLE call_events DROP CONSTRAINT...")` — läuft auf PostgreSQL, crasht auf SQLite mit "Cannot drop constraint."
**Warum:** render_as_batch=True transformiert nur Alembic-Op-Aufrufe (op.drop_constraint, op.add_column etc.), nicht raw SQL in op.execute().
**Vermeidung:** Constraint-Operationen ausschließlich via `batch_alter_table()` Context Manager mit `batch_op.drop_constraint()` + `batch_op.create_check_constraint()`.

### Pitfall 2: mode_initial-INSERT fehlt call_id im Timing-Fenster
**Was schiefläuft:** create_call_for_sid() schreibt call_id in _session_state, aber der mode_initial-INSERT liest call_id aus dem State statt die lokale Variable `cid` zu nutzen.
**Warum:** Zwischen State-Write und mode_initial-INSERT könnte (theoretisch) pop_session_state() laufen.
**Vermeidung:** mode_initial-INSERT nutzt die lokale Variable `cid` direkt (nicht aus _session_state lesen), da `cid` am gleichen Stack-Frame verfügbar ist.

### Pitfall 3: uwg_blocked-Key bleibt in init_session_state
**Was schiefläuft:** uwg_blocked Key wird in init_session_state nicht entfernt. Code der den Key liest (z.B. noch unbereinigtes deepgram_service.py) funktioniert zufällig — bis jemand explizit prüft ob der Key noch existiert.
**Vermeidung:** uwg_blocked-Key aus init_session_state() LÖSCHEN (Z.368: `'uwg_blocked': False`). Grepping nach 'uwg_blocked' nach Refactor.

### Pitfall 4: pip-mode-indicator Button-Reset fehlt
**Was schiefläuft:** `<button>` ohne CSS-Reset hat sichtbaren Browser-Default-Rahmen, anderen Font und anderen Background — sieht nicht wie der alte span aus.
**Vermeidung:** Expliziter CSS-Reset für #pip-mode-indicator: `border: none`, `background: var(--glass-bg)`, `font-family: inherit`, `font-size: 11px`, `font-weight: 600`.

### Pitfall 5: aria-label statisch statt dynamisch
**Was schiefläuft:** aria-label="Modus wechseln zu Entscheider" wird im HTML hardcoded und nie aktualisiert — nach Toggle-Klick zeigt der Screen-Reader noch die alte Richtung.
**Vermeidung:** _updateContactCategory() (pip-launcher.js Z.2440) aktualisiert neben textContent auch das aria-label dynamisch:
```javascript
if (indicator) {
    indicator.dataset.mode = mode;
    var label = (mode === 'gatekeeper') ? 'Sekretär' : 'Entscheider';
    indicator.textContent = label;
    indicator.setAttribute('aria-label', 
        'Modus wechseln zu ' + ((mode === 'gatekeeper') ? 'Entscheider' : 'Sekretär'));
}
```

### Pitfall 6: Claude-Service-Block wird vergessen
**Was schiefläuft:** deepgram_service.py bereinigt, aber claude_service.py Z.1082-1183 noch nicht. Acceptance-Grep gibt 0 Treffer in deepgram_service.py aber nicht für claude_service.py.
**Vermeidung:** SPEC.md Acceptance-Criterion lautet: `grep -rn "detect_trigger_phrases\|classify_contact\|apply_hysteresis" services/deepgram_service.py services/claude_service.py` — beide Dateien im Grep! Claude-Service-Block explizit als eigene Task im Plan.
