### D-02: spaCy-Modell & Sprache

- **Modell:** `de_core_news_lg` — per Architektur-Konsolidierung Sektion B-3 explizit verankert
- **Begründung:** Word-Vectors helfen bei OOV-Eigennamen (Firmen-Namen, Branchen-Spezial-Begriffe). sm/md ohne Word-Vectors haben ~5-8% niedrigere Re-ID-Robustheit im Vertriebs-Kontext. Re-ID-Test-Schwellenwert <5% steht oder fällt mit dem Modell-Typ.
- **Sprache:** Nur Deutsch. Englisch für Training-Szenarien ist eigene Folge-Phase.
- **RAM-Footprint:** ~700MB (lg) + ~700MB (gunicorn + App) = ~1.4GB gesamt. Passt auf Hetzner CX22 (4GB RAM, 2.5GB Puffer verbleiben).
- **Startup-Zeit:** ~3-5 Sek längere App-Start-Zeit. Akzeptabel (Service-Restart selten).
- **Lading:** Lazy-Load via Modul-Init oder `@lru_cache`. Einmal geladen, bleibt im Prozess-Memory.
- **Installation:** `pip install spacy && python -m spacy download de_core_news_lg`

### D-03: Token-Format & AnrufAnonymisierer-Klasse

Per Architektur-Konsolidierung Sektion B-5:

- **Token-Format:** `[PERSON_A]`, `[ORG_B]`, `[LOC_C]` — Buchstaben-suffixed, per Auftritts-Reihenfolge vergeben
- **Zwei verschiedene Personen im selben Anruf:** `[PERSON_A]`, `[PERSON_B]` — Person-Bezüge bleiben erhalten ('`[PERSON_A]` hat `[PERSON_B]` das Angebot weitergegeben' bleibt verständlich)
- **Briefing-PII zuerst:** `register_briefing_pii(briefing_data, cache)` direkt nach Cache-Erstellung → bekommt A, B, ... Buchstaben. Live-Mitschrift-Treffer kommen danach.
- **Cross-Session-Unabhängigkeit:** 'Herr Müller' ist in Anruf 1 `[PERSON_A]`, in Anruf 2 evtl. `[PERSON_B]`. Bewusst: verhindert Cross-Session-Aggregation ('wie oft kommt Müller vor').
- **Cache niemals persistiert:** nur RAM. Never in DB, Redis, oder Logs.
- **Erweiterung bei >26 Treffern:** `[PERSON_AA]`, `[PERSON_AB]`, ...

```python
class AnrufAnonymisierer:
    def __init__(self):
        self._lock = threading.Lock()
        self.mapping = {}   # 'Müller' -> '[PERSON_A]'
        self.counters = {'PERSON': 0, 'ORG': 0, 'LOC': 0}

    def get_or_assign_token(self, entity_text: str, entity_type: str) -> str:
        with self._lock:
            if entity_text in self.mapping:
                return self.mapping[entity_text]
            idx = self.counters[entity_type]
            suffix = chr(ord('A') + idx) if idx < 26 else f'A{idx - 25}'
            token = f'[{entity_type}_{suffix}]'
            self.mapping[entity_text] = token
            self.counters[entity_type] += 1
            return token
```

### D-04: Art-9-Filter (Dritter Pipeline-Schritt)

Per Architektur-Konsolidierung Sektion B-4: Keyword-Listen statt Mini-Klassifikator.

- **Implementierung:** `services/art9_keywords.py` mit `Dict[str, List[str]]` nach Kategorie
- **Kategorien (~175 Keywords total):**
  - Gesundheit: Krankheit, Diagnose, Symptom, Arzt, Klinik, Medikament, Therapie, Behandlung, Schwangerschaft, Allergie, Diabetes, Krebs, HIV, Aids, Depression, Burnout, ... (~50 Keywords)
  - Religion: katholisch, evangelisch, muslimisch, jüdisch, buddhistisch, Konfession, Kirche, Moschee, Synagoge, ... (~30 Keywords)
  - Gewerkschaft: Gewerkschaft, IG Metall, Verdi, Betriebsrat, Streik, Tarif, ... (~20 Keywords)
  - Sexuelle Orientierung: schwul, lesbisch, homosexuell, bisexuell, queer, LGBTQ, ... (~15 Keywords)
  - Politische Überzeugung: CDU, SPD, Grüne, FDP, AfD, Linke, Konservativ, Sozialist, Wähler, Partei, ... (~30 Keywords)
  - Ethnische Herkunft: Migrationshintergrund + kuratierte Identifikations-Marker mit Kontext-Regeln (~30 Keywords)
- **Ersetzung:** Bei Treffer → ganzer Snippet wird `[ART9_REDACTED]` (nicht nur das Treffer-Wort). Satz-Kontext geht verloren aber das ist DSGVO-Pflicht.
- **False-Negative-Rate:** MUSS 0% sein (anders als Re-ID wo <5% akzeptabel ist)
- **BayLDA-Auditierbarkeit:** Keyword-Liste ist transparenter als Mini-Classifier

### D-05: Pipeline-Interface & quality_tier

```python
def anonymize(text: str, cache: AnrufAnonymisierer) -> Tuple[str, str]:
    """
    Returns: (anonymized_text, quality_tier)
    quality_tier='A': sauber anonymisiert, keine Art-9-Treffer, hohe NER-Confidence
    quality_tier='B': sauber anonymisiert, einige Edge-Cases (unsichere NER-Treffer)
    quality_tier='C': Art-9-Treffer → '[ART9_REDACTED]', oder Pipeline-Exception → '[ANON_FEHLER]'
    """
    # Schritt 1: Regex-Vorfilter (E-Mail, Telefon, IBAN, etc.)
    # Schritt 2: spaCy NER (PERSON/ORG/LOC → Token-Cache)
    # Schritt 3: Art-9-Keyword-Scan
    # Wenn Art-9-Treffer: return ('[ART9_REDACTED]', 'C')
    # Sonst: return (text_anonymized, 'A' oder 'B')
```

- **`quality_tier`-Spalte:** Neue Alembic-Migration in 08.23.2.B
  - `Phrase.quality_tier VARCHAR(1) NOT NULL DEFAULT 'A'`
  - `CallEvent`-Payload: quality_tier als Feld im JSONB (kein separates Column)
  - Weitere Tabellen (ConversationLog): Plan-Author entscheidet nach Insert-Stellen-Audit
- **DPO-Training-Konsequenz (Phase 08.23.2.E):** `dpo_pairs`-Sammler filtert `WHERE quality_tier IN ('A', 'B')`
- **'[ART9_REDACTED]'** vs **'[ANON_FEHLER]'** — unterschiedliche Tokens für Art-9-Treffer vs. Pipeline-Exception, damit DB-Review unterscheidbar ist

### D-06: Token-Cache-Lifecycle

- **Erstellung:** Bei Session-Start (SocketIO `start_live_session` Event-Handler). Gespeichert in `ls._session_state[sid]['anonymizer']`
- **Briefing-Vorbefüllung:** Sofort nach Erstellung: `register_briefing_pii(state['precall_briefing'], cache)` wenn Briefing im Session-State vorhanden
- **Löschung** — drei Trigger:
  1. `session_end` Event (regulärer Anruf-Ende)
  2. `disconnect` Event (Browser-Tab geschlossen, Netzwerk-Verlust)
  3. 30-Minuten-Stale-Timeout (verhindert Memory-Leak bei vergessenen Sessions)
  - Cleanup: `del ls._session_state[sid]['anonymizer']` — nie persistiert
- **Reconnect:** Neuer leerer Cache + Briefing-Re-Registrierung. Token-Neuvergabe (A, B neu) — akzeptables Risiko per Architektur-Konsolidierung B-5
- **Process-Restart:** Cache weg, Calls brechen eh ab, neuer Cache bei Reconnect — kein fail-open
- **Thread-Safety:** `threading.Lock()` im Instanz-Konstruktor. Pro `session_id` isolierte Instanz. Kein Inter-Session-Konflikt.
- **Debug-Logging:** `[ANON] Token assigned: ... -> [PERSON_A]` nur auf DEBUG-Level. Niemals Klartext-PII im Production-Log.

### D-08: Fallback-Verhalten bei Pipeline-Fehler

**Kategorie A — Modell-Lade-Fehler (kritisch, fail-safe):**
- Auslöser: spaCy `de_core_news_lg` nicht ladbar beim App-Start
- `services/anonymization.py` setzt `is_pipeline_healthy = False`
- `anonymize()` + `anonymize_output()` raisen `AnonymizationPipelineUnavailable`-Exception
- Alle Mitschrift-Schreib-Stellen fangen Exception → KEIN INSERT, Buffer verworfen
- Live-Call läuft weiter (Audio + EWB-Buttons), aber Mitschrift wird NICHT persistiert
- `/api/health` → `pipeline_status='unavailable'`
- Dashboard zeigt **roten** Hinweis-Streifen: "Anonymisierungs-Pipeline gestört — Anruf-Aufzeichnung temporär ausgesetzt."

**Kategorie B — Einzel-Snippet-Exception (non-critical, fail-open mit Marker):**
- Auslöser: anonymize() wirft bei konkret einem Snippet (Unicode-Edge-Case, pathologisch langer String, etc.)
- Return: `('[ANON_FEHLER]', 'C')` — KEIN Klartext in DB
- Exception in Server-Log mit Stack-Trace, ohne Snippet-Text (nur Snippet-Länge + Exception-Typ)
- `quality_tier='C'` verhindert DPO-Training-Nutzung
- Live-Call läuft weiter, nächste Snippets normal

**Kategorie C — Rolling-Error-Schwellenwert:**
- Auslöser: >5 Snippet-Exceptions in 10 Minuten (konfigurierbar via Env-Variable)
- `/api/health` → `pipeline_status='degraded'` plus `error_count_10min`
- Dashboard zeigt **gelben** Hinweis-Streifen: "Anonymisierungs-Pipeline produziert vermehrt Fehler (X Snippets mit Tier C in 10 Min)."

**Test-Pflicht für Kategorie A+B+C:**
- Test A: Mock spaCy-Lade-Fehler → `/api/health` `unavailable`, 0 neue `conversation_logs`-Einträge, Banner sichtbar
- Test B: Mock Snippet-Exception → `text='[ANON_FEHLER]'`, `quality_tier='C'`, andere Snippets unverändert
- Test C: 6 Snippet-Exceptions in 10 Min → `/api/health` `degraded`, gelbes Banner
