## Goal

Phase 08.23.2.D liefert die technische Foundation (Classifier, Schema, DB-Persistierung). Phase D.UX macht daraus eine UX, die tatsächlich genutzt wird: Outcome-Erfassung als Pflicht-Schritt vor dem Score-Reveal, ein Score-Modell das den Outcome als Multiplikator einbaut, Security-Fixes aus dem Code Review, und Classifier-Qualitäts-Verbesserungen — 4 Waves mit expliziten Live-Test-Kriterien.

## Background

**Was existiert nach Phase 08.23.2.D (Production 2026-05-27):**
- `calls`-Tabelle: `outcome`, `outcome_confidence`, `outcome_note`, `outcome_source`, `audio_health_score`
- Haiku-Classifier in `services/outcome_service.py` — klassifiziert Post-Call
- Dreistufige Outcome-UX im PiP: Auto-Ring 30s (ai_auto), Badge+Ring (ai_auto_unsicher), Korrektur-Modal (low-conf) — als floating Overlay
- Dashboard Inline-Korrektur: Unsicher-Dot + 5-Button-Accordion bei `outcome_source='ai_auto_unsicher'`
- `_calcScore()` in `pip-launcher.js`: process_score 0-100 (kb_end×0.4 + behandelt_rate×0.3 + redeanteil×0.2 + skript×0.1)

**Was fehlt / falsch ist:**

*Security (Code-Review CR-01/CR-02/WR-01/WR-02, IN-03):*
- `dashboard.html:865` — `correct_outcome` POST ohne `X-CSRFToken`-Header (CR-01 CRITICAL)
- `_audio_health_bg` schreibt `audio_health_score` ohne `user_id`-Ownership-Filter auf fremde Calls (CR-02 CRITICAL)
- `or_()` SQLAlchemy-Muster in Dashboard-Reminder-Query falsch (Pipe-Operator statt `or_()`) — WR-01
- `_buildRecommendations()` rendert Strings ungefiltert als HTML (XSS) — WR-02
- Debug-Print-Block in `app_routes.py:488-494` in Production-Pfad — IN-03

*Klassifikations-Qualität (Wave 2):*
- Haiku-Prompt ist generisch — klassifiziert "Dienstag 14 Uhr + Kalender-Einladung" als "Kein Interesse" (Live-Bug 2026-05-27)
- `outcome_service.py` hat keine Snippet-Heuristik (leerer Input geht zu Haiku statt sofort `unknown`)
- WR-03: Confidence-Boundary-Kommentar weicht von Code-Verhalten ab

*UX (Wave 3):*
- Outcome erscheint nebenher — "wenn es nebenher beim scoring irgendwo im pip auftaucht wird es keine sau jucken" (André 2026-05-27)
- 30s-Auto-Confirm-Countdown: User ignoriert Outcome-Sektion
- Score sichtbar GLEICHZEITIG mit Outcome — kein Pflicht-Flow

*Score-Architektur (Wave 4):*
- `_calcScore()` ignoriert Outcome komplett
- Kein `calls.coaching_score` Feld — Score nie persistiert
- Dashboard Edit-Knopf fehlt für nachträgliche Korrektur aller Calls

## Requirements

### Wave 1: Security-Fixes

1. **CSRF-Fix correct_outcome POST**: `dashboard.html:865` sendet `X-CSRFToken`-Header.
   - Current: POST ohne CSRF-Token — jede authentifizierte Session kann outcome überschreiben
   - Target: Header ergänzt um `'X-CSRFToken': document.querySelector('meta[name="csrf-token"]').getAttribute('content')` — analog `pip-launcher.js`
   - Acceptance: DevTools Network-Tab zeigt `X-CSRFToken`-Header in POST nach Klick auf Inline-Korrektur

2. **Ownership-Filter audio_health_bg**: Thread erhält `user_id`-Parameter; Query filtert `Call.user_id == user_id`.
   - Current: `db.query(Call).filter(Call.id == call_id)` — kein User-Ownership-Check
   - Target: Thread-Signatur: `_audio_health_bg(call_id, user_id, ...)`; Query: `filter(Call.id == call_id, Call.user_id == user_id)`
   - Acceptance: POST auf `/api/calls/<fremde-uuid>/correct_outcome` mit falscher Session → 404 (curl-Test)

3. **SQLAlchemy or_() Fix**: Dashboard-Reminder-Query nutzt `or_()` aus `sqlalchemy import or_`.
   - Current: `(Call.outcome_source == 'ai_auto_unsicher') | (Call.outcome.is_(None))` — Pipe-Operator kein ORM-OR
   - Target: `or_(Call.outcome_source == 'ai_auto_unsicher', Call.outcome.is_(None))`
   - Acceptance: SQL-Log zeigt korrekte OR-Logik; Dashboard-Reminder-Stripe erscheint korrekt

4. **XSS-Fix Recommendations-Renderer**: `_buildRecommendations()` escaped alle User-facing Strings via `escHtml()`.
   - Current: Strings direkt als `.innerHTML` eingefügt
   - Target: Alle Strings durch vorhandenes `escHtml()` aus `pip-launcher.js` bevor DOM-Insert
   - Acceptance: `<img src=x onerror=alert(1)>` in Recommendation → als Text gerendert, kein Script

5. **Debug-Print-Cleanup**: Block `app_routes.py:488-494` entfernt.
   - Current: `print('[Phase08.23.2.D] DEBUG Lookup: ...')` auf jedem `api_beenden`-Call
   - Target: Block entfernt
   - Acceptance: `grep "[Phase08.23.2.D] DEBUG Lookup"` in journalctl nach Deploy = 0 Treffer

### Wave 2: Klassifikations-Qualität

6. **Snippet-Heuristik in outcome_service.py**: Edge-Cases vor API-Call abfangen.
   - Current: Jedes Input-Snippet → Haiku, auch leere Texte
   - Target: (a) leerer Input → `{outcome: 'unknown', confidence: 0.0}` sofort, kein API-Call; (b) Input < 20 Wörter → Confidence-Ceiling 0.65; Heuristik als Docstring dokumentiert
   - Acceptance: Unit-Test: `classify('')` ohne HTTP-Call → `unknown/0.0`; `classify('ja tschüss')` → `confidence <= 0.65`

7. **Haiku-Prompt Few-Shot-Erweiterung**: 3 Few-Shot-Beispiele + Rangfolge-Anweisung.
   - Current: Generischer Prompt (Live-Bug: "Termin" → "Kein Interesse")
   - Target: Prompt mit 3 Few-Shot-Beispielen (meeting_booked/no_interest/callback) + Anweisung "Termin > Rückruf > Kein Interesse bei Überlappung"
   - Acceptance: Live-Test Call 1 (Termin-Signal) → `meeting_booked` ≥ 0.85; Call 2 (Ablehnung) → `no_interest` ≥ 0.85; Call 3 (vage) → Confidence < 0.70 oder `unknown`

8. **WR-03 Boundary-Kommentar-Fix**: Kommentar in `outcome_service.py` zeigt `>= 0.70` für ai_auto_unsicher.
   - Current: Kommentar sagt `> 0.70`, Code behandelt `>= 0.70` korrekt
   - Target: Kommentar: `# confidence >= 0.70 and < 0.90 → ai_auto_unsicher`
   - Acceptance: grep zeigt `>= 0.70` im Kommentar

### Wave 3: Outcome-Pflicht-Schritt vor Score-Reveal

9. **Score-Sektion hidden bis User-Click**: `nlp-section-postcall` initial `display:none`; enthüllt nach Outcome-Button-Klick.
   - Current: Score sichtbar gleichzeitig mit Outcome; 30s-Countdown überspringbar
   - Target: Nach `outcome_ready`-Event: Score-Sektion hidden. Nach User-Click: Score-Sektion `display:block`. Auto-Confirm-Countdown ENTFÄLLT. Kein Skip, kein Timer-Bypass.
   - Acceptance: Wave-3-Live-Test: Score nicht sichtbar nach Call-Ende; sichtbar nach Outcome-Klick ohne Reload; 0 JS-Errors

10. **Dreistufige Inline-Sektion (kein floating Modal)**: Eine `pip-outcome-section`-Box, 3 States mit einheitlicher Struktur.
    - Current: 3 verschiedene DOM-Muster; floating Korrektur-Grid
    - Target: State A (≥0.90): KI-Vorschlag + Bestätigen-Btn + dezenter "Andere Wahl"-Link. State B (0.70–0.89): wie A + Teal-Outline-Badge "KI war unsicher". State C (<0.70): 5 Buttons direkt sichtbar. Gleiche Container-Größe/Padding für alle States. 44px Touch-Target. `outcome_source`-Mapping: Bestätigt A → `ai_auto`; bestätigt B → `ai_auto_unsicher`; Andere Wahl oder State C → `user_corrected`.
    - Acceptance: `sec.dataset.outcomeRendered = '1'` gesetzt; `outcome_source` stimmt mit Tier + Aktion überein (3 Test-Calls mit gemockten Confidence-Werten)

### Wave 4: Score-Multiplikator + Dashboard Edit-Knopf

11. **Outcome-Multiplikator in coaching_score**: Neues Alembic-Feld `calls.coaching_score`; `_calcScore()` + `correct_outcome`-Endpoint erweitert.
    - Current: `_calcScore()` ignoriert Outcome; kein persistierter Score
    - Target: Neue Migration: `calls.coaching_score FLOAT NULL`. Formel: process_score = `kb_end×0.30 + behandelt_rate×0.30 + redeanteil_score×0.20 + skript×0.10 + frage_qualitaet×0.10` (frage_qualitaet = 0 in v1). Modifier: `contract_signed→1.15, meeting_booked→1.10, callback→0.95, no_interest→0.85, wrong_person→1.00`. `final_score = clamp(round(process × modifier), 0, 100)`. `correct_outcome` berechnet + persistiert `coaching_score`.
    - Acceptance: Deterministischer Pytest: bekannte Inputs → berechenbarer Zielwert; `calls.coaching_score` nicht NULL nach API-Call

12. **Dashboard Pencil-Edit-Button**: Jede Call-Zeile hat Inline-Korrektur-Möglichkeit.
    - Current: Inline-Korrektur nur bei `ai_auto_unsicher`-Calls (Unsicher-Dot)
    - Target: Kleiner Pencil-Icon-Button (Lucide `pencil`, 14px, `n-btn-ghost`) neben Outcome-Label in jeder Zeile. Klick: 5-Button-Accordion. Nach Auswahl: `outcome_source='user_corrected'`, Score re-rendered ohne Reload. Unsicher-Dot bleibt parallel.
    - Acceptance: Pencil in JEDER Zeile; Klick + Auswahl → Score + Outcome-Label ohne Reload; alter Call (`outcome=NULL`) → korrekt; Unsicher-Dot nicht entfernt
