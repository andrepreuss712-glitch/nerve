### WR-01: `_select_snippets` duplicate entries when `dauer_sek=0`

**Files modified:** `services/outcome_service.py`
**Commit:** `5f547d0`
**Applied fix:** Added `late_threshold_ms = max(0, (dauer_sek - 60) * 1000)` before the late-slice list comprehension and replaced the inline `(dauer_sek - 60) * 1000` expression with the guarded variable. When `dauer_sek=0` the threshold is now `0` instead of `-60000`, preventing all entries from matching the late slice and appearing twice in the Haiku prompt.

### WR-02: `correct_outcome` — `outcome_note` silently becomes NULL on anonymization exception

**Files modified:** `routes/app_routes.py`
**Commit:** `a3f7588`
**Applied fix:** Initialized `anon_note_failed = False` before the `if new_note` block. Set `anon_note_failed = True` in the `except Exception as _e_anon` handler alongside the existing `row.outcome_note = None` fail-safe. In the success response, replaced the direct `return jsonify({...})` with a `resp` dict that conditionally includes `'note_dropped': True` when the flag is set. The frontend can now detect the silent data loss and surface a warning to the user.

---

### WR-03: Dashboard accordion — unsicher-dot stays visible after successful inline correction

**Files modified:** `templates/dashboard.html`
**Commit:** `564c61b`
**Applied fix:** In both the unsicher-dot inline-correction handler (ending with `ext.parentNode.removeChild(ext)`) and the pencil accordion handler (ending with `acc.parentNode.removeChild(acc)`), replaced `if (dot) outcomeSpan.appendChild(dot)` with `if (dot && dot.parentNode) dot.parentNode.removeChild(dot)`. The yellow unsicher indicator is now removed from the DOM immediately after a successful correction instead of being re-appended, eliminating the need for a page reload to clear it.

---

### WR-04: `api_calls_latest_outcome` — nullable `started_at` can cause wrong row to be returned

**Files modified:** `routes/app_routes.py`
**Commit:** `05524c5`
**Applied fix:** Replaced `q.order_by(Call.started_at.desc())` with `q.order_by(Call.started_at.desc().nullslast(), Call.created_at.desc())`. The `.nullslast()` modifier makes NULL handling explicit (not relying on PostgreSQL default behaviour), and the secondary sort on the always-non-null `created_at` ensures deterministic ordering when `started_at` is NULL.
