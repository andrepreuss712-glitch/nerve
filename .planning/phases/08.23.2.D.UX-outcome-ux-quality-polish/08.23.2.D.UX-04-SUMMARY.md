# Phase 08.23.2.D.UX Plan 04: Klassifikations-Tuning Summary

**One-liner:** Word-count snippet heuristic replaces broken top-3-longest logic, plus 5-example few-shot SYSTEM_PROMPT with 7-class ranking for Haiku classification.

## What Was Built

Three changes to `services/outcome_service.py` fixing the 2026-05-27 live bug where short closing sentences ("Montag um 10") fell out of Top-3 snippets and were classified as "Kein Interesse":

### 1. Snippet Heuristic (D-W2-03)

`_estimate_tokens()` + `_select_snippets()` replaced the old "top-3 longest statements" with word-count heuristic:
- Full transcript if < 2000 estimated tokens (1.4 tokens/word German)
- Fallback: first 30s + last 60s (ts_ms-based, or first/last 15 entries if ts_ms absent)

### 2. Few-Shot SYSTEM_PROMPT (D-W2-01/02/04)

`SYSTEM_PROMPT` module constant with 7-class definitions, ranking instruction (meeting_booked > callback > no_interest), and 5 XML-tagged examples covering all key classes including new `send_info` and `gatekeeper_blocked`. `_build_prompt()` now only contains user-message context data.

### 3. VALID_OUTCOMES + classify() fixes (REQ-D.UX-6/7/8)

- VALID_OUTCOMES: 8 values (added `send_info`, `gatekeeper_blocked`)
- `classify()`: early exit returns `{'outcome': 'unknown', 'confidence': 0.0}` not `None`
- `classify()`: `system=SYSTEM_PROMPT`, `max_tokens=80`
- Confidence ceiling 0.65 for inputs < 20 words (post-processing)
- WR-03: comment on `>= 0.70 and < 0.90 -> ai_auto_unsicher` in `routes/learning.py`
