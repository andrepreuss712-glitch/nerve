## Critical Issues

### CR-01: XSS — Unescaped server data injected into Toast innerHTML

**File:** `templates/dashboard.html:832`
**Issue:** Notification toast content from `/api/notifications` is injected directly into `innerHTML` without escaping. `n.text` and `n.icon` come from the server-side `get_notifications()` route (currently hardcoded strings), but any future dynamic content (e.g. user-name interpolation, streak count) would introduce XSS. The pattern is already flagged because `n.icon` is rendered raw and contains emoji, meaning the path is already concatenating trusted + potentially-untrusted data unsanitized.

```javascript
// Current — unsafe pattern:
t.innerHTML = '<span class="toast-icon">' + n.icon + '</span>'
            + '<span class="toast-text">' + n.text + '</span>'
            + '<span class="toast-arrow">→</span>';

// Fix — use escHtml() for all interpolated values:
t.innerHTML = '<span class="toast-icon">' + esc(n.icon) + '</span>'
            + '<span class="toast-text">' + esc(n.text) + '</span>'
            + '<span class="toast-arrow">→</span>';
```

Note: the `esc()` helper already exists in dashboard.html (line 854). Apply it here. For the click handler, `n.url` is already safely used as `window.location.href` (not injected into HTML), so that path is fine.

### CR-02: XSS — User-supplied email rendered unescaped in waitlist_admin.html innerHTML

**File:** `templates/waitlist_admin.html:115-116`
**Issue:** The `invite()` function builds innerHTML using a template literal that directly interpolates `d.email` from the API response. While email addresses are validated server-side before storage, rendering them via `innerHTML` without escaping allows a crafted email like `<img src=x onerror=alert(1)>@evil.com` (if server validation is ever relaxed) to execute in the admin UI. Principle of defense-in-depth requires escaping at the render site.

```javascript
// Current — unsafe:
content.innerHTML = `✓ Eingeladen: <strong>${d.email}</strong><br>
  Registrierungslink: <span class="invite-link">${window.location.origin}${d.register_link}</span>
  <button onclick="navigator.clipboard.writeText('${window.location.origin}${d.register_link}');this.textContent='✓ Kopiert'"
    class="btn btn-secondary btn-xs" style="margin-left:8px">Kopieren</button>`;

// Fix — escape email; use a separate data attribute for the copy button:
function escHtml(s) {
  return String(s||'').replace(/&/g,'&amp;').replace(/</g,'&lt;')
    .replace(/>/g,'&gt;').replace(/"/g,'&quot;');
}
var link = window.location.origin + d.register_link;
content.innerHTML = '✓ Eingeladen: <strong>' + escHtml(d.email) + '</strong><br>'
  + 'Registrierungslink: <span class="invite-link">' + escHtml(link) + '</span>'
  + '<button class="btn btn-secondary btn-xs" style="margin-left:8px" data-copy-link>Kopieren</button>';
content.querySelector('[data-copy-link]').onclick = function() {
  navigator.clipboard.writeText(link).then(function(){ this.textContent = '✓ Kopiert'; }.bind(this));
};
```

### WR-04: copyInviteLink restores wrong text after clipboard copy (coach_dashboard.html)

**File:** `templates/coach_dashboard.html:163-171`
**Issue:** The `copyInviteLink()` function saves the invite URL before copying (via `el.textContent`), then on the 2-second timeout attempts to restore it from `el.dataset.url`. But `dataset.url` is never set anywhere — the `inviteLink` element has no `data-url` attribute. After 2 seconds, the link text becomes the `textContent` at the time of the click (which may already be "✓ Kopiert!" if the user clicked fast), not the original URL. The link text becomes permanently corrupted.

```javascript
// Current — broken restore:
setTimeout(()=>{
  el.classList.remove('invite-copied');
  el.textContent = document.getElementById('inviteLink').dataset.url || el.textContent;
}, 2000);

// Fix — capture original text before mutation:
function copyInviteLink(el){
  var originalText = el.textContent;  // capture BEFORE any mutation
  navigator.clipboard.writeText(originalText).then(()=>{
    el.classList.add('invite-copied');
    el.textContent = '✓ Kopiert!';
    setTimeout(()=>{
      el.classList.remove('invite-copied');
      el.textContent = originalText;
    }, 2000);
  });
}
```

### IN-02: CSS comment inside HTML `<style>` tag using HTML comment syntax (register.html)

**File:** `templates/register.html:8`
**Issue:** Line 8 contains `<!-- Design-Tokens aus nerve.css, KEINE hardcoded Farben (CLAUDE.md Regel) -->` inside a `<style>` block. HTML comments (`<!-- -->`) inside `<style>` blocks are technically invalid CSS and may cause rendering issues in some browsers (treated as a selector or silently ignored depending on parser mode). This pattern is repeated across many templates but only `register.html` places it inside a standalone `<style>` tag (not an `{% block extra_style %}` block).

**Fix:** Use a CSS comment instead:
```css
/* Design-Tokens aus nerve.css, KEINE hardcoded Farben (CLAUDE.md Regel) */
```

**File:** `routes/dashboard.py:437,665`
**Issue:** `db.query(UserModel).get(g.user.id)` uses the legacy `Query.get()` method, which is deprecated in SQLAlchemy 2.0 (emits a deprecation warning and will be removed). The root route already uses the modern `db.get(UserModel, flask_session['user_id'])` (line 423). The `index()` and `dismiss_nudge()` routes still use the old pattern.

**Fix:**
```python
# Replace:
user = db.query(UserModel).get(g.user.id)
# With:
user = db.get(UserModel, g.user.id)
```
