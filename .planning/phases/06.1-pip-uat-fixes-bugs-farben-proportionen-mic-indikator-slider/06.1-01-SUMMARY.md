# Phase 06.1 Plan 01: UAT-Bugfixes (EWB-Labels, Opener-Integration, Scrollbar) Summary

3 funktionale Bugs aus dem Phase-06-UAT behoben: EWB-Buttons rendern jetzt lesbare Labels aus dem `kategorie`-Feld statt `[object Object]`, der Opener erscheint als erster Teleprompter-Block statt Slot A zu blockieren, und beide KI-Slots erhalten eine konsistente 4px-Custom-Scrollbar wie der Teleprompter.

## Ergebnisse

### Task 1: BUG-1 — EWB-Label-Fallback-Chain (D-01)

**Problem:** `_renderEwbButtons` in `static/pip-launcher.js` verwendete `e.typ || e.name || String(e)` als Fallback fuer Objekte. Profile-Editor speichert Einwaende als `{kategorie, intensitaet, einwand, ...}` — weder `.typ` noch `.name` vorhanden, daher fiel der Code auf `String(e)` = `"[object Object]"` zurueck.

**Fix (Zeilen 977-982):**
- Neue Fallback-Chain: `e.kategorie || e.typ || e.name || e.einwand || ''`
- `e.kategorie` an erster Stelle (Profile-Editor-Format)
- Leere Labels werden uebersprungen (`if (!typ) return ''`) statt `[object Object]` zu rendern
- `.slice(0, 5)` und `escHtml(typ)` bleiben unveraendert

**Commit:** `dc5e7ea`

---

### Task 2: BUG-3 — Opener-Integration in Teleprompter (D-03)

**Problem:** `_showPipLive` schrieb den Opener-Text direkt in `pip-slot-body-0` und setzte `pip-slot-label-0` auf `'OPENER'`. Dadurch blieb Slot A dauerhaft belegt und das Dual-Slot-Konzept wurde im Live-Einsatz unsichtbar.

**Fix — drei koordinierte Aenderungen:**

1. **`_showPipLive` (Zeilen 953-966 entfernt):** Die gesamte Slot-0-Zuweisung wurde entfernt. Beide Slots starten jetzt mit dem HTML-Default `"Warte auf Gespraechsinhalt..."`.

2. **`_initTeleprompter` (Zeilen 1192-1206):** Opener-Resolution-Chain (editedOpenerText → selectedOpenerId → profileDaten.opener) vor dem Block-Parsing eingefuegt. Opener wird als `blocks[0]` in das `state.teleprompterBlocks`-Array eingefuegt: `var blocks = openerText ? [openerText].concat(skriptBlocks) : skriptBlocks`.

3. **`_startAudio` (Zeilen 771-782):** `skript_bloecke` fuer den `start_live_session`-Socket-Emit enthaelt jetzt den Opener als Block 0, damit das Backend die KI-Position-Erkennung korrekt als Phase 0 = Opener interpretieren kann.

**Commit:** `2f9c7ed`

---

### Task 3: BUG-2 — Custom-Scrollbar fuer KI-Slots und Teleprompter (D-02)

**Problem:** `.pip-ki-slot` hatte `overflow-y:auto` aber keine Custom-Scrollbar-Regeln — Browser zeigte den haesslichen Default-Scrollbar bei langem KI-Text in Slot B.

**Fix (`templates/base.html` Zeilen 204-213):** Die bestehenden Teleprompter-Scrollbar-Regeln (3 Zeilen) durch einen konsolidierten 10-Zeilen-Block ersetzt:
- WebKit (Chrome/Edge/Safari): `pip-ki-slot` + `pip-teleprompter` mit `width:4px`, transparenter Track, `rgba(0,0,0,0.15)` Thumb
- Firefox: `scrollbar-width:thin` + `scrollbar-color` fuer beide Container
- Farbe `rgba(0,0,0,0.15)` statt vorher `rgba(255,255,255,0.15)` — bereits auf hellen Body (Plan 02) vorbereitet

**Commit:** `d3e85de`
