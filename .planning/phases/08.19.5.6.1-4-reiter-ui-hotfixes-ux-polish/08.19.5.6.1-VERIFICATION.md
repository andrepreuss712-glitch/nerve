## Re-verification: Gaps Closed

### WR-01 — Pitch resolution in `_initTeleprompter()`

**Previous gap:** `_initTeleprompter()` never resolved `selectedPitchId` into `inhalt`. Pitch-only scenario showed "Kein Skript hinterlegt".

**Closure confirmed:**
- Line 2468-2472: Pitch resolution block inserted after Skript resolution, before the `hasOpener` guard
- Line 2477: `var hasPitch = !!state.selectedPitchId;` declared
- Line 2481: Guard condition extended to `!hasOpener && !hasErlaubnis && !hasPitch`
- `grep -c "hasPitch" pip-launcher.js` = 2 (declaration + guard use)
- `grep -n "selPitch" pip-launcher.js` = lines 1481-1483 (pre-existing `_resolvedTeleprompterSkript` block) + lines 2470-2471 (new WR-01 block)
- Misleading comment at former line 2503 removed; replaced with accurate comment at line 2509

### WR-02 — `_wireInlineEdit()` `state._editedOpenerText` guard

**Previous gap:** All three inline-edit tabs (opener, erlaubnis, pitch) called `_wireInlineEdit()` with `type='opener'`, causing erlaubnis/pitch edits to overwrite `state._editedOpenerText`.

**Closure confirmed:**
- Line 1214: `if (type === 'opener' && state.activeTab === 'opener') state._editedOpenerText = newText;`
- Old unguarded form `if (type === 'opener') state._editedOpenerText` = 0 grep matches (form removed)
- `grep "activeTab.*opener.*_editedOpenerText"` = exactly 1 match at line 1214

### WR-03 — `r.ok` checks on both `/api/precall/personalize/save` fetch chains

**Previous gap:** Both `.then(function(r) { return r.json(); })` calls had no `r.ok` check. HTTP 4xx/5xx responses with non-JSON bodies would not trigger `.catch()`.

**Closure confirmed:**
- Line 669: fetch at `_savePersonalizedAndStartCall` (line 652, `fetch('/api/precall/personalize/save', ...)`) — `.then(function (r) { if (!r.ok) throw new Error('HTTP ' + r.status); return r.json(); })`
- Line 815: fetch in cap-delete-save handler (line 797) — same pattern
- `grep -c "throw new Error('HTTP "` = exactly 2 matches
