## Claudian-Stellungnahme: DAFUER — mit einer Ergaenzung

Ich bin **nicht** dagegen. Vier Gruende:

1. **Es lokalisiert den Fehler.** Eine falsche Vorhersage entwertet ab jetzt **eine
   Markierung**, nicht die ganze Phase.
2. **Es nimmt den Anreiz zum Zurechtbiegen.** Es gibt keine Summe mehr, die man
   „passend machen" kann — jede Markierung ist eine falsifizierbare Aussage ueber
   **einen** Test.
3. **Es erhoeht die Aufloesung, nicht die Nachsicht.** „12 statt 11" sagt nichts;
   „`test_b02` ist markiert `rot_vor_fix`, war aber PASSED" nennt Datei, Test und
   Ursache.
4. **Die Disziplin bleibt strenger, nicht lockerer.** Bisher konnte ein Test aus dem
   falschen Grund rot sein und in der Summe untergehen (R2-7). Pro Test faellt das auf.

**ERGAENZUNG (die eine Sache, die die Gesamt-Zahl konnte und die Markierung allein
nicht kann):** Die Summe haette gemerkt, dass **Tests verschwinden**. Genau das ist
F-B2 — zehn Tests **skipped**. Wenn nur „markiert-rot muss failen" geprueft wird,
rutscht ein `SKIPPED` durch, weil es kein `PASSED` ist. Deshalb gilt:

- **`SKIPPED` ist IMMER ein Verstoss** — in beide Richtungen, ohne Ausnahme.
- **`ERROR` / Collection-Fehler ist IMMER ein Verstoss.**
- Die Test-Menge wird **aus der Collection abgeleitet**, nicht vorhergesagt: jeder in
  den zwei Dateien gesammelte Test **muss** im Bericht auftauchen. Damit bleibt
  „ein Test ist still verschwunden" gefangen — **ohne** eine vorher festgelegte Zahl.

## Konkrete Bau-Vorgabe fuer den Umbau

**A. Markierung am Test.** Jeder Test in `tests/test_ownership_state_guard.py` und
`tests/test_ownership_endpoints.py` traegt genau eine Markierung:
- `@pytest.mark.rot_vor_fix` — **muss** im ROT-Lauf FAILED sein
- keine Markierung — **muss** im ROT-Lauf PASSED sein
Die Markierung steht **am Test**, mit einer Zeile Begruendung darunter (bei
`rot_vor_fix`: *welches* Loch sie aufreisst; ohne Markierung: *warum* sie schon gruen
ist und was sie trotzdem prueft).

**B. Auswertung statt Summe.** Plan 02 Task 1 laeuft `pytest` ueber die zwei Dateien und
schreibt eine **Tabelle je Test**:
`nodeid | Markierung | Ergebnis (PASSED/FAILED/SKIPPED/ERROR) | Urteil (ok / VERSTOSS)`.
Verstoss-Klassen, jede einzeln benannt:
| Fall | Urteil |
|---|---|
| `rot_vor_fix` + FAILED | ok |
| `rot_vor_fix` + PASSED | **VERSTOSS** — der Anker beisst nicht (das ist R2-1/F-B3) |
| ohne Markierung + PASSED | ok |
| ohne Markierung + FAILED | **VERSTOSS** — unerwartet, Ursache klaeren |
| **irgendwas + SKIPPED** | **VERSTOSS** — Umgebung falsch (das ist F-B2) |
| **irgendwas + ERROR** | **VERSTOSS** — Collection/Import kaputt |

**C. Abbruch-Regel neu.** Statt „Verteilung weicht ab → nicht weiterbauen" gilt:
**jeder** Verstoss blockiert, und die Meldung nennt **Test + Klasse**. Ein Verstoss wird
behoben, indem der **Test** oder die **Markierung** korrigiert wird — **nie**, indem
eine Zahl nachgezogen wird.

**D. Was aus der Zahlen-Tafel VERSCHWINDET:** ZT-12 (`12 failed / 7 passed`), ZT-13
(`19 passed`) und die Zaehl-Anker `grep -c "def test_" == 9` / `== 10` (ZT-8/ZT-9).
Der GRUEN-Lauf in Plan 04 wird zu: *„jede `rot_vor_fix`-Markierung ist jetzt PASSED,
kein SKIPPED, kein ERROR"* — ebenfalls **ohne** Zielzahl.

**E. Was BLEIBT (nicht wegvereinfachen):**
- Die **Mindest-Soll-Zahlen der abgeleiteten Mengen** (ZT-2…ZT-6). Das sind keine
  Ergebnis-Vorhersagen, sondern Punkt-31-Sperren gegen den **stillen Ausfall der
  Ableitung** — ohne sie wird der Waechter blind statt rot.
- Die **Namens-Anker je Test** (`grep -cF "def test_b01_…"`) — sie sind bereits
  pro Test statt aggregiert und damit genau im Geist des Umbaus.
- Die **Rot-Beleg-Pflicht** und die verbatim-Protokollierung im SUMMARY.

**F. Werkzeug-Hinweis:** die Markierungen gehoeren in `pytest.ini`/`pyproject`
