### Task 2: static/profile_editor.js

**renderFaqRow() — Toggle state initialization (D-15):**
After `faq-kategorie` value assignment, reads `faq.mode` (default `'ki_generated'`) and:
- Sets `modeChk.checked = isKi`
- Calls `_setModeVisual(isKi)` → track background `#00D4AA` (ki) / `#888` (literal), thumb `translateX(18px)` / `translateX(0)`, desc text

**Ghost-toggle guard (Finding 5):**
When `data-faq-id` is empty (new FAQ before POST), `modeChk.disabled = true` + `modeTrack.style.opacity = '0.5'`. Prevents PUT calls to undefined FAQ ID.

**Change-event with optimistic revert + disabled-during-fetch (D-16, Finding 4):**
- `prevChecked = !modeChk.checked` captured before `_setModeVisual()` (correct pre-change state)
- Optimistic update: `_setModeVisual(modeChk.checked)` immediately
- `modeChk.disabled = true` + `opacity = '0.5'` before fetch (prevents rapid-fire race conditions)
- `fetch PUT /profiles/api/profile/faqs/<id>` with `X-CSRFToken` header
- `.then()`: re-enables toggle; calls `_revertAndNotify()` if `!r.ok`
- `.catch()`: re-enables toggle; calls `_revertAndNotify()` on network error
- `_revertAndNotify()`: resets checkbox + visual to `prevChecked`, shows `alert()` with "Speichern fehlgeschlagen — bitte erneut versuchen"

**persistFaq() POST-success ghost-enable (Finding 5):**
Extended the `.then(data)` handler: after setting `data-faq-id`, queries `.faq-mode-toggle` on the row, sets `disabled = false`, clears opacity, and syncs toggle state from `data.mode` if present (inline track/thumb/desc update since `_setModeVisual` is out of scope).
