# Phase 08.19.3 Plan 01: Schema-Migration mode-Spalte + daten.fragen Backfill Summary

**One-liner:** Added `profile_faqs.mode` VARCHAR(20) column with advisory-lock migration, literal-backfill for existing rows, and idempotent `daten.fragen` → `profile_faqs` migration.

## What Was Built

### Task 1: ProfileFaq ORM — mode column
Added `mode = Column(String(20), nullable=False, default='ki_generated')` to the `ProfileFaq` class in `database/models.py` after the `used_count` column.

### Task 2: app.py _migrate() — ALTER TABLE + Backfill + daten.fragen Migration
Three migration blocks added:

**Block A+B** (inside `_migrate()`, after profile_faqs CREATE TABLE):
- `ALTER TABLE profile_faqs ADD COLUMN mode VARCHAR(20) NOT NULL DEFAULT 'ki_generated'`
- Backfill: `UPDATE profile_faqs SET mode='literal' WHERE mode='ki_generated'` — runs only when ALTER TABLE succeeds (single try/except guarantees first-run-only execution)
- Explicit print logging on both success and skip (no silent pass)

**_migrate_fragen_to_faqs()** (top-level function, called at end of `_migrate()`):
- Advisory-lock pattern (SQLite: BEGIN EXCLUSIVE, PostgreSQL: pg_advisory_xact_lock(81930))
- Loops all profiles, reads `daten.fragen` JSON array
- Per-entry idempotency: `SELECT EXISTS ... WHERE frage_muster=trim(:frage)` before INSERT
- INSERT with `mode='ki_generated'` for each unmigrated frage
- D-04: sets `daten['fragen'] = []` after migration (key preserved, emptied)
- Per-entry errors: logs `profile_id` + frage preview, never silent pass
- Outer advisory-lock body: `app.logger.error(...) + raise` for unexpected errors
