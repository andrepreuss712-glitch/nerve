# Phase 08.19.3 Plan 02: mode-Filter + FAQ Q+A-Block in Prompt Summary

**One-liner:** mode-aware FAQ routing in claude_service.py (literal-only to match_faq) + FAQ Q+A-Block injection in build_profile_context() (all modes, max 20 by used_count DESC).

## What Was Built

### Task 1: claude_service.py — mode field + mode filter

**`_qa_load_faqs()`**: Added `'mode': r.mode` to the dict in the list comprehension. This makes the `mode` attribute available at every call site without an additional DB query.

**`_qa_pipeline_dispatch()`**: Replaced the direct `_faqs = _qa_load_faqs(...)` call with a two-step pattern:
```python
_faqs_all = _qa_load_faqs(_active_profile_id)
_faqs = [f for f in _faqs_all if f.get('mode') == 'literal']
_matched_faq = match_faq(neuer_text, _faqs, threshold=0.75) if _faqs else None
```
When `_faqs` is empty (no literal FAQs), `match_faq` is not called and `_matched_faq` stays `None`. The existing standard EWB fallback pipeline activates automatically — no extra guard needed (D-08).

### Task 2: prompt_pipeline.py — FAQ Q+A-Block in build_profile_context()

Inserted a new block after the `beweise` block and before `# ── Ton/Stil`:
- Reads `active_profile_id` from `ls.state` via `state_lock` (established pattern from _qa_pipeline_dispatch)
- Queries ALL `profile_faqs` (both `literal` and `ki_generated` modes) for the active profile
- Cap: `.order_by(_PF.used_count.desc()).limit(20)` — max 20 most-used FAQs
- Info-log `[Pipeline] FAQ-Cap reached for profile {id} (count 20+)` when cap is hit
- Format: `- F: {frage_muster}` + `  A: {antwort}` per FAQ
- Full `try/except Exception` wrap with `print(f"[Pipeline] FAQ-Block skip: {_faq_e}")` — MUST NOT raise (live-loop safety)
