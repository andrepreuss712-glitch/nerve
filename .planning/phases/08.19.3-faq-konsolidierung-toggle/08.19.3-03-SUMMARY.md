# Phase 08.19.3 Plan 03: Routen-Erweiterung mode-Feld GET/POST/PUT Summary

**One-liner:** Extended three FAQ API endpoints in routes/profiles.py to return, accept, validate and persist the `mode` field (literal/ki_generated) with whitelist guard and partial-PUT preservation.

## What Was Built

### Task 1: routes/profiles.py — mode-Feld in GET-Response, PUT-Handler und POST-Handler

**Änderung 1 — api_faqs_list() GET (D-12):**
Added `'mode': r.mode or 'ki_generated'` to the list comprehension dict in `api_faqs_list()`. Frontend can now read toggle state from GET response.

**Änderung 2 — api_faqs_create() POST:**
- Added `mode_val = (data.get('mode') or 'ki_generated').strip()` after kategorie validation
- Added whitelist check: `if mode_val not in ('literal', 'ki_generated'): return 400`
- Passed `mode=mode_val` to `ProfileFaq()` constructor
- Extended 201 response: `{'id': row.id, 'used_count': row.used_count or 0, 'mode': row.mode}`
- Ghost-toggle initialization after POST now has correct initial mode state

**Änderung 3 — api_faqs_update() PUT (D-11):**
- Added `if 'mode' in data:` block after kategorie block
- Whitelist validation: `if m not in ('literal', 'ki_generated'): return 400`
- Assignment: `row.mode = m` after validation
- Partial-PUT: mode is only updated if present in request body; all other fields remain untouched
