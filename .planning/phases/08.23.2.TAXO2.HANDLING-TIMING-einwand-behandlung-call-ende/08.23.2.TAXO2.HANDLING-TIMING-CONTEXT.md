<decisions>
## Locked Decisions (aus der binding SPEC)

### Kern: Beobachtung statt Note
- **Nutzer bekommt KEINE Zahl** — keine Gesamtnote, keine Schulnote pro Dimension. Stattdessen Klartext-Beobachtungen, jede mit wörtlichem Beleg-Zitat aus dem Transkript. Klar gelabelt als **KI-Einschätzung / Coaching-Hinweis**, nicht Gutachten.
- **Feste Dimensions-Liste (~4)**, je eine Ein-Satz-Definition, versioniert/festgezurrt (Vergleichbarkeit über die Zeit). Start mit den **erklärbaren** Dimensionen (z.B. offene vs. geschlossene Fragen = fast regel-checkbar) + den echt-subjektiven (Gesprächsführung, Einwand-Behandlung). Erweitern = eine Zeile. Liste festzurren, Bewertung locker lassen.

### Architektur: Urteil von Rechnung trennen
- Der Judge **beobachtet + belegt, verrechnet NICHT** — keine Gewichte, keine Gesamtnote im Modell. Falls je aggregiert wird → **außerhalb in wenigen Zeilen Code**, jederzeit änderbar, ohne den Judge anzufassen.
- **Nicht over-engineered** (Leitsatz 2 / Punkt 27): der Judge tut das Simpelste — schauen + zitieren. Kein Gewichtungs-Theater.

### Outcome strikt trennen (das eine Architektur-Muss)
- Outcome (contract_signed/meeting_booked/callback/no_interest/wrong_person) **physisch RAUS** aus dem Bewertungs-Prompt. Der Judge sieht Transkript + Briefing + Marker — NICHT, ob der Deal zustande kam.
- Outcome nachgelagert als Meta-Label **getrennt gespeichert** (Korrelation später). Ein Kunden-Nein ist KEINE schlechte Leistung (Verhalten-only).

### Verhaltens-Call vs. Übernahme-Call GETRENNT
- **Verhaltens-Call** bewertet nur Verhalten und **kennt die NERVE-Vorschläge NICHT** (sonst Bias).
- **Übernahme-Call** (hat der Verkäufer den Vorschlag aufgegriffen) ist ein SEPARATER Call; Übernahme per **LLM/NLI-Urteil, NIE mechanisch** (BLEU/ROUGE/Cosine scheitern an Paraphrase + am Stichpunkt-Toggle).

### Intern (unsichtbar, fürs Lernen)
- Pro Dimension grobe Ausprägung **schwach/ok/stark** (kein Score) — separat gespeichert, nie an den Nutzer.
- Outcome-States getrennt daneben.

### Pflicht-Technik (billig + wirksam)
- **Beleg-VOR-Note** (erst wörtliches Transkript-Zitat → Begründung → Einstufung; Note-zuerst halluziniert).
- **BARS-Anker als Klartext im Prompt** (schwach/ok/stark mit je einem Beispiel) — Formulierungs-Hilfe, kein Rechenapparat.
- **Erzwungenes JSON-Schema** (Anthropic Tool-Use/structured output — Context7 prüfen).

### Report-Ergänzungen (mitnehmen)
1. **Selbst-Gefälligkeit:** der Übernahme-Call lässt Claude eigene Vorschläge beurteilen → **Cross-Family-Zweit-Urteil (Gemini/GPT) auf Stichprobe = Phase-2-Ticket** (jetzt nur Ticket, nicht bauen).
2. **„Mitte geht unter" (Lost-in-the-Middle)** bei langen Transkripten → Transkript taggen + Rubrik an **Anfang UND Ende** des Prompts.
3. **Kaltakquise-Redeanteil 55:45** (Gong-Cold-Call), NICHT 43:57 (Discovery).
4. **Hard-Cap:** Weiterdrücken nach mehrfacher klarer Ablehnung **deckelt** die Gesprächsführungs-Bewertung („nicht Verkauf, sondern Belästigung"; verbindet mit „wiederkehrender Einwand → tiefer").
</decisions>
