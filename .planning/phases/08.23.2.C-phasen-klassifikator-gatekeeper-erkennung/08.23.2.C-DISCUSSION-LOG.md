## NER-Voting-Logik

| Option | Description | Selected |
|--------|-------------|----------|
| Union (einer reicht) | Wenn irgendeines der drei Modelle einen Namen erkennt, gilt er als Treffer | |
| Majority (2 von 3) | Mindestens 2 der 3 Quellen müssen den Namen erkennen | |
| Dual-Gate (GLiNER ODER spaCy reicht, Regex als Override) | GLiNER oder spaCy allein genügt, Regex zusätzlich immer | |

**User's choice:** Zwei separate Voting-Strategien für zwei Anwendungsfelder:
1. anonymize() (DSGVO): Union für Namen (GLiNER ODER spaCy), Regex separat für strukturierte PII
2. classify_contact() (Gatekeeper): Konsens — spaCy UND GLiNER müssen denselben Namen erkennen

**Notes:** Begründung: False-Positive bei Klassifikation = falscher PiP-Modus. False-Negative = unknown + sicherer manueller Toggle. Confidence-Score-Nutzung für spätere Kalibrierung vorsehen, aber MVP ohne Confidence-Weighting.
