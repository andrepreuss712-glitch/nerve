## Was gebaut wurde

### Task 1: GLiNER-Integration in services/anonymization.py

**`_get_gliner()`** (nach _get_nlp() eingefuegt):
- Thread-safe Double-Checked Locking analog _get_nlp()
- `from gliner import GLiNER` innerhalb der Funktion (Cross-AI-Finding 1: kein Modul-Level-Import)
- `GLiNER.from_pretrained('urchade/gliner_multi-v2.1')` mit threshold=0.5
- Bei Load-Exception: `is_pipeline_healthy = False`, return None (Fallback-A aktiv)

**`_apply_ner()` erweitert (Union-Voting D-01):**
- Sammelt spaCy-Spans (ent.start_char / ent.end_char) und GLiNER-Spans in `all_spans`
- GLiNER-Offset-Strategie: `if 'start' in ent and 'end' in ent:` native Offsets — sonst `re.finditer(re.escape(ent_text), text)` als Fallback (Review Finding 1, kein text.find-while-Loop)
- Dedup via `set()` auf (start, end, token_type, text) Tuples
- Replacement von hinten nach vorne (kein Offset-Shift)
- GLiNER-Fehler werden gelogged, kein Fail-Hard (spaCy-only-Treffer reichen)

**`_apply_ner_parallel()`** (neue Funktion, Review Finding 2):
- `concurrent.futures.ThreadPoolExecutor(max_workers=2)` fuer concurrent spaCy + GLiNER
- Gleiche Offset-Logik wie sequentielles _apply_ner()
- Als Default NICHT aktiviert — erst nach Server-Smoke (gliner_smoke.py) P95-Entscheidung

**`extract_entities(text, cache=None)`** (neue oeffentliche Funktion, D-02):
- Gibt `List[dict]` mit `{text, type, source}` zurueck
- `source`: `'spacy'` oder `'gliner'`
- `type`: `'PERSON'` | `'ORG'` | `'LOC'`
- Fuer Konsens-Voting in `services/gatekeeper.classify_contact()` (Plan 06)
- Leere Liste bei NER-Fehler (kein Hard-Crash)
