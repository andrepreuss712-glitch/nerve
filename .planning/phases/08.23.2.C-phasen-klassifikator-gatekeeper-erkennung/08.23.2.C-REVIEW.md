## Summary

This phase introduces the Phase Classifier + Gatekeeper Detection system: a mode-aware Haiku-backed phase classifier (`classify_phase`), a hysteresis guard (`apply_hysteresis`), NER-based contact classifier (`classify_contact`), trigger-phrase detection, and the UWG §7 hard-block guard. Scope also includes the `mode` column migration for `phrases`, DSGVO anonymization pipeline (spaCy + GLiNER union voting), and the per-SID session state scaffolding for gatekeeper state.

The architecture is solid and the threat model is well-considered. Most patterns (ghost-SID guards, rolling error rate, union/consensus voting asymmetry, per-SID isolation) are correct. One critical bug was found in the `config/__init__.py` cleanup logic that will crash on an empty `config.py`. Five warnings cover logic gaps in the anonymization pipeline, hysteresis edge cases, a schema inconsistency in the corpus gate validator, a missing `is_pipeline_healthy` flag reset path, and a race condition in the UWG guard. Four info items cover dead variable, duplicate code, magic numbers, and a TODO left in a seed fixture.

## Critical Issues

### CR-01: `config/__init__.py` crashes with `NameError` when `config.py` has no public names

**File:** `config/__init__.py:23`
**Issue:** The cleanup line `del _ilu, _os, _sys, _config_py, _k, _v` references `_k` and `_v` unconditionally. These variables are only bound if the `for _k, _v in vars(_mod).items()` loop executes at least once — i.e., if `config.py` exports at least one public name. If `config.py` exists but is empty or contains only private names (prefixed `_`), the loop body never runs, `_k` and `_v` are never assigned, and the `del` statement raises `NameError` at import time, crashing every service that does `from config import ...`.

In practice `config.py` always has public names (ANALYSE_INTERVALL, etc.), so this is latent but will surface if `config.py` is temporarily stripped or in a fresh environment during testing.

**Fix:**
```python
# Replace the unconditional del at line 23 with safe cleanup:
del _ilu, _os, _sys, _config_py
# _k, _v are loop variables — only defined if config.py has >=1 public name
try:
    del _k, _v
except NameError:
    pass
```

## Warnings

### WR-01: `anonymization.py` — overlapping NER spans cause incorrect token substitution

**File:** `services/anonymization.py:289-303`
**Issue:** `_apply_ner()` deduplicates spans via `set(all_spans)` (which removes exact duplicates) but does NOT handle overlapping spans from different models. When spaCy returns `(0, 10, 'PERSON', 'Herr Meyer')` and GLiNER returns `(5, 10, 'PERSON', 'Meyer')`, both survive deduplication. After sorting ascending and reversing for replacement, the earlier span `(0, 10)` is applied last — at this point `result[0:10]` already contains the GLiNER token `[PERSON_A]`, not the original text. The replacement `result[:0] + [PERSON_B] + result[10:]` works on wrong offsets derived from the original string length, producing a corrupted output.

**Fix:** Filter overlapping spans before replacement — keep the longest span when two spans share any characters:
```python
def _remove_overlaps(spans):
    """Keep longest span when two spans overlap. Input sorted by start asc."""
    result = []
    last_end = -1
    for span in sorted(spans, key=lambda x: (x[0], -(x[1]-x[0]))):
        if span[0] >= last_end:
            result.append(span)
            last_end = span[1]
    return result

unique_spans = _remove_overlaps(list(set(all_spans)))
unique_spans.sort(key=lambda x: x[0])
```
Apply same fix to `_apply_ner_parallel()` at line 361.

### WR-02: `apply_hysteresis()` — `phase_entered_at=None` silently bypasses dwell check

**File:** `services/gatekeeper.py:213`
**Issue:** When `state['phase_entered_at']` is `None` (as initialized in `init_session_state`), the guard `entered_at = state.get('phase_entered_at') or time.monotonic()` assigns `time.monotonic()` — the current instant. This makes `elapsed = time.monotonic() - entered_at` approximately `0`, so `elapsed < min_dwell` is True and the transition is blocked. This is actually the safe/conservative outcome. However, the intent documented in the state initialization comment is that `None` means "not yet entered", which should arguably allow an immediate first transition (no dwell to serve yet). The current behavior silently blocks the *first* phase transition for `min_dwell` seconds even though the session just started. For `opener` (min_dwell=5s) this means the first 5 seconds of a call can never trigger a phase change — which may or may not match product intent but is undocumented.

**Fix:** Clarify intent with a documented decision and add a comment:
```python
# If phase_entered_at is None (session just started, no dwell yet):
# Conservative: treat as "just entered" -> full min_dwell must still pass.
# This prevents spurious phase changes in the first few seconds.
entered_at = state.get('phase_entered_at') or time.monotonic()
```
Or if first transition should be instant:
```python
if state.get('phase_entered_at') is None:
    # No prior phase entry recorded -> skip dwell check for first transition
    pass  # fall through to transition check
else:
    elapsed = time.monotonic() - state['phase_entered_at']
    if elapsed < min_dwell:
        return None
```

### WR-03: `verify_corpus_gate.py` — gatekeeper corpus allows `expected_phase=5` or `6` but gatekeeper only has 4 phases

**File:** `scripts/verify_corpus_gate.py:63-64`
**Issue:** `VALID_PHASES = set(range(1, 7))` — `{1, 2, 3, 4, 5, 6}` — is used for all modes including `gatekeeper`. The gatekeeper mode only has 4 phases (per `_PHASE_NAMES_GATEKEEPER` in `claude_service.py`). A corpus entry with `mode='gatekeeper'` and `expected_phase=5` would pass the gate validator but fail the `classify_phase()` range check at runtime (`1 <= phase <= max_phase` where `max_phase=4`), causing the test to always return `None` and count as a miss.

**Fix:** Apply mode-aware phase range validation in `_validate_phase_entry()`:
```python
def _validate_phase_entry(entry, idx):
    ...
    mode = entry.get('mode')
    ep = entry.get('expected_phase')
    max_phase = 4 if mode == 'gatekeeper' else 6
    if not isinstance(ep, int) or not (1 <= ep <= max_phase):
        errs.append(f"Eintrag {idx}: expected_phase='{ep}' ungueltig fuer mode='{mode}' (erlaubt: 1-{max_phase})")
```

### WR-04: `anonymization.py` — `is_pipeline_healthy` never reset to `True` after rolling-error recovery

**File:** `services/anonymization.py:388-398`
**Issue:** `_register_error()` sets `is_pipeline_healthy = False` when the rolling error count exceeds `ROLLING_ERROR_THRESHOLD`. There is no code path that resets `is_pipeline_healthy` back to `True` after the error rate falls below the threshold again. Once the flag trips, `anonymize()` raises `AnonymizationPipelineUnavailable` for all subsequent calls permanently — even after a transient spike resolves. This means a brief GLiNER instability (5 errors in 10 minutes) permanently disables anonymization for the process lifetime, blocking all transcript processing.

**Fix:** Check current error rate in `get_pipeline_status()` and also add a recovery path in `_register_error()` or at the top of `anonymize()`:
```python
def anonymize(text, cache):
    global is_pipeline_healthy
    # Auto-recovery: check if rolling error rate has fallen below threshold
    if not is_pipeline_healthy:
        now = time.monotonic()
        with _error_lock:
            cutoff = now - ROLLING_ERROR_WINDOW_S
            recent = sum(1 for ts in _error_timestamps if ts >= cutoff)
        if recent <= ROLLING_ERROR_THRESHOLD:
            is_pipeline_healthy = True  # recovered
            print('[ANON] Pipeline-Status wiederhergestellt (Error-Rate unter Schwellenwert)')
    if not is_pipeline_healthy:
        raise AnonymizationPipelineUnavailable(...)
    ...
```

### WR-05: `deepgram_service.py` — UWG hard-block state read without lock is a TOCTOU race

**File:** `services/deepgram_service.py:48-49`
**Issue:** The UWG guard reads `ls._session_state.get(sid, {}).get('state', {}).get('uwg_blocked')` without acquiring `ls._session_state_lock`. The Deepgram callback runs in a Deepgram-owned thread. Concurrent writes to `_session_state[sid]['state']['uwg_blocked']` happen under `ls._session_state_lock` (line 163-165). While CPython dict operations are GIL-protected and the worst case is a missed block on a single transcript chunk (the next chunk will be blocked), this is a TOCTOU gap in a security-relevant guard and should be made explicit.

**Fix:** Use the existing helper pattern:
```python
# Replace the bare dict access at line 48:
if ls._session_state.get(sid, {}).get('state', {}).get('uwg_blocked'):
    return
# With a lock-protected read (or document the GIL-safe rationale):
with ls._session_state_lock:
    _uwg_blocked = ls._session_state.get(sid, {}).get('state', {}).get('uwg_blocked', False)
if _uwg_blocked:
    return
```
Alternatively, add a comment documenting that the GIL makes this safe for CPython and that a missed read on one chunk is the acceptable worst case, analogous to the `get_sid_paused()` helper.

def _gliner_label_to_token_type(label: str) -> Optional[str]:

### IN-03: `scripts/gliner_smoke.py` — P95 index calculation is off-by-one for small N

**File:** `scripts/gliner_smoke.py:63-64`
**Issue:** `p95_idx = int(len(latencies_sorted) * 0.95)` for N=100 gives index 95, which is the 96th element — correctly the P95 value. But for N=20 it gives index 19 (the last element), which is P100, not P95. This is a diagnostic script only (exit always 0), so it cannot block deploys, but the measurement shown as "P95" would be inaccurate if run with fewer iterations.

**Fix:** Use the same `_percentile()` helper already defined in `calibrate_phase_durations.py`, or apply the standard formula: `p95_idx = min(int(n * 0.95), n - 1)`.
