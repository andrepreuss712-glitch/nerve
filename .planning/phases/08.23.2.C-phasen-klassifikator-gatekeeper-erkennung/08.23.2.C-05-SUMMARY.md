## What Was Built

### Task 1 — claude_service.py

Drei neue Modul-Konstanten als Phasen-Listen:

- `_PHASE_NAMES_COLD_CALL` — 6 Phasen (opener, permission, reason, pitch, discovery, closing)
- `_PHASE_NAMES_MEETING` — 6 Phasen (intro, agenda, discovery, pitch, objection, closing)
- `_PHASE_NAMES_GATEKEEPER` — 4 Phasen (greeting, identify, bypass, handoff)
- `_PHASE_NAMES_BY_MODE` — Hilfs-Mapping `mode -> (phase_dict, max_phase)`

`classify_phase()` waehlt per `_PHASE_NAMES_BY_MODE.get(mode, fallback)` die richtige Phasen-Liste. Die Range-Validation wurde von `1 <= phase <= 6` (hardcoded) auf `1 <= phase <= max_phase` (modus-spezifisch) umgestellt — Gatekeeper kann also nie Phase > 4 zurueckgeben.

`PHASE_CLASSIFIER_PROMPT` wurde auf `{labels}` + `{mode}` Platzhalter umgebaut — der Prompt erhält jetzt zur Laufzeit die modus-spezifische Phasen-Label-Liste.

`_PHASE_NAMES` (Titel-Case, de) bleibt als Backward-Compat-Alias — Analyse-Loop-Callers an Z.970/974/983/984 haben keinen Modus-Kontext und nutzen diese Liste fuer Log-Output.
