## Stehende Diagnose (NICHT neu diagnostizieren — per Live-Logs Prod 28./29.06. bewiesen)

Quelle: `.planning/debug/ewb-pip-overwrite-multifire.md` (Diagnose + Instrumentierung Pass 1 bereits gebaut + deployed).

- **Wurzel Überschreiben (Bug B):** Manueller EWB-Stream (`streame_manual_ewb_variante`) schreibt slot1 OHNE Lock (per Design `sets_lock=False`). Auto-Erkenner (`streame_auto_variante`/keyword, `qa_slot1`/`analyse_loop`, `coldcall_infer`) schreiben denselben slot1 ~6-8s später und überschreiben die Antwort mitten im Vorlesen.
- **Selbst-Trigger:** NERVE hört DSGVO-bedingt nur den Berater. Liest der die NERVE-Antwort vor, hört der Erkenner NERVEs eigene Worte und feuert fälschlich „neuen Einwand" → genau das treibt das Überschreiben im Lese-Fenster.
- **Lock fragmentiert in 2 Stores:** Keyword-Pfad nutzt GLOBAL `ls.state[...]`; `analyse_loop`/QA nutzt PER-SID `_session_state[sid]['state'][...]`. Diese teilen den Wert evtl. gar nicht; der manuelle Pfad nutzt keinen.
- **Zeitstempel-Bug C (separater Bug):** Knopf-Transkript-Einträge schreiben `ts` als float-epoch (`time.time()`), `_ts_to_ms_of_day` erwartet `'HH:MM:SS'` → `str(ts).split(':')` ohne `:` → ValueError → `ts_ms=0`. Folge-Müll: wenn der erste Transcript-Entry ein Knopf ist (abs=0 → base=0), ergibt eine spätere gesprochene Zeile `ts_ms` = absolute Tageszeit (z.B. ~61019000 ≈ 17h, unmöglich) → Judge-Sortierung nach ts_ms ASC bricht.

<decisions>
## Implementation Decisions (5 Punkte — LOCKED)

### (a) Auto-Erkenner raus aus der Lese-Zone
- Der Auto-Erkenner (`streame_auto_variante`/keyword, `qa_slot1`/`analyse_loop`, `coldcall_infer`) darf slot1 / die Lese-Zone (`pip-slot-body-1`) NIE mehr beschreiben.
- Erlaubt ist ihm nur: bekannten Einwand → den passenden bestehenden Button aufleuchten lassen (Highlight); neuer Einwand (kein Button) → einen zusätzlichen Button erzeugen.
- **Newest-wins-Puffer Größe 1** — kein Stapeln, keine wachsende Liste verpasster Einwände. Jüngstes Auto-Signal gewinnt, bewusst lossy.

### (b) Selbst-Trigger-Gating in der EINFACHSTEN Form
- Solange ein **Pin aktiv** ist (eine Antwort steht in der Lese-Zone / wird vorgelesen), läuft der Erkenner im „Puffern, nicht anzeigen"-Modus.
- Kopplung an den Pin-Lifecycle — **KEIN Sprachabgleich** in dieser Phase (der tolerante Wort-Abgleich „liest er gerade ~die Antwort?" ist optional/später, NICHT Pflicht für PIP.1). Pin aktiv = Gating an. Punkt.
- Erkenner wird dadurch NICHT taub: er darf weiter über die Button-Zone signalisieren (Highlight gepuffert), nur eben nicht in die Lese-Zone schreiben.

### (c) Pin-Lifecycle ereignisbasiert
- Ein geklickter Vorschlag (Pin) persistiert, bis ein nutzergetriebenes Event ihn löst.
- **Legitime Löser — NUR zwei:** (1) Berater drückt einen ANDEREN Button → neue Antwort übernimmt; (2) Berater dismissed explizit (× / Wisch).
- **KEINE Timer / kein Zeitablauf.** Der Auto-Erkenner löst NIE einen Pin (sonst ist der Bug zurück).
- Sprach-Löser (3) („weitergezogen / redet frei") = PIP.3, NICHT jetzt.

### (d) Coaching-TEXT raus aus dem Antwort-Fenster
- Erstmal NUR stoppen, dass Coaching-Text in der Lese-Zone / dem KI-Antwort-Fenster gerendert wird.
- Volle Symbolleiste / Rahmenfarbe / Hover-Tooltip = PIP.2, NICHT jetzt. Hier reicht: Coaching-Text erscheint nicht mehr in der Lese-Zone.

### (e) Zeitstempel-Fix C — SEPARATER atomarer Commit (Punkt 17, kein Vermischen)
- Ein Format-Mismatch, zwei Symptome (ts_ms=0 + Folge-Müll-Timestamp). Fix-Optionen (Planner wählt die saubere):
  - ENTWEDER Knopf-Transcript-Einträge im selben Zeitformat schreiben wie gesprochene (`'HH:MM:SS'`),
  - ODER `_ts_to_ms_of_day` float-epoch-tolerant machen.
  - **Ein Format, kein ts_ms=0 mehr.** Nicht beide Pfade widersprüchlich lassen.
- **MUSS ein eigener Commit sein, getrennt vom Anzeige-Trennungs-Fix.** Kein Refactor-Beifang (Punkt 17).
