## Fix
Die Knopf-Transcript-Zeile (`ls.conversation_log.append(... '*ewb button*' ...)` in
`deepgram_service.py`) schrieb `ts` als float-epoch (`time.time()`). `_ts_to_ms_of_day`
(`routes/app_routes.py:36`) parst aber nur `'HH:MM:SS'` → `str(ts).split(':')` ohne `:`
→ ValueError → `ts_ms=0`. Folge-Muell: war der erste Transcript-Entry ein Knopf
(abs=0 → base=0), ergab eine spaetere gesprochene Zeile `ts_ms` = absolute Tageszeit
(~61019000 ≈ 17h, unmoeglich) → Judge-Sortierung nach `ts_ms ASC` bricht.

**Fix-Wahl (CONTEXT (e), Option 1 — ein Format an der Quelle):** Der Knopf-Pfad schreibt
`ts` jetzt via `datetime.now().strftime('%H:%M:%S')` — exakt wie die gesprochene Zeile
(`deepgram_service.py:66`). `datetime` ist modul-importiert (Z.5). `_ts_to_ms_of_day` +
`_transcript_entries_to_segments` (Konsument) UNVERAENDERT. Nur die eine Append-Zeile
angefasst (kein Refactor-Beifang).
