# Cross-AI Plan Review — Phase 08.23.2.PIP

## Gemini Review

### 1. Summary
Das Plan-Set liefert eine architektonisch starke Loesung fuer Bug B. Indem dem Auto-System
der Schreibzugriff auf die Lese-Zone (`pip-slot-body-1`) komplett entzogen und auf Button-Highlights
reduziert wird (Plan 01), ist die Race-Condition (Text-Ueberschreiben beim Vorlesen) strukturell
eliminiert. Plan 02 fuehrt eine saubere ereignisbasierte State-Machine fuer den Pin ein, Plan 03 fixt
den Timestamp-Bug korrekt an der Quelle. Die Plaene respektieren JS-Single-Threading und die
Null-LLM-Latenz-Vorgabe im UI-Pfad.

### 2. Strengths
- **Architektur-Fix statt Symptom-Management:** Plan 01 trifft die Wurzel. Auto-`pip_token`-Emits
  entfernen + FE-Source-Gate (`d.source === 'manual_button'`) = saubere Defense-in-Depth.
- **Latenz & Kosten:** Entfernen der `streame_auto_variante`-LLM-Generierung nur fuers Highlight
  spart unnoetige Haiku-Calls und verkuerzt die UI-Update-Zeit (Punkt 25).
- **Pin-Lifecycle (Plan 02):** rein ereignisbasiert ohne Timer — keine unvorhersehbaren UI-Shifts
  waehrend des Sprechens.
- **Timestamp-Fix C (Plan 03):** `strftime('%H:%M:%S')` an der Quelle statt Parser verkomplizieren
  ist der sauberste Weg (Punkt 22: "was lebt, gewinnt").

### 3. Concerns & Risks

**[HIGH] Plan 01 — Voller LLM-Text leakt als Button-Label via `_emit_qa_slot1`**
In `services/claude_service.py` wird `_emit_qa_slot1(text)` aktuell mit `_antwort_text` aufgerufen —
einem ganzen, von Haiku generierten Absatz. Baut der Executor `_emit_qa_slot1` naiv auf
`ewb_signal(typ=text)` um, erzeugt die FE einen riesigen Button mit einem ganzen Absatz Text.
*Risiko:* zerstoertes UI-Rendering + kaputte `data-typ`-Delegation.
*Fix:* Executor MUSS die `_kat`-Closure-Variable (das Klassifikations-Label, z.B. 'zu_teuer') aus
`_qa_pipeline_dispatch` als `typ` fuer `ewb_signal` nutzen und den `text`-Parameter komplett verwerfen.

**[HIGH] Plan 01 — `_emit_soft_hint` emittiert lange Strings als Buttons**
`_emit_soft_hint` emittiert aktuell Text wie "Neuer Einwand — noch kein Vorschlag". Geht das als
`ewb_signal` mit `known=False` raus, erzeugt die FE einen Button mit genau diesem Label-Text.
*Risiko:* schlechte UX; Klick auf den Button schickt den ganzen String als Einwand-Typ an die LLM.
*Fix:* Wenn kein sauber klassifiziertes Kurz-Label vorliegt → GAR KEIN Signal emittieren (kein
Fallback-/Hint-Text-Button). Der Plan deutet das an, muss es aber als harte Executor-Anweisung sagen.

**[MEDIUM] Plan 02 — `_clearPin()`-Seiteneffekt bei Call-Ende**
Plan 02 ruft `_clearPin()` in den Reset-Pfaden (3027 / 3482). `_clearPin()` triggert
`_applyBufferedAutoSignal()` — also Rendern eines neuen Button-Highlights Sekundenbruchteile bevor
die UI versteckt wird.
*Risiko:* visuelles Flackern oder Fehler, wenn DOM-Elemente schon teilweise abgeraeumt sind.
*Fix:* `_clearPin(isReset)`-Flag. Bei `isReset=true` KEIN `_applyBufferedAutoSignal()` aufrufen.

**[LOW] Plan 01/02 Contract-Drift — `state.pinActive`-Initialisierung**
Plan 01 nimmt an, `state.pinActive` ist undefined/falsy → `ewb_signal` wendet sofort an. Korrekt &
funktional fuer Welle 1. Keine Aenderung noetig, aber Executor muss sicherstellen, dass `state.pinActive`
in Plan 01 nirgends versehentlich auf `true` initialisiert wird.

### 4. Suggestions for the Executor
- **Plan 01 Task 1 (BE-Emit):** explizite Anweisung ergaenzen: *"Beim Umbau von `_emit_qa_slot1` in
  `claude_service.py` MUSST du die `_kat`-Closure-Variable als `typ`-Payload fuer `ewb_signal` nutzen.
  NICHT den `text`-Parameter (voller Absatz, zerstoert das Button-Layout)."*
- **Plan 01 Task 1 (Soft-Hint):** *"In `_emit_soft_hint` einfach `return`/`pass`. KEIN `ewb_signal` mit
  Literal-Text 'Neuer Einwand — noch kein Vorschlag'."*
- **Plan 02 Task 1 (Clear-Pin):** *"Beim Aufruf von `_clearPin()` aus den Reset-Pfaden (3027/3482)
  keine gepufferten Signale in ein sich versteckendes DOM anwenden — z.B. `_clearPin(isReset=true)`."*
- **Plan 04 Task 2 (Debounce):** Falls `fix-now`, die Debounce-Logik NACH den UI-Updates
  (`_renderSlotResult` + `pinActive = true`) aber VOR dem `socket.emit` platzieren — UI bleibt
  responsiv beim ersten Klick, nur der Netzwerk-Egress wird gedrosselt.

### 5. Risk Assessment
**Overall Risk: MEDIUM.** Das Architektur-Redesign ist aeusserst solide und eliminiert die
Race-Condition elegant. Das Hauptrisiko liegt rein in der Ausfuehrung — konkret die Gefahr, lange
Konversations-Strings (statt kurzer Kategorie-Labels) in das neue `ewb_signal`-Event zu geben, was
die FE-Button-Reihe visuell zerstoeren wuerde. Achtet der Executor auf das Variablen-Scoping in
`_qa_pipeline_dispatch`, wird das Deployment hochstabil.
