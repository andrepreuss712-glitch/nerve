## Root-Cause (Fable, verifiziert)

`_migrate_profile_json()` (app.py:1379, Aufruf :2039) fährt bei jedem Start `ALTER TABLE profile_opener ADD COLUMN type …` (:1423) in `try/except: pass` ("idempotent") **OHNE rollback**. Die Spalte `type` **existiert schon** (Prod-verifiziert) → **DuplicateColumn** → die Postgres-Transaktion ist **vergiftet** → alle Folge-Statements sterben still als `InFailedSqlTransaction` (Postgres-only, auf SQLite unsichtbar). Sichtbar nur bei einem **versions-losen Profil** (ProfileOpener-sync :1454 + UPDATE :1504). Fingerabdruck: `"Profile ?"` im Log (der v4-Batch hätte `"Profile 10"` geloggt) → der Fehler stammt aus `_migrate_profile_json`, nicht aus dem v4-Batch.

## ★ Cross-Layer-Korrektur (Claudian 2026-07-13, Punkt 21/22 — VOR dem Plan gefangen)

**`profiles` hat KEINE Spalte `schema_version`** — die Version lebt AUSSCHLIESSLICH im `daten`-JSON (`Profile`-Model: id/org_id/name/branche/**daten**/erstellt_von/…/consent_text; der v4-Batch liest `_daten.get('schema_version')` app.py:1009). `daten` ist `Text` (kein JSONB). **Folge für die Guards (a)/(b):** die Kurzschreibweise „`SELECT schema_version FROM profiles`" ginge gegen eine **nicht existierende Spalte** ins Leere. Die Guards MÜSSEN `schema_version` aus dem `daten`-JSON lesen:
- Cross-DB-sicher: `SELECT daten FROM profiles WHERE id=:id` → in Python `json.loads(...).get('schema_version') or 1`.
- NICHT `daten::json->>'schema_version'` (PG-only, und `daten` ist Text) und NICHT ein Spalten-SELECT.

## Scope = Option A + Wächter (André + Fable + Claudian, LOCKED)

1. **Totes ALTER + Step-B raus** (app.py:1421-1435) — die echte Mine. (Falls defensiv behalten: `ADD COLUMN IF NOT EXISTS` + rollback. Default-Entscheidung: **raus**, da Spalte Prod-existent + Backfill abgeschlossen.)
2. **`conn.rollback()` in JEDEN swallowing-except auf der `conn`** (:1426, :1434 [entfallen mit Step A/B], :1474, :1492, :1511) — nie `except: pass`/stiller except auf einer Postgres-`conn` ohne rollback.
3. **v4-Batch (:1004-1020): Pro-Profil-Savepoint** (`begin_nested()`) statt Ein-Commit-für-alle — ein defektes Profil kippt nicht den ganzen Batch.
