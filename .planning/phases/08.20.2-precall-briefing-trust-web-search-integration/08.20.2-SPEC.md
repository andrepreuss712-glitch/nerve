# Phase 08.20.2: PreCall-Briefing-Trust + Web-Search-Integration — Specification

**Created:** 2026-04-30
**Ambiguity score:** 0.12 (gate: ≤ 0.20)
**Requirements:** 9 locked

## Goal

`precall_service.py` wird von einem freien Markdown-Briefing zu einem dreischichtigen, verifizierbaren Firmen-Recherche-Output umgebaut: Schicht 1 (strukturierte Pflichtfeld-Karte mit per-Feld Confidence + Source-URL), Schicht 2 (gehärteter Fließtext mit Anti-Halluzinations-Regeln), Schicht 3 (Gesprächs-Empfehlungen als separater Call via `build_profile_context()`).

## Background

`precall_service.py` (235 Zeilen, Phase 04.13) liefert aktuell `{text: free_markdown, firmenname, ansprechpartner, quellen_count}` — keine Struktur, keine Confidence-Level, keine per-Feld-Quellen. Production-UAT 08.20 zeigte zwei Probleme: (1) Halluzinationen bei Firmen mit wenig Web-Präsenz, (2) fehlende strukturierte Sicht auf vertriebsrelevante Kern-Felder.

**HIGH-03-Status (aus deep-dive-training-coaching-precall.md, 2026-04-24):** GELÖST in Phase 08.20. `build_profile_context()` Section 8 `## PreCall-Briefing` (volatile, per-SID) fließt via `ewb_pipeline.py` in Live-EWB. 08.20.2 muss das nicht nochmals reparieren, muss aber sicherstellen dass der neue strukturierte Output korrekt in `_per_sid_briefing` gespeichert wird.

**Was bereits existiert:**
- `_brave_search()` liefert schon `{title, description, url}` pro Treffer — URL-Daten sind verfügbar
- `branchen_data.py` mit `build_branchen_hint()` bereits in Phase 08.20 gebaut
- `build_profile_context()` 9-Sektionen-Pipeline (Sektion 8 = PreCall-Briefing) fertig
- In-Memory-Cache `_briefing_cache` (TTL 5 Min), kein DB-Store für strukturierte Felder

## Requirements

1. **Schicht-1-Output-Schema**: `_generiere_briefing()` gibt ein strukturiertes `fields`-Dict zurück, das die Pflichtfeld-Karte repräsentiert.
   - Current: `_generiere_briefing()` gibt `{text: str, firmenname: str, ansprechpartner: str, quellen_count: int}` zurück
   - Target: Return-Dict erweitert auf `{fields: dict, text: str, empfehlungen: str, firmenname: str, ansprechpartner: str, quellen_count: int}`; `fields` hat pro Feld exakt die Struktur `{value: str, source_url: str|null, confidence: "high"|"medium"|"not_found"}`
   - Acceptance: `isinstance(briefing['fields'], dict)` is True; jedes Feld-Dict hat genau die Keys `value`, `source_url`, `confidence`; keine anderen Keys

2. **Pflichtfelder hard-required**: Vier Felder immer im `fields`-Dict vorhanden, auch wenn `not_found`.
   - Current: Kein strukturiertes Feld-Dict vorhanden
   - Target: `fields` enthält immer die Keys `geschaeftsfuehrer`, `branche`, `mitarbeiterzahl`, `hauptprodukt`; bei nicht-Fund: `{"value": "not_found", "source_url": null, "confidence": "not_found"}`
   - Acceptance: `recherche_firma("CompanyXYZ_die_keine_Online-Praesenz_hat")` gibt `fields` mit allen 4 hard-required-Keys zurück; jeder Key mit `confidence == "not_found"` hat `value == "not_found"` und `source_url == null`

3. **Optionale Felder**: Vier Felder nur bei Fund im `fields`-Dict.
   - Current: Nicht existent
   - Target: `fields` kann zusätzlich die Keys `standorte`, `gruendungsjahr`, `usp_positionierung`, `aktuelle_news` enthalten — NUR wenn `confidence != "not_found"`; nie mit `not_found`-Value
   - Acceptance: Bei einer Firma ohne bekannte Standort-Information fehlt Key `standorte` komplett im `fields`-Dict (kein `{"value": "not_found"}`)

4. **Confidence-Algorithmus**: Claude-System-Prompt enthält explizite, quantifizierte Confidence-Regeln.
   - Current: `PRECALL_SYSTEM_PROMPT` enthält nur "Erfinde KEINE Fakten" als unspezifische Regel
   - Target: System-Prompt enthält exakte Regeln: `high` = Wert in ≥2 unabhängigen Suchergebnissen bestätigt ODER Wert aus einer Primärquelle (Impressum, Handelsregister, Bundesanzeiger); `medium` = Wert in genau 1 Sekundärquelle belegt (Unternehmenswebseite, LinkedIn, Branchenverzeichnis, Pressemitteilung); `not_found` = kein ableitbarer Wert in den Suchergebnissen — KEIN Wert erfinden
   - Acceptance: Grep auf den neuen System-Prompt findet alle drei Confidence-Level mit Quellentyp-Beispielen; kein `low`-Level taucht auf

5. **Schicht-2-Härtung**: Narrative Zusammenfassung (bestehender `text`-Block) mit Anti-Halluzinations-Constraints im System-Prompt.
   - Current: Freier Fließtext ohne Quellenreferenz, Halluzinationen möglich
   - Target: System-Prompt enthält Regeln: jede Aussage über Firma muss aus Schicht-1-Feldern ableitbar sein ODER explizit als `(Annahme)` / `(nicht verifiziert)` markiert werden; kein Raten von Zahlen (Umsatz, Mitarbeiterzahl) ohne Fund; Aktualitätsschwelle: Quellen älter als 36 Monate nicht für Fakten nutzen
   - Acceptance: System-Prompt enthält "nicht verifiziert" oder equivalente Formulierungen für Annahmen-Markierung; keine Zahlen-Raten-Formulierung im Prompt ohne explizite Quellenregel

6. **Schicht-3-Empfehlungen**: Gesprächs-Empfehlungen als separater zweiter Claude-Call nach dem Briefing-Call.
   - Current: Empfehlungen sind im Freitext von `_generiere_briefing()` eingebettet, kein eigenständiger Call
   - Target: Neue interne Funktion `_generiere_empfehlungen(sid, firmenname, fields)` ruft `build_profile_context(user_id, sid=sid)` auf (9-Sektionen-Voll-Profil inkl. frisch generiertem PreCall-Briefing als Section 8) und erstellt damit Empfehlungen; nutzt nur Schicht-1-Felder mit `confidence in ("high", "medium")` als Factbase; Result landet in `briefing['empfehlungen']`
   - Acceptance: `briefing['empfehlungen']` ist non-empty string wenn ≥1 Schicht-1-Feld confidence ≥ medium hat; zweiter Claude-Call ist in der Implementierung als separate Funktion isoliert (nicht im gleichen Haiku-Call wie Schicht-1+2)

7. **briefing_dict-Erweiterung**: `recherche_firma()` gibt das erweiterte Dict zurück und persistiert Schicht-1-Felder in DB.
   - Current: Return: `{text, firmenname, ansprechpartner, quellen_count}` — kein `fields`, kein `empfehlungen`
   - Target: Return: `{fields: dict, text: str, empfehlungen: str, firmenname: str, ansprechpartner: str, quellen_count: int}`; `_per_sid_briefing` speichert kompaktes Schicht-1-Summary + Schicht-2-Text (Schicht-3-Empfehlungen NICHT — die sind für UI, nicht für EWB-Context)
   - Acceptance: Return-Dict hat alle 6 Top-Level-Keys; `ConversationLog.precall_briefing` (bestehend) behält Schicht-2-Text; `set_briefing_for_sid()` bekommt `schicht1_summary + "\n\n" + text` (nicht die Empfehlungen)

8. **DB-Persistenz `precall_fields`**: Neue JSON-Spalte in `ConversationLog` für Schicht-1-Dict.
   - Current: `ConversationLog` hat `precall_briefing TEXT` — nur Freitext, kein strukturiertes Feld
   - Target: Neue Spalte `precall_fields TEXT` (JSON-serialisiertes Schicht-1-Dict) in `ConversationLog`; App-Migration in `app.py` nach dem bewährten Pattern (ALTER TABLE + silent-fail bei bereits vorhandener Spalte)
   - Acceptance: Nach `recherche_firma()` mit `sid`-Param ist `ConversationLog.precall_fields` mit validierbarem JSON befüllt (nicht None); `json.loads(conv.precall_fields)` ergibt Dict mit `geschaeftsfuehrer`, `branche`, `mitarbeiterzahl`, `hauptprodukt` als Keys

9. **UI 3-Layer-Anzeige im PreCall-Modal**: PreCall-Modal zeigt alle drei Schichten sichtbar.
   - Current: PreCall-Modal zeigt `briefing.text` als flachen Markdown-Block
   - Target: Modal enthält drei visuelle Sektionen: (A) Pflichtfeld-Karte oben — kompaktes Grid/Liste mit Feldname + Value + Confidence-Icon; (B) Fließtext-Block (Schicht-2) darunter; (C) Empfehlungs-Block (Schicht-3) darunter; `not_found`-Felder in der Karte mit neutralem Text ("Nicht gefunden") und gedämpfter Darstellung
   - Acceptance: PreCall-Modal enthält HTML-Elemente für alle drei Sektionen (A/B/C) unterscheidbar; `not_found`-Felder werden angezeigt (nicht ausgeblendet) mit eigenem visuellen Stil; Karte ist oben (DOM-Reihenfolge vor Fließtext)

## Boundaries

**In scope:**
- `precall_service.py` komplett überarbeitet: neues Schicht-1-JSON-Schema + Anti-Halluzinations-Prompt + separater Schicht-3-Call
- Neues `PRECALL_FIELDS_SYSTEM_PROMPT` (JSON-strukturierter Output mit Confidence-Algorithmus)
- `_generiere_briefing()` → Schicht-1+2 (JSON fields + text)
- Neue Funktion `_generiere_empfehlungen()` → Schicht-3 (via `build_profile_context()`)
- `recherche_firma()` orchestriert beide Calls und gibt erweitertes Dict zurück
- `ConversationLog.precall_fields` Spalte + App-Migration
- `set_briefing_for_sid()` bekommt Schicht-1-Summary + Schicht-2-Text (kein Schicht-3)
- UI: PreCall-Modal 3-Layer-Layout (JS + HTML/Jinja-Seite des Modals)
- Confidence-Symbole im UI (UI-Icon per Level: high=✓ grün, medium=~ gelb, not_found=— grau)

**Out of scope:**
- Briefing-Lebenszyklus (Refresh, Veraltet-Markierung, 4 User-Optionen für Skript-Verschmelzung) — gehört zu Phase 08.20.3
- Edit-/Override-Hooks (User korrigiert Felder manuell) — Phase 08.20.3 / Briefing-Lifecycle-Phase
- Cross-User-Firmen-DB / zentrale Firmen-Wissensdatenbank — eigene Entscheidung in `04 Entscheidungen/` + spätere Phase
- Visual-Polish (Farben, Animationen, Design-Overhaul) — Block O Design-Phase
- Branchen-Cluster-Mapping für `branche`-Feld (Freitext bleibt in 08.20.2) — kann in späterem Refactor auf `branchen_data.py`-Cluster gemappt werden
- `geschaeftsfuehrer`-Strukturierung (Position, LinkedIn-URL) — Freitext-Name reicht in 08.20.2
- Redis-Cache für cross-Worker-Sharing (MEDIUM-07) — nach Stabilitätsnachweis separate Phase
- `user_id=None` Cost-Tracker-Fix (MEDIUM aus Audit) — separates Cleanup-Ticket
- EWB-Prompt-Format-Änderung für Section 8 (Section 8 bleibt wie in 08.20 definiert, nur der Inhalt wird besser)

## Constraints

- **Modell:** `MODEL_PRECALL` (aktuell Haiku 4.5) für BEIDE Calls (Schicht-1+2 und Schicht-3). Sonnet NICHT für PreCall — kostenpolitische Regel aus `CLAUDE.md` (Haiku für alles außer Post-Call).
- **Output-Format Schicht-1:** Claude muss valides JSON ausgeben. System-Prompt muss explizite JSON-Struktur-Vorlage enthalten. Kein Markdown-Wrapper um das JSON. Python-seitig: `json.loads()` mit Exception-Handling + graceful degradation (bei Parse-Fehler: alle Pflichtfelder auf `not_found` setzen, `text` bleibt erhalten).
- **Zwei separate Claude-Calls:** Schicht-1+2-Call zuerst, dann Schicht-3-Call. Schicht-3-Call darf erst nach `set_briefing_for_sid()` starten (wegen build_profile_context() Section 8).
- **DSGVO D-03:** Keine Rohdaten-Speicherung von Suchergebnissen in DB. `precall_fields` speichert nur Claude-extrahierte Felder, NICHT die rohen Brave-Search-Snippets.
- **Backward Compatibility:** `briefing['text']` bleibt im Return-Dict erhalten (bestehende Consumer: `session_detail.html`, `_per_sid_briefing`). Cache-Key und TTL bleiben unverändert (5 Min In-Memory).
- **DB-Migration Pattern:** Nach bewährtem `app.py`-Pattern: `ALTER TABLE conversation_logs ADD COLUMN precall_fields TEXT` mit silent-fail bei `duplicate column` (identisch zu bestehenden Migrationsstellen in `app.py`).
- **Brave Search bleibt:** Kein Provider-Wechsel in 08.20.2. Wenn später auf anderen Anbieter gewechselt wird, ist das eine eigene Phase.

## Acceptance Criteria

- [ ] `recherche_firma()` gibt Dict mit Keys `fields`, `text`, `empfehlungen`, `firmenname`, `ansprechpartner`, `quellen_count` zurück
- [ ] `fields` enthält immer alle 4 Keys: `geschaeftsfuehrer`, `branche`, `mitarbeiterzahl`, `hauptprodukt`
- [ ] Jeder Eintrag in `fields` hat genau die Keys `value`, `source_url`, `confidence`
- [ ] `confidence` ist immer genau einer von: `"high"`, `"medium"`, `"not_found"` — kein anderer Wert
- [ ] Felder mit `confidence == "not_found"` haben `value == "not_found"` und `source_url == null`
- [ ] Optionale Felder (`standorte`, `gruendungsjahr`, `usp_positionierung`, `aktuelle_news`) erscheinen NUR bei `confidence != "not_found"` im Dict
- [ ] `ConversationLog` hat Spalte `precall_fields TEXT` (nullable); `json.loads(conv.precall_fields)` ergibt valides Dict nach einem PreCall
- [ ] `ConversationLog.precall_briefing` (bestehend) enthält weiterhin Schicht-2-Text (keine Regression)
- [ ] `_per_sid_briefing` wird mit Schicht-1-kompaktem-Summary + Schicht-2-Text befüllt (NICHT nur text, NICHT die Empfehlungen)
- [ ] `_generiere_empfehlungen()` ist eine isolierte Funktion (nicht im gleichen Call wie `_generiere_briefing()`)
- [ ] `_generiere_empfehlungen()` ruft `build_profile_context()` auf (verifizierbar via Code-Review)
- [ ] Neues System-Prompt enthält alle drei Confidence-Level (`high`, `medium`, `not_found`) mit Quellentyp-Kriterien explizit formuliert
- [ ] PreCall-Modal zeigt drei visuelle Abschnitte: Pflichtfeld-Karte (oben), Fließtext (mitte), Empfehlungen (unten)
- [ ] `not_found`-Felder in der Karte werden angezeigt (nicht ausgeblendet), mit eigenem CSS-Stil
- [ ] Bestehende PreCall-Tests laufen durch (keine Regressions-Breaks in `test_*precall*` Dateien)
