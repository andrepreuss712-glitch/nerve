# Phase 07.1 — POLISH-24: Session-Detail-Redesign

## Scope (gelockt)

Route `/session/<id>` (Template `templates/session_detail.html`) komplett auf MAIN DESIGN umbauen. 8 Sektionen von oben nach unten:

1. **Header:** Session #id | Modus-Badge (Cold Call / Meeting) | Datum | Dauer | Result
2. **Score-Hero:** Grosse Score-Zahl + Breakdown mit 4 Komponenten:
   - `kb_end` (Kaufbereitschaft Ende) 40%
   - `behandelt-Rate` (erfolgreich behandelte Einwaende) 30%
   - `redeScore` (Redeanteil) 20%
   - `skript` (Skript-Abdeckung) 10%
   - Plus Trend vs Schnitt letzte 5 (`/api/postcall/trend?n=5`, existiert bereits aus POLISH-22)
3. **Kaufbereitschafts-Verlauf:** Grosse Chart-Kachel mit X/Y-Achsen via Chart.js (bereits in `static/vendor/`)
4. **Einwand-Timeline:** chronologisch, je Einwand mit gewaehlter Option + erfolgreich-Badge
5. **Phasen-Visualisierung:** horizontaler Strip ueber Call-Dauer, Phasen farblich
6. **Skript-Abdeckung:** Progress-Bar mit Block-Breakdown
7. **Painpoints-Liste:** wenn vorhanden (Empty-State sonst)
8. **PreCall-Briefing:** collapsible, wenn vorhanden (Empty-State sonst)

**Explizit NICHT drin:** Transkript (Phase 4.19), Lernkarten (eigene Phase), Audio-Player.

## DB-Migration (eigener Task VOR UI-Redesign)

1. `ALTER TABLE conversation_logs ADD COLUMN kb_verlauf TEXT;` (SQLite)
2. In `/api/beenden`-Handler ConversationLog-Create: `kb_verlauf=_json.dumps(kb_verlauf, ensure_ascii=False)`
3. Smoke-Test: Neuer Call -> Ende -> DB-Check dass `kb_verlauf` gefuellt ist
4. Fuer alte Sessions: leer/null -> Empty-State in UI (Chart-Kachel mit "Noch keine Daten")

## Design-Constraints (CRITICAL — nicht abweichen)

- **MAIN DESIGN (Phase 7):** weisse Kacheln, schwarze Schrift, teal Akzent (#00D4AA), kein Gelb/Gold, Header-Schwarz **nur** im PiP (auf session_detail Standard-weiss-Header)
- **Borders:** `border: 1.5px solid var(--n-border)` aus `nerve.css` — NIEMALS inline
- **Keine Inline-Styles.** Der aktuelle `<style>`-Block in `session_detail.html` muss RAUS. Alle Styles in `nerve.css` als `.n-session-detail-*` Klassen-Familie (prefix konsolidiert)
- **CSS_VERSION bumpen** nach Deploy (aktuell `'20260418-1'` -> `'20260418-2'`) wegen Browser-Cache
- **Kein `data-theme`** — Phase 7 hat den Dead-Code entfernt, nicht wieder einfuehren
- **Mobile-responsive** (Kacheln untereinander, Charts vollbreit)
- **Zurueck-Navigation zu `/logs`** funktioniert (Header-Link oder Breadcrumb)

## RULE-Checks

- **RULE-01 (Socket-Events):** Welche Frontend-Handler schreiben auf `session_detail`-DOM? -> Antwort: **keine**, reine SSR-Seite. Safe.
