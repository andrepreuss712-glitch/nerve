## Spacing Scale

Declared values (alle Vielfache von 4, orientiert am 8-Punkt-Raster):

| Token | Value | Usage in diesem Phase |
|-------|-------|-----------------------|
| xs | 4px | Icon-Gaps in Badges, Badge-Inner-Gap |
| sm | 8px | Zwischen Label und Value in KPI-Cards, Chart-Legend-Gap |
| md | 16px | Default Card-Padding vertikal (Section-Header zu Content), Grid-Gap zwischen Kacheln, Gap zwischen Recommendation-Cards |
| lg | 24px | Card-Padding Innen (`.n-session-detail-card`), vertikal zwischen Sektionen (1-11) |
| xl | 32px | Top-Padding der Seite unter dem Header, Abstand Score-Hero zu Chart-Sektion |
| 2xl | 48px | Abstand Header-Block zu erster Inhaltssektion (Score-Hero), Bottom-Padding vor Footer |
| 3xl | 64px | Nicht verwendet (Page ist content-dense, kein Hero-Breathing-Space noetig) |

**Exceptions:**
- Chart-Canvas-Hoehe: 280px (fixer Pixel-Wert, keine Spacing-Token — Chart.js rendert auf Canvas-Pixelmass, responsive via Chart.js-Option `maintainAspectRatio:false`)
- Phasen-Strip-Hoehe: 32px (horizontaler Balken, feste Hoehe damit Phasen-Segmente lesbar bleiben)
- Progress-Bar-Hoehe: 8px (Skript-Abdeckung, abgeleitet aus `--metric-track-height` in nerve.css skaliert um 2.7x fuer groessere Prominenz)
- Badge-Padding (Modus-Badge): nutzt bestehendes `--badge-padding: 3px 10px` aus nerve.css — nicht neu definieren
- Mobile-Breakpoint `<768px`: Grid kollabiert auf `1fr`, Card-Padding reduziert auf `md` (16px)
- Recommendation-Card left-border: 3px (feste Pixel-Angabe fuer die teal Akzent-Linie in Sektion 9 — aus Spacing-Skala ausgenommen, da Border-Width, nicht Layout-Spacing)

### Data-Source (Backend-Contract)

Neuer Helper in `routes/app_routes.py`:

```python
def _derive_practice_recommendations(conv, events):
    """POLISH-24: Heuristik-basierte Trainings-Empfehlungen aus persistierten Metriken.
    Returns: List[Dict] mit max 3 Eintraegen, sortiert nach Prioritaet (schwerster Patzer zuerst).

    Keys pro Eintrag:
      - icon: 'target' | 'alert-circle' | 'trending-down' (Lucide-Name, ASCII)
      - observation: str (14px/600, konkrete Zahl + was passiert ist)
      - explanation: str (14px/400, ein Satz warum das kritisch ist)
      - training_focus: str (z.B. 'objections:kein_bedarf') — ASCII-Slug fuer Phase 4.12
      - training_url: str (heute immer '/training', nach Phase 4.12 '/training?focus=...')
    """
```

Priorisierungs-Reihenfolge (hoechste Prioritaet zuerst):

1. **Nicht behandelte Einwaende:** Aus `events` filtern auf `event_type='objection'` mit `success=false` → Zaehle nach `einwand_typ` (z.B. `kein_bedarf`, `zu_teuer`). Wenn Count fuer einen Typ ≥ 2: `training_focus=f"objections:{einwand_typ}"`, Observation `f"Du hast {count}x '{typ_label}' nicht behandelt"`.
2. **Kaufbereitschafts-Drop:** Aus `kb_verlauf` die groesste Absenkung zwischen zwei benachbarten Datenpunkten berechnen. Wenn Drop ≥ 15 Punkte: `training_focus="kb:drop"`, Observation `f"Deine Kaufbereitschaft fiel um {drop} Punkte im Verlauf"` (Phase-Referenz nur wenn Phasen-Daten eindeutig).
3. **Redeanteil zu hoch/niedrig:** `redeanteil_avg < 25` oder `> 65` → `training_focus="redeanteil:too_high"` oder `"redeanteil:too_low"`. Observation z.B. `f"Du redest {redeanteil}% — {target-Aussage}"`.
4. **Skript-Abdeckung niedrig:** `skript_abdeckung < 60` → `training_focus="skript:coverage"`, Observation `f"Opener/Skript nur zu {skript}% abgedeckt"`.

Helper liefert max 3 Eintraege. Wenn <3 Trigger feuern: liefert die feuernden. Wenn 0 Trigger: liefert `[]` → Template rendert Empty-State.

Parser-Robustheit: bei `kb_verlauf is None` oder leerem Array → skip-Regel (2) komplett. Bei `events is None` → skip-Regel (1). Bei `redeanteil_avg is None` → skip-Regel (3).
