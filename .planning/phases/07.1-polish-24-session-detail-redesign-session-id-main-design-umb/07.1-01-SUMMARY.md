# Phase 07.1 Plan 01: backend-db-helper Summary

**One-liner:** Backend-Foundation fuer POLISH-24 Session-Detail-Redesign — DB-Spalte
`kb_verlauf` migriert, Persistierung in `/api/beenden` verdrahtet, typ+mode-aware
`_derive_practice_recommendations` Helper mit Cross-Context-Queries angelegt und
`session_detail`-Route um 8 Template-Context-Variablen erweitert.

## What Was Done

### Task 1 — DB Migration + ORM + Persistenz (Commit `63e5485`)

1. **app.py:** Idempotenter Phase-07.1-Migrationsblock eingefuegt (direkter Spiegel
   des 04.9-Blocks). `ALTER TABLE conversation_logs ADD COLUMN kb_verlauf TEXT` mit
   `try/except Exception: pass` fuer zweiten Start.
2. **database/models.py:** `ConversationLog.kb_verlauf = Column(Text, nullable=True)`
   nach `precall_briefing` eingefuegt. JSON-Shape dokumentiert als
   `[{ts: "HH:MM:SS", wert: 0-100}]`.
3. **routes/app_routes.py:** In `/api/beenden` ConversationLog-Create die lokale
   Variable `kb_verlauf` via `_json.dumps(..., ensure_ascii=False)` persistiert.

### Task 2 — Helper + Route Erweiterung (Commit `435ffce`)

1. **routes/app_routes.py:** Drei neue Funktionen nach `_calc_call_score`:
   - `_cross_context_objections_live(db, user_id, einwand_typ)` — Live-Session →
     Training-Stats (14 Tage, `AVG(CL.kb_end)` nicht sterne, SC-1).
   - `_cross_context_objections_training(db, user_id, einwand_typ)` — Training-Session
     → Live-Stats (14 Tage, `COUNT + SUM(success)`).
   - `_derive_practice_recommendations(db, conv, events)` — typ+mode-aware Regeln
     mit max 3 Eintraegen, sortiert nach Prioritaet. Cross-context dict nur bei
     Objection-Recommendations.
2. **routes/dashboard.py:** `session_detail`-Route erweitert um `pt` (PersonalityType
   pre-resolve), `trend_avg` (live-only), `chart_data_json` (typ-diskriminierend),
   `schwierigkeit_label` (aus phasen_details.schwierigkeit), `recommendations`
   (Helper-Output), `score_total` (Live: `_calc_call_score`, Training: `kb_end or 0`).
   Inline-Imports fuer `PersonalityType` und Helper, keine Circular-Import-Risks.

## Key Technical Decisions

### ObjectionEvent-Attribut heisst `success`, nicht `erfolgreich`

Der Plan referenzierte `OE.erfolgreich` / `r.erfolgreich` / `ev.erfolgreich` an
vier Stellen. Das tatsaechliche Model (`database/models.py:349`) hat
`success = Column(Boolean, default=False, nullable=False)`. Blosse Ausfuehrung des
Plans haette zu `AttributeError` beim ersten Helper-Call gefuehrt.

**Rule 1 Auto-Fix:** In allen 4 neuen Stellen `erfolgreich` → `success` geaendert,
plus inline-Kommentar "ObjectionEvent-Column heisst success, nicht erfolgreich"
fuer zukuenftige Wartung.

### W-01: `select_from(OE)` explizit

Beide Cross-Context-Helpers nutzen `db.query(...).select_from(OE).join(CL, ...)`
weil das Query-Tupel mit Aggregaten (`func.count`, `func.avg`) plus JOIN auf CL die
Root-Entity fuer SQLAlchemy 2.x ambiguous machen wuerde. Ohne `select_from` wirft
`InvalidRequestError`. Smoke-Test bestaetigt (`CROSS_OK {'sessions': 0,
'avg_score': None, ...}`).

### W-02: Kein Circular-Import

`routes/app_routes.py` enthaelt keinen `from routes.dashboard` Import. Dashboard
importiert Helper aus app_routes, nicht umgekehrt. Verifiziert:
`grep -c "from routes.dashboard" routes/app_routes.py` = 0.

### W-06: `score_total` typ-aware in Route

Route berechnet `score_total` server-seitig und uebergibt an Template. Live:
`_calc_call_score(conv)`. Training: `conv.kb_end or 0`. Trend-Badge wird nur fuer
Live gerendert (`trend_avg` bleibt fuer Training None). Verifiziert:
`grep -c "score_total" routes/dashboard.py` = 4.
