### 2.4 `routes/app_routes.py` — `_derive_practice_recommendations` Helper (role: helper, flow: read-only ORM + CPU)

**Analog 1 (Signatur + Style):** `routes/app_routes.py:573-583` — `_calc_call_score(conv)`

**Exact excerpt:**
```python
def _calc_call_score(conv):
    """Server-seitige Spiegelung der client-seitigen _calcScore()-Formel in pip-launcher.js.
    Gewichtung: kb_end 40%, behandeltRate 30%, redeScore 20%, skript 10%."""
    kb = conv.kb_end if conv.kb_end is not None else 30
    einw_total = conv.einwaende_gesamt or 0
    einw_ok = conv.einwaende_behandelt or 0
    behandelt_rate = (einw_ok / einw_total) if einw_total > 0 else 0.5
    redeanteil = conv.redeanteil_avg if conv.redeanteil_avg is not None else 50
    rede_score = max(0, 100 - abs(redeanteil - 40) * 2)
    skript = conv.skript_abdeckung or 0
    return min(100, max(0, round(kb * 0.4 + behandelt_rate * 100 * 0.3 + rede_score * 0.2 + skript * 0.1)))
```

**Muster zu spiegeln:**
- Plain `def`, keine Decorators
- Docstring mit Gewichtung / Zweck
- None-Guards via `or N` oder `x if x is not None else N`
- Return als `min/max/round`-Clamp fuer numerische Ergebnisse
- Side-effect-frei, liest `conv` + uebergebene Kollektionen

**Analog 2 (ORM-Query-Pattern fuer Cross-Context):** `routes/app_routes.py:602-618` — `api_postcall_trend`

**Exact excerpt:**
```python
db = get_session()
try:
    recent = (
        db.query(ConversationLog)
          .filter(ConversationLog.user_id == g.user.id)
          .filter(ConversationLog.typ == 'live')
          .order_by(ConversationLog.created_at.desc())
          .limit(n)
```

```python
@dashboard_bp.route('/session/<int:sid>')
@login_required
def session_detail(sid):
    from database.models import ConversationLog as CL, ObjectionEvent, PersonalityType
    db = get_session()
    try:
        conv = db.query(CL).filter(CL.id == sid, CL.user_id == g.user.id).first()
        if not conv:
            abort(404)
        events = db.query(ObjectionEvent).filter(ObjectionEvent.conversation_log_id == sid).all()

        # Phase 07.1 NEU — Trend der letzten 5 Calls desselben typ

        recent = (db.query(CL)
                    .filter(CL.user_id == g.user.id, CL.typ == conv.typ)
                    .filter(CL.id != conv.id)
                    .order_by(CL.created_at.desc()).limit(5).all())
        trend_avg = round(sum(_calc_call_score(c) for c in recent) / len(recent)) if recent else None

        if conv.typ == 'training':
            chart_data_json = conv.stimmung_history or '[]'
        else:
            chart_data_json = conv.kb_verlauf or '[]'

        # Phase 07.1 NEU — Schwierigkeit aus phasen_details parsen (siehe RESEARCH Q2)
        schwierigkeit_label = '—'
        # ... parse logic ...

        # Phase 07.1 NEU — Recommendations
        recommendations = _derive_practice_recommendations(db, conv, events)

        return render_template('session_detail.html',
                               conv=conv, events=events,
                               pt=pt, trend_avg=trend_avg,
```

## 4. Risk Callouts (Analog ≠ Phase-Requirement)

### 4.1 `.n-page` / `.n-h1` / `.n-h2` existieren NICHT in nerve.css

**Finding:** Grep in `static/nerve.css` nach `\.n-page`, `\.n-h1`, `\.n-h2` → **0 Treffer**. Die Klassen werden aktuell im `templates/session_detail.html` (Dark-Mode-inline-Block) und in `templates/analytics.html` (ebenfalls Dark-Mode-inline) referenziert, sind aber **nicht global** in nerve.css definiert.

**Konsequenz fuer Planner:** Die UI-SPEC Rev 3 Zeile 323-326 sagt "Bestehende Klassen wiederverwendet: `.n-page`, `.n-h1`, `.n-h2`". Die sind aber in der aktuellen nerve.css nicht existent. **Planner muss entscheiden:**
- **Option A (empfohlen):** Diese drei Klassen in nerve.css global deklarieren (Teil der 07.1-CSS-Arbeit). Dann sind sie auch fuer analytics.html verwertbar sobald die auf MAIN DESIGN umgebaut wird.
- **Option B:** Ersetze `.n-page` durch einen neuen `.n-session-detail-page`-Container und vermeide die Abhängigkeit komplett.

**Empfehlung:** Option A, mit minimalen CSS-Definitionen (MAIN DESIGN-Farbwerte). Das macht die 07.1-CSS-Arbeit marginal groesser aber raeumt eine echte Luecke auf.

### 4.2 `templates/analytics.html` ist aktuell Dark-Mode (nicht MAIN DESIGN)

**Finding:** `analytics.html:35-40` zeigt inline-Dark-Styles (`background:#1C2333`, `color:#fff`, `border:1.5px solid #2D3748`). Das widerspricht der RESEARCH-Behauptung (CONTEXT.md-Implied) "analytics.html ist bereits MAIN DESIGN".

**Konsequenz fuer Planner:** Der Zurueck-Link `← Zurück zur History` zeigt auf `/logs`, das noch Dark-Mode ist. **Nicht blockierend fuer 07.1** — aber kosmetischer Bruch: Nutzer klickt Back auf Light-Mode-Detail, landet auf Dark-Mode-Liste. **Nicht in 07.1 fixen** (Scope-Creep), aber als Follow-Up-Phase `POLISH-25 /logs-Redesign` im Plan vermerken.

### 4.3 `dashboard.html:880-923` Chart-Init ist DARK-Mode — muss bei Kopie getauscht werden

**Finding:** Die Chart-Colors in `dashboard.html:883-884` (`#8B949E`, `rgba(255,255,255,0.05)`) sind Dark-Mode-Farben.

**Konsequenz:** Planner KOPIERT das Init-Gerüst, tauscht aber Ticks/Grid-Farben auf MAIN DESIGN (siehe 2.6 oben + UI-SPEC Rev 4 Zeile 555-568).

### 4.4 Chart.js NICHT in base.html — muss pro-Template geladen werden (SC-2)

**Finding:** `base.html:8` laedt nur `lucide.min.js`. Chart.js wird in `dashboard.html:380` und `training.html:2226` einzeln per `<script>`-Tag eingebunden.

**Konsequenz fuer Planner:** Im `session_detail.html` **am Ende des `{% block content %}`** folgenden Tag einfuegen (vor dem Init-Script):
```html
<script src="{{ url_for('static', filename='vendor/chart.umd.min.js') }}"></script>
```

**Nicht** in `base.html` hochziehen — Chart.js ist Seiten-spezifisch und wuerde auf `/live`, `/logs`, `/settings` unnoetig Payload kosten.

### 4.5 `conv.sterne` ist fuer Training-Sessions IMMER NULL (SC-1)

**Finding:** `models.py:263` hat Spalte `sterne` (nicht `sterne_rating`). `routes/training.py:692-708` schreibt `sterne` nicht. Training-Sessions haben `sterne=NULL`.

**Konsequenz fuer Planner:**
- UI-SPEC Rev 3 Variante C Score-Breakdown „Sterne-Rating 40%" → Planner muss stattdessen `conv.kb_end` (Claude's gesamt_score, 0-100) nutzen
- Cross-Context-Query bei Live → Training: statt `AVG(sterne)` → `AVG(kb_end)` (siehe 2.4 Analog 2)
- Cross-Context-Badge-Copy anpassen: `"Zuletzt im Training: Ø {avg_score}/100 aus {n} Sessions"` statt `"Ø {avg_sterne}★"`

### 4.6 SQLite unterstützt `INTERVAL` nicht (SC-7)

**Finding:** UI-SPEC Rev 3 SQL-Pseudo-Code nutzt `NOW() - INTERVAL '14 days'`. SQLite kennt das nicht.

**Konsequenz:** Python-side cutoff via `datetime.utcnow() - timedelta(days=14)` (siehe 2.4 Analog 2).

### 4.7 `ObjectionEvent`-FK heisst `conversation_log_id`, nicht `conv_id` (SC-8)

**Finding:** `models.py:345` — `conversation_log_id = Column(Integer, ForeignKey('conversation_logs.id'))`.

**Konsequenz:** Alle JOINs `.join(CL, CL.id == OE.conversation_log_id)` — nicht `.join(... == OE.conv_id)`.

### 4.8 CSS_VERSION sitzt in `app.py:28`, nicht in `base.html`

**Finding:** `app.py:28` setzt `app.config['CSS_VERSION'] = '20260418-1'`. `base.html:7` liest nur via `{{ config.get('CSS_VERSION', '1') }}`.

**Konsequenz:** Der Bump `'20260418-1'` → `'20260418-2'` passiert in `app.py` (eine Zeile), **nicht** in `base.html`. Das Briefing-Spawn-Prompt hat das falsch zugeordnet.

### 4.9 `personality_type_id` hat KEIN `relationship()` — Template muss pre-resolved bekommen

**Finding:** `models.py:278` — raw Column, kein `relationship()`. `conv.personality_type` ist nicht attribute-accessible.

**Konsequenz:** Route muss `pt` via zweite Query pre-laden und als Template-Kontext uebergeben (siehe 2.5 oben).

### 4.10 `events` haben praktisch denselben Timestamp (RESEARCH R1)

**Finding:** `ObjectionEvent.created_at` ist Call-Ende-Zeit (alle Events werden bei `/api/beenden` gebulk-inserted). Keine sub-Sekunde-Präzision pro Click.

**Konsequenz:** Sektion 4 "Einwand-Timeline chronologisch" — Planner nimmt `ObjectionEvent.id` als Reihenfolge-Kriterium (auto-increment). Zeitstempel nur als "HH:MM" anzeigen (alle gleich = OK), oder ganz weglassen und nur Nummer+Typ+Erfolg zeigen.

### 4.11 `deploy.sh` muss NICHT angepasst werden

**Finding:** Cache-Bust erfolgt via CSS_VERSION-URL-Param, nicht via deploy.sh. `deploy.sh` ist im Excludes-Block (sich-selbst-exclude) und wird auch nicht hochgeladen.

**Konsequenz:** `deploy.sh` aus der Datei-Liste entfernen. Kein Touch-Pattern.

### 4.12 Training-Sessions haben meist leere Sektionen 4, 5, 6, 7, 8 (RESEARCH Empty-State-Matrix)

**Finding:** `routes/training.py:692-716` schreibt keine `painpoints_details`, keine `precall_briefing`, keine `gegenargument_details` (sondern `ga_details`), kein Skript-Abdeckung. `phasen_details` enthaelt bei Training das `scoring`-Dict, nicht klassische Phasen-Liste.

**Konsequenz fuer Planner:** Alle Empty-State-Handler im Template MUESSEN robust sein. Training-View ist dominiert von Empty-Placeholders — das ist kein Bug dieser Phase, sondern der aktuelle Zustand.
