## Warnings

### WR-01: PiP-Tab shown with empty body when `precallBriefing.text` is null

**File:** `static/pip-launcher.js:1917`

**Issue:** The PiP-Tab gate fires when `state.precallBriefing && state.precallBriefing.firmenname` is truthy (line 1917–1918). This condition does not require `precallBriefing.text` to be present. If the briefing API returned only a firmenname with no analysis text (e.g., all fields `not_found`, no markdown body), the tab is shown with the firmenname as title but an empty content div. The user sees a visible tab that expands to nothing.

This can occur when the Step 4 "Briefing übernehmen" confirm handler fires: `ta` is null (textarea was not rendered because `briefingText` was empty), so `state.precallBriefing.text` is never written — it may remain `null` or `''`.

**Fix:** Extend the gate condition to also require non-empty text, or render a fallback message in the content div:

Option A — stricter gate (tab only appears with content):
```javascript
// pip-launcher.js ~line 1917
if (state.precallBriefing &&
    state.precallBriefing.firmenname &&
    state.precallBriefing.text) {
```

Option B — show fallback text when content is empty (tab stays visible for firmenname):
```javascript
// pip-launcher.js ~line 1925
if (contentEl) {
  var briefingHtml = state.precallBriefing.text
    ? mdToHtml(state.precallBriefing.text)
    : '<p style="color:var(--page-text-muted);font-size:12px">Keine Analyse-Daten verfügbar.</p>';
  contentEl.innerHTML = briefingHtml;
}
```

Option A is simpler and aligns with the phase intent (tab = briefing content in PiP).
