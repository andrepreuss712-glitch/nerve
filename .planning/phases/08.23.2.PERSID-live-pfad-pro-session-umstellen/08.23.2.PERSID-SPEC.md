## Goal

Der komplette Live-Anruf-Pfad wird von **modul-globalem** Zustand auf **pro-Session-Zustand** (`_session_state[sid]`) umgestellt, sodass zwei EA-User, die gleichzeitig telefonieren, sich strukturell NICHT mehr vermischen können — heute vermischen sich ihre Daten bis ins rohe Transkript und den persistierten Anruf-Datensatz über Firmen-Grenzen hinweg (RLS fängt das NICHT), und wer auflegt reißt dem anderen den Live-Zustand weg (`reset_session` fasst alle aktiven Sessions an). Launch-Blocker + Vorbedingung für das geparkte Gedächtnis-Feature (TAXO3-b).

## Background

## Requirements

1. **`_merge_pending` pro Session keyen (rohes Transkript, schwerster Fund)**: Der Transkript-Zusammenführungs-Puffer wird pro `sid` gehalten statt nach Sprecher-String global.
   - Current: `_merge_pending` global, gekeyt nach `str(speaker)` `"0"/"1"/"unknown"` (`deepgram_service.py:195`, `live_session.py:91`, `_flush_segment` `live_session.py:797-814`) → parallele Calls schütten Transkript-Segmente in denselben Puffer.
   - Target: Puffer + Flush liegen unter `_session_state[sid]`; jeder Call sieht nur seine eigenen Segmente.
   - Acceptance: Im Nebenläufigkeits-Test (Req 12) enthält `transcript_segments` von Session A KEINE Wörter der Session B (Cross-Tenant-PII-Beweis, gepaarte Assertion: eigenes DA + fremdes WEG).

2. **`record_suggestion_offer`/`record_ewb_click` pro Session**: Vorschlags-/Knopf-Ereignisse landen im Session-Bucket, nicht global.
   - Current: beide `append` in globale `state['ewb_clicks']`/`state['suggestion_offers']` ohne sid (`live_session.py:983-1023`).
   - Target: beide schreiben in `_session_state[sid]`; ohne sid → sauberes No-Op/None-Muster (kein Raten).
   - Acceptance: Nach zwei parallelen Calls trägt `suggestion_reactions` je Call den richtigen `tenant_id`; A-Ereignisse erscheinen nicht bei B.

3. **`/api_beenden`-Lesequellen pro Session**: Der gespeicherte Call-Record wird aus dem Session-Bucket gebaut, nicht aus Globalen.
   - Current: liest ~10 Globale direkt (`app_routes.py:97-450`): `conversation_log`, `painpoints`, `kaufbereitschaft_verlauf`, `covered_phases`, `aktive_phase_idx`, `phasen_log`, `hilfe_log`, `quick_action_log`, `gegenargument_log`, `state['precall_briefing']`.
   - Target: alle Lesequellen pro `sid`; der finalisierte `ConversationLog`/Call-Record enthält nur die Daten der auflegenden Session.
   - Acceptance: Im Test tragen die `ConversationLog`-Felder + die TXT-Log-Datei von Call A ausschließlich A-Inhalt; gepaarte Assertion gegen B.

4. **`reset_session` fasst nur die eigene sid an**: Auflegen tötet nur den eigenen Zustand.
   - Current: iteriert `list(_session_state.keys())` und setzt ALLE SIDs + zentrale Globale zurück (`live_session.py:864-942`).
   - Target: nimmt eine sid entgegen und räumt ausschließlich diese; andere aktive Sessions bleiben unberührt.
   - Acceptance: Reset-Überlebens-Check mit Objekt-Identität — nach Reset von Session A gilt `get_anonymisierer(sidB) is anon_b_before` (B lebt unverändert weiter).

5. **`claude_service` globale Writes → per-SID**: Ergebnis-/Status-/Versions-/Hint-/Button-Schreibungen liegen pro Session.
   - Current: `state['ergebnis'/'aktiv'/'version'/'active_hint'/'ewb_buttons']` global geschrieben (`claude_service.py:1137-1372`).
   - Target: alle unter `_session_state[sid]`; die schon saubere Auslieferung `sio.emit(room=sid)` bleibt unangetastet.
   - Acceptance: Emit-Schicht-Check — `client_B.get_received()` enthält NIE den A-Marker; Versions-Zähler laufen pro Call getrennt.

6. **`start_live_session`-Config pro Session (Split-Brain schließen)**: Anrede/Skript/Sprecher-Config pro `sid`.
   - Current: `session_anrede`, `aktives_skript_inhalt`/`skript_bloecke` global geschrieben, per-SID gelesen → „kommt nie an" (`deepgram_service.py:619,641-642`).
   - Target: gleiche Schicht schreibt + liest (per `sid`), Split-Brain aufgelöst.
   - Acceptance: Im Test bekommt jede Session ihre eigene Anrede/ihr eigenes Skript; A-Skript erscheint nicht bei B.

7. **Rest-Legacy-Globale umziehen**: Die verbleibenden modul-globalen Live-Zustände wandern in den Session-Bucket.
   - Current: `session_meta`, `roles_swapped`, `is_paused`, KB-Familie, `_bof_count`, Speaker-Familie, `transcript_buffer`-Fallbacks alle global (`live_session.py:40-195`).
   - Target: alle pro `sid` in `_session_state[sid]`; keine modul-globale Live-Zustands-Variable bleibt übrig (außer bewusst dokumentierten, nicht-Live-Pfad-Globalen).
   - Acceptance: Statischer Global-Wächter (Req 12, Teil 2) ist grün — `assert not hasattr(ls, '<global>')` für ALLE getöteten Globalen + AST/grep-Sweep gegen die vollständige Global-Inventur.

8. **F2 sicher stilllegen (Schreiben abklemmen, ohne Deadlock)**: Der per-Ereignis-Benoter schreibt keine Leerlauf-Zeilen mehr — OHNE dass Calls in „wird ausgewertet" hängen bleiben.
   - Current: Benoter schreibt durchweg `handling_status='abstained'`/NULL; naives „nicht laufen lassen" erzeugt Fan-In-**Deadlock** (Events bleiben `'pending'` → `_pending_events(call_id)>0` für immer → Call-Ende-Merge/`rubric_score` feuert nie, `slow_lane.py:592/842`, `intent_event_writer.py:139`).
   - Target: In `_persist_event_ref` (`slow_lane.py:230-284`) direkt nach dem Idempotenz-Skip das Event SOFORT terminal auf den **existierenden** Status `'not_gradable'` (`slow_lane.py:364`) setzen + return — VOR Confidence-Gate/`grade_handling`. NULL Schema-Änderung (nur Consumer-Schreibverhalten), umgeht auch den RLS-fail-closed-Loop (`slow_lane.py:262-276`).
   - Acceptance: (i) `_pending_events` zählt nur `=='pending'` → drainet auf 0 → Merge/`rubric_score` feuert normal; (ii) `compute_rubric` toleriert leere handling_score-Menge (kein Div-durch-Null, `rubric_dimensions.py:393-402`); (iii) kein Gate/Test fordert `abstain_log`-Befüllung (verifizieren gegen `test_abstain_log_rls.py`). DB-Felder (`handling_score_numeric`/`handling_status`/`abstain_log`) bleiben erhalten.

9. **Wächter (a): `build_intent_payload()` zentralisieren + Struktur-/Schlüssel-Test**: Anti-Erosions-Fang für die gespeicherten Live-Ereignisse.
   - Current: Payload-Bau + `extra_payload` schütten heute ungeprüft beliebige Keys in `payload_jsonb` (`intent_event_writer.py:100-118`); keine Struktur-Absicherung.
   - Target: neue `intent_payload.py` mit `build_intent_payload()` (Auslagerung aus `intent_event_writer.py:100-115` — **die EINE bewusst abgenickte Nicht-Isolations-Naht**, reine Auslagerung ohne Verhaltens-Change) + Test: Pflichtfelder (`source`, `inference_basis`, `taxonomy_version`, `abstained`, `speaker_role`, `speaker_id`, `is_simulation`, `origin_type`, `triggering_text`), Typen (`taxonomy_version` non-null, `abstained`/`is_simulation` bool), **Erlaubte-Keys-Whitelist** (jeder neue Key rot bis bewusst aufgenommen). `schema_version` bleibt optionaler, noch-nicht-vergebener Slot — NICHT Pflicht (TAXO3-b bringt sie additiv als `MIRROR_SCHEMA_VERSION`).
   - Acceptance: Test rot, wenn ein Pflichtfeld fehlt / ein Nicht-Whitelist-Key auftaucht / `taxonomy_version` null ist; grün gegen den aktuellen Payload. `taxonomy_version` (Intent-Taxonomie) ≠ `schema_version` (Payload-Form) — nicht verwechselt.

10. **Wächter (b): TTFT-Messung am echten Knopf-Pfad `streame_manual_ewb_variante`**: Die Zeit-bis-erstes-Token wird dort gemessen, wo Nutzer wirklich drücken.
    - Current: TTFT-Messung nur am toten `streame_auto_variante`; `streame_manual_ewb_variante` (`claude_service.py:740-865`) misst nur Kosten, KEINE TTFT.
    - Target: TTFT-Messung im manuellen Knopf-Pfad (TAXO3-b RV-2 braucht das); Latenz bleibt im Budget (Punkt 25).
    - Acceptance: Ein manueller Knopf-Aufruf im Test/Live erzeugt einen TTFT-Messwert für `streame_manual_ewb_variante`.

11. **Wächter (c): Heiler für hängende Auswertungen**: Calls, die in „wird ausgewertet" hängen, werden aufgelöst.
    - Current: bei fehlgeschlagenem `api_beenden`-UPDATE bleiben beide resolved-Flags False → Call hängt dauerhaft in „wird ausgewertet".
    - Target: Sweep/Heiler erkennt hängende resolved-Flags und löst sie (setzt terminal), OHNE einen neuen Zeit-Sweep der Bereitschafts-Naht zu brechen (Punkt 22).
    - Acceptance: Ein künstlich hängen gelassener Call (resolved-Flags False) wird vom Heiler in einen terminalen/aufgelösten Zustand überführt; Test belegt Übergang.

12. **Akzeptanz-Netz im Deploy-Gate (deterministisch, kein Audio/Netz)**: Zwei Test-Artefakte, die die Phase absichern und bei jedem künftigen Deploy mitlaufen.
    - Current: kein Nebenläufigkeits-Test, kein Global-Wächter; die Fehlerklasse kann still zurückkehren.
    - Target:
      - **(1) `test_persid_concurrency.py`** — In-Prozess, ZWEI Tenants (User A Org 1 / User B Org 2, NICHT ein User mit zwei Tabs), zwei SocketIO-Test-Clients, gemockte Nähte (`_open_deepgram_connection`, `analysiere_mit_claude`/Haiku, `anonymize` als **Identity** — sonst Vacuous-Green). Muster: `tests/test_medium_lane_intent_event_live.py` (`_OneShotTrigger`). Assertions je Fund **GEPAART** (eigenes DA positiv + fremdes WEG isolation): `_per_sid_transcript`/`_coaching_buffer`, `ConversationLog`-Felder, `transcript_segments`, `ObjectionEvent`, `suggestion_reactions` (richtiger `tenant_id`), TXT-Log-Datei, Emit-Schicht (`get_received()` ohne fremden MARKER), + Reset-Überlebens-Check (Objekt-Identität).
      - **(2) Statischer Klassen-Wächter (~50 Zeilen, Muster `test_schild_guard.py`)** — `assert not hasattr(ls, '<global>')` für ALLE getöteten Globalen + grep/AST-Sweep auf `ls.state[…]`/`ls.conversation_log…` mit per-sid-Whitelist, gegen die VOLLSTÄNDIGE Global-Inventur (Plan-Schritt 1).
      - Beide laufen im bestehenden `nerve_test`-Deploy-Gate (`deploy.sh:193`). **Rot-vor-Fix-Disziplin:** Test zuerst rot gegen HEAD, dann Fix; Test+Fix im selben Deploy, kein `xfail`.
      - Pflicht-Fallen: (a) `anonymize` als Identity patchen; (b) `analyse_loop`/`coaching_loop`-Daemon-Start (`app.py:2214-2215`) hinter TESTING-Guard; (c) `MERGE_WINDOW_S` klein patchen; (d) `/api/beenden` VOR disconnect; (e) rot-vor-Fix.
    - Acceptance: Beide Test-Artefakte sind zuerst rot gegen HEAD, nach den Fixes grün, und Teil des `deploy.sh`-Gates. Der echte Founder-Doppel-Anruf ist einmalige UAT NACH dem Fix — NIEMALS das Gate.

## Boundaries

**In scope:**
- Umzug aller modul-globalen **Live-Pfad**-Zustände in `_session_state[sid]` über 4 Module (`live_session`, `deepgram_service`, `claude_service`, `routes/app_routes`/`api_beenden`).
- `reset_session`-Fix (nur eigene sid).
- F2 sicher stilllegen (Schreib-Abklemmung via `'not_gradable'`-Terminal, deadlock-frei; DB-Felder bleiben).
- Drei Wächter: (a) `build_intent_payload()`-Zentralisierung + Struktur-/Whitelist-Test, (b) TTFT am echten Knopf-Pfad, (c) Heiler für hängende resolved-Flags.
- Zwei Akzeptanz-Artefakte im Deploy-Gate: `test_persid_concurrency.py` + statischer Global-Wächter.
- Die EINE bewusst abgenickte Nicht-Isolations-Naht: reine Auslagerung `build_intent_payload()` (kein Verhaltens-Change).

**Out of scope:**
- **`schema_version` an `intent_event` einführen** — TAXO3-b bringt sie additiv (`MIRROR_SCHEMA_VERSION`); wäre hier themenfremder Edit an der heißesten Schreibstelle (Punkt 17).
- **Gespiegelt-Marker / Gedächtnis-Feature (TAXO3-b)** — geparkt bis dieses Fundament grün ist.
- **Stille-Verschwendung-Mini-Phase (F3/F4/F5)** — bezahlte unsichtbare QA-Sonnet-Calls (F3), Judge-ohne-Briefing (F4), Kosten-Label (F5); real, aber kein Launch-Blocker.
- **🟡-Härtung:** RLS-Netz (FORCE) auf Kern-Tabellen, `training_service`-Kosten ohne user_id, Flask-Admin `scoped_session` ohne `.remove()`.
- **DB-Felder löschen** (`handling_score_numeric`/`handling_status`/`abstain_log`) — spätere Aufräum-Phase / Foundation-Code-Register.
- **Tenant/RLS/Auth/Slow-Lane/Billing-Zuordnung** — schon sauber pro-Kontext, NICHT anfassen (Fable-2 verifiziert).
- **Auslieferungs-Schicht `sio.emit(room=sid)`** — schon sauber, nur Zustand+Persistenz fixen.
- **Echter Founder-Doppel-Anruf als Gate** — das ist einmalige UAT NACH dem Fix, nicht der automatische Deploy-Check.
- **Refactor huckepack** (Punkt 17) — nur der per-Session-Umzug + F2 + 3 Wächter, nichts „bei der Gelegenheit" (Ausnahme: die eine abgenickte `build_intent_payload()`-Auslagerung).

## Constraints

- **🔴 Cross-AI / 3-Sichten Pflicht** vor Execute (Punkt 7/24). Claudian-Pre-Execute-Audit (Punkt 19).
- **Kein Refactor huckepack (Punkt 17)** — außer der einen bewusst abgenickten `build_intent_payload()`-Auslagerung.
- **Race-/Bereitschafts-Disziplin (Punkt 14 + 22)** bei jedem Umzug HART: parallele Loops, Socket-Events, Timer, Reconnect, Tab-Hintergrund; Schreib-Pipeline ≠ Lese-Pipeline im Zeitversatz.
- **F2-Deadlock-Schranke:** der Schnitt MUSS `_pending_events` auf 0 drainen lassen — „nicht starten"/„Default ändern"/„nicht enqueuen" sind alle FALSCH (Deadlock oder Migration).
- **Latenz-Budget (Punkt 25):** kein Live-Pfad wird spürbar langsamer; TTFT am Knopf-Pfad bleibt im Budget.
- **Deterministisches Gate:** die Akzeptanz-Tests laufen In-Prozess im `nerve_test`-Gate — kein Audio, kein Netz, gemockte Nähte, `anonymize` als Identity (sonst Vacuous-Green).
- **Kein Local-Dev:** Verify läuft im Deploy-Gate auf Production; der einmalige Founder-Doppel-Anruf ist UAT auf `getnerve.app`.
- **Muster folgen, nicht neu erfinden:** `analysiert_bisher` (per-SID-Vorbild), `cost_tracker` („ohne sid → None"-Muster), `init_session_state`/`pop_session_state`.
