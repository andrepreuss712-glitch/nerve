<decisions>
## Implementation Decisions

### Zugriffsmuster (der ~40× wiederholte Kern-Mechanismus)
- **D-01:** **Raw-Dict-Zugriff, faithful zum bestehenden Muster.** Direkter `_session_state[sid][key]`-
  Zugriff unter `_session_state_lock` an jeder Umzugs-Stelle — exakt wie heute in `cost_tracker` und
  `init_session_state` (`live_session.py:301-455`). **KEIN neuer Accessor-Layer** (get_ss/set_ss) und
  **KEIN State-Objekt** — beide wären ein 40-Stellen-Refactor am heißesten Code = Punkt-17-Verstoß
  ("kein Refactor huckepack") und widerspräche "Muster folgen, nicht neu erfinden".
- **D-02:** **`ohne sid → None`-No-Op-Muster** übernehmen (kanonisch belegt: `cost_tracker.
  _resolve_user_id_from_live_session` `:31-50`) — kein Raten bei fehlender sid, lieber NULL/No-Op als
  Fehlzuordnung. Gilt für `record_suggestion_offer`/`record_ewb_click` (SPEC Req 2) und alle neuen
  per-sid-Lesungen.
- **D-03:** **Lock-Disziplin bleibt manuell** und wird im 3-Sichten-Review + Pre-Execute-Audit HART
  geprüft (Punkt 14): Snapshot unter Lock nehmen, Lock vor langen Ops (LLM/Netz/DB) freigeben — nie
  über einen langen Op halten. Race-/Bereitschafts-Fragen (Punkt 14 + 22) pro Umzug explizit.

### Wächter-Strenge (statischer Global-Wächter, Punkt 28, permanente Deploy-Gate-Ratsche)
- **D-04:** **Streng.** Der statische Wächter (`test_no_live_global_state.py`-Klasse, Muster
  `test_schild_guard.py`) poliziert NUR **Live-Pfad-Globale** und ist rot bei jedem nicht-per-sid-
  gekeyten veränderlichen Live-State. `assert not hasattr(ls, '<global>')` für ALLE getöteten Globalen
  + AST/grep-Sweep gegen die vollständige Global-Inventur (Welle 0).
- **D-05:** **Erlaubte Überlebende = enge, explizit dokumentierte Whitelist:** unveränderliche
  Konstanten, Locks, Modell-Caches (spaCy/GLiNER), explizit dokumentierte tenant-neutrale Caches +
  bewusst nicht-Live-Pfad-Globale (SPEC Req 7). **Kein temporärer Deprecated-Zustand** — die pragmatische
  Variante (noch-nicht-migrierte Live-Globale via `DEPRECATED-GLOBAL`-Marker temporär durchlassen) wird
  NUR gezogen, falls die Inventur (Welle 0) beweist, dass ein Live-Global in dieser Phase nicht migrierbar
  ist; Default ist "in dieser Phase fertig migrieren oder löschen".

### Wellen-Schnitt (Migrations-Granularität + rot-vor-Fix-Staging)
- **D-06:** **Gerüst = test-first, gestaffelt** (Option 1): Welle 0 als Fundament, danach gestaffelte
  Wellen, 3-Sichten pro Naht, kein Bau auf einem Fundament mit bekanntem Loch (Punkt 24).
- **D-07 (Founder-Direktive, HART):** **Schnitt nach DATEN-FAMILIE statt nach Modul.** Eine Welle bündelt
  eine zusammengehörige Datenfamilie über Modulgrenzen hinweg, nicht ein Modul.
- **D-08 (Founder-Direktive, EISERNE REGEL — Punkt 26 auf die Migration selbst angewandt):** Der **Leser
  einer Datenfamilie wird NIE vor seinen Schreibern umgestellt** — Schreiber + Leser derselben Familie
  gehen im **selben Deploy** live. Sonst leere Call-Records auf Prod: `api_beenden` liest
  `conversation_log`/`painpoints`/`kaufbereitschaft`(+`_verlauf`)/`gegenargument_log`/`phasen_log`/
  `covered_phases`, geschrieben von `claude_service`/`deepgram_service`. Ein per-sid-Leser, dessen
  Schreiber noch global schreibt (oder umgekehrt), liest den falschen/leeren Bucket.
- **D-09 (Founder-Direktive):** **Welle 0 = pro Global Fix-vs-Löschen mit grep-Beleg** (Punkt 22
  Verbindungs-Karte + Punkt 28 Zombie-Regel). Viel toter **write-only-Code** → **löschen statt
  migrieren.** Genannte Kandidaten (grep-verifizieren, nicht blind löschen): `session_meta`,
  `last_postcall`, `hilfe_log`/`quick_action_log`, `aktive_phase_idx`, `roles_swapped`, Teile von `state`.
- **D-10 (Founder-Direktive, OPERATIV KRITISCH):** **Rot-Beweis manuell gegen HEAD auf dem Server
  dokumentieren** — KEIN committeter roter Test. Ein committeter roter Test würde das `deploy.sh`-Gate
  (`deploy.sh:193`) für ALLE Deploys blockieren. Der **Voll-Test wird erst mit der letzten Welle grün**
  committet. Rot-vor-Fix-Disziplin bleibt (Beweis dass der Test beißt), aber der Beweis ist ein
  dokumentierter manueller Lauf gegen HEAD auf dem Prod-Server, kein eingecheckter `xfail`.

<specifics>
## Specific Ideas

- **Rot-Beweis-Operativität (D-10):** Der committete Test darf nie rot ins `deploy.sh`-Gate — der Beweis
  "Test beißt gegen HEAD" ist ein dokumentierter manueller Serverlauf, der Grün-Commit kommt erst mit der
  letzten Welle. Das ist die konkrete Auflösung der Spannung "rot-vor-Fix" vs. "deploy.sh blockiert bei
  rotem committeten Test".
- **Fix-vs-Löschen ist ein Erst-Klass-Ergebnis von Welle 0 (D-09):** nicht alles wird migriert — write-
  only-Zombies werden per grep-Beleg gelöscht. Die Global-Inventur ist damit zugleich Migrations- UND
  Prune-Landkarte.
- **Daten-Familie-Deploy-Kopplung (D-08) ist die riskanteste Invariante:** jeder Wellen-Schnitt muss
  beweisen, dass kein per-sid-Leser ohne seinen per-sid-Schreiber (oder umgekehrt) live geht.
</specifics>
