## 4. Edge-Case-Analyse

1. **Session bricht ab (Client-Disconnect, Exception):** werden die akkumulierten Sekunden trotzdem
   geflusht? → `finally`-Pfad, sonst Datenverlust genau bei den abgebrochenen Calls.
2. **Session ohne Sprache (0 Sekunden):** kein 0-Log erzwingen (Rausch-Zeilen vermeiden).
3. **DB nicht erreichbar aus nerve_rt:** `log_api_cost` schluckt (raist nie) → **still**. Deshalb
   zusätzlich ein `print`, damit man den Ausfall überhaupt sieht — und W3 (Plan 04) zählt es.
4. **Import zieht Flask-Ballast:** verlangsamt den FastAPI-Start oder braucht App-Kontext →
   Task 0 fängt das ab, sonst STOP-Stufe 3.
5. **`msg.usage` fehlt bei Streaming-Antworten:** prüfen, ob der Adapter streamt — wenn ja, kommt
   `usage` an anderer Stelle. Nicht raten.

### Race-Condition-Audit (Punkt 14)
1. **Gleichzeitiges Feuern:** zwei parallele nerve_rt-Sessions → **der Kern-Risiko-Punkt.** Per-Session
   gekeyt (Punkt 28), nie modul-global. Im SUMMARY explizit belegen.
2. **Verbindungsabbruch mid-Operation:** Deepgram-Verbindung stirbt → siehe Edge-Case 1 (`finally`).
3. **Wiederverbinden mit altem Zustand:** neue Session = neue Akkumulation; eine alte Session-Kennung
   darf **nicht** in die neue Summe laufen. Explizit prüfen.
4. **Tab im Hintergrund:** Browser pausiert → Session läuft weiter oder endet; beide Pfade müssen
   flushen.
