## 4. Edge-Case-Analyse

1. **`usage` fehlt / API-Antwort abgeschnitten:** Hook in try/except, Fehler still schlucken
   (`log_api_cost` raist ohnehin nie) — aber **mit print**, damit es nicht unsichtbar wird.
2. **Kein `g`-Kontext (Hintergrund-Runner):** `g.user`/`g.org` würde `RuntimeError` werfen →
   deshalb bei #1/#2/#3 ausdrücklich der Call-Objekt-Weg. Vorher belegen, nicht annehmen.
3. **Deepgram-Response ohne `metadata.duration`:** kein Schätzwert, Hook überspringen + print.
4. **Doppel-Logging bei Retry:** feuert ein Call-Site zweimal (Retry-Schleife), entstehen zwei
   `api_cost_log`-Zeilen. Das ist **fachlich korrekt** (zwei bezahlte Calls) — im SUMMARY festhalten,
   damit es später niemand für einen Bug hält.
5. **Stripe-Invoice ohne Betrag / Betrag 0:** kein Fee-Log erzwingen; 0-Zeilen vermeiden.

### Race-Condition-Audit (Punkt 14)
1. **Gleichzeitiges Feuern:** `log_api_cost` öffnet eine **eigene** `SessionLocal` (:103) → keine
   Kollision mit der Session des Aufrufers. Mehrere parallele Calls schreiben unabhängige Zeilen.
2. **Verbindungsabbruch mid-Operation:** Hook nach dem Call → bricht der API-Call ab, gibt es keine
   `usage` → kein Log. **Bewusst:** wir loggen nur bezahlte, abgeschlossene Calls.
3. **Wiederverbinden mit altem Zustand:** n/a (keine Session-/Socket-Identität berührt).
4. **Tab im Hintergrund:** n/a.
5. **Punkt 28 (kein globaler Live-Zustand):** kein Hook legt Modul-Globals an — alle Werte sind lokal
   im Call-Frame. Explizit im SUMMARY bestätigen.
