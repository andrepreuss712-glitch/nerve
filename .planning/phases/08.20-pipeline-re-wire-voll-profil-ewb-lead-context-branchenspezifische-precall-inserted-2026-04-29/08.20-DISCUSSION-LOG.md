## Voll-Profil-Kontext Format

| Option | Description | Selected |
|--------|-------------|----------|
| Sektion-Header-Blöcke | Markdown `##`-Headings, stabile Cache-Anker, 9 Sektionen deterministisch | ✓ |
| Flat Key-Value | Alle Felder als `Schlüssel: Wert`-Zeilen, keine Trenner | |
| Gemischt | Basis-Felder flat, Blöcke für Einwände/Phasen | |

**User's choice:** Markdown `##`-Headings (nicht `Sektion:` Notation).

**Notes:**
- Kanonische 9-Sektionen-Reihenfolge: Branche → Basis → Zielkunde → Schmerzen → Einwände → Phasen → KI-Verhalten → PreCall-Briefing → Lead-Kontext
- Leere Sektionen NICHT skippen — immer `(noch nicht ausgefüllt)` / `(noch nicht erstellt)` / `(Recherche fehlgeschlagen)`
- Cache-Layering: Sektionen 1-7 cache-stable, 8-9 cache-volatile am Ende (Anthropic-Best-Practice)
- Listen-Format konsistent: Einwände = Markdown-Liste (`-`), Phasen = nummerierte Liste
- Pflicht: deterministischer Output + Test-Case für byte-gleichen Output bei identischem Input
- `##`-Headings sind eindeutigere Cache-Anker als `:`-Endungen (`:` kann als Inhalt missinterpretiert werden)
