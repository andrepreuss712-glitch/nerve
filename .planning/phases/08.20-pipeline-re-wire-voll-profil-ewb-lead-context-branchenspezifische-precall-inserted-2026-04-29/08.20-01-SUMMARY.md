# Phase 08.20 Plan 01: Foundation Layer — Briefing Cache + Branchen Data + Schema v3→v4 Summary

**One-liner:** Per-SID briefing cache as `_session_state` sub-key with Ghost-SID guards, pure `branchen_data.py` module with 10 clusters, and idempotent v3→v4 schema migration dropping `einwaende` in favor of `einwaende_detail` across 11 consumer callsites.

## What Was Built

### Task 1: Briefing Cache Infrastructure + branchen_data.py

**live_session.py — 3 changes:**

1. `set_briefing_for_sid(sid, text)` — stores `_session_state[sid]['_briefing']` under `_session_state_lock`. Ghost-SID guard drops write if SID not in `_session_state` (async PreCall completing after disconnect).

2. `get_briefing_for_sid(sid)` — reads `_session_state.get(sid, {}).get('_briefing')` under `_session_state_lock`. Returns `None` for unknown SID, never raises.

3. `set_profile_for_sid()` — Ghost-SID guard added: checks `sid not in _session_state` before writing to `_per_sid_profile`. GIL-safe cross-dict check (approximate liveness is sufficient here).

4. `pop_session_state()` — docstring updated to clarify `_briefing` sub-key is auto-cleared when `_session_state[sid]` is popped (no separate cleanup needed).

**Key architectural decision:** The PLAN.md interfaces took precedence over PATTERNS.md here. PATTERNS.md described `_per_sid_briefing` as a separate dict with its own lock (older spec). PLAN.md `<interfaces>` block specified briefing as `_session_state[sid]['_briefing']` sub-key to eliminate deadlock risk. The must_haves.truths in PLAN.md confirm the sub-key approach.

**services/branchen_data.py (new):**
- Pure static module, no imports beyond `from __future__ import annotations`
- `build_branchen_hint(user_branche: str) -> str` — deterministic, idempotent, always non-empty
- 10 canonical cluster keys + aliases map + default fallback
- 7 clusters: maschinenbau, it-saas, versicherung, finanzdienstleistung, pharma, medizintechnik, telco, unternehmensberatung, automobil, automotive

**tests/test_live_session_ghost_sid.py:**
- `test_ghost_sid_briefing_silently_dropped()` — confirms no `_session_state` entry created for non-existent SID
- `test_deadlock_stress_no_deadlock()` — 10 threads, Connect→briefing write→Disconnect, no deadlock within 10s

### Task 2: Schema v3→v4 Migration + 11 Consumer Callsites

**services/profile_schema.py:**
- Early-return guard changed from `>= 3` to `>= 4` (allows v3 profiles to reach new migration)
- v1→v2 block wrapped in `if version < 3:` guard (prevents v3 profiles from re-running v1→v2)
- v3→v4 migration block: migrates `einwaende: List[dict]` to `einwaende_detail`, drops `einwaende` key, bumps `schema_version` to 4, writes AuditLog entry

Migration field mapping: `einwand`, `varianten`, `gegenargument` (falls back to `gegenargument_1`), `technik`, `intensitaet`, `kurzlabel`, `kategorie`, `einwand_typ`. String entries in old list converted to minimal dicts with defaults. Idempotency: `if version < 4` gate prevents double-migration.

- **Found during:** Task 2 implementation

- **Fix:** Wrapped entire v1→v2 block in `if version < 3:` guard so only v1/v2 profiles run it.
- **Files modified:** `services/profile_schema.py`
- **Commit:** `cd5edb3`

**2. [Rule 2 - Missing] PATTERNS.md vs PLAN.md spec conflict for briefing storage**

- **Found during:** Task 1 pre-implementation read
- **Issue:** PATTERNS.md specified `_per_sid_briefing` as separate dict + `_per_sid_briefing_lock`. PLAN.md `<interfaces>` and `must_haves.truths` specified `_session_state[sid]['_briefing']` sub-key with no separate lock.
- **Fix:** Followed PLAN.md (more recent specification, eliminates deadlock risk).
- **Decision:** Documented — PLAN.md interfaces take precedence over PATTERNS.md when they conflict.
