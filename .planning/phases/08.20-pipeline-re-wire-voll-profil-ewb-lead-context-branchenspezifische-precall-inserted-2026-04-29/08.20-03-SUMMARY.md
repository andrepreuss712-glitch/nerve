# Phase 08.20 Plan 03: PreCall Branchen-Hint + QA Voll-Profil-Context Summary

**One-liner:** Branche-aware PreCall briefings via `build_branchen_hint()` injection, Anti-Header-Constraint in `PRECALL_SYSTEM_PROMPT`, `set_briefing_for_sid()` on success (D-09), and QA pipeline wired to full Voll-Profil context via `{profile_context}` placeholder and `build_profile_context(sid=sid)` (LB-3-Fix).

## What Was Built

### Task 1: precall_service.py — branchen hint inject + set_briefing_for_sid write

**4 changes to `services/precall_service.py`:**

1. **Anti-Header-Constraint** appended to `PRECALL_SYSTEM_PROMPT` (before closing triple-quote):
   ```
   - Deine Antwort darf keine ##-Markdown-Header enthalten — nur Fließtext und einfache Bullet-Listen (-).
   ```
   Prevents nested `##` chaos when briefing text is embedded as Sektion 8 in `build_profile_context()`.

2. **`sid: str = None` parameter** added to `recherche_firma()` signature — backward-compatible (sole HTTP caller `routes/app_routes.py` passes positional args, `sid` defaults to `None`).

3. **Branchen-hint injection** in `_generiere_briefing()` — before `claude_client.messages.create()`:
   ```python
   try:
       from services.branchen_data import build_branchen_hint as _build_branchen_hint
       _branchen_hint = _build_branchen_hint(branche or '')
       _system = PRECALL_SYSTEM_PROMPT + '\n\n' + _branchen_hint
   except Exception as _bhe:
       print(f"[PreCall] branchen_hint build failed (non-fatal): {_bhe}")
       _system = PRECALL_SYSTEM_PROMPT
   ```
   `system=_system` replaces `system=PRECALL_SYSTEM_PROMPT` in the `messages.create()` call.

4. **`set_briefing_for_sid()` call** in `recherche_firma()` success path (after cache write):
   ```python
   if briefing and briefing.get('text') and sid:
       try:
           from services.live_session import set_briefing_for_sid
           set_briefing_for_sid(sid, briefing['text'])
           ...
   ```
   Ghost-SID guard (from Plan 01) drops the write silently if SID not in `_session_state`. Since the sole current caller passes `sid=None`, this block never executes in production yet — the infrastructure is ready for future SocketIO callers.

### Task 2: QA pipeline — {profile_context} placeholder + sid parameter + caching

**Changes to `services/qa_pipeline.py`:**

1. **`{profile_context}` as first line** of `_SYSTEM_PROMPT_QA` (before "Analysiere den Einwand"):
   ```python
   _SYSTEM_PROMPT_QA = """\
   {profile_context}

   Analysiere den Einwand. Entscheide:
   ...
   ```

2. **`sid: str = None` parameter** added to `generate_qa_response()` signature.

3. **`build_profile_context(user_id=user_id, sid=sid)` call** before `_SYSTEM_PROMPT_QA.format()`:
   ```python
   _profile_context = ''
   try:
       _profile_context = build_profile_context(user_id=user_id, sid=sid)
   except Exception as _pce:
       print(f"[QA] build_profile_context failed (non-fatal): {_pce}")
   ```
   Hot path: when `sid` is set and `_profile_cache` is warm — 0 DB queries, < 5ms (from Plan 02 infrastructure).

4. **`profile_context=_profile_context`** added to `.format()` call — existing `tabu_block` and `anrede` unchanged.

5. **Caching block** already used `len(system_prompt)` (formatted string) — no change needed. With Voll-Profil context (~4000+ chars) the cache threshold will always be exceeded.

**Changes to `services/claude_service.py`:**

Both `generate_qa_response()` callers in `_qa_pipeline_dispatch()` updated to pass `sid=_active_sid` — `_active_sid` is in scope at both call sites.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] test_fail_closed_on_exception expected `''` but LB-3-Fix changed behavior**

- **Found during:** Task 2 test run (`pytest tests/test_qa_pipeline.py`)
- **Issue:** Old test asserted `generate_qa_response(...) == ''` when `build_profile_context` raised. With the new non-fatal try/except, the error is swallowed, `_profile_context = ''`, and the function continues to the Claude call (which fails in test env without API key) → returns `_FALLBACK_RUECKFRAGE` not `''`.
- **Root cause:** Test called `generate_qa_response('wie teuer?', 'frage', {}, 'Sie', 'v1', 0)` positionally — `'v1'` landed as `confidence` argument, `float('v1')` raised ValueError, triggering outer except which returned `_FALLBACK_RUECKFRAGE`. The test was fragile.
- **Fix:** Updated test to use keyword args (`confidence=1.0, version='', user_id=0`) and assert non-empty string (correct LB-3-Fix behavior: error is non-fatal, function never propagates, returns fallback).
- **Files modified:** `tests/test_qa_pipeline.py`
- **Commit:** `f28c729`
