## B-02 — End-call ("Beenden") button misclick protection — DECISION (mode: yolo)

**Decision: Placement isolation + short press-and-hold (BOTH). No second "Sicher?" dialog.**

CONTEXT B-02 rejects a confirmation dialog (too much friction for a frequent, non-destructive event)
and delegates the concrete form here. The existing trigger is `#nlp-btn-beenden` (click handled via
delegation, `pip-launcher.js:1788`). Chosen form:

### 1. Placement isolation (primary protection)
- The Beenden trigger sits **alone, visually separated from the frequently-used PiP controls**
  (mode toggle `#pip-mode-indicator`, EWB row `#nlp-ewb-row`). It is the **isolated terminal control**
  in the PiP control area, with a **minimum 16px gap** to the nearest neighbor control — no adjacency
  to high-frequency buttons.
- Visual style: `.n-btn-danger` token set — red-on-transparent at rest
  (`--btn-danger-bg rgba(248,113,113,0.1)`, `--btn-danger-text #f87171`, `--btn-danger-border`),
  solid red on hover (`--btn-danger-bg-hover #f87171`, white text). Pill radius `9999px`,
  padding `12px 28px`, 44px min touch height. Label: **"Beenden"** with a Lucide stop/`phone-off`
  inline `<svg>` (16px) to the left.

### 2. Press-and-hold to commit (secondary protection)
- A single tap does **not** end the call. The user must **press and hold for 600ms**.
- **Affordance:** on `pointerdown`, the button fills with a left-to-right progress wipe in **red**
  (`--btn-danger-text #f87171` over the red-tint base — teal-free) and the label switches to
  **"Halten zum Beenden…"**. At 600ms the hold completes, the button flashes to its solid hover state
  for ~120ms, then the existing `endCall()` fires (`_stopMic()` immediately, then Ladebalken 1).
- **Cancel:** releasing (`pointerup` / `pointerleave` / `pointercancel`) before 600ms aborts, resets the
  wipe, and restores the "Beenden" label. No call ends.
- **Duration rationale:** 600ms defeats accidental brush/double-tap but stays well under the ~1s
  threshold where holds feel like a chore for an intentional action. It is deliberately shorter than the
  Ladebalken-1 timeout so the two never visually compete.
- **Accessibility / keyboard:** keyboard activation (Enter/Space on the focused Beenden button) shows a
  one-line inline confirm affordance ("Nochmal drücken zum Beenden") and requires a **second** Enter/Space
  within 2s — the keyboard equivalent of the hold (a hold gesture is not keyboard-expressible). No modal
  dialog.

**Rationale (recorded):** Misclick protection lives in the button itself per B-02. Placement isolation
removes the most common cause (fat-finger on an adjacent frequent control); the 600ms hold removes the
second cause (accidental single tap / double-tap bounce). Neither adds a blocking dialog, neither slows a
deliberate end. Red styling honestly signals "this is the terminal action" without implying data loss
(data is saved and dashboard-correctable per B-04).

## U-01 — Uncertain-outcome (`ai_auto_unsicher`) ROT highlight — DECISION (mode: yolo)

**Chosen token: the `--btn-danger-*` warn/danger family (`#f87171`), NOT `--danger-red #EF4444`, NOT any Gelb.**

This is the project's single sanctioned non-teal warn color, already used for `.pip-audio-warn`,
live-badge, and `--session-score-low`, so it reads as "attention / verify" inside the PiP without
introducing an ad-hoc red (CLAUDE.md Punkt 8 satisfied). This **supersedes** the D.UX.1 Teal-Outline
`.pip-outcome-badge-unsicher` for the uncertain case (per CONTEXT U-04).

### Pre-selected-but-red treatment (uncertain case, `_decideModalState` → `'unsicher'`)
- The AI's best-guess outcome button **is visibly pre-selected** (carries a selected state) **but in red,
  not teal**. Implementation: a **new modifier class** is NOT required — apply a red selected variant
  (e.g. `pip-outcome-btn--selected-unsicher`) OR inline the `--btn-danger-*` tokens on the pre-selected
  button:
  - Border: `1.5px solid var(--btn-danger-text)` (`#f87171`).
  - Background: `var(--btn-danger-bg)` (`rgba(248,113,113,0.1)`).
  - Label text: `var(--btn-danger-text)` (`#f87171`), weight 600.
  - A small Lucide `alert-triangle` (16px inline `<svg>`, stroke `#f87171`) left of the label on the
    pre-selected button.
  > If a new CSS class is added it must use **tokens only** (no ad-hoc hex) and live in nerve.css next
  > to the existing `.pip-outcome-btn--selected`. This is the one styling addition this phase allows,
  > and it is token-bound.
- The other 6 outcome buttons render in the **neutral** resting state (existing
  `.n-btn-ghost.pip-outcome-btn`: `--btn-ghost-bg`, `--btn-ghost-border`, `--btn-ghost-text`).

### Disclaimer copy (user-facing, echte Umlaute)
- Directly **above** the button grid, below the heading: a one-line warn note replacing the old
  `.pip-outcome-badge-unsicher` text:
  - **"KI unsicher, bitte prüfen"**
  - Style: 11-13px, weight 600, color `var(--btn-danger-text)` `#f87171`, with a 16px Lucide
    `alert-triangle` to its left. No background fill (the red button already carries weight).

### Disabled → enabled Bestätigen states
- **Initial (uncertain):** Bestätigen is **disabled** even though a red pre-selection is visible.
  - Disabled style = existing `.pip-outcome-btn--disabled` (`opacity: 0.45; cursor: not-allowed`)
    applied to the `.n-btn-primary.pip-outcome-confirm-btn`. Label stays **"Bestätigen"**.
  - Implementation note: in the current code, "unsicher" preselects nothing and the disclaimer reads
    "KI unsicher — bitte wählen". This phase changes it so a red preselection **is shown** but
    Bestätigen stays disabled until an **active tap** (per CONTEXT U-01). The `selectedOutcome` variable
    must therefore NOT be treated as confirmable until the user taps, even though a button shows the red
    preselect styling.
- **Activation:** the moment the user **actively taps any outcome button** — the red pre-selected one
  (= accept) OR a different one (= correct):
  1. The tapped button switches to the **teal** `.pip-outcome-btn--selected` state; the red warn styling
     is cleared from the previously red button.
  2. The disclaimer line is removed (uncertainty consciously resolved).
  3. **Bestätigen becomes enabled** (`.n-btn-primary` full teal, `.pip-outcome-btn--disabled` removed).
- This enforces the deliberate, data-quality-protecting click in exactly the uncertain case (U-02),
  with zero friction in the confident case.

### Confident case (`ai_auto`, `_decideModalState` → `'sicher'`) — for contrast
- Pre-selected button in **teal** `.pip-outcome-btn--selected` (no red, no disclaimer, no alert icon).
- **Bestätigen immediately clickable** — the fast path, no extra tap required.

### Timeout / no-attempt case (LB-02 fallback, `_decideModalState` → `'kein_versuch'`)
- **No pre-selection.** All 7 outcome buttons render equal in the neutral ghost state.
- No disclaimer line. Bestätigen **disabled until the user actively picks one** (then teal selected →
  Bestätigen enabled). Same activation mechanics as the uncertain case, minus the red. (The existing
  `'kein_versuch'` hint text "Automatische Erkennung nicht verfügbar" may be kept or dropped — it is
  honest and non-error; keep it for continuity.)

## Call-end sequence — complete visual + interaction contract

### Step 1 — Beenden trigger (B-02)
See B-02 above. Existing `#nlp-btn-beenden`. Hold completes → `_stopMic()` fires immediately (as today,
inside `endCall()`) → Ladebalken 1 shown.

### Step 2 — Ladebalken 1: "KI wertet das Gespräch aus…" (LB-01, LB-02)
- **Form:** indeterminate spinner / pulse. **NO percent bar, NO time estimate, NO fake fill.**
  Reuse the existing pulse motion (`@keyframes n-pulse`) or a simple indeterminate spinner; build on the
  existing `_showPostcallLoading()` skeleton (`pip-launcher.js:3225`).
- **Placement:** centered in the PiP body (replaces the live transcript / live section area).
- **Text:** **"KI wertet das Gespräch aus…"** (14px, weight 600, `--page-text-color`), spinner above or
  left of text with an 8px gap. Echte Umlaute, real ellipsis "…".
- **Timeout:** **9 seconds** (chosen value within the LB-02 ~8-10s frame; comfortably above the normal
  2-5s Haiku time so a real answer is never cut off, while still bounding a hang). On timeout the spinner
  stops and the screen transitions to the **no-preselect** outcome screen (Step 3, `'kein_versuch'`
  variant).
- **Real AI failure (LB-04):** same UX as timeout → no-preselect outcome screen (planner specifies the
  backend degraded path; UX-side identical).

### Step 3 — Outcome selection screen (B-01, B-03, L-03, U-01, LB-02) — terminal / forced-choice
- **Heading:** **"Call wirklich beenden?"** (16px, weight 600). This heading IS the confirmation (B-01) —
  there is no separate Ja/Nein dialog.
  > **Change from current code:** `_renderOutcomeUx` currently sets `pip-outcome-header` text to
  > "Gesprächsergebnis bestätigen". This phase changes that header text to **"Call wirklich beenden?"**
  > (B-01 makes the outcome screen itself the end-confirmation). Keep the `pip-outcome-header` class.
- **No back-to-call, no in-place mic resume** (B-03). The screen is terminal; the user must confirm an
  outcome. Recovery from accidental end = start a fresh live session (B-04), not handled in this screen.
- **Disclaimer line** (uncertain case only): "KI unsicher, bitte prüfen" — see U-01.
- **Outcome button grid (the 7 outcome classes):** reuse existing `.pip-outcome-btn-grid`
  (flex-wrap, 6px gap, 44px touch targets) + `.n-btn-ghost.pip-outcome-btn`. German labels come from the
  **existing live `_OUTCOME_OPTS` / `_outcomeLabelDe()` maps** — these are the source of truth and MUST
  NOT be reworded in this reordering phase:

  | Enum value (`outcome`) | German label (live, user-facing, Umlaute) |
  |------------------------|--------------------------------------------|
  | `meeting_booked` | Termin gebucht |
  | `callback` | Rückruf vereinbart |
  | `send_info` | Infos zusenden |
  | `wrong_person` | Falsche Person |
  | `gatekeeper_blocked` | Gatekeeper blockt |
  | `no_interest` | Kein Interesse |
  | `contract_signed` | Abschluss |

  > These are the exact strings shipped in `pip-launcher.js:3639` (`_OUTCOME_OPTS`) and `:3848`
  > (`_outcomeLabelDe`). `unknown → Unklar` exists in `_outcomeLabelDe` only as a fallback label and is
  > **not** a user-pickable grid button. The grid presents all 7 classes regardless of pre-selection state.
  > Render order = the `_OUTCOME_OPTS` order above; do not reorder in a reordering phase.

- **Three pre-selection states** (driven by `_decideModalState(data)` → `outcome_source`):

  | Case | `_decideModalState` | Pre-selection | Highlight | Disclaimer | Bestätigen |
  |------|---------------------|---------------|-----------|------------|-----------|
  | (a) Confident `ai_auto` | `'sicher'` | yes | teal `.pip-outcome-btn--selected` | none | **enabled immediately** |
  | (b) Uncertain `ai_auto_unsicher` | `'unsicher'` | **yes** (red) | **red** `--btn-danger-*` + alert icon | "KI unsicher, bitte prüfen" | **disabled** until active tap |
  | (c) Timeout / no attempt | `'kein_versuch'` | none | 7 equal neutral buttons | none (optional hint) | **disabled** until active pick |

  > `'final'` (reconnect on already-confirmed call) stays read-only as today and is out of this phase's
  > new flow. Row (b) is the behavioral change vs. current code (today `'unsicher'` shows no preselect).

- **Bestätigen button:** existing `.n-btn-primary.pip-outcome-confirm-btn`, label **"Bestätigen"**,
  44px min height. Disabled styling = existing `.pip-outcome-btn--disabled` (opacity 0.45, not-allowed).
  Existing in-flight label "Bewertung wird berechnet…" is acceptable to keep.

### Step 4 — Score reveal + base analytics (S-01, S-03) — instant, no animation
On Bestätigen click → `correct_outcome` response already carries `coaching_score` + `final_score`
synchronously (S-01). Render immediately, **no animation, no second roundtrip**. Reveal the score section
(`nlp-section-postcall` → `display:block`, as established in D.UX Plan 05 D-W3-04).

**Panel order (top → bottom):**
1. **Panel heading:** "Auswertung" (16px, weight 600).
2. **Score card** — single coaching score, 28px JetBrains Mono value (`.n-kpi-value`), label
   "Coaching-Score" (11px `.n-kpi-label`). Value color by band: high `--session-score-high #00D4AA`,
   mid `--session-score-mid #6B7280`, low `--session-score-low #f87171`. Render the server `final_score`
   directly (D-W4-02). **Exactly one score** (L-01: remove the preliminary `_calcScore()` from the score
   render path — `_calcScore` at `pip-launcher.js:2982` must no longer feed the displayed score).
3. **Base-analytics row** — appears **together with** the score card, instantly (ran in the background via
   `/api/beenden`, deterministic). Three KPI tiles (`.n-kpi` style, 12px gap):
   - **Kaufbereitschaft** (KB) — value + 11px label.
   - **Redeanteil** — value (%) + 11px label.
   - **Einwände** (Zähler) — count + 11px label.

### Step 5 — Ladebalken 2: "Detail-Auswertung läuft…" (S-03, L-04)
- **Placement:** **only under the Sonnet learning-cards section**, BELOW the already-rendered score card
  and analytics row. It must **never overlay or hide** the values from Step 4 — score and base analytics
  stay fully visible while this runs.
- **Form:** same indeterminate spinner/pulse as Ladebalken 1 (no fake progress).
- **Text:** **"Detail-Auswertung läuft…"** (14px, weight 600, `--page-text-secondary`), spinner 8px gap.
- On Sonnet completion: the spinner is replaced in place by the rendered learning cards. Nothing above moves.
