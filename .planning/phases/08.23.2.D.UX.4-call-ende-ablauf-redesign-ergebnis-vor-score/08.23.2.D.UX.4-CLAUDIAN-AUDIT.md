## 1. [BLOCKER — vor Execute fixen] Score + Analytics landen im falschen Fenster (NEW-1)
Im PiP (schwebendes Anruf-Fenster) liegen Score-/Auswertungs-Kacheln in einem anderen Dokument als der Plan-Code sucht. Plan 03 Task 3 greift auf nacktes `document` statt den PiP-Fenster-Helfer `pipEl()` → nach dem Bestätigen wird der Score schlicht nicht sichtbar. **Fix:** Plan 03 Task 3 muss `pipEl()` (korrekter PiP-Root) nutzen statt `document`. Das ist der Grund für "mit Auflagen" statt glatt "GO".

## 2. [MITTEL — im Plan klären] Lernkarten fehlen wenn Nutzer nicht bestätigt (NEW-2)
Heute werden KI-Lernkarten immer erstellt. Nach dem Umbau hängen sie hinter dem Bestätigen-Knopf — bricht der Nutzer ab → 0 Lernkarten (stille Verschlechterung). Empfehlung: Karten-Erzeugung unabhängig vom Bestätigen laufen lassen. (Plan 02)

## 3. [MITTEL — im Plan klären] Plan beschreibt Lernkarten-Anzeige im PiP die es nicht gibt (NEW-3)
Plan 03 sagt "nutze die bestehende Lernkarten-Anzeige" — die existiert im PiP nicht. Executor müsste neue UI erfinden (gegen "nur umsortieren"-Regel + Farb-/Token-Risiko). Klären: im Scope (→ eigener UI-Schritt mit Tokens) oder streichen.

## 4. [MITTEL — im Execute beachten] HIGH-2 "Schicht 2" zeigt auf falschen Namen (F5)
Die beworbene zweite Schutzschicht gegen späte Antworten nennt falsche ID (`nlp-outcome-section` statt `pip-outcome-section`) + falsches Dokument → tut nichts. Schicht 1 reicht allein, aber die Redundanz ist nur auf dem Papier. Fix: ID auf `pip-outcome-section` + `pipEl()` statt `document`.

## 5. [MITTEL — im Execute entscheiden] Hold-to-end vs. bestehende Verdrahtung (F10/NEW-4)
Beenden-Knopf ist heute "kugelsicher" über einen zentralen Listener gebunden (übersteht PiP-Neuaufbauten). Plan will Halte-Logik direkt an den Knopf hängen → kann beim Neuaufbau den Listener verlieren. Lösung: über denselben zentralen Listener binden ODER bei jedem Neuaufbau neu anhängen, im richtigen Fenster.

## 6. [MITTEL — im Plan klären] Score-Sektion evtl. zu früh sichtbar + Trend ohne Datenquelle (F9)
