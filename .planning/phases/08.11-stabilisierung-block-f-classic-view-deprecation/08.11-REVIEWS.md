# Cross-AI Plan Review — Phase 08.11

## Gemini Review

This review evaluates the 4-wave implementation plan for **Phase 08.11: Classic-View-Deprecation**.

### 1. Summary
The plan is exceptionally well-researched and strategically sound. By separating backend logic removal, frontend file deletion, and legacy bridge cleanup into distinct waves, the strategy minimizes the "blast radius" of deleting ~2,500 lines of code. The decision to maintain `OBJECTION_TRIGGER_PROMPT_BASE` demonstrates a high level of situational awareness regarding the system's seeding logic, preventing a total breakdown of the prompt versioning system.

### 2. Strengths
- **Dependency Awareness:** Explicitly identifying that `OBJECTION_TRIGGER_PROMPT_BASE` must be kept despite the route deletion is critical for system stability.
- **Surgical Backend Deletion:** The distinction between Classic-only routes and PiP-essential routes (like `api_launcher_init`) is clearly defined.
- **Syntax Validation:** Using `node --check` for `pip-launcher.js` in Wave 3 is an excellent defensive measure against syntax errors in the core JS file.
- **Logical Transition:** The use of `redirect(url_for('dashboard_bp.dashboard'))` for the `/live` route ensures that external bookmarks or browser history do not lead to 404s.
- **Test Management:** Anticipating and documenting the intentional test failure in Wave 1/2 shows professional rigor.

### 3. Concerns

| Severity | Concern |
|----------|---------|
| MEDIUM | **Link UX:** Plan 02 replaces `href="/live"` with `onclick="NerveLauncher.open()"` on `<a>` tags but the plan action text does specify `href="javascript:void(0)"` — executor must not omit this or the hand cursor and link affordance are lost. |
| MEDIUM | **Onboarding flow:** `onboarding.html:632` changes `window.location.href='/live'` to `NerveLauncher.open()` — this may fail if the launcher script isn't fully initialized at that moment in the onboarding flow, or trigger popup blockers. |
| LOW | **Global JS audit missing:** Research covered templates but no `grep -r "location.href.*live" static/` was run on JS files other than app.js and pip-launcher.js. A hidden redirect could remain. |

### 4. Suggestions
- **Wave 2 acceptance criteria:** Add `grep -rn "location.href.*live\|href.*=.*['\"]\/live['\"]" salesnerve/static/` to Wave 2 verification (besides the templates check already there).
- **Seeding extra verify:** In Wave 1 Task 2, add explicit check: `python -c "from routes.app_routes import OBJECTION_TRIGGER_PROMPT_BASE; print(OBJECTION_TRIGGER_PROMPT_BASE[:20])"` to confirm constant wasn't swept.
- **301 vs 302:** Consider `redirect(url_for('dashboard_bp.dashboard'), 301)` for the `/live` route to signal permanent deprecation to browsers — though 302 is safer initially.
- **Onboarding fallback:** Consider `window.NerveLauncher ? window.NerveLauncher.open() : window.location.href='/dashboard'` as the onboarding replacement to handle the not-yet-initialized edge case.

### 5. Risk Assessment
**Risk Level: LOW**

1. The project has a robust baseline of 266 tests.
2. Classic-View was already functionally superseded by PiP.
3. The plan includes an explicit "Keep" list for routes, protecting PiP functionality.
4. The intentional test failure management ensures no false alarm on test_ft_seed.
5. The only significant remaining risk is a hidden `/live` redirect in a non-covered JS file, mitigated by the redirect fallback to `/dashboard`.
