# Phase 08.11 — Block F: Manual Smoke Tests

**Zeitpunkt:** Nach Wave-3-Commit, vor git push
**Ziel:** Verifikation dass PiP-Flows nach Classic-View-Deletion funktionieren
**Voraussetzung:** App laeuft lokal (`python app.py` oder `flask run`)

---

## Flow 1: Login → Dashboard-Landing (nicht Classic-View)

- [ ] Browser oeffnen, URL: `http://localhost:5000/login` (oder lokale App-URL)
- [ ] Mit Test-Account einloggen
- **Expected:** Redirect nach Login geht zu `/dashboard`, NICHT zu `/live`
- [ ] `/live` direkt aufrufen → Expected: 302-Redirect zu `/dashboard` (kein 404, kein 500)
- [ ] Dashboard laeuft ohne JS-Fehler (DevTools Console pruefen)

---

## Flow 2: Profil aktivieren

- [ ] Dashboard aufrufen (`/dashboard`)
- [ ] Ein EA-Profil aus der Liste auswaehlen / aktivieren
- **Expected:** Profil wird als aktiv markiert (UI-Feedback: aktives Profil hervorgehoben)
- [ ] Kein JS-Fehler in der Console
- [ ] `/api/set_profile` Request liefert 200 (Network-Tab pruefen)

---

## Flow 3: PiP-Launcher oeffnen

- [ ] Dashboard-Seite: "Call starten"-Button klicken
- **Expected:** PiP-Launcher oeffnet sich (kein Navigation zu `/live`)
- [ ] Sidebar "Live-Assistent"-Icon klicken
- **Expected:** PiP-Launcher oeffnet sich ebenfalls
- [ ] Logs-Seite aufrufen (`/logs` oder aequivalent) → /live-Button pruefen
- **Expected:** Klick oeffnet PiP-Launcher, navigiert NICHT zu `/live`
- [ ] Kein 404 fuer `/live` direkt im Launcher-Flow

---

## Flow 4: Cold-Call starten (Headset-Modal)

- [ ] PiP-Launcher ist offen
- [ ] Profil auswaehlt (falls noch nicht aktiv)
- [ ] "Call starten" oder "Start"-Button im Launcher klicken
- **Expected:** Headset-/Mikrofon-Modal erscheint (DSGVO-Einwilligung oder Mikrofon-Check)
- [ ] Mikrofon-Zugriff bestaetigen
- **Expected:** Session startet, PiP-Fenster zeigt Live-Status
- [ ] `/api/launcher/init` liefert 200 (Network-Tab)
- [ ] Socket-Verbindung aufgebaut (kein "Connection refused" in Console)

---

## Flow 5: EWB-Buttons triggern + Beenden + PostCall

- [ ] Aktive Session laeuft (Flow 4 abgeschlossen)
- [ ] EWB-Button im PiP-Window klicken (Einwand-Button)
- **Expected:** Socket-Event `manual_ewb` wird gesendet (Network-Tab: WS-Frame sichtbar)
- **Expected:** Nach kurzer Verarbeitung erscheint Gegenargument/EWB-Karte im PiP
- [ ] "Beenden"-Button klicken
- **Expected:** `/api/beenden` liefert 200, Session-Abschluss-Logik laeuft
- **Expected:** PostCall-Karte oder PostCall-Ansicht erscheint
- [ ] PostCall-Daten sichtbar (kein Leerscreen, kein 500)
- [ ] Kein Aufruf von `/api/ewb_trigger` oder `/api/postcall_insights` in Network-Tab (Classic-Routen geloescht)

---

## Gesamt-Ergebnis

- [ ] Alle 5 Flows ohne Fehler durchgelaufen
- [ ] Keine JS-Exceptions in DevTools Console
- [ ] Keine 404/500 in Network-Tab (ausser erwartete 302 fuer `/live`)
