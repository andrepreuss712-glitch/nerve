## Summary

This phase removes 10 classic-only HTTP routes, replaces `/live` with a redirect to `/dashboard`, strips the `_SuppressPolling` class and the `api_frage` prompt seed from `app.py`, migrates all `/live` links in templates to `window.NerveLauncher.open()` calls, removes legacy opener fallback branches from `pip-launcher.js`, and updates the `test_ft_seed.py` seed count from 5 to 4.

The template and JS changes are clean. The seed count in `app.py` and the test assertions are in sync. One critical runtime crash bug was introduced: the module-level dict `_letzte_gemeldete_version` was deleted together with the classic polling routes, but a reference to it on line 454 of `api_beenden` was not removed. Every `POST /api/beenden` call will raise a `NameError` and crash without saving the post-call record to the database.

## Critical Issues

### CR-01: `NameError` crash in `api_beenden` — `_letzte_gemeldete_version` deleted but still referenced

**File:** `routes/app_routes.py:452-454`

**Issue:** The module-level dict `_letzte_gemeldete_version = {}` (and `_MAX_VERSION_CACHE`) lived at the top of `app_routes.py` alongside the classic polling routes that were deleted in this phase. Line 454 still references it:

```python
# CR-02: clear stale version counter so first poll after session start logs correctly
uid_end = getattr(g, 'user', None) and g.user.id
if uid_end:
    _letzte_gemeldete_version.pop(uid_end, None)   # <-- NameError here
```

At runtime, every `POST /api/beenden` call reaches this code path (it is not inside a try/except), causing a `NameError: name '_letzte_gemeldete_version' is not defined`. The DB write, point awards, fair-use tracking, and postcall snapshot all execute *before* this line (lines 199-429), but the function crashes before returning the JSON response to the client. The client receives a 500 and cannot display the post-call overlay or navigate to the detail view. The comment "CR-02" in the source also refers to this as the correct clearing location.

**Fix:** Either re-add the module-level declaration (one-liner, no other usage exists after the deletion), or simply remove the now-dead three lines (the polling versioning mechanism no longer exists):

```python
# Option A — remove the dead block entirely (preferred, matches Block F intent)
# Delete lines 451-454:
#   print("[Beenden] State zurückgesetzt.")
#   return jsonify(...)  <- keep this

# Option B — restore the declaration at module level (top of file, after imports)
_letzte_gemeldete_version: dict = {}
```

Option A is preferred because the polling mechanism (`/api/ergebnis`) was part of the deleted classic routes; the version-cache clearing is now meaningless.

## Warnings

### WR-01: `onboarding.html` fallback for `target === 'live'` silently degrades when `NerveLauncher` not loaded

**File:** `templates/onboarding.html:632`

**Issue:** The onboarding completion handler uses:

```javascript
else if (target === 'live') window.NerveLauncher ? window.NerveLauncher.open() : window.location.href = '/dashboard';
```

`onboarding.html` is a standalone page (`<!DOCTYPE html>` — does **not** extend `base.html`). The `pip-launcher.js` script is only injected by `base.html` when `g.user` is truthy. The onboarding page loads `nerve.css` and `lucide.min.js` directly, but does not load `pip-launcher.js`. The ternary guard prevents a crash, but the fallback navigates to `/dashboard` instead of opening the launcher. If a freshly-onboarded user clicks "Live starten" as their first action, they land on the dashboard with no launcher opened — silent UX failure.

This existed before this phase (the fallback was already there), but since this phase is specifically auditing all `/live`→launcher migrations, the gap is worth flagging: onboarding is the only surface that does the migration correctly at code level but silently fails at runtime.

**Fix:** Load `pip-launcher.js` in `onboarding.html` after the user reaches the final step (or unconditionally at the bottom of `<body>`), or navigate to `/dashboard` and open the launcher via a query-param that `dashboard.html` detects on load:

```html
<!-- At bottom of onboarding.html, before </body> -->
<script src="{{ url_for('static', filename='pip-launcher.js') }}?v={{ static_mtime('pip-launcher.js') }}"></script>
```

## Info

### IN-01: `render_template` removed from imports but `redirect`/`url_for` now imported inline

**File:** `routes/app_routes.py:3` and `26-30`

**Issue:** `render_template` was correctly removed from the top-level import (line 3 now reads `from flask import Blueprint, jsonify, request, g, session as flask_session`). However the new `live()` redirect handler re-imports `redirect` and `url_for` inside the function body:

```python
@app_routes_bp.route('/live')
@login_required
def live():
    # Classic-View entfernt (Block F). Redirect auf Dashboard.
    from flask import redirect, url_for
    return redirect(url_for('dashboard_bp.dashboard'))
```

This is a minor inconsistency: `redirect` and `url_for` should be imported at the top of the file alongside the other Flask imports, not deferred. Deferred imports are a common project pattern for lazy-loading heavy modules, but `redirect` and `url_for` are lightweight Flask builtins that belong at the top level.

**Fix:**
```python
# line 3 — extend the existing import
from flask import Blueprint, jsonify, redirect, request, url_for, g, session as flask_session
```
Then remove the two inline import lines from `live()`.

### IN-02: `_MAX_VERSION_CACHE` constant also deleted — no orphaned reference, but confirm intent

**File:** `routes/app_routes.py` (module level — now absent)

**Issue:** `_MAX_VERSION_CACHE = 500` was the safety cap for `_letzte_gemeldete_version`. Both were deleted together. If CR-01 is fixed by Option A (removing the dead block), there is no orphan. If fixed by Option B (restoring the dict), `_MAX_VERSION_CACHE` should also be restored or the cap logic removed from the surviving reference site. Since no polling route remains to populate the dict, Option A remains the clean path.

**Fix:** No action needed if CR-01 is resolved via Option A (removal). Document only.
