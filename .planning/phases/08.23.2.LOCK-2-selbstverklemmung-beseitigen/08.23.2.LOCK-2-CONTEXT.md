## Implementation Decisions (LOCKED)

### D-1 — Der Fix: Sub-Key-Read, eine Zeile, kein neuer Helfer

Im Block `:2062` liegt `_sid_pp_state` (= `ls._session_state.get(sid)`) **bereits in der Hand**:

```python
# statt:  _anon_cache = ls.get_anonymisierer(sid)
_anon_cache = _sid_pp_state.get('anonymisierer')
```

Der Anonymisierer liegt genau dort (`live_session.py:452` schreibt ihn, `:610` legt den Schluessel an).
Das ist das im Code dokumentierte Muster **„direkt aus dem schon-gehaltenen State lesen"**
(`live_session.py:859-863`; `claude_service.py:1441` macht es fuer `get_counterpart` genauso).

**Die S4-Atomaritaet bleibt erhalten** (Duplikat-Check + append unter EINEM Erwerb, Kommentar `:2060-2061`).

**Verworfene Alternative:** Aufruf vor den Block ziehen (wie `:2090`) — ginge auch, oeffnet aber ein
winziges TOCTOU-Fenster. **Entscheidung: Sub-Key-Read.**

**KEIN RLock** (`live_session.py:308-310` woertlich: „Ein RLock wuerde diesen Design-Zwang lautlos
aufloesen"). **Kein neuer Helfer.**

`_anon_cache` kann `None` sein (Anonymisierer noch nicht initialisiert) — das ist **derselbe
Rueckgabewert wie bisher** (`get_anonymisierer` gibt None bei Ghost-SID / nicht initialisiert),
der umgebende `try/except` + der defensive Umgang in `anonymize_output` bleiben unveraendert.
**Kein Verhaltensunterschied ausser dem entfallenen Riegel-Erwerb.**

### D-2 — Rot-Beleg VOR dem Fix (PFLICHT, harte Reihenfolge)

Der erweiterte Waechter muss **am ALTEN Stand rot werden**, mit **Treffer `claude_service.py:2076`**,
**bevor** der Fix committed wird. Ein Waechter, der nie rot war, beweist nichts.

- Reihenfolge im Plan: **Waechter erweitern → Rot-Beleg ziehen und im SUMMARY belegen → dann fixen → gruen**.
- Der Rot-Beleg ist ein **Acceptance-Artefakt**, keine Nebenbemerkung: die Trefferzeile
  (`claude_service.py:2076`) gehoert woertlich ins SUMMARY.
- **Zusatz-Erkenntnis aus dem Rot-Lauf:** meldet der Waechter am alten Stand **mehr als** `:2076`,
  ist das ein **Widerspruch zum gesetzten Fable-Ergebnis** → STOP + im DIALOG melden, nicht
  stillschweigend mitfixen. Meldet er **weniger/nichts**, greift die Erweiterung nicht → Waechter reparieren.

### D-3 — Waechter 2 erweitern, nicht neu bauen

Basis: `tests/test_session_lock_blocking_calls_guard.py`. Wiederverwenden:
`_ist_session_state_lock:136` · Block-Sammler `_sammle_bloecke:147` / `_sammle_try_bloecke:168` ·
Regions-Logik `_riegel_region:185`.

**Die fuenf Konstruktionspunkte (alle PFLICHT):**

1. **Nehmer-Liste aus dem Code ableiten, nichts hartkodieren.** Funktion ist Nehmer, wenn im
   **eigenen** Rumpf ein Riegel-`with` ODER `.acquire()` liegt — **verschachtelte `def`s ausnehmen**,
   sonst haftet `api_beenden` faelschlich fuer `_load_beenden_state`. Neue Nehmer sind damit
   automatisch mitgeschuetzt; eine gepflegte Liste wuerde veralten und dieselbe Luecke neu erzeugen.
2. **Transitiv per Fixpunkt-Iteration** statt Rekursion (terminiert bei Zyklen garantiert, beliebige
   Tiefe). Kanten nur ueber **aufloesbare** Ziele: nackter Name im Modul; `alias.name` wenn der Alias
   auf ein Modul in `_SCAN_DIRS` zeigt (deckt `ls` / `_ls` / `_ls_av` / `ls_module`).
3. **Zweitpass namensbasiert** fuer nicht aufloesbare Methoden-Aufrufe (faengt
   `matcher.match_with_dedup`). Ausnahmen **nur** ueber die bestehende `# FALSCH-TREFFER:`-Regel.
4. **Nur Call-Positionen melden, keine Argument-Referenzen** — sonst wird
   `threading.Timer(…, ls._flush_segment)` ein Dauer-Falschtreffer.
5. **Selbst-Test mit synthetischem 2-Ebenen-Fall** (Block → Helfer → Riegel), sonst ist nicht
   unterscheidbar, ob die Transitivitaet ueberhaupt greift. **Plus Mindest-Soll fuer die Zahl
   abgeleiteter Nehmer (heute 48 produktive)** — faellt die Ableitung still aus, wird der Test
   **rot statt blind**.

### D-4 — Warnkommentar an die FUNKTIONSDEFINITION
