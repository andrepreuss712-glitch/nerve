## Fixed Issues

### CR-01: SQL Injection via ILIKE with User-Controlled Input

**Files modified:** `services/integration_engine.py`
**Commit:** f8430f8
**Applied fix:** Added `_escape_like()` helper function that escapes `%` and `_` SQL LIKE wildcards in user input. Applied the escape to both `ilike` queries in `_persist_training_recommendation` before interpolating `einwand_typ` into the LIKE pattern. Also added `import re` at module level.

### WR-01: DB Session Used After Commit in Learning Event Logging

**Files modified:** `routes/learning.py`
**Commit:** 77f8b09
**Applied fix:** Consolidated double-commit pattern in 4 locations (`api_save_card`, `api_update_status`, `api_mark_applied`, `api_user_text`). In each case, moved the `log_learning_event()` call before the single `db.commit()` so both the model change and the learning event are committed atomically in one transaction. The try/except around the event logging is preserved so a logging failure does not prevent the primary operation from committing.

### WR-02: Global Mutable State for Polling Version Tracking

**Files modified:** `routes/app_routes.py`
**Commit:** 4fc3c8d
**Applied fix:** Changed `_letzte_gemeldete_version` from a single integer (shared across all users in a worker) to a per-user dict keyed by `user_id`. The polling log message now correctly tracks version per user, preventing one user's poll from suppressing another user's "new result" log entry.

### WR-03: `_detect_female` Defined Inside Nested Function Scope But Referenced Outside

**Files modified:** `routes/training.py`
**Commit:** 9bd255c
**Applied fix:** Moved `_detect_female()` from inside `training_start()` (line 280) to module level (before `training_start` definition). This fixes a `NameError` that would occur at runtime when `training_respond()` calls `_detect_female()` during secretary-to-customer voice switch. The function body is unchanged.

### WR-04: Raw SQL with json_extract Not Portable Beyond SQLite

**Files modified:** `services/integration_engine.py`
**Commit:** 1904d00
**Applied fix:** Added `# NOTE: json_extract() is SQLite-specific` comments to all three raw SQL query locations that use `json_extract()`. These comments flag the queries for attention during any future PostgreSQL migration.

### WR-05: Boolean JSON Comparison May Not Match in SQLite json_extract

**Files modified:** `services/integration_engine.py`
**Commit:** 1904d00
**Applied fix:** Changed `json_extract(metadata, '$.success') = 'false'` to `= 0` in the training failure pattern detection query (D-05). SQLite's `json_extract` returns integer 0/1 for JSON booleans, not the strings 'false'/'true'. The previous comparison would never match, effectively disabling the "3x Training failure" recommendation trigger.
