## Warnings

### WR-01: Stiller Early-Return laesst Launcher im undefinierten Zustand

**File:** `static/pip-launcher.js:635`
**Issue:** In `_showConsentModal` fuehrt der Guard `if (!overlay || !scriptEl || !acceptBtn || !rejectBtn || !cancelBtn) return;` bei fehlenden DOM-Elementen zu einem stillen Return _ohne_ den Callback zu invokieren. Der Aufrufer in `startCall` (Zeile 823) bleibt dann im `return;`-Zweig (Zeile 834) stecken: `state.consentDone` bleibt `false`, der Launcher ist nicht geschlossen (`close()` wird in `startCall` erst nach dem Gate aufgerufen), und kein Nutzer-Feedback erscheint. Im Produktiv-Build passiert das nur, wenn `base.html` falsch gerendert wurde (z.B. Template-Inheritance-Bug) — aber dann ist das Symptom "Button tut nichts" und schwer zu debuggen.
**Fix:**
```js
if (!overlay || !scriptEl || !acceptBtn || !rejectBtn || !cancelBtn) {
  console.error('[NerveLauncher] Consent modal DOM missing — falling back');
  callback('cancelled');  // oder: 'accepted' mit Warn-Log, je nach DSGVO-Policy
  return;
}
```
Empfehlung: `'cancelled'` zurueckgeben, damit der User nicht ungewollt in einen Meeting-Call rutscht, ohne das Script gelesen zu haben.

### WR-02: Focus-Trap matched nicht fuer disabled/hidden buttons und ignoriert Backdrop-Dismiss

**File:** `static/pip-launcher.js:629-698`
**Issue:** Das Consent-Modal fehlt im Gegensatz zu anderen Overlays (`_showSaveToProfileDialog` Zeile 623) eine Backdrop-Click-Dismiss-Option. Ausserdem wird in `onKeydown` (Zeile 669) der `keydown`-Listener auf `document` registriert — aber `_showHeadsetModal` tut das gleiche, sodass wenn Headset- und Consent-Modal nacheinander getriggert werden, der Listener des geschlossenen Modals theoretisch noch haengen koennte. In der aktuellen Code-Struktur passiert das nicht (Gates sind mode-exklusiv: cold_call vs meeting), aber der Mechanismus ist fragil. Zusaetzlich: ESC → `onCancel()` → Launcher bleibt offen bei Step 5 ohne State-Aufraeum.
**Fix:**
1. Backdrop-Dismiss optional ergaenzen (konsistent mit `_showSaveToProfileDialog`):
```js
function onBackdropClick(e) { if (e.target === overlay) onCancel(); }
overlay.addEventListener('click', onBackdropClick);
// in closeModal():
overlay.removeEventListener('click', onBackdropClick);
```
2. Verifizieren, dass `onCancel`-Pfad keinen haengenden UI-State hinterlaesst (Launcher-Modal sollte explizit offen/sichtbar bleiben — das ist korrekt, aber einen Kommentar dazu ergaenzen).

## Info

### IN-01: Inkonsistente Umlaute/Sonderzeichen (ae/oe/ue statt ä/ö/ü)

**File:** `templates/base.html:361, 364, 371, 378-379` und `static/pip-launcher.js:627, 643`
**Issue:** Texte wie "Gespraechspartner", "hoert", "Gespraechsinhalt" verwenden ASCII-Ersatzschreibweise, waehrend andere Stellen in derselben Datei korrekte UTF-8-Zeichen nutzen (z.B. "Bearbeiten", "Auswaehlen", Flash-Messages). In `_resetLiveState` Zeile 1725 z.B. steht korrekt "Warte auf Gesprächsinhalt…". Nutzer sehen damit gemischte Schreibweisen.
**Fix:** Einheitlich UTF-8-Umlaute (ä/ö/ü) verwenden — die Datei ist bereits `lang="de"` und UTF-8-encodiert.

### IN-02: Magic string `'[Name]'` fuer Token-Replacement

**File:** `static/pip-launcher.js:643`
**Issue:** Der Token `[Name]` ist hart im Code eingebrannt. Wenn ein User in `profile_daten.consent_text` `{Name}` oder `%Name%` schreibt (wie in manchen CRM-Tools), wird nicht ersetzt. Ausserdem nur _erstes_ Vorkommen wird ersetzt (kein Regex + `g`-Flag).
**Fix:**
```js
var NAME_TOKEN = /\[Name\]/g;
// ...
if (state.precallFormData && state.precallFormData.person) {
  text = text.replace(NAME_TOKEN, state.precallFormData.person);
}
```
Plus: Token-Format (`[Name]`) in der Profil-Settings-UI dokumentieren.

### IN-03: `previousFocus.focus()` kann nach PiP-Teardown failen

**File:** `static/pip-launcher.js:660-662`
**Issue:** `previousFocus` wird beim Oeffnen gecached (Zeile 649). Wenn der Launcher-Modal zwischenzeitlich schliesst oder das urspruengliche Element entfernt wird (z.B. weil `renderStep` den Launcher-Content neu rendert waehrend der Consent-Dialog offen ist), kann `focus()` zwar silent failen (try/catch ist da), aber das Feature "Focus restoration" funktioniert nicht sinnvoll.
**Fix:** Dokumentieren per Kommentar, dass der try/catch bewusst ist — oder `document.body.focus()` als expliziter Fallback.

### IN-04: Kein `aria-describedby` fuer Consent-Script

**File:** `templates/base.html:376-387`
**Issue:** `role="dialog"` + `aria-modal="true"` + `aria-labelledby="consent-title"` ist gesetzt, aber der rechtlich relevante Vorlese-Text (`#consent-script`) hat kein `aria-describedby`. Screenreader lesen nur den Titel, nicht das Pflicht-Script.
**Fix:**
```html
<div class="consent-overlay" ... aria-labelledby="consent-title" aria-describedby="consent-script">
```
