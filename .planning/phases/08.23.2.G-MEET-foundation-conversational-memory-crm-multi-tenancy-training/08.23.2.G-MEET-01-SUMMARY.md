## Security decisions (Gemini SQL-layer review, both verified on Production)

- **mk_tenant_org() is SECURITY INVOKER** (Gemini Q1, 🔴 HIGH; T-G1-01 mitigated). nerve_app OWNS
  `tenant_orgs`, so the INVOKER trigger (running as nerve_app on an org INSERT) already has INSERT —
  no escalation. `SECURITY DEFINER` (would run as postgres superuser per org INSERT) is REMOVED. No
  `SET search_path` (single static INSERT, no dynamic SQL → no hijack surface). **Verified on prod:
  `pg_proc.prosecdef=f`, `proconfig=NULL`.**
- **Post-backfill hard-RAISE guard** (Gemini Q3, 🟡 MEDIUM; André decision). The join is total
  (users.org_id NOT NULL + seed over ALL orgs in the same transaction). **Verified on prod: guard did
  NOT fire → 0 orphan calls (`SELECT count(*) FROM calls WHERE tenant_id IS NULL = 0`).** Column stays
  NULLABLE (no NOT NULL added) — `test_calls_tenant_id_stays_nullable` remains valid (constraint, not row state).
