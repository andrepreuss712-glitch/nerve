    Wire the session-tenant-UUID into a Postgres GUC, atomically with the policies (D-12.1 — both ship same wave/deploy).

    ⚠ CONNECTION-AFFINITY IS THE WHOLE POINT (the B-1 trap): the GUC `app.tenant_id` is connection-local. If you SET it on connection X and the ORM query then runs on a DIFFERENT pooled connection Y, `current_setting('app.tenant_id')` is NULL on Y → RLS returns 0 rows on every legitimate own-tenant read → the app ships fail-closed-BROKEN. The naive "open a `get_session()` in before_request, SET, commit, close" does EXACTLY this (it sets on a connection then returned to the pool, while the request's real queries grab a different one). RESEARCH Open-Q 1's recommendation — adopt it literally — is to set the GUC on the SQLAlchemy pool **`checkout`** event, so the SET and the subsequent queries on that connection share ONE physical connection for the connection's whole checked-out life. The request never SETs directly; it only deposits the tenant UUID into a contextvar that the checkout listener reads.

    1. **Resolve tenant UUID at login** (avoids per-request bridge reload, D-11): in the login flow (routes/auth.py `_do_login`/`_login_user`), after resolving the user's org, look up `tenant_orgs.id WHERE legacy_org_id = user.org_id` and store it in the Flask `session` as `session['tenant_id']` (string UUID) alongside the existing org_id.

    2. **contextvar + before_request publish** (database/db.py + app.py): define a module-level contextvar in database/db.py so the pool events can read the tenant regardless of Flask context (the checkout event also fires for worker-thread checkouts).     3. **Pool `checkout` SET — the connection-affinity fix (D-12.1, B-1):** add to database/db.py, mirroring the existing `@event.listens_for(engine, "connect")` idiom (db.py:20-24), but gated on the Postgres dialect (inverse of the SQLite WAL hook). It fires the moment a connection leaves the pool to serve work, so the SET lands on the SAME connection the request's ORM queries then use. PARAMETERIZE — never string-interpolate the UUID (SQL-injection, T-G2-05):
    ```python
    if 'sqlite' not in _DATABASE_URL:
        @event.listens_for(engine, "checkout")
        def _set_tenant(dbapi_conn, conn_record, conn_proxy):
            tid = _current_tenant_id.get()
            if not tid:
                return  # no tenant context (pre-login / static / worker w/o tenant) -> GUC stays unset -> RLS fail-closed (0 rows)
    ```

    4. **Pool `checkin` RESET — the leakage killer (D-12.3):** in the SAME `if 'sqlite' not in _DATABASE_URL:` block, pair a checkin listener that RESETs the GUC on the same connection lifecycle, so a returned connection cannot leak tenant A's id to tenant B's next checkout:
    ```python
        @event.listens_for(engine, "checkin")
        def _reset_tenant(dbapi_conn, conn_record):
            try:
    ```
