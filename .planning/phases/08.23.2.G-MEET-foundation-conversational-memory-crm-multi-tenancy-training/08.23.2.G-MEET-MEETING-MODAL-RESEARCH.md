## 1. `crm.user_preferences` Design Decision (with evidence)

### The user-key tension (the one real decision)
`public.users.id` is **INTEGER** (VERIFIED). crm tables are tenant-scoped on **UUID** `tenant_id`. The foundation rule is **"no wall-FKs to public *alttabellen*"** — but crm tables DO FK to `tenant_orgs` (which lives in public, and is the tenancy root, NOT a legacy alttabelle). See `0012:75` `tenant_id UUID NOT NULL REFERENCES public.tenant_orgs(id)` — proof that a crm→public FK is allowed *when the target is the tenancy infra*.

`users` IS a legacy alttabelle (integer-keyed, predates tenancy). Following the foundation pattern (D-08 soft-link `call_id` has NO FK; D-17 wall):

**DECISION (recommended, evidence-backed): `user_id INTEGER NOT NULL`, NO hard FK to `public.users`.**
- Consistent with the soft-link precedent (`meetings.call_id uuid` with NO FK, `0012:119`).
- Avoids a crm→legacy-alttabelle FK (keeps the wall clean; only `tenant_orgs` is FK'd across, mirroring all 4 crm tables).
- Tradeoff: no DB-level referential integrity to `users` (an orphan pref row is possible if a user is hard-deleted). Acceptable — same tradeoff already accepted for `call_id`. Integrity is enforced at app layer (route always writes `g.user.id`).
- `[ASSUMED→confirm in discuss]` that solo-founder accepts the soft-link tradeoff over a cross-wall FK; flag A1.

### Proposed DDL (clone 0012's exact pattern)
```sql
CREATE TABLE IF NOT EXISTS crm.user_preferences (
    id                UUID PRIMARY KEY DEFAULT gen_random_uuid(),   -- core on PG 16.14
    tenant_id         UUID NOT NULL REFERENCES public.tenant_orgs(id),
    user_id           INTEGER NOT NULL,            -- soft link to public.users.id, NO FK (mirrors call_id D-08)
    auto_save_meeting BOOLEAN NOT NULL DEFAULT false,  -- DSGVO: default OFF mirrors unchecked-by-default UI
    schema_version    SMALLINT NOT NULL DEFAULT 1,  -- D-19 parity with other crm tables
    created_at        TIMESTAMPTZ DEFAULT now(),
    updated_at        TIMESTAMPTZ DEFAULT now(),
    CONSTRAINT uq_user_preferences_tenant_user UNIQUE (tenant_id, user_id)  -- one prefs row per user per tenant
);
```
Then **exactly** clone the RLS block from `0012:138-146`:
```sql
ALTER TABLE crm.user_preferences ENABLE ROW LEVEL SECURITY;
ALTER TABLE crm.user_preferences FORCE ROW LEVEL SECURITY;
CREATE POLICY tenant_isolation ON crm.user_preferences
  USING (tenant_id = nullif(current_setting('app.tenant_id', true), '')::uuid)
  WITH CHECK (tenant_id = nullif(current_setting('app.tenant_id', true), '')::uuid);
CREATE INDEX IF NOT EXISTS idx_user_preferences_tenant ON crm.user_preferences(tenant_id);
```
- **NO `GRANT`** statement — default ACL covers it (§0.3, PROVEN).
- **NO `ALTER OWNER`** — keep postgres-owned so RLS engages for nerve_app (§0.3).
- **Uniqueness:** `UNIQUE (tenant_id, user_id)` → enables UPSERT (`ON CONFLICT (tenant_id, user_id) DO UPDATE SET auto_save_meeting=…, updated_at=now()`). One row per user per tenant.

- `@login_required` (mirror existing crm routes).
- CSRF: Flask-WTF CSRF is global (`csrf.exempt(...)` only for webhooks, `app.py:2186-2190`). A browser POST MUST send `X-CSRFToken`. The PiP fetch already does this via `getCsrfToken()` (`pip-launcher.js:8-11`, used at `:3035` etc.). So the route needs NO csrf exemption.

### How the route stamps `tenant_id` (the RLS-critical part)
The route does an **ORM INSERT inside the normal request session** (`get_session()`). Because `app.py:2193 before_request` ran `set_current_tenant(session['tenant_id'])` and `db.py:62 after_begin` issues `set_config('app.tenant_id', <uuid>, true)` at txn start, **the GUC is already set to the user's tenant for any query in this request.**

WITH CHECK requires `meetings.tenant_id == current_setting('app.tenant_id')`. **The route MUST stamp the row's `tenant_id` with the SAME uuid.** Source it from `g.tenant_id` (set at `app.py:2201`) — do NOT re-derive:
```python
from flask import g
tenant_id = g.tenant_id            # the exact string UUID published into the GUC this request
if not tenant_id:
    return jsonify(error='Kein Mandant'), 403   # fail-closed (unauthenticated/no tenant_org)
m = Meeting(tenant_id=tenant_id, call_id=..., scheduled_at=..., notes=..., account_id=..., contact_id=...)
db.add(m); db.commit()             # WITH CHECK passes because m.tenant_id == GUC
```
If `tenant_id` mismatched the GUC (or were omitted → NULL on a NOT NULL col) the INSERT would error / be rejected. Single-source it from `g.tenant_id`.

### Resolve-or-create accounts/contacts
Match by `(tenant_id, name)` — RLS already scopes the query to the tenant, so the filter is just `name`:
```python
def _resolve_account(db, tenant_id, firma):
    firma = (firma or '').strip()
    if not firma:
        return None                              # blank → NULL account_id (UI-SPEC allows blank)
    acc = db.query(Account).filter(Account.name == firma).first()   # RLS scopes to tenant
    if acc is None:
        acc = Account(tenant_id=tenant_id, name=firma)              # tenant_id stamped → WITH CHECK ok
        db.add(acc); db.flush()                                     # flush to get acc.id before meeting INSERT
    return acc.id
# contact analogous: match (name), create with tenant_id + account_id (the just-resolved acc.id)
```
- **Blank Firma/Ansprechpartner → NULL** (`account_id`/`contact_id` are NULLABLE, §0.2). No row created. UI-SPEC §"Field set" confirms 3 of 4 fields prefill but may be blank.
- Order: resolve account first → resolve/create contact with `account_id=acc.id` → INSERT meeting with both ids.

### `call_id` mapping
Frontend `state.lastCallId` (`pip-launcher.js:3050`, a uuid from `data.call_id`) → POST body `call_id` → route writes `meetings.call_id` (uuid, no FK). Type-compatible (calls.id is uuid). Nullable — if absent, write NULL.

### Validation + error contract (matches UI-SPEC failure path)
- `scheduled_at`: parse the `datetime-local` string; if unparseable → 400 with inline message (UI keeps form open, "Konnte nicht gespeichert werden. Nochmal versuchen?").
- All fields optional except the row needs a valid tenant. Return `jsonify(ok=True, firma=<name>, thema=<notes>, scheduled_at=<iso>)` so the frontend can render the confirmation view (`{Firma}`, briefing-preview `{Thema} · {Datum}`).
- On exception: rollback, `jsonify(ok=False, error='…'), 500` (sanitize — frontend `sanitizeErrorMsg` `pip-launcher.js:14` strips tracebacks). NEVER 200-with-silent-failure.
