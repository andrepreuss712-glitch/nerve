### Prompt-Caching (LOCKED — POLISH-58)

- **Aktivierung:** NUR wenn System-Prompt ≥ 4000 Token (sonst nicht amortisierbar)
  - Cache-Write-Preis: 1.25× normal → amortisiert erst ab ~5-7 Calls pro Session
  - Cache-Hit-Preis: 0.1× normal → ~90% Ersparnis auf gecachte Tokens
  - Formel: Caching lohnt sich bei ≥ 4000 Token System-Prompt + ≥ 2 Calls/Session
- **Implementierung:** `cache_control: {"type": "ephemeral"}` auf System-Prompt-Block
  ```python
  messages = [{"role": "user", "content": [
      {"type": "text", "text": system_prompt, "cache_control": {"type": "ephemeral"}},
      {"type": "text", "text": user_message}
  ]}]
  ```
- **5-Minuten-TTL:** System-Prompt muss byte-identisch sein pro Session-Zeitfenster
- **Cache-Hit-Rate loggen:** aus `response.usage.cache_read_input_tokens`
- **Call-Sites die Caching bekommen (System-Prompt vermutlich ≥ 4000 Token):**
  - EWB-Generation (claude_service.py — Profil + Persona + Einwand-Kontext)
  - QA-Response (claude_service.py — Profil + Skript + FAQ)
  - Analyse-Loop (trotz Haiku — System-Prompt ist groß durch Profil-Kontext)
- **Call-Sites ohne Caching (kurze Prompts):**
  - Personality-Gen, Weekly-Summary, CRM (kurze System-Prompts)

## Specific Ideas / Constraints

### Kombinations-Hebel Caching + Sonnet
Sonnet gecacht = $0.30/MT Input vs. Haiku ungecacht = $0.80/MT.
Für 4000-Token System-Prompt: Sonnet mit Cache-Hit ist ~2.7× BILLIGER als Haiku ohne Cache.
Das macht den Sonnet-Upgrade für input-schwere Calls nicht nur qualitativ besser, sondern auch günstiger.
