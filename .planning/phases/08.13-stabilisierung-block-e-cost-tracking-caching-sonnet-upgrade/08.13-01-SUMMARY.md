# Phase 08.13 Plan 01: Foundation (Model-Konstanten + DB-Migration + cost_tracker) Summary

**One-liner:** ApiRate-Seeding (6 neue Rows), 21 MODEL_*-Konstanten + 3 CACHE_*-Booleans in config.py, ApiCostLog um latency_ms/call_site erweitert mit idempotenter DB-Migration und cost_tracker-Signaturerweiterung.

## Was wurde gebaut

### Task 0: ApiRate-Seeding (Wave 0 Pre-Check)

**Ausgangslage:** 4 Anthropic-ApiRate-Rows vorhanden (haiku-4-5 input/output, sonnet-4 input/output). 6 der 8 benoetigten Rows fehlten.

**Ergebnis:** 6 neue Rows geseedet:
- `sonnet-4-5 / per_1k_input_tokens` = $0.003
- `sonnet-4-5 / per_1k_output_tokens` = $0.015
- `sonnet-4-5 / per_1k_cache_read_tokens` = $0.0003
- `sonnet-4-5 / per_1k_cache_write_tokens` = $0.00375
- `haiku-4-5 / per_1k_cache_read_tokens` = $0.00008
- `haiku-4-5 / per_1k_cache_write_tokens` = $0.001

Alle 8 benoetigten ApiRate-Rows sind jetzt vorhanden. Kein Cost-Log wird mehr silent gedroppt wegen fehlender Rate fuer sonnet-4-5.

### Task 1: config.py MODEL_*-Konstanten + CACHE_*-Booleans (TDD)

**21 MODEL_*-Konstanten** in config.py eingefuegt:
- 9 Sonnet-4.5-Konstanten (MODEL_EWB, MODEL_QA, MODEL_POSTCALL_INSIGHTS, MODEL_POSTCALL_ANALYSIS, MODEL_WEEKLY_SUMMARY, MODEL_PRECALL, MODEL_CRM, MODEL_TRAINING_HELP, MODEL_TRAINING_SCORING)
- 12 Haiku-4.5-Konstanten (MODEL_ANALYSE, MODEL_TRAINING_DIALOG, MODEL_PERSONALITY_GEN, MODEL_PHASE_CLASSIFY, MODEL_COLDCALL_INFER, MODEL_PIP_AUTOVAR, MODEL_PIP_VARIANTE, MODEL_COACHING, MODEL_VALIDATE_USER_TEXT, MODEL_TRAINING_PREVIEW)

**3 CACHE_*-Booleans** (CACHE_EWB=True, CACHE_QA=True, CACHE_ANALYSE=False)

Alle mit os.getenv() — ENV-Override via .env + systemctl restart funktioniert.

**TDD:** 24 Tests RED → GREEN. Einfugestelle: zwischen CLASSIFIER_CONFIDENCE_THRESHOLD und MERGE_WINDOW_S.

### Task 2: DB-Migration + ApiCostLog + cost_tracker (TDD)

**database/models.py:**
```python
latency_ms  = Column(Integer, nullable=True)
call_site   = Column(String(50), nullable=True)
```
Nach context_tag in ApiCostLog.

**app.py `_migrate()`:** Zwei idempotente ALTER TABLE Bloecke am Ende der _migrate()-Funktion:
```
ALTER TABLE api_cost_log ADD COLUMN latency_ms INTEGER
ALTER TABLE api_cost_log ADD COLUMN call_site VARCHAR(50)
```
Beide per try/except idempotent — zweiter App-Start wirft keine Exception.

**services/cost_tracker.py:** Signatur von log_api_cost() erweitert:
```python
latency_ms: int | None = None,    # NEU: Phase 08.13
call_site: str | None = None,     # NEU: Phase 08.13
```
db.add(ApiCostLog(...)) schreibt beide neuen Felder. Vollstaendig rueckwaertskompatibel.

**TDD:** 11 Tests RED → GREEN. Alle bestehenden log_api_cost()-Aufrufe unveraendert funktionsfaehig.
