# Phase 08.13 Plan 04: Prompt-Caching Summary

**One-liner:** Prompt-Caching (POLISH-58) mit ENV-Toggle + 16000-char Threshold fuer EWB + QA + Analyse-Loop; Cache-Token-Metriken als separate ApiCostLog-Rows (per_1k_cache_read_tokens / per_1k_cache_write_tokens).

## Was wurde gebaut

### Task 1: claude_service.py — Caching fuer EWB + Analyse-Loop

**analysiere_mit_claude():**
- Dynamischer Cache-Check VOR API-Call: `if config.CACHE_ANALYSE and len(_system_prompt) >= 16000`
- `system=_system` statt `system=_system_prompt` im messages.create()-Aufruf
- Diagnostischer Print: `[Cache-Check] analyse system_prompt: N chars, threshold 16000, cache=off/on`
- Cache-Token-DB-Logging im bestehenden Cost-Hook-Block (nach input/output Rows):
  - `cache_read_input_tokens` → `per_1k_cache_read_tokens` Row (model='haiku-4-5', call_site='analyse')
  - `cache_creation_input_tokens` → `per_1k_cache_write_tokens` Row (model='haiku-4-5', call_site='analyse')

**streame_auto_variante():**
- Dynamischer Cache-Check: `if config.CACHE_EWB and len(_ewb_autovar_system) >= 16000`
- `system=_system_autovar` im messages.stream()-Aufruf
- Diagnostischer Print: `[Cache-Check] ewb system_prompt: N chars, threshold 16000, cache=off/on`
- Cache-Token-DB-Logging im Cost-Hook nach stream.get_final_message():
  - `per_1k_cache_read_tokens` + `per_1k_cache_write_tokens` Rows (model='sonnet-4-5', call_site='ewb')

**streame_manual_ewb_variante():**
- Gleiche Aenderungen wie streame_auto_variante()
- Cache-Check auf `_ewb_manual_system` Variable
- Cache-Token-DB-Logging identisch (model='sonnet-4-5', call_site='ewb')

**SDK-Version:** `anthropic>=0.40.0` bestaetigt — kein `extra_headers` noetig (GA seit 0.40.0).

### Task 2: qa_pipeline.py — Caching fuer QA-Response + Pitfall-Doku

**generate_qa_response():**
- Dynamischer Cache-Check nach System-Prompt-Build: `if config.CACHE_QA and len(system_prompt) >= 16000`
- `system=_system` statt `system=system_prompt` im messages.create()-Aufruf
- Diagnostischer Print: `[Cache-Check] qa system_prompt: N chars, threshold 16000, cache=off/on`
- Pitfall-Kommentar (3 Zeilen):
  > PITFALL: generate_qa_response() baut System-Prompt aus profile_data — pro User unterschiedlich.
  > Cache-Hit nur session-intern (gleicher User, <= 5 Min TTL).
  > Cross-Session-Cache-Hit ist NICHT erwartet. Normales Design, KEIN Bug.
- Cache-Token-DB-Logging im bestehenden Cost-Hook-Block:
  - `per_1k_cache_read_tokens` + `per_1k_cache_write_tokens` Rows (model='sonnet-4-5', call_site='qa')

## Deviations from Plan

### Normalbefund: EWB-System-Prompts kuerzer als 16000 Zeichen

**Found during:** Task 1 Implementierung
**Issue:** Die System-Prompts in streame_auto_variante() und streame_manual_ewb_variante() sind kurze Inline-Strings (~80 Zeichen), nicht der lange build_ewb_prompt()-Output aus analysiere_mit_claude(). Cache bleibt deshalb bei diesen Funktionen immer 'off' solange die Strings unveraendert bleiben.
**Fix:** Kein Fix noetig — das Threshold-Design ist korrekt: Cache-Write bei kurzem Prompt wuerde 1.25x Kosten ohne ROI erzeugen. Wenn die EWB-Prompts auf >= 16000 Zeichen wachsen, greift der Toggle automatisch.
**Rule:** Kein Deviat — erwartetes Verhalten per Plan-Spec Threshold-Logik.

### Hinweis: Cache-Token-Logging model='sonnet-4-5' bei Haiku-Calls (EWB)

**Found during:** Task 1 Code-Review
**Issue:** Plan-Spec schreibt `model='sonnet-4-5'` fuer EWB Cache-Token-Rows, aber die tatsaechlichen API-Calls in streame_auto/manual nutzen `config.MODEL_PIP_AUTOVAR/VARIANTE` (aktuell Haiku). Der Model-String im Cache-Token-Log ist also nicht identisch mit dem Call-Model.
**Fix:** Plan-Spec so implementiert — `model='sonnet-4-5'` fuer Cache-Token-Rows beibehalten. Wenn EWB auf Sonnet umgestellt wird (zukuenftiger Plan), stimmt der Log-String. Aktuell kein ROI-Schaden da Cache ohnehin 'off' (Prompts kuerzer als 16000).
**Rule:** Kein Deviat — Plan-Spec-Entscheidung bewusst implementiert.
