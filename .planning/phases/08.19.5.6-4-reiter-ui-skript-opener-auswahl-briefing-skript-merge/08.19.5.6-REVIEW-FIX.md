## Fixed Issues

### CR-01: `type` field missing from opener-items API responses

**Files modified:** `routes/app_routes.py`
**Commit:** a7da144
**Applied fix:** Added `'type': o.type or 'opener'` to the opener-item dict in both `api_launcher_init` (line ~845) and `api_launcher_profile` (line ~890). Without this field every `o.type === 'opener'` / `'erlaubnis'` / `'pitch'` filter in `renderStep5` returned an empty array, making all three tabs show "Noch kein X hinterlegt" regardless of actual data.

### WR-01: Profile-change fetch in `renderStep5` swallows errors silently

**Files modified:** `static/pip-launcher.js`
**Commit:** 00ab9be
**Applied fix:** Replaced the silent `.catch(function () {})` with a proper `r.ok` check that throws on non-200 responses, and a `.catch` handler that logs to `console.warn('[Launcher] Profil laden fehlgeschlagen:', err)`. Non-200 responses (e.g. 404 org-mismatch) now surface in the console instead of leaving stale opener/skript data in `state`.

---

### WR-02: `_showCapSubModal` second save path missing `cap_exceeded` check

**Files modified:** `static/pip-launcher.js`
**Commit:** 4114dbc
**Applied fix:** Added a `data.cap_exceeded` guard at the top of the `.then(data)` handler in the delete+save path (before the existing `data.error` check). If the server returns `cap_exceeded: true` on the second request (race condition), `_showCapSubModal` is re-shown with the fresh item list and the delete button is re-enabled. The call no longer falls through to `startCall(true)` in this case.

---

### WR-03: Inline-edit wiring uses wrong `itemId` for Erlaubnisfrage and Pitch tabs

**Files modified:** `static/pip-launcher.js`
**Commit:** 4c7f413
**Applied fix:** Two changes applied together:
1. `renderStep5` call-site expanded from a single `else` branch to three explicit branches: `erlaubnis` passes `state.selectedErlaubnisId`, `pitch` passes `state.selectedPitchId`, and `opener` (default) passes `state.selectedOpenerId` as the new fifth argument to `_wireInlineEdit`.
2. `_wireInlineEdit` signature updated to `(btnId, previewId, textareaId, type, overrideItemId)`. The `itemId` derivation now uses `overrideItemId` when provided: `type === 'skript' ? state.selectedSkriptId : (overrideItemId !== undefined ? overrideItemId : state.selectedOpenerId)`. This prevents PUT requests being sent to `state.selectedOpenerId` when the user edits text in the Erlaubnisfrage or Pitch tab.
