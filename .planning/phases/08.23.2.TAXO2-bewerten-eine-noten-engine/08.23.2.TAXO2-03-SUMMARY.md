## Task 3 — `_persist_event_ref` echt + benotend (Statemachine + Poison-Pill)

- **Idempotenz (F-01):** `handling_status != 'pending'` -> return (scored/abstained/failed werden
  NICHT neu verarbeitet -> kein Doppel-`abstain_log` bei Consumer-Restart). NICHT mehr
  "handling_score_numeric is not None".
- **Tor-1-Konfidenz (D-03):** `confidence < gate` (`mode_weight_config.confidence_gate` fuer
  `(mode, vorwand_behandlung)` oder Default `0.70`) -> `handling_status='failed'` (Ereignis garbage),
  **KEIN** abstain_log (Tor 1 != Tor 2). `confidence=None` failt NICHT (D-07 grosszuegig).
- **Statemachine (In-Place-UPDATE):** score 1-3 -> `handling_score_numeric=score; status='scored'`;
  `None` (Abstention) -> `score` bleibt NULL, `status='abstained'` + `abstain_log`-INSERT;
  **Exception/Poison-Pill (F-05)** -> `status='failed'`, kein abstain_log, kein Crash.
- **FOLD B P1:** `triggering_text=ev.payload_jsonb.get('triggering_text')` durchgereicht (None-safe).
- **`_find_next_advisor_utterance`** (best-effort): `intent_event.call_id -> calls.id ->
  calls.conversation_log_id -> transcript_segments` (speaker='berater', created_at >= ev.timestamp,
  geordnet). Keine verlaessliche Folge-Aussage -> `None` -> grade_handling abstainiert (D-07).
- **KEIN commit in _persist_event_ref** (TAXO1-Vertrag); **der Consumer committet jetzt pro Item**
  (TAXO1 war No-Op ohne commit — sonst ginge der In-Place-UPDATE verloren). Rollback bei Fehler
  -> Zeile bleibt 'pending' -> H-3 re-queued sie.
- **F-06 Multi-Worker-Vorsorge:** Arbeitsliste = `WHERE handling_status='pending'`; Code-Kommentar
  + dieser SUMMARY-Eintrag: Aktivierung Block M via `... FOR UPDATE SKIP LOCKED`. JETZT 1
  Consumer-Thread, KEIN SKIP LOCKED gebaut (Foundation-Register).
- **Bau-Regel 1 (kein Write aus Fast/Medium Lane):** `grep -rn "handling_score_numeric|handling_status"
  services/einwand_keyword_matcher.py services/claude_service.py == 0` (verifiziert).

## Task 4 — H-3 Bootstrap-Re-Queue (`_requeue_pending`)

- **`def _requeue_pending(limit=500) -> int`**: eigene `get_session()` ->
  `SELECT event_id FROM intent_event WHERE handling_status='pending' ORDER BY timestamp LIMIT n`
  -> je `slow_lane.put({'event_id': eid})`. try-finally close. Log `[SLOW] requeue_pending: N re-enqueued`.
- **Bootstrap (Haupt-Pfad):** `slow_lane_consumer()` ruft `_requeue_pending()` EINMAL vor dem
  `while`-Loop -> pending-Events ueberleben Crash/Deploy/`systemctl restart` statt ewig
  liegenzubleiben (sonst Call haengt "wird ausgewertet…", Plan-04-Merge feuert nie).
- **Safety-Net (gedrosselt):** `_requeue_pending_safety_net` als Tick-Hook — nur alle 6 Ticks (~30s)
  UND nur wenn `slow_lane.qsize()==0` (Queue-Bloat-Schutz). Idempotent harmlos (Skip via Statemachine).
- **`qsize()`** zur SlowLaneQueue ergaenzt (Drossel-Bedingung).

## Deviations from Plan

**1. [Rule 2 — Korrektheit] `abstain_log.event_id`: BigInteger statt UUID (FK-Ziel korrigiert).**
- **Gefunden bei:** Task 2 (Persistenz-Schicht-Verifikation, Punkt 21 — Cross-Layer-Check gegen das reale Schema).
- **Issue:** Der Plan spezifizierte `event_id UUID` -> `ForeignKey('intent_event.id', ...)`. Der reale
  TAXO1-Vertrag (Migration `0016`, `models.py:763`) hat **kein `id`-UUID** — der intent_event-PK ist
  `event_id BIGSERIAL` (BigInteger). Der Producer (`emit_intent_event`) und der event_ref
  (`{'event_id': eid}`) tragen genau diesen BigInt. Eine UUID-FK auf ein nicht existentes `id`
  haette die Migration sofort brechen lassen.
- **Fix:** `event_id = BigInteger -> ForeignKey('intent_event.event_id', ondelete='CASCADE')` (ORM +
  Migration-DDL). Die F-08-Cascade-Kette bleibt durchgehend (intent_event.call_id ist harter FK CASCADE).
- **Dateien:** `database/models.py` (AbstainLog), `alembic/versions/0022_abstain_log.py`. Im Code/Schild dokumentiert.

**2. [Rule 1 — Notwendig] Consumer committet jetzt pro Item.**
- **Issue:** Der TAXO1-Consumer-Loop committet NICHT (No-Op-Aera). Mit dem TAXO2-In-Place-UPDATE
  ginge der Schreib-Vorgang ohne commit verloren.
- **Fix:** `db.commit()` (+ `db.rollback()` im except) in den Per-Item-Zweig des Consumers
  (`_persist_event_ref` selbst committet weiterhin NICHT — TAXO1-Vertrag). Rollback laesst die Zeile
  'pending' -> H-3 re-queued. `flush_to_db` committet weiterhin gesammelt.

**3. [Rule 4 — Konsistenz] Stale-Test entfernt.**
- `tests/test_slow_lane_flush.py::test_persist_event_ref_is_noop_on_intent_event` testete den
  TAXO1-No-Op-Vertrag und ist mit dem TAXO2-Contract-Change obsolet -> entfernt; Docstring angepasst.
  Neue Statemachine-Abdeckung in `tests/test_handling_score_marker.py`.
