## 1. Lokaler Kontext (Punkt 14 — _persist_event_ref-Insert)
`_persist_event_ref(event_ref, db)` ist in TAXO1 ein No-Op (Marker `# SLOW LANE: No-Op in TAXO1`). TAXO2 ersetzt den Body. Kein early-return-Problem (eigene Funktion). Aufgerufen aus `slow_lane_consumer`-Loop (eigene DB-Session) + `flush_to_db` (drain-Session).

## 2. Funktions-Skelett
`_persist_event_ref(event_ref, db)`: hole intent_event per event_id → wenn schon benotet (handling_score_numeric not None) return (idempotent) → Tor-1-Konfidenz prüfen → "nächste Berater-Aussage" finden → grade_handling() → wenn score: UPDATE in-place; wenn Abstention: handling_score_numeric bleibt NULL + abstain_log-INSERT → commit (vom Consumer/flush gesteuert).

## 3. Cross-File-Awareness
`grep -rn "_persist_event_ref\|slow_lane\|handling_score_numeric" services/ routes/`: slow_lane.py (Consumer+flush), emit_intent_event/Plan 04 (Producer put), Engine Plan 02 (liest handling_score_numeric als Eingang). KEIN Fast/Medium-Lane-Treffer der schreibt (Task-0-Gate beweist auch: keiner der liest).

## 4. Edge-Case-Analyse + Race-Condition-Audit (Punkt 14)
1. **Gleichzeitiges Feuern:** Mehrere Consumer? TAXO1 = 1 Consumer-Thread → keine parallele Schreibung auf dieselbe Zeile. Fast/Medium schreiben handling_score_numeric NIE (Bau-Regel 1). → keine Race auf der Spalte.
2. **Verbindungsabbruch mid-Operation:** Consumer-Crash vor commit → Zeile bleibt handling_score_numeric IS NULL → bei Restart neu in Arbeitsliste (re-derivierbar). Kein halb-fertiger Zustand persistiert.
3. **Wiederverbinden mit altem Zustand:** Idempotenz — _persist_event_ref skippt schon-benotete Zeilen (handling_score_numeric not None). Doppel-Verarbeitung schreibt nicht doppelt.
4. **Tab im Hintergrund:** n/a (Server-seitiger Daemon, kein Browser-Timer).
5. **Race-Beweis-Gate (Task 0):** kein Live-Leser von intent_event → das In-Place-Update kann mit keiner Live-Lese-Query kollidieren.
