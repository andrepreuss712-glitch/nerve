## Implementation Decisions — ALLE GELOCKT (André 2026-07-28)

### Grundentscheidung
- **ABREISSEN statt sechstes Pflaster.** Kein weiterer Patch auf den bestehenden Mechanismus.
- Die Wurzelanalyse (Fable, am echten Code + Prod-Logs) ist **fertig**. **Nicht neu diagnostizieren.**

### Die zwei Begriffe
- `call_type` ∈ `{cold_call, meeting}` — Server-Session-State, **ändert sich nie** während eines Anrufs.
- `counterpart` ∈ `{gatekeeper, decision_maker}` — Server-Session-State, **per Toggle**.
- **`'cold_call'` darf beim Gesprächspartner NIE wieder vorkommen.** Keine Wort-Überlappung zwischen
  den beiden Achsen — das ist der ganze Punkt der Phase.

### Der Toggle kehrt sich um (Kern des Umbaus)
- Browser sendet `toggle_counterpart` **OHNE Wert** — ein reiner Befehl, keine Berechnung.
- **SERVER** berechnet das Gegenteil aus **SEINEM** Zustand.
- Server sendet `counterpart_changed {counterpart}`.
- Browser = **reine Anzeige**, hält keinen entscheidungsrelevanten Zustand mehr.
- **Selbstheilend:** ein verlorenes Echo = 1 Sekunde falsche Anzeige, **nie ein toter Knopf**.

### Was ersetzt wird
- `current_mode` (Server) → `counterpart`
- `contact_category` (Server) → `counterpart`
- `state.contactCategory` (Browser) → reine Anzeige-Ableitung
- `state.currentMode` (Browser) → **TOT, kein Leser, ersatzlos löschen**
- gemischtes `_PHASE_NAMES_BY_MODE` → Phasenmodell **explizit nach `(call_type, counterpart)`** wählen

### Was bleibt
- `calls.call_mode` (DB, Achse A) — unangetastet.
- `services/gatekeeper.py` — 17-Zeilen-Stub seit C.R, bleibt Stub. **Nicht anfassen.**
- `/api/gatekeeper/phrases` — reiner Lese-Endpoint für Button-Texte, bleibt.

### Event-Umbenennung — ENTSCHIEDEN durch den Punkt-20-grep (2026-07-28, erledigt)

Lernkarten- oder Slow-Lane-Konsument). Nach Andrés Regel ist die Umbenennung damit **erlaubt**.
