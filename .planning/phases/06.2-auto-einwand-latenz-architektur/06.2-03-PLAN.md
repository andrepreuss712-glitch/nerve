    title: "Socket-Handler keyword_einwand_match"
    description: >
      In _registerSocketEvents() hinzufuegen:

        state.socket.on('keyword_einwand_match', function (d) {
          if (!d) return;
          if (state.micMuted) {
            console.log('[NerveLauncher] keyword match ignoriert — mic muted');
            return;
          }
          var typ = d.typ || (d.profile_einwand && (d.profile_einwand.kurzlabel || d.profile_einwand.kategorie)) || 'Einwand';
          var pe = d.profile_einwand || {};
          var ga = (pe.gegenargument_1 || pe.gegenargument || '').trim();
          if (!ga) return;  // kein Profil-Gegenargument -> kein Render
          console.log('[NerveLauncher] keyword einwand match:', typ);

          // Slot 0 direkt rendern ueber _renderSlotResult (reuse bestehender Einwand-Render)
          var fake = { einwand: true, typ: typ, gegenargument_1: ga };
          // Streaming-State fuer Slot 0 aufraeumen falls da gerade ein Haiku-Stream laeuft
          state.pipSlots[0].streaming = false;
          state.pipSlots[0].text = '';
          state.pipSlots[0].rawText = false;
          var body0 = pipEl('pip-slot-body-0');
          var container0 = pipEl('pip-slot-0');
          if (body0) body0.classList.remove('pip-streaming');
          if (container0) container0.classList.remove('pip-slot-streaming');
          _renderSlotResult(0, fake);

          // EWB-Button hervorheben (aehnlich wie bei manual-click)
          _highlightEwbButton(typ);

          // State-Marker: Slot 0 ist bereits vom Keyword-Match belegt -> analyse_loop's
          // pip_token_done soll dies nicht ueberschreiben, wenn Claude DENSELBEN typ erkennt
          state.slot0LastKeywordTyp = typ;
          state.slot0LastKeywordAt = Date.now();
        });

  - id: task-2
    title: "pip_token_done-Handler Respekt vor Keyword-Match"
    description: >
      Im bestehenden state.socket.on('pip_token_done') Handler: wenn slot === 0 und
      state.slot0LastKeywordTyp existiert UND (Date.now() - state.slot0LastKeywordAt < 3000ms)
      UND der gerade angekommene ergebnis.typ matcht den KeywordTyp (case-insensitive)
      -> _renderSlotResult NICHT aufrufen fuer Slot 0 (Profil-Text bleibt).
      Andernfalls normale Render-Logik.

      Hintergrund: Keyword-Match rendert in ~150ms, Claude in ~1.2s. Ohne diesen
      Schutz wuerde Claude den Profil-Text mit seiner eigenen Formulierung ueberschreiben
      sobald es ankommt.

      Wenn Claude einen ANDEREN typ erkennt (z.B. Keyword sagt 'Zeit', Claude sagt
      'Budget') UND das Profil dafuer ein Gegenargument hat -> _renderSlotResult
      laeuft normal weiter (wird durch frontend-swap in Slot 0 zum neuen Typ).
    autonomous: true
