# Phase 06.2 — Auto-Einwand-Erkennung Latenz-Architektur

## Problem

Nach BUG-10 Teil 1 (Commits `d13851a`, `da1d21b`) ist Dual-Slot + Streaming + State-Reset stabil. Aber die **gefühlte Latenz** bleibt 2-2.5s nach dem ausgesprochenen Einwand-Satz — im Telefonat eine tote Pause, Feature unbenutzbar als USP.

**Diagnose:**
- Hauptverursacher ist **NICHT** Claude-API, sondern **Deepgram-Endpointing**: 500-1000ms Silence-Wait bis Final-Transcript committed
- Detection + Claude startet erst auf Final-Basis → Gesamt = Silence-Wait + Claude-Stream
- Aktueller Haiku-Roundtrip ist bei ~1-1.5s, aber die wahrgenommene Pause entsteht vor dem ersten sichtbaren Token

## Harte Akzeptanz-Kriterien

Nicht verhandelbar — Cold-Call-Realität:
- **Slot 0 (Profil-Match):** sichtbar < 300ms nach Einwand-Erkennung
- **Slot 1 (Claude-Stream, erstes Token):** < 1s nach Einwand-Erkennung
- **Gesamt-Gefühl:** < 500ms bis etwas Sichtbares erscheint

## Architektur (User-Vorgabe)

### 1. Deepgram Interim-Results statt Finals

- Deepgram-Client mit `interim_results=True` starten (falls nicht schon aktiv)
- Interim-Updates alle 150-300ms während User noch spricht → spart Endpointing-Wait
- **Prüfen:** läuft `services/deepgram_service.py` bereits mit `interim_results=True`? Wenn ja, nur den Handler erweitern.

### 2. Lokaler Keyword-Klassifikator

- Wortstamm-Match auf Interim-Transkript (DE-tolerant für Beugungen, Case-insensitive)
- **Startliste** (als Default, Profil kann erweitern):
  - "keine zeit", "zu teuer", "kein interesse", "muss überlegen", "skeptisch", "schon was", "nicht der richtige", "zu kompliziert"
- **Profil-Verknüpfung:** Nur Keywords für die auch `profile.einwaende[]` Antworten existieren → sonst wäre Slot-0-Instant sinnlos
- Match → mappe auf `profile_einwand` → **Slot 0 instant rendern** (client-side wie beim Button-Klick)
- Kein API-Call, rein lokal, <1ms Latenz

### 3. Parallel Claude-Haiku für Slot 1

- Claude bekommt Interim-Transkript als Input (oder Final sobald verfügbar)
- Streaming wie bisher (raw_text, wortweise)
- Startet **gleichzeitig** mit Slot-0-Match — nicht sequentiell

### 4. De-Duplication-Guard

- Interim ändert sich ständig → Match darf nicht 20× feuern pro Einwand-Satz
- Pattern analog zu `_variant_busy_until` aus `analyse_loop`: wenn Einwand-Typ X gerade aktiv (innerhalb Fenster), skip
- **Reset-Bedingung:** neuer Satz erkannt (Deepgram Utterance-End) ODER alter Match >10s her

## Explizite Risiken & Mitigationen

| Risiko | Mitigation |
|---|---|
| **False Positives** bei wechselnden Interims ("keine Ze..." → "keine Zeitschrift") | Match erst ab Wort-Boundary, nicht auf Prefixes. Stabilität: Match muss 2 aufeinanderfolgende Interims überleben ODER Final sein. |
| **Deepgram-Kosten** (Interim = mehr Events) | Abrechnung ist per-MIN-Audio, NICHT per-Event. Interim-Results sind kostenneutral. Prüfen + dokumentieren. |
| **Mismatch Slot 0 vs. Slot 1** (Keyword sagt "Zeit", Claude sagt "Budget") | Wenn Claude später anderen Typ erkennt UND Profile-Match dafür existiert → Slot 0 wird upgraded. Solange nicht: Keyword-Match bleibt (Slot 0 ist immer nutzbar, auch wenn Claude nuancierter ist). |
| **Background-Speech / Nebengespräch** triggert Match | Mute-Status respektieren: wenn `state.micMuted` true ODER Deepgram keine audio_chunks bekommt → Keyword-Match deaktiv. |
| **Multi-Language** — Keyword nur DE | Scope: aktuell DE-only (Markt DACH). Sprache aus Profil-Setting lesen und Keyword-Liste wechselbar machen als Zukunfts-Hook. |

## Scope-Grenzen

**IN Scope:**
- `services/deepgram_service.py` — Interim-Handler
- Neues Modul `services/einwand_keyword_matcher.py` — Keyword-Match-Logik
- `services/claude_service.py` `analyse_loop` — Interim-Trigger statt nur Final-Trigger
- `static/pip-launcher.js` — neuer Socket-Event `keyword_einwand_match` mit Slot-0-Render

**OUT of Scope:**
- Meeting-Modus (nur Cold-Call)
- Button-Klick-Pfad (`manual_ewb`) — NICHT anfassen
- Teleprompter-Position
- Coaching-Loop
- DB-Schema
- Existing postcall-Analytics

## Messbare Verifikation

- Timestamp-Logs: `[KeywordMatch]` + `[AutoVar]` + `[Slot0Render]` mit monotonic-ms
- Delta zwischen Interim-Ankunft und Slot-0-Render muss <300ms sein
- Delta zwischen Interim-Ankunft und erstem `pip_token` muss <1000ms sein
- Dedup: ein Einwand-Satz produziert max. 1 Slot-0-Render + 1 Slot-1-Stream
