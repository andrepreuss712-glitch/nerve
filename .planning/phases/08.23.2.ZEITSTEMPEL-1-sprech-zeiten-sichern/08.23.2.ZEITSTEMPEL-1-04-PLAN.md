## 4. Edge-Case-Analyse (Punkt 14)

1. **`words` ist leer bei `is_final=True`** (laut Deepgram bei reinen Interpunktions-Ergebnissen
   moeglich): `_extract_word_times` gibt `(None, None, None)` zurueck; die Zeile wird trotzdem
   geschrieben, mit NULL in allen drei Spalten. Ehrlich statt geraten. `words[0]` wird nie auf
   einer leeren Liste angefasst. **Benannte Daten-Kante** (Gemini LOW): der Abschnitt faellt damit
   aus jeder Statistik heraus, obwohl gesprochen wurde. Kein Fix — `0` waere schlechter (D-04).
2. **`result` ist kaputt / hat kein `channel`**: `_extract_word_times` faengt `Exception` ab und
   gibt `(None, None, None)`. Muster von `_get_speaker` (`:58-70`). Der Live-Loop-Thread darf hier
   nie sterben.
3. **Ghost-SID** (Session bereits beendet, Callback noch unterwegs): `_append_transcript_entry`
   prueft `sid in ls._session_state` unter dem Riegel — wie der Bestandscode. Kein `KeyError`.
4. **Zwei gleichzeitige Anrufe**: alles liegt in `ls._session_state[sid]`, kein Modul-Global.
   `tests/test_no_live_global_state.py` wuerde ein Global fangen; dieser Plan baut keines. Die
   einzigen neuen Modul-Objekte sind eine **unveraenderliche** Zeichenketten-Konstante und zwei
   Funktionen.
5. **Die Ausnahme im `else`-Zweig** (Weg C): wirft `_append_transcript_entry` selbst, landet der
   Fluss im `except Exception`-Zweig. `_zs_gespeichert` ist dann noch `False`, also wird dort eine
   Platzhalter-Zeile geschrieben — **nie** die rohe. Genau dafuer existiert das Flag.

### Race-Condition-Audit — alle vier Fragen (Pflicht, keine "betrifft uns nicht")

1. **Gleichzeitiges Feuern:** Pro Deepgram-Verbindung liefert das SDK die Transcript-Callbacks
   **seriell in einem Thread**; zwei Ergebnisse derselben `sid` ueberlappen nicht. Verschiedene
   `sid` laufen in verschiedenen Threads, teilen aber nichts ausser `_session_state_lock`.
   ⚠ **Praezisierung nach dem Review (Sicht 2 MEDIUM-5): das beantwortet NEBENLAEUFIGKEIT, nicht
   INHALTS-REIHENFOLGE — das sind zwei verschiedene Fragen.** Nichts schuetzt das gespeicherte
   Paar davor, dass ein `is_final` mit `start` **unterhalb** des vorigen `end` ankommt (mit
   `endpointing=900` und `smart_format` aus dem Code allein **nicht entscheidbar** —
   **UNVERIFIED**). Folge: negative Pausen sind moeglich, und die Summe `end_ms - start_ms` je
   Sprecher kann die Wall-Clock-Dauer uebersteigen.
   **Behandlung in dieser Phase:** benennen, nicht klemmen. Der Hinweis steht im Spalten-Schild
   von `start_ms` (Plan 03); die **Klemm-Regel gehoert nach METRIK-1**. Plan 06 Task 2 hat dafuer
   eine eigene Abnahme-Zeile an echten Daten — der einzige Weg, es ueberhaupt zu erfahren.
2. **Verbindungsabbruch mitten in der Operation:** `_make_on_close`/`_make_on_error`
   (`:339-359`) machen ausschliesslich `print` + `sio.emit`. Es bleibt kein halbfertiger Zustand:
   das Eintrags-Dict wird in `_append_transcript_entry` **vollstaendig gebaut und in einem Zug**
   angehaengt. Bricht die Verbindung ab, fehlen schlicht die folgenden Abschnitte — die bereits
   geschriebenen bleiben gueltig.
3. **Reconnect mit altem Zustand:** ⚠ **umbenannt nach dem Review** — der frueher hier als
   „Reconnect" etikettierte Pfad ist in Wahrheit der **Start-Handler-Pfad**
   (`handle_start_live_session`), und genau dieses falsche Etikett hat den urspruenglichen
   Fehlbefund erzeugt. Er ruft `pop_session_state` + `init_session_state`
   (`services/deepgram_service.py:764-766`), loescht damit `conversation_log` und `call_id` und
   legt anschliessend immer einen **neuen** Anruf an. **Fuer diesen Plan bedeutet das: nichts.**
   Es gibt keinen Zustand mehr, den diese Phase ueber `pop`/`init` tragen muesste — der Versatz
   ist gestrichen. Dass ein Verbindungsabriss dabei das ganze bisherige Transkript verliert, ist
   ein **eigener** Befund (Fragen-Kanal, eigene Phase).
4. **Tab im Hintergrund:** Der Browser drosselt Timer, das Mikrofon laeuft weiter; die
   SDK-KeepAlives halten die Verbindung offen. Kommt in einem gedrosselten Tab **weniger oder
   kein** Audio an, steht die Deepgram-Uhr still, die Wall-Clock nicht. **Diese Luecke ist nach
   der Streichung des Markers weiterhin erkennbar** — an der Divergenz der zwei Uhren
   (`ts_ms` laeuft, `start_ms/end_ms` nicht). Ein Marker haette diesen Fall ohnehin **nicht**
   erfasst, weil `handle_audio_chunk` dann gar nicht feuert. **Benannte Restluecke**, gehoert ins
   SUMMARY (Plan 06).

```python
def _extract_word_times(result):
    """Phase 08.23.2.ZEITSTEMPEL-1 (D-07/D-08) — Deepgram-Wortzeiten -> (start_ms, end_ms, word_count).

    word.start/word.end sind Float-SEKUNDEN ab Oeffnung der Deepgram-Verbindung
    (developers.deepgram.com/docs/diarization) — eine ANDERE Achse als ts_ms (Wall-Clock,
    Sekunden-Aufloesung). Nie gegeneinander rechnen.

    KEIN Versatz-Parameter: der frueher geplante Reconnect-Versatz (D-05) ist nach dem
    Cross-AI-Review vom 2026-08-10 gestrichen, zusammen mit dem Naht-Marker (D-06a) — sie
    waren ein Paar. Ohne Versatz wird naechster.start_ms minus voriger.end_ms nach einer
    neuen Verbindung NEGATIV; eine negative Pause ist physikalisch unmoeglich und damit ein
    selbsterklaerendes "unbekannt", das keine Spalte kostet und keine Dauer vernichtet.

    Die Wortanzahl kommt aus den ROHEN Wortobjekten, also VOR der Anonymisierung: der
    Platzhalter [PERSON_A] ersetzt zwei gesprochene Woerter durch eines und wuerde das
    Sprechtempo systematisch nach unten verzerren.

    Gibt (None, None, None) zurueck, wenn keine Wortobjekte vorliegen oder das Ergebnis
    unerwartet geformt ist. NIEMALS 0 als Ersatz — 0 hiesse 'hat nichts gesagt', None heisst
    'unbekannt' (D-04). Der Live-Loop-Thread darf hier nie sterben (Muster _get_speaker).

    BEKANNTE KANTE: ein Endergebnis mit Text, aber ohne Wortobjekte (nur Satzzeichen) liefert
    dreimal None, obwohl gesprochen wurde. Bewusst nicht gefixt; steht im Schild von
    word_count und in den SUMMARY-Restluecken.
    """
    try:
        words = result.channel.alternatives[0].words
        if not words:
            return (None, None, None)
        start_ms = int(round(float(words[0].start) * 1000))
        end_ms = int(round(float(words[-1].end) * 1000))
        return (start_ms, end_ms, len(words))
    except Exception:
        return (None, None, None)
```
