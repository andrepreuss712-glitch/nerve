<decisions>
## Implementation Decisions

### D-01: Wizard-Fix-Richtung — Backend auf JSON

- **D-01:** Backend auf `request.get_json(force=True)` umstellen — konsistent mit allen anderen API-Routen ab `routes/profiles.py:343`. Frontend sendet weiterhin JSON via `fetch()`.
- **D-02:** CSRF-Pattern aus `profile_editor.html` kopieren: `X-CSRFToken`-Header via `_getCsrfToken()` (liest `meta[name=csrf-token]` aus `base.html`). Das Wizard-fetch bekommt denselben Header.

### D-03: Feldnamen-Mapping — Backend-Schema ist die Wahrheit

- **D-03:** Beide Seiten angleichen, Backend-Schema (`services/profile_schema.py` ProfileSchema v3/v4) ist kanonische Quelle. Frontend wird angepasst um Backend-Felder zu erfassen.
- **D-04:** Pro Backend-Feld entscheiden (Plan-Phase + Cross-AI): **Pflicht im Wizard** (3 Schritte, unter 5 Minuten) ODER **optional → "weitere Felder im Profil-Editor ausfüllen"-Hinweis**.
- **D-05:** Frontend-Felder die das Backend nicht kennt (`preismodell`, `phasen` als Wizard-Felder) klären: behalten wenn UX-Mehrwert, oder entfernen. Cross-AI prüft ob Wizard-UX nach Umbau noch unter 5 Minuten Onboarding-Friction bleibt.
- **D-06:** Cross-AI-Review im Plan-Phase ist Pflicht für das Feldmapping (vollständigkeit + UX-Friction-Check).

### D-07: Wave-1-Methodik — Mischvariante

- **D-07:** Wave 1 läuft in zwei Schritten ab:
  1. **Claude autonom:** Scannt `templates/*.html` + `routes/*.py`, identifiziert technische Findings (tote Buttons, fehlende onclick/href-Handler, broken Links zwischen Templates und Routes, deprecated Code-Pfade). Output: erste Version `03 Planung/UI-Audit-Ergebnis-2026-05-03.md`.
  2. **Gemeinsamer Durchgang André + Claude:** Klickt Seite für Seite durch Live-App. Ergänzt UX-Perspektive — Discoverability-Lücken, verwirrende Labels, Workflow-Brüche, Erwartungs-Lücken die Code-Analyse nicht findet.
- **D-08:** Beide Schritte zusammen = Wave 1 vollständig. Erst danach Wave-1→Wave-2-Checkpoint.
- **D-09:** Bericht-Format pro Finding: Was / Wo (Datei:Zeile) / Warum problematisch / Vorschlag-Fix / Quelle (Claude-autonom oder André-UX). Sortierung: kritisch / mittel / kosmetisch.

### D-10: PiP-Bug — Fixen (nicht defer)

- **D-10:** PiP-Schließ-Bug wird gefixt — kein Aufschub. Architekturentscheidung (BroadcastChannel + localStorage, Service Worker, oder anderer Ansatz) wird im Plan-Phase mit Cross-AI (Gemini) bestimmt.
- **D-11:** Stack-Constraint gilt: Flask + Vanilla JS bleibt. Kein Framework-Wechsel für PiP-Fix.
- **D-12:** André hat keine Vorab-Präferenz für den Architekturansatz — Cross-AI entscheidet auf Basis von `pip-launcher.js` Setup und documentPictureInPicture-Constraint.

### Claude's Discretion

- Nav-Label-Fix (`base.html:56` — "Profil" → "Profile"): trivial, Claude entscheidet Implementierung ohne Rückfrage.
- Dashboard Session-Row fix: Pattern aus SPEC.md klar (`onclick="location.href='/session/' + s.id"`), Claude führt direkt aus.
- Wave-1 technischer Scan: Reihenfolge der 11 Seiten und Scan-Tiefe liegt bei Claude.
