**Architektur-Entscheidung (dokumentiert per D-10, D-12):**

`window.documentPictureInPicture.requestWindow()` benoetigt eine User-Gesture (Chrome-Spec). Es gibt keinen programmatischen Weg um PiP ohne Klick zu oeffnen. "PiP ueberlebt Navigation nahtlos" ist mit dieser API unmoeglich.

Implementierter Fix: localStorage Re-Launch-Flow:
1. Bei Navigation weg von der Seite (pagehide): Flag setzen wenn Call aktiv war
2. Auf jeder Seite (via base.html): Flag pruefen, Re-Launch-Banner zeigen
3. User klickt Banner (= User-Gesture): PiP wird neu geoeffnet

**pip-launcher.js — pagehide-Handler erweitern:**

Finde den pagehide-Handler (Zeile ca. 1579). Innerhalb des Handlers, NACH `el.style.display = 'none'` und VOR dem `if (state.pipWindow === pipWindow)` Block, ergaenzen:

```javascript
// PiP Re-Launch Flag: setzen wenn Call aktiv war (fuer Banner auf Zielseite)
if (state.micStarted) {
  try { localStorage.setItem('nerve_pip_was_active', '1'); } catch(e) {}
}
```

**pip-launcher.js — Flag beim normalen Call-Ende loeschen:**

Suche nach der endCall-Funktion oder _cleanup (grep: `function endCall\|function _cleanup\|endCall\|_cleanup`). Finde den Aufruf wo `state.micStarted = false` gesetzt wird oder wo der Call offiziell beendet wird. Dort ergaenzen:

```javascript
try { localStorage.removeItem('nerve_pip_was_active'); } catch(e) {}
```

Falls endCall mehrere Stellen hat: einmal im Haupt-Cleanup wo der State zurueckgesetzt wird.

**base.html — Re-Launch-Banner:**

Finde das `</body>`-Tag in base.html. Direkt DAVOR einfuegen:

```html
<!-- PiP Re-Launch Banner — wird angezeigt wenn PiP waehrend Navigation aktiv war -->
```
