# Phase 08.19.5.2: Code Review Report

**Reviewed:** 2026-05-03
**Depth:** standard
**Files Reviewed:** 7
**Status:** issues_found

## Summary

This phase removes the onboarding wizard gate (auth.py, onboarding.py), stubs out the wizard/profiles routes as 302 redirects, and adds a PiP re-launch banner mechanism via localStorage. The removals are clean and well-commented. No critical security issues were found. Three warnings concern an XSS risk from unescaped server data in dashboard.html, a dead `onboarding_done` write in `_login_user()`, and a localStorage flag that is never cleared on normal session end (only on mic stop). Three info items cover unused imports in onboarding.py, the `BRANCHE_TEMPLATES` constant being dead code, and a minor JS logic inconsistency in the re-launch banner.

## Warnings

### WR-01: XSS — `r.icon` rendered unescaped in `renderRecommendations`

**File:** `templates/dashboard.html:750`
**Issue:** In `renderRecommendations()`, `r.icon` is injected directly into innerHTML without sanitisation while `r.title` and `r.subtitle` correctly use `esc()`. The `icon` field is currently emoji literals set by server-side Python (performance.py lines 399-434), so this is not exploitable today. However, if the recommendations API ever reflects user-controlled data or is extended, this is a stored/reflected XSS vector. The inconsistency is also a latent bug — any future `icon` value containing `<` or `>` will break the card layout without raising an error.

```javascript
// Current (line 750):
html += '<div class="db2-reco-icon">' + r.icon + '</div>';

// Fix — apply esc() consistently:
html += '<div class="db2-reco-icon">' + esc(r.icon) + '</div>';
```

### WR-02: PiP re-launch localStorage flag not cleared on normal session end / logout

**File:** `static/pip-launcher.js:1585` and `templates/base.html:804`
**Issue:** `nerve_pip_was_active` is set in the `pagehide` handler of the PiP window and cleared only in `_stopMic()`. If a user closes the PiP window via the browser's own close button (X on the pip-window chrome) without the microphone being actively running at that moment — e.g., if the mic was already stopped but the PiP window was still open for reviewing results — then `_stopMic()` is not called, the flag is never cleared, and the re-launch banner will appear on every subsequent page until the user manually dismisses it or the next `_stopMic()` runs.

Additionally, the flag is not cleared on logout (auth.py line 306). After logout the banner will show on the login/landing page if `base.html` renders it there, which is confusing and potentially alarming to non-technical users.

**Fix — clear the flag in `_cleanup()` and/or on the logout `onclick`:**

```javascript
// In pip-launcher.js _cleanup() function, add:
try { localStorage.removeItem('nerve_pip_was_active'); } catch(e) {}
```

```html
<!-- In base.html logout link (line 143), extend existing onclick: -->
<a href="/logout" class="popup-item popup-item-logout"
   onclick="try{sessionStorage.removeItem('headsetConfirmed')}catch(e){}; try{localStorage.removeItem('nerve_pip_was_active')}catch(e){}">Abmelden</a>
```

### WR-03: `onboarding_done` written to session but gate is removed — stale session key

**File:** `routes/auth.py:109,132`
**Issue:** `_login_user()` still reads `user.onboarding_done` and stores it as `'onboarding_done'` in the returned `user_info` dict (line 132). The session key is NOT written to Flask session (it was never written, only returned in the dict), but the `api_register` call at line 236 ignores the returned dict entirely — which is fine. However `user_onboarding_done` is read on line 109 and the field remains in the returned dict which callers may inspect. More importantly: `_create_org_and_user()` at line 182 still sets `onboarding_done=False` when creating new users, which now has zero effect since the gate in `login_required` was removed. This is not broken today, but it sets up a trap: any future developer who looks at the DB column or `user_info['onboarding_done']` will act on it without knowing the gate is gone.

**Fix — either:**

1. Remove `onboarding_done` from `_login_user()` return dict and stop reading it (preferred, keeps it as a pure DB field for future Onboarding 2.0), or
2. Add a comment in `_login_user()` that this key is intentionally returned for future use but the gate is currently inactive.

```python
# Option 2 — add clarifying comment at line 109:
# NOTE (08.19.5.2): onboarding gate removed. This field is preserved for
# future Onboarding 2.0 — not currently checked by login_required.
user_onboarding_done = bool(user.onboarding_done) if hasattr(user, 'onboarding_done') else True
```

### IN-03: Re-launch banner shown on all pages including public/logged-out pages

**File:** `templates/base.html:803-816`
**Issue:** The PiP re-launch banner script runs unconditionally on every page render, including pages where `g.user` is None (logged-out users, landing page). A logged-out user who somehow has `nerve_pip_was_active=1` in localStorage (e.g. shared browser, or the flag leaked from a previous session) will see the banner and clicking it will call `NerveLauncher.open()` which is a no-op without the script loaded, but the banner still renders visibly on all pages.

**Fix — guard the banner check with a user-presence condition in the Jinja template:**

```html
<!-- Replace the unconditional script block (lines 807-816) with: -->
{% if g.get('user') %}
<script>
(function() {
  try {
    if (localStorage.getItem('nerve_pip_was_active') === '1') {
      var b = document.getElementById('pip-relaunch-banner');
      if (b) b.style.display = 'block';
    }
  } catch(e) {}
})();
</script>
{% endif %}
```
