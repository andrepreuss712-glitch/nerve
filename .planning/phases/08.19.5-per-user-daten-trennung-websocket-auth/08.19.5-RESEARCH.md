## User Constraints (from CONTEXT.md)

### Locked Decisions

**D-01: `state` dict Migration — Nested in _session_state[sid]**
Der globale `state` dict (30+ Felder) wird als Sub-Key `_session_state[sid]['state']` gespeichert. Caller-Diff minimieren ist Priorität. Overlap-Duplikate (`kaufbereitschaft`, `active_profile_id`) werden konsolidiert — `state[...]` ist künftig der einzige Write-Pfad, top-level Keys werden entfernt oder auf Read-Through-Aliases reduziert.

**D-02: Route-Konflikt — app_routes.py → /api/session-rating**
Sternebewertung in `routes/app_routes.py` (~Zeile 898) wird umbenannt zu `POST /api/session-rating`. `routes/feedback.py` bleibt auf `POST /api/feedback`. FE-Caller in `static/app.js` (nach `/api/feedback` im POST-Context suchen) wird auf `/api/session-rating` aktualisiert.

**D-03: WebSocket Connect-Handler — deepgram_service.py::register_audio_handlers()**
Neuer `@sio.on('connect')` Handler in `register_audio_handlers()` vor `@sio.on('start_live_session')`. `flask.session.get('user_id')` prüfen, bei Fehlen `return False`. Auth-Mechanismus: Cookie-basierte Flask-Session.

**D-04: session_meta + Tracking-Logs — _session_state[sid] Sub-Keys**
`session_meta`, `phasen_log`, `gegenargument_log`, `hilfe_log`, `quick_action_log`, `painpoints` als Sub-Keys in `_session_state[sid]`.

### Claude's Discretion

- `analyse_trigger` / `coaching_trigger` (threading.Event) — können global bleiben
- `analysiert_bisher` — wird per-SID als `_session_state[sid]['analysiert_bisher'] = []`
- `is_paused` — REQ-01: `_session_state[sid]['state']['is_paused']` konsistent mit D-01
- Overlap-Bereinigung `kaufbereitschaft`, `active_profile_id`, `berater_words`, `kunde_words`, `conversation_log`

### Deferred Ideas (OUT OF SCOPE)

- Per-SID `threading.Event` für analyse_trigger/coaching_trigger
- Flat-Merge `state` → `_session_state[sid]`

## Summary

Phase 08.19.5 migriert alle verbleibenden Modul-Globals in `services/live_session.py` auf per-SID-State, ergänzt WebSocket-Auth, löst einen Route-Konflikt auf, entfernt tote Tabellen und schließt drei Test-Lücken.

Die Codebase-Analyse zeigt, dass die Ausgangslage komplexer ist als SPEC und CONTEXT beschreiben: `ls.is_paused` wird an **4 Stellen** gelesen (nicht 2), `ls.analysiert_bisher` wird noch global in claude_service.py gelesen (Coaching-Loop-Zweig), und `ft_objection_events` ist **nicht vollständig tot** — `routes/admin_ewb.py` liest die Tabelle via Raw-SQL in einer A/B-Auswertungsabfrage. Diese Findings erfordern Anpassungen am Plan gegenüber SPEC.

Die per-SID-Infrastruktur aus Phase 08.19.4 ist vollständig vorhanden: `_session_state`, `_session_state_lock`, `_per_sid_profile`, `_per_sid_transcript`, `_per_sid_coaching_buffer` existieren und funktionieren. `init_session_state()` und `pop_session_state()` sind die Erweiterungspunkte für alle neuen Sub-Keys. Bestehende Tests laufen mit 2 bekannten Failures (Test-Design-Bug, nicht Code-Bug).

**Primary recommendation:** Plan in 3 Wellen: (1) Globals-Migration + is_paused-Fix, (2) Route-Konflikt + Tabellen, (3) Tests + Error-Propagation. Nicht alles in einem Giant-Commit.

### Pattern: is_paused per-SID in Loop-Kontext (claude_service.py)

In `analyse_loop()` und `coaching_loop()` iteriert der Code bereits pro SID (D-03 Phase 08.19.4). Der globale `is_paused`-Check ist ein vorgelagerter Early-Exit für "alle User pausiert". Nach Migration wird dieser Check entfernt — stattdessen prüft jeder SID-Block seinen eigenen `is_paused`:

```python
# Alt:
with ls.pause_lock:
    if ls.is_paused:
        continue  # überspringt die ganze Iteration

# Neu (kein globaler Pause-Check mehr):
for sid in active_sids:
    with ls._session_state_lock:
        sid_state = ls._session_state.get(sid)
    if sid_state is None:
        continue
    if sid_state.get('state', {}).get('is_paused', False):
        continue  # nur diesen SID pausiert
    # ... process ...
```

### Pattern: WebSocket connect-Handler Auth

```python
# In register_audio_handlers(sio), vor @sio.on('start_live_session'):
@sio.on('connect')
def handle_connect(sid=None, environ=None, auth=None):
    from flask import request, session as flask_session
    _sid = request.sid if sid is None else sid
    user_id = flask_session.get('user_id')
    if not user_id:
        print(f"[WS-Auth] Unauthorized connect rejected: sid={_sid}")
        return False  # Flask-SocketIO: disconnect client
    with ls._session_state_lock:
        ls._session_state.setdefault(_sid, {})['_user_id'] = user_id
    print(f"[WS-Auth] Authenticated connect: sid={_sid} user_id={user_id}")
```

**Flask-SocketIO 5.6.1 Verhalten:** `return False` im `@sio.on('connect')` Handler wird von Flask-SocketIO als Connection Rejection behandelt. Der Client erhält eine Disconnect-Nachricht. Kein HTTP 401 — das ist SocketIO-Protokoll-Ebene. [VERIFIED: Flask-SocketIO 5.6.1 installiert, async_mode='threading']

**Wichtig:** Der Handler muss `from flask import request` intern importieren (gleiche Pattern wie alle anderen Handler in der Datei — Zeile 316, 468, etc.). Nicht auf Modul-Level importieren.

### Pattern: next_line_id() per-SID

```python
def next_line_id(sid: str) -> str:
    with _session_state_lock:
        if sid not in _session_state:
            return '0'  # Ghost-SID guard
        cnt = _session_state[sid].get('_line_id_counter', 0) + 1

```

Der globale `_line_id_counter` und `_line_id_lock` können nach Migration entfernt werden.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| WebSocket Auth | Custom Token-System | Flask Session Cookie | Bereits verfügbar, WS-Handshake leitet Cookie weiter |
| Thread-Safety | Eigene Atomic-Ops | `_session_state_lock` (existing) | Bereits im Projekt, bewährtes Pattern |
| DB Table Drop | Raw SQL ohne Safety | `IF EXISTS` in Migration Block (app.py) | Idempotenz für mehrfache Migration-Runs |
| Test-DB | Echter DB-Connect | `conftest.py` `db_session` fixture | In-Memory SQLite, bereits vorhanden |

## Common Pitfalls

### Pitfall 1: Ghost-SID-Guard in jedem set_profile_for_sid-Caller

**Was schiefgeht:** `set_profile_for_sid()` prüft `if sid not in _session_state` — dropped silently wenn SID nicht initialisiert. Der bestehende Test `test_two_sids_independent_profiles` FAILS weil er `set_profile_for_sid()` ohne vorheriges `init_session_state()` aufruft.

**Warum es passiert:** Ghost-SID-Guard wurde Phase 08.19.4 eingebaut. Tests wurden nicht angepasst.

**Wie vermeiden:** In jedem neuen Test und in jedem Code-Pfad: `init_session_state()` **vor** `set_profile_for_sid()` aufrufen. Für Tests die keinen DB-Zugriff brauchen: `ls.init_session_state(sid, user_id=1, org_id=1)` reicht.

### Pitfall 2: state_lock vs _session_state_lock — zwei verschiedene Locks

**Was schiefgeht:** Code-Autoren verwenden `with ls.state_lock: ls.state[...]` (global) statt `with ls._session_state_lock: ls._session_state[sid]['state'][...]` (per-SID). Beide Locks existieren nach Migration noch — der alte Lock guardiert nichts Sinnvolles mehr.

**Wie vermeiden:** Plan muss für jeden Caller von `ls.state_lock` / `ls.state[...]` den Migrations-Schritt explizit nennen. Suche nach allen Stellen:
- `grep -rn "ls\.state_lock\|ls\.state\[" services/ routes/` → 50+ Treffer

### Pitfall 3: analysiert_bisher — partial per-SID, partial global

**Was schiefgeht:** Der Haupt-analyse_loop schreibt per-SID (korrekt), aber Phase-Classifier-Block und Coaching-Loop lesen noch den globalen `ls.analysiert_bisher`. Nach Migration des Globals auf leere Liste werden diese Blöcke mit leerem Kontext arbeiten.

**Wie vermeiden:** Alle 5 globalen Read-Stellen (`claude_service.py:1027, 1063, 1097`, `deepgram_service.py:154, 587`) auf per-SID umstellen. In Coaching-Loop und Phase-Classifier: `sid_state.get('analysiert_bisher', [])` verwenden (analog zu wie analyse_loop es bereits macht).

### Pitfall 4: load_learning_cards() schreibt noch global

`services/live_session.py:381-386` — `load_learning_cards()` schreibt in `ls.state['active_learning_cards']`. Diese Funktion wird in deepgram_service.py aufgerufen. Muss als Teil der `state`-Migration auf `_session_state[sid]['state']['active_learning_cards']` umgestellt werden.

[VERIFIED: grep -n "load_learning_cards" services/live_session.py]

### Pitfall 5: reset_session() und pop_session_state() — Duplikat-Aufräumen

`reset_session()` (Zeile 495-595) räumt alle Globals auf. Nach Migration macht diese Funktion sinnlos — `pop_session_state(sid)` ist der korrekte Cleanup-Pfad. Aber: `reset_session()` wird möglicherweise noch aus app_routes.py aufgerufen.

**Recherche:** `grep -rn "reset_session" routes/ services/` — Planner muss prüfen ob `reset_session()` nach Migration noch gebraucht wird oder durch `pop_session_state(sid)` ersetzt werden kann.

### Pitfall 6: _flush_segment() verwendet noch global laengster_monolog_sek, speech_lock

`_flush_segment()` (Zeile 429-482) verwendet `global berater_words, kunde_words, laengster_monolog_sek, _current_monolog_start` mit `speech_lock`. Diese Sprachstatistik-Tracking-Globals müssen per-SID gemacht werden. Die `sid` ist im `pending`-Dict verfügbar (`pending.get('sid')`).
