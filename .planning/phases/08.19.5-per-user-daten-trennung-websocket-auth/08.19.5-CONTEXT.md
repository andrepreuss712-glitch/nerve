<decisions>
## Implementation Decisions

### D-01: `state` dict Migration — Nested in _session_state[sid]

**Entscheidung:** Der globale `state` dict (30+ Felder) wird als Sub-Key `_session_state[sid]['state']` gespeichert — nicht flat-gemerged, nicht als eigenes `_per_sid_state` Dict.

**Begründung:** Minimaler Caller-Diff (alle `state[...]`-Zugriffe werden zu `_session_state[sid]['state'][...]`), kein neues Lock-Objekt. Overlap-Duplikate (`kaufbereitschaft`, `active_profile_id` die bereits als top-level Keys in `_session_state[sid]` existieren) werden beim Lesen konsolidiert — `state[...]` ist künftig der einzige Write-Pfad für diese Felder, top-level Keys werden entfernt oder auf Read-Through-Aliases reduziert.

**init_session_state()-Ergänzung:**
```python
_session_state[sid]['state'] = {
    'version': 0,
    'aktiv': False,
    'ergebnis': None,
    # ... alle bisherigen state-Felder ...
}
```

**Caller-Pattern:**
```python
# Alt (global):
with state_lock:
    state['kaufbereitschaft'] = wert

# Neu (per-SID):
with _session_state_lock:
    _session_state[sid]['state']['kaufbereitschaft'] = wert
```

Lock: `_session_state_lock` (kein separater state_lock mehr nach Migration).

### D-02: Route-Konflikt — app_routes.py → /api/session-rating

**Entscheidung:** Die Sternebewertung in `routes/app_routes.py` (stars + comment nach Call) wird umbenannt zu `POST /api/session-rating`. `routes/feedback.py` bleibt auf `POST /api/feedback`.

**Begründung:** Die Sternebewertung ist Post-Call UX, kein generisches Feedback-Konzept — `/api/session-rating` ist semantisch korrekt. Der bestehende FE-Caller in `static/app.js` (suchen nach `/api/feedback` im POST-Context) wird auf `/api/session-rating` aktualisiert.

### D-03: WebSocket Connect-Handler — deepgram_service.py::register_audio_handlers()

**Entscheidung:** Neuer `@sio.on('connect')` Handler wird in `services/deepgram_service.py::register_audio_handlers()` angelegt — an der gleichen Stelle wie alle anderen Socket-Handler (start_live_session, stop_live_session, audio_chunk, disconnect etc.).

**Implementierung:**
```python
@sio.on('connect')
def handle_connect(sid=None, environ=None, auth=None):
    from flask import session as flask_session
    user_id = flask_session.get('user_id')
    if not user_id:
        return False  # SocketIO disconnect — unauthorized
    # SID → user_id registrieren für spätere Ghost-SID-Guards
    with ls._session_state_lock:
        ls._session_state.setdefault(sid, {})['_user_id'] = user_id
```

**Auth-Mechanismus:** Flask-Session (Cookie-basiert) — `flask.session.get('user_id')`. Kein neues Token-System. Flask-SocketIO leitet den Cookie im WS-Handshake weiter.

### D-04: session_meta + Tracking-Logs — _session_state[sid] Sub-Keys

**Entscheidung:** `session_meta`, `phasen_log`, `gegenargument_log`, `hilfe_log`, `quick_action_log`, `painpoints` werden als Sub-Keys in `_session_state[sid]` initialisiert.

**init_session_state()-Ergänzung:**
```python
_session_state[sid]['session_meta'] = {
    'profil_name': '', 'profil_branche': '', ...  # alle bisherigen Felder
}
_session_state[sid]['phasen_log'] = []
_session_state[sid]['gegenargument_log'] = []
_session_state[sid]['hilfe_log'] = []
_session_state[sid]['quick_action_log'] = []
_session_state[sid]['painpoints'] = []
```

Lock: `_session_state_lock` (gleicher Lock wie für alle _session_state-Zugriffe).

**Caller-Pattern:** Alle aktuellen `phasen_log.append(...)` / `session_meta['key'] = val` Zugriffe werden zu `_session_state[sid]['phasen_log'].append(...)`.

### Claude's Discretion

- `analyse_trigger` / `coaching_trigger` (threading.Event) — Diese sind Signals, keine Daten. Sie können global bleiben, wenn der analyse_loop/coaching_loop nach Migration über `_session_state.keys()` iteriert und pro SID separat auf den sub-keyed state zugreift. Plan-Agent entscheidet ob per-SID Events nötig sind (Latency-Implikation).
- `analysiert_bisher` — Liste bereits analysierter Segmente. Wird per-SID als `_session_state[sid]['analysiert_bisher'] = []`.
- `is_paused` — REQ-01 klar: `_session_state[sid]['state']['is_paused']` oder als separater Key — Plan-Agent entscheidet konsistent mit D-01.
- Overlap-Bereinigung: `kaufbereitschaft`, `active_profile_id`, `berater_words`, `kunde_words`, `conversation_log` existieren bereits als top-level Keys in `_session_state[sid]`. Nach state-Migration werden diese zu Aliassen auf `state[...]` oder entfernt — Plan-Agent entscheidet.

<specifics>
## Specific Ideas

- **Route-Naming:** `/api/session-rating` ist explizit gewählt (nicht `/api/feedback/event` wie SPEC-Vorschlag) — semantisch klarer für Post-Call-Kontext
- **state-Nesting:** Caller-Diff minimieren ist Priorität — kein Flat-Merge trotz architektonischer Eleganz
- **Connect-Auth:** `return False` ist das Flask-SocketIO Standard-Muster zum Ablehnen einer Verbindung — kein HTTP 401

</specifics>
