## Phase-Ziel

**Was wird geliefert:** Alle verbleibenden Modul-Globalen in `services/live_session.py` werden auf per-SID-Dicts migriert. WebSocket-Verbindungen erhalten eine Auth-Prüfung im connect-Handler. Zwei Daten-Architektur-Probleme (Route-Konflikt `/api/feedback`, tote Tabellen) werden beseitigt. Drei Test-Lücken aus SP6 werden geschlossen.

**Warum jetzt:** DSGVO-Pflicht vor Early-Access-Launch. `is_paused = False` als Modul-Global pausiert alle User gleichzeitig. 25+ weitere Globals teilen State über User-Grenzen. WebSocket-Auth-Lücke erlaubt theoretisches Mithören mit erratener SID.

## Anforderungen

### REQ-01: is_paused per-SID
- **Aktuell:** `is_paused = False` in `live_session.py` Zeile 40 — ein einziger Boolean für alle User. `deepgram_service.py` Zeilen 45 + 489 lesen `ls.is_paused` global.
- **Ziel:** `is_paused` wird als Key in `_session_state[sid]` gespeichert. `deepgram_service.py` liest `get_session_state(sid, 'is_paused', False)`. Das globale `is_paused = False` wird entfernt.
- **Akzeptanzkriterium:** ☐ Unit-Test: zwei gleichzeitige SIDs, SID-A pausiert → SID-B `is_paused` bleibt False. Kein globales `is_paused` mehr in live_session.py (grep-Verifikation).

### REQ-02: Alle verbleibenden Modul-Globalen per-SID
- **Aktuell:** `state`, `transcript_buffer`, `conversation_log`, `coaching_buffer`, `session_meta` und ~10 weitere Speaker/BOF/Merge-Tracking-Variablen sind Modul-Level.
- **Ziel:** Alle diese Variablen leben als Keys in `_session_state[sid]` oder als eigene `_per_sid_*`-Dicts (gleiche Pattern wie `_per_sid_transcript`). `init_session_state()` initialisiert alle nötigen Keys beim Session-Start. `pop_session_state()` räumt sie beim Session-Ende auf.
- **Akzeptanzkriterium:** ☐ `grep -n "^[a-z_]* = " services/live_session.py` liefert maximal Konstanten und Lock-Objekte — keine mutable State-Variablen mehr auf Modul-Level. ☐ Zwei-SID-Isolation-Test: transcript von SID-A erscheint nicht in SID-B's `get_transcript(sid_b)`.

### REQ-03: WebSocket connect-Handler Auth-Prüfung
- **Aktuell:** WebSocket-Verbindungen werden ohne User-Auth-Prüfung akzeptiert. Wer die Socket-ID kennt oder errät kann Events empfangen.
- **Ziel:** Im `on('connect')` Handler (oder equivalent in Flask-SocketIO) wird `session.get('user_id')` geprüft. Ist kein `user_id` in der Session → `return False` (Socket-IO disconnect). Authenticated Users: `request.sid` wird mit `user_id` in `_session_state` verknüpft.
- **Akzeptanzkriterium:** ☐ Test: unauthenticated Socket-Connect wird mit disconnect beantwortet (HTTP 401 oder SocketIO False-Return). ☐ Authenticated Connect: SID wird in `_session_state` mit user_id registriert.

### REQ-04: Route-Konflikt /api/feedback auflösen
- **Aktuell:** Laut SP7-Audit registrieren zwei Blueprints (`feedback_bp` und ein zweiter) beide `POST /api/feedback`. Flask registriert die zweite silent — eine Route ist nie erreichbar.
- **Ziel:** Genau ein `POST /api/feedback` Endpoint aktiv. Der zweite wird auf eine eigene URL umgezogen (z.B. `/api/feedback/event`) oder die Logik wird zusammengeführt.
- **Akzeptanzkriterium:** ☐ `flask routes | grep "api/feedback"` zeigt genau einen POST-Endpoint. ☐ Beide vorherigen Code-Pfade sind über ihre jeweiligen URLs erreichbar.

### REQ-05: Tote Tabellen entfernen
- **Aktuell:** `ft_objection_events` und `ft_qa_events` sind in `database/models.py` definiert. Laut SP7: kein Writer und kein Reader im Produktionscode. Tabellen existieren ggf. in der DB leer.
- **Ziel:** Beide Tabellen-Modelle aus `models.py` entfernt. DB-Migration dropped die Tabellen wenn sie existieren (mit `IF EXISTS`). Keine Code-Referenzen mehr.
- **Akzeptanzkriterium:** ☐ `grep -rn "ft_objection_events\|ft_qa_events" services/ routes/ templates/` ergibt 0 Treffer. ☐ Migration läuft idempotent (zweiter Durchlauf kein Fehler).

### REQ-06: Test — _load_profile_cache() Integration
- **Aktuell:** `_load_profile_cache()` ist laut SP6-Audit komplett ungetestet. Wenn der Cache nicht befüllt wird, liefern alle Profil-Sektionen leere Marker.
- **Ziel:** Integration-Test ruft `_load_profile_cache(sid, profile_id)` mit Fake-DB-Session auf. Assert: `get_profile_for_sid(sid)` gibt danach `(name, daten_dict)` zurück, `daten_dict` enthält mindestens `'basis'` Key.
- **Akzeptanzkriterium:** ☐ Test `test_load_profile_cache_populates_sid` läuft grün. ☐ Test ist ein Function-Call-Return-Test (kein Source-Presence-Test gem. CLAUDE.md-Regel).

### REQ-07: Test — vorwissen_level UI→Backend Chain
- **Aktuell:** `vorwissen_level`-Chain (UI-Picker → WebSocket-Event → `_session_state[sid]['vorwissen_level']` → `build_profile_context()` Output) ist laut SP6-Audit komplett ungetestet.
- **Ziel:** Test ruft `handle_set_vorwissen(sid, 'hoch')` auf (oder äquivalenten Handler), dann `build_profile_context(sid)`. Assert: Returnwert enthält String-Match für `'hoch'` oder `'Vorwissen'` im Output-String.
- **Akzeptanzkriterium:** ☐ Test `test_vorwissen_level_flows_into_profile_context` läuft grün.

### REQ-08: streame_manual_ewb_variante() Error-Propagation
- **Aktuell:** `streame_manual_ewb_variante()` hat `try/except` um `build_profile_context()` das Fehler still schluckt. Wenn Profil-Kontext fehlt, generiert Haiku mit leerem Kontext ohne Fehlerindikation.
- **Ziel:** Exception aus `build_profile_context()` wird geloggt (`print("[EWB] profile_context error: {e}")`) und die Funktion gibt einen Error-Response zurück statt mit leerem Kontext fortzufahren.
- **Akzeptanzkriterium:** ☐ Test: `build_profile_context` wirft Exception → `streame_manual_ewb_variante()` returned Error-Dict (nicht leeren Stream). ☐ Kein silent Fail mehr.

## Constraints

- **Threading-Safety:** Alle neuen per-SID-Dicts brauchen ihr Lock-Objekt. Pattern aus `_per_sid_profile` / `_per_sid_lock` verwenden. Keine Lock-Hierarchie-Verletzungen (SP6: SID-Ghost-Guard vor jedem Write).
- **Keine Live-Loop-Regression:** `is_paused`-Migration darf keine Latenz in den Audio-Verarbeitungs-Loop einführen. Lock-Contention messen.
- **Haiku-only im Live-Loop** bleibt unverändert (CLAUDE.md Constraint).
- **DB-Safety:** Tote Tabellen-Drop mit `IF EXISTS` + Check ob leer vor Drop. Produktions-DB auf Hetzner hat ggf. echte (leere) Tabellen.
- **Backward-Compatibility Tests:** Alle bestehenden grünen Tests müssen nach Phase grün bleiben (Regression-Check).
- **WebSocket-Auth darf bestehende User-Flows nicht brechen:** Authenticated Flask-Session via Cookie ist der Auth-Mechanismus. Kein neues Token-System.
