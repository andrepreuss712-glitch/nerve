## Profil-Scoping-Architektur

| Option | Description | Selected |
|--------|-------------|----------|
| Per-SID in-memory dict | `_per_sid_profile = {sid: (name, data)}`, analog zu `_deepgram_sessions`, kein DB-Hit | ✓ |
| DB-Lookup per Call | Jeder Caller liest aus DB via `User.active_profile_id`, teuer bei 50 Concurrent-Sessions | |
| Flask session + gecacht | Cookie-basiert, bricht in WebSocket-Thread ohne Flask-Request-Context | |

**User's choice:** Per-SID in-memory dict (Option 1)
**Notes:** Low latency für Live-Hot-Path, Pattern existiert bereits mit `_deepgram_sessions`. Drei Pflicht-Lifecycle-Punkte identifiziert: Disconnect-Cleanup (Memory-Leak-Prävention), Set-Hook in start_live_session (DB-Load), None-Default für unbekannte SID. Plus Race-Condition-Test (disconnect ∥ background-thread-read). DB-Check: `User.active_profile_id`-Spalte existiert bereits (nullable=True, kein Schema-Change).
