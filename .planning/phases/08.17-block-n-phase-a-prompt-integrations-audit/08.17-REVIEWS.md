# Cross-AI Plan Review — Phase 08.17

## Gemini Review

Here is a structured review of Plan 08.17-01 (Audit-Verifikation):

### 1. Summary
The plan is highly focused, well-structured, and clearly understands its role as a read-only verification task bridging the gap between recent refactorings and upcoming redesigns. It correctly identifies the critical path: updating the matrix based on specific changes introduced in recent phases (dead code pruning, QA pipeline fixes). However, it slightly misses the full scope of the recent phase changes (specifically the model consolidation in 08.14) and could benefit from broader search parameters to ensure no prompt-building logic is missed outside of the assumed 7 service files.

### 2. Strengths
* **Strict Constraint Adherence:** The "NO CODE CHANGES" rule is prominently featured in the objective, setting the correct boundary for an audit task.
* **Targeted Delta Analysis:** Breaking down the audit into specific historical deltas (A through E) mapping to previous project phases (08.8, 08.9, 08.11, 08.13) ensures the agent knows exactly *what* to look for, rather than just doing a generic read.
* **Empirical Focus:** Requiring file:line pointers for André's suspicion list ensures the resulting audit is grounded in actual code reality, not AI assumptions.
* **Automated Verification:** Including `grep` commands to automatically verify the structural integrity of the generated markdown document is an excellent practice for autonomous execution.

### 3. Concerns
* **[MEDIUM] Missing Phase 08.14 (Model Consolidation) Check:** The plan's delta analysis (Task 1) skips Phase 08.14. Consolidating to Claude 3.5 Sonnet often involves changing how prompts are passed to the API (e.g., utilizing the dedicated `system` parameter instead of injecting context into the user prompt). The audit must verify if prompt structures changed during this migration.
* **[MEDIUM] Restricted Search Scope:** Task 1 explicitly limits the reading to 7 predefined service files. If any prompt-building logic was moved to a new helper file (e.g., `prompt_utils.py` or `context_builder.py`) during the recent refactoring phases, the audit will miss it and report false negatives (dead code).
* **[LOW] Incomplete "No Code Changes" Verification:** While "NO CODE CHANGES" is stated in the objective, the automated verification block only checks the markdown file. It lacks a programmatic check to guarantee no source files were accidentally touched.

### 4. Suggestions
* **Expand Task 1 to include Delta F (Phase 08.14):** Explicitly instruct the agent to analyze how the transition to Sonnet 4.5 impacted prompt assembly (e.g., check for `system=` kwargs in Anthropic API calls) and document if this changed the integration paths.
* **Broaden the Search Strategy:** Instead of only reading 7 predefined files from top to bottom, instruct the agent to use `grep` across the entire `services/` and `core/` directories for profile field keys (e.g., `kaufsignale`, `einwaende`) and prompt-building function signatures. This guarantees all usages are caught, even in newly created files.
* **Enhance Automated Verification:** Add a safeguard command to the verification block to ensure source code wasn't altered. For example: `git status --porcelain | grep ".py"` (expected: 0 output).
* **Define "Partial" Integration:** Briefly define what qualifies as a "partial" (⚠️) integration for the agent to ensure consistent grading (e.g., "Field is passed to the function, but not actually appended to the final string sent to the LLM").

### 5. Risk Assessment
**Risk Level: LOW**
**Justification:** The primary risk of this task is generating a wildly inaccurate audit that misleads Phase 08.18 and 08.19. Because the plan requires strict file:line citations and maps directly to known recent refactorings, the chance of hallucination is low. Furthermore, since the task is strictly read-only and constrained to modifying a markdown file in `.planning/audits/`, the risk to the application's stability is near zero. Implementing the suggested broader search strategy will eliminate the remaining medium-severity concerns regarding missed code paths.
