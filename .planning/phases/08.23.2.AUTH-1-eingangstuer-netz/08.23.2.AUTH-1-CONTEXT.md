## Implementation Decisions

### CSRF-Fix (A1 „Token mitschicken" — gewählter Weg, kein Alternativen-Bau)
- **D-01:** Weg **A1** — Meta-Token in `templates/marketing/landing.html` einbauen + `X-CSRFToken`-Header in den 3 state-changing Fetches. NICHT A2 (Endpunkt-exempt, schwächt Login-Schutz) und NICHT A3 (globaler Wrapper, jetzt zu groß). Folgt dem existierenden App-Muster.
- **D-02:** `templates/marketing/landing.html` ist eine **eigenständige** HTML-Datei (erbt NICHT von `base.html`) → sie hat das `<meta name="csrf-token">`-Tag nicht, das `base.html:6` bereits hat. Fix = dasselbe Meta-Tag (`<meta name="csrf-token" content="{{ csrf_token() }}">`) in `landing.html` `<head>` einfügen.
- **D-03:** Die 3 zu behandelnden Fetches: `/api/login` (landing.html:829), `/api/register` (landing.html:897), `/waitlist/join` (landing.html:921). Jeder bekommt den Header `'X-CSRFToken': <token aus dem Meta-Tag>`. Der Stats-Fetch `/waitlist/stats` (landing.html:952) ist **GET / nicht state-changing → KEIN Token**, bleibt unangetastet (und ist im Wächter-Whitelist-Sinn irrelevant, weil GET).
- **D-04:** `WTF_CSRF_TIME_LIMIT = None` setzen (in der App-Config, wo `CSRFProtect(app)` bei `app.py:54` läuft). Grund: sonst 400 nachdem die Anmelde-Seite >1h offen stand. `CSRFProtect(app)` existiert bereits — hier wird NICHTS neu verdrahtet, nur die Zeitgrenze entschärft. Lokaler `WTF_CSRF_ENABLED=False`-Override (app.py:58-60) bleibt unangetastet.

### Drei Deploy-Gate-Wächter (Muster: `tests/test_no_live_global_state.py` / `test_schild_guard.py`; laufen im deploy.sh-pytest-Gate mit)
- **D-05:** `tests/test_signup_journey.py` — E2E-Lebenszyklus **MIT CSRF AN** (nicht CSRF-aus = genau das blinde Grün, das den Bug durchließ): Landing → Token holen → register → Dashboard → Profil → Team → Logout → Login. **ERST ROT gegen HEAD** (muss am CSRF-400 scheitern), DANN A1 fixen (Test-Netz-Ratsche-Disziplin, CLAUDE.md „ERST rot, DANN fixen"). Beweist, dass der Test beißt.
- **D-06:** `tests/test_csrf_fetch_guard.py` — statischer Sweep über `templates/**` + `static/*.js`: jeder state-changing `fetch(` (POST/PUT/PATCH/DELETE) ohne `X-CSRFToken` → ROT mit Datei:Zeile. Whitelist nur die bewusst exempten (Stripe-Webhook + Google/Microsoft-OAuth-Callbacks). Fängt die ganze Klasse „token-loser Schreib-Fetch" für immer.
