## Deviations from Plan

### Auto-fixed Issues

**1. [Rule: Plan-Lücke / Persistenz-Schicht] Cleanup-Tracker um trigger-erzeugte tenant_orgs-Row erweitert**
- **Found during:** Task 1 (cleanup_tracker-Design)
- **Issue:** Plan-Spec trackte nur `{Session, User, Organisation}`. `/api/register` → `_create_org_and_user` legt eine Organisation an → `trg_mk_tenant_org` (Migration 0011) erzeugt eine `tenant_orgs`-Row (`legacy_org_id` FK → organisations.id, KEIN ondelete). Ohne diese Row im Cleanup FK-stallt der Organisation-Delete → Row leakt → `[BASELINE-AUTO-FIX]`/`[PGTEST-CLEANUP]`-Warnung.
- **Fix:** `'public.tenant_orgs'`-String-Key in den Tracker; id nach erfolgreichem Register aus der DB geholt (`SELECT id FROM tenant_orgs WHERE legacy_org_id`).
- **Verification:** Gate B grün, keine Cleanup-Warnungen zu organisations/tenant_orgs/sessions.
- **Committed in:** `bbb1b25`

**2. [Rule: Blocking — Prod-Regression] landing.html Struktur zerschossen: Jinja verarbeitete {% extends %} im JS-Kommentar**
- **Found during:** nach Gate-B-Deploy (André curl gegen getnerve.app)
- **Issue:** Der Wrapper-Kommentar in der **standalone** landing.html trug den Literal `{% extends 'base.html' %}`. Jinja verarbeitet Template-Tags zur Render-Zeit **auch in JS-Kommentaren** → landing.html erbte fälschlich von base.html → ausgelieferte Struktur zerschossen (`<script>` vor `<html>`, head verschluckt, Doppel-Wrapper), Startseite tot/nicht klickbar. Nur landing.html betroffen (base.html-Kommentar trägt kein `{% extends %}`). Der Server-E2E-Test blieb grün, weil das Meta-Tag via die falsche Vererbung trotzdem rendert.
- **Fix:** `{% extends %}` aus dem Kommentar entfernt + Warnkommentar; **Struktur-Wächter** `test_landing_renders_valid_structure` ergänzt (prüft die AUSGELIEFERTE Struktur: `<html>` vor jedem `<script>`, genau 1 Wrapper).
- **Verification:** Gate B-rerun 886 passed inkl. Struktur-Wächter; `curl` beginnt `<!DOCTYPE>/<html>/<head>`, kein Script davor, 1 sauber geschlossener Wrapper; Browser klickbar. Debug-Session `.planning/debug/resolved/auth1-landing-wrapper-jinja-extends.md`.
- **Committed in:** `76d54de`

## Lehre (für STATE + künftige Deploys)
Bei HTML/JS-Template-Deploys die **ausgelieferte Struktur** prüfen (curl/gerenderte DOM), nicht nur String-Vorhandensein im Quelltext. Jinja verarbeitet `{% %}`/`{{ }}` auch in HTML-/JS-Kommentaren zur Render-Zeit — ein Tag-Literal in einem Kommentar ist KEIN toter Text. Der neue Struktur-Wächter fängt genau das (script-vor-html / Doppel-Wrapper) ab jetzt automatisch im Deploy-Gate.
