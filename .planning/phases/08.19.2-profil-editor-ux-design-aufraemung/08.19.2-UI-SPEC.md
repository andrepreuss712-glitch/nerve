## Interaction Contracts

### Accordion — Einwände (D-03)

**Collapsed state (default):**
- Shows: Einwandtext (13px body) + Kurzlabel badge (10px)
- Height: single-row card (~48px)
- Expand trigger: Klick anywhere on the card row, OR expand chevron icon (right edge)

**Expanded state:**
- Shows all sub-fields in this order:
  1. Einwandtext (textarea, full)
  2. Gegenargument (textarea)
  3. Technik (select/text)
  4. Metadaten (Kategorie, Kurzlabel) — 2-column grid
- Transition: `height` CSS transition or `display:block` toggle (Vanilla JS `classList.toggle`)
- Collapse trigger: same click on header or collapse chevron

**No sliders anywhere in Einwände section.** Intensität-Slider, emotionale_trigger-Score-Sliders — all removed from UI. Schema fields stay in DB (D-03 decision: schema cleanup deferred to 08.19.1).

Source: CONTEXT.md D-03.

### Branche Section — Wisdom Stub (D-04)

**Branche dropdown:** Moved from topbar to Section #1. Standard `<select>` element, full width.

**Wisdom prefill box:** Info-tinted box below dropdown.
- Background: `rgba(0,212,170,0.06)` (very subtle teal tint, not accent-heavy)
- Border: `1px solid var(--border-light)`
- Text: André's exact wording (see Copywriting Contract below)
- Button: `[Vorschläge laden]` — disabled state, teal border at 50% opacity, cursor `not-allowed`
- Tooltip on disabled button: "Aktiv ab Phase 08.22"

**Topbar Branche dropdown:** Removed entirely (no dual-presence). Route in `routes/profiles.py` unchanged.

Source: CONTEXT.md D-04.

### Multi-Entry Pattern — Erlaubnisfrage + Pitch (D-05)

Both Erlaubnisfrage and Pitch adopt the existing Opener-Sammlung multi-entry pattern:
- Array list with `+Hinzufügen`-Button (`.btn-add`)
- Each entry: text input + `.btn-rm` delete button
- Same JS pattern as existing Opener-Sammlung (copy existing handler, do not invent new)

Source: CONTEXT.md D-05.

### Inline Help — 2-Level Hybrid (D-06)

**Level 1 — `.field-desc` (always visible):**
- Position: directly below the field `<label>`, before the `<input>`
- Style: `class="field-desc"` — 12px, `--page-text-muted`, line-height 1.5
- Content: max 1 sentence + optional example. Required for every field where user might guess wrong.

**Level 2 — Tooltip icon (`.tip-icon`) (on-demand):**
- Position: inline after label text, small `ⓘ` or `?` icon
- Max content: 150 characters
- Reserved for: definitions, rare edge-case notes
- Implementation: `title` attribute or existing tooltip pattern in profile_editor.html

**Level 3 (drawer):** NOT in this phase. Deferred.

Source: CONTEXT.md D-06.

### Auto-Save vs. Save Button (Claude's Discretion)

Based on UX-research (Linear/Notion-pattern) and the existing save architecture: **Auto-Save replaces the explicit Save button** on per-field level. A single "Alle Änderungen gespeichert" indicator top-right replaces individual save triggers.

Implementation: debounced `input` event (500ms debounce) → `fetch` POST to existing save endpoint → update indicator.

If technical complexity blocks auto-save in the plan phase, fallback: keep single "Profil speichern" button top-right, but remove per-field inline save buttons where they exist.

Source: UX-best-practices Sektion 5, Claude's Discretion.

### Section Anchor Navigation

Sidebar link click → `element.scrollIntoView({ behavior: 'smooth', block: 'start' })` with a scroll offset of 16px to avoid header overlap.

Source: CONTEXT.md D-08 (Section-Anchor-Navigation).

### EWB-Preview Placeholder (D-07)

Per each consolidated section group, a small inline notice:

`<span class="sec-hint">Live-Preview der KI-Nutzung kommt in Phase 08.20.</span>`

Visible for sections where fields are known to NOT yet reach the EWB-prompt (Kaufsignale, Verkaufstechniken, Übergänge per 08.17 audit).

Source: CONTEXT.md D-07.

## Implementation Constraints

These are hard constraints the executor must not violate:

1. **nerve.css is Single Source of Truth.** All new CSS classes go into `static/nerve.css`. No new `.css` file. No `<style>` block in the template for new persistent styles.
2. **No framework introduction.** Accordion, tooltip, and multi-entry patterns use Vanilla JS `classList.toggle`, `addEventListener`, existing patterns in the file.
3. **No backend changes.** All 08.19.2 work is confined to `templates/profile_editor.html` and `static/nerve.css`. Routes in `routes/profiles.py` remain untouched.
4. **Slider removal is UI-only.** `emotionale_trigger` dict and `einwaende[].intensitaet` fields stay in DB schema. Python schema untouched. Only the `<input type="range">` HTML elements and their JS handlers are removed.
5. **Accordion does not reorder DB data.** Visual reordering of sub-fields (Einwandtext first, Metadaten last) is display-only — the JS that reads/writes the array items maintains the same JSON structure.
6. **Disabled stub button must not fire any request.** `disabled` attribute + `cursor:not-allowed`. No click handler.
7. **Exact Branche wisdom text.** Copy André's wording verbatim (see Copywriting Contract). Do not paraphrase or shorten.
8. **Deutsche Umlaute in user-facing text.** "Gesprächsleitfaden" (ä), "Einwände" (ä), "Übergänge" (ü) — all correct in HTML content. Code identifiers: ASCII (`einwaende`, `uebergaenge`).

Source: CLAUDE.md constraints section, CONTEXT.md D-01/D-03/D-04/D-08.
