### WR-01: Double-rollback anti-pattern in `api_personalize_skript_save`

**Files modified:** `routes/app_routes.py`
**Commit:** `a2f8c5b`
**Applied fix:**
Removed the redundant `_db.rollback()` call inside the `except Exception` block that wrapped the `with _db.begin():` context manager. The `with begin()` block already performs automatic rollback on exception. The except clause now simply re-raises, letting the outer `finally: _db.close()` run cleanly.

---

### WR-02: Cap-check race condition — two concurrent saves can both pass cap < N

**Files modified:** `routes/app_routes.py`
**Commit:** `afd97e5`
**Applied fix:**
Moved the cap count query inside the `with _db.begin():` transaction block and added `.with_for_update()` to acquire a row-level lock (effective on Postgres; no-op on SQLite). Added a `_CapExceeded` sentinel exception class at module level to cleanly exit the transaction when the cap is hit without triggering the generic error handler. The cap-exceeded items list is built inside the transaction, stored in `cap_exceeded_response`, and returned after `_db.close()`. This eliminates the window where two concurrent requests could both read count < cap and both insert.

---

### WR-04: `precall_service` cache returns stale empfehlungen for cache-hit callers

**Files modified:** `services/precall_service.py`
**Commit:** `e43a78c`
**Applied fix:**
On a cache hit, a shallow copy of the cached dict is made (to avoid mutating the cached original), `set_briefing_for_sid()` is called with the cached text to register the briefing for the current `sid`, and `_generiere_empfehlungen()` is re-run for the current `sid` and `firmenname`. The re-generated empfehlungen replace the cached (stale) ones before returning. Schicht-1+2 results (expensive) remain served from cache; only the cheap Schicht-3 call is repeated per session.
