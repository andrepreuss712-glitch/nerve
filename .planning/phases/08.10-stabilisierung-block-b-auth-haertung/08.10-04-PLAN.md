Wave 4: Session-Fixation-Fix in _login_user() + Org-Scoping-Assertion in login_required.

Purpose: Session-Fixation erlaubt es einem Angreifer, eine Session-ID vor dem Login zu setzen und nach dem Login dieselbe Session-ID für privilegierten Zugang zu nutzen. session.clear() vor dem Schreiben der Session-Keys verhindert das.     @wraps(f)
    def decorated(*args, **kwargs):
        if 'user_id' not in session:
            return _login_redirect_with_next()
        db = get_session()
        try:
            user = db.get(User, session['user_id'])

        return f(*args, **kwargs)

**M-AU-1: Org-Scoping-Assertion — login_required() (nach g.org = db.get(...)):**

NACH `g.org = db.get(Organisation, user.org_id)` und VOR `onboarding_done = ...`:
```python
            # M-AU-1: Org-Scoping-Assertion — verhindert Cross-Org-Datenzugriff bei
            # inkonsistenter DB-State (z.B. org geloescht, user-org_id verwaist).
            if g.org is None or g.org.id != user.org_id:
                session.clear()

```

Alternativ-Implementierung mit assert (raise AssertionError bei Verletzung):
```python
            assert g.org is not None and g.org.id == user.org_id, \
                f"Org-Scoping-Verletzung: user.org_id={user.org_id}, g.org={g.org}"
```

Verwende die if-Variante (nicht assert): AssertionError würde einen 500er produzieren, der im Error-Handler landet. Die if-Variante gibt einen sauberen Redirect ohne Stack-Trace.
