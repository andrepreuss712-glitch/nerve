<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Nginx → Gunicorn/Flask (Reverse-Proxy) | SSL terminiert bei Nginx — Flask sieht HTTP ohne ProxyFix |
| Browser → Server (Cookie) | Session-Cookie wird bei jedem Request übertragen |
| JS → Cookie | HttpOnly verhindert JavaScript-Zugriff auf Session-Cookie |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08.10-02-A | Spoofing / Session Hijacking | Flask Session-Cookie | mitigate | SESSION_COOKIE_SECURE=True in Prod verhindert Cookie-Übertragung über HTTP |
| T-08.10-02-B | Tampering | Flask Session-Cookie | mitigate | SESSION_COOKIE_HTTPONLY=True verhindert XSS-basiertes Cookie-Stehlen via JS |
| T-08.10-02-C | Cross-Site Request Forgery | Flask Session-Cookie | mitigate (partial) | SESSION_COOKIE_SAMESITE=Lax reduziert CSRF-Angriffsfläche als Defense-in-Depth (vollständiges CSRF-Schutz kommt in Wave 3) |
| T-08.10-02-D | Spoofing / Cookie Drop | ProxyFix fehlt bei Nginx-Reverse-Proxy | mitigate | ProxyFix(x_for=1, x_proto=1) stellt sicher dass Flask hinter Nginx HTTPS-Requests korrekt erkennt. x_host=1 WEGGELASSEN — fixed Domain, Host-Header-Injection-Vektor vermieden |

Residual-Risk: SameSite=Lax schützt nicht gegen alle CSRF-Angriffe (nur GET safe-method). Wave 3 (CSRFProtect) schließt diese Lücke vollständig. Backwards-Compatibility: Bestehende User-Sessions bekommen neue Cookie-Flags beim nächsten Login ausgestellt — kein erzwungener Logout.
</threat_model>
