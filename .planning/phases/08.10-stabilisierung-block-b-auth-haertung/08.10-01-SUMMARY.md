# Phase 08.10 Plan 01: Traceback-Leak-Fix + Frontend-Filter Summary

**One-liner:** Python-Tracebacks aus allen 500-Error-Responses entfernt; sanitizeErrorMsg() als Defense-in-Depth-Filter in pip-launcher.js eingefuegt.

## What Was Built

**Task A — Error-Handler-Leaks bereinigt (app.py + 3 Route-Files):**

- `app.py` `_handle_500`: `'traceback': tb_str[-1000:]` und `str(e)` entfernt — gibt jetzt `'internal server error'` zurueck. Plaintext-Fallback: leerer Body statt Traceback.
- `app.py` `_handle_exception`: analog — `'Internal Server Error'`, leerer Plaintext-Fallback.
- `routes/training.py` 5 Handler bereinigt:
  - training_start inner except (KI-Antwort): `type+str`-Leak → `'internal'`
  - training_start outer except: `last_frame[:500]`-Leak → `'internal'`; `lines`/`last_frame`-Variablen entfernt
  - training_help: `type+str`-Leak → `'internal'`
  - training_transcribe: `str(e)`-Leak → `'internal'`; `print()` fuer Server-Logging hinzugefuegt
  - api_training_personality_generate: `type+str`-Leak → `'internal'`
- `routes/admin_views.py` CRM-Note: `str(e)` → `'internal'`
- `routes/app_routes.py`: `api_analyse_line` in Phase 08.11 geloescht — kein Leak mehr vorhanden, kein Fix noetig

**Task B — Frontend-Traceback-Filter (pip-launcher.js):**

- `sanitizeErrorMsg(msg)` Hilfsfunktion am Anfang der IIFE eingefuegt
- Filtert `Traceback`, `File "`, `  File ` aus Fehlermeldungen vor DOM-Write
- Beide `errEl2.textContent`-Zuweisungen (then-Handler + catch-Handler) verwenden `sanitizeErrorMsg()`
