### Gaps Summary

No automated gaps found. All 6 security measures are fully implemented and wired.

**Known Issues (non-blocking, tracked):**

**CR-01 (redirect target):** `confirm_email()` calls `redirect(url_for('dashboard.index'))` after token validation. An unauthenticated user (not logged in) who clicks the email link will have email_confirmed set to True but then be redirected to dashboard, which in turn redirects to login. The confirmation flash message may be lost in the chain. Fix: redirect to `url_for('auth.login')` with `next` parameter, or auto-login the user after confirmation.

**CR-02 (TOCTOU race):** In `oauth.py microsoft_callback`, `_login_user(db, new_user)` is called before the `email_confirmed=False` write happens in a second DB session. There is a narrow window where a request arriving between login completion and the email_confirmed=False commit could access protected routes without email confirmation. Fix: set `new_user.email_confirmed = False` in the same DB session that creates the user, before calling `_login_user()`.

Both issues are known from code review and tracked. They do not block the phase goal — the email confirmation gate is functional for the normal flow.
