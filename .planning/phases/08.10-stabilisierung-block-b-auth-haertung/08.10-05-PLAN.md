Wave 5: Brute-Force-Schutz via flask-limiter — Rate-Limiting auf /api/login und /api/register.

Purpose: Ohne Rate-Limiting kann ein Angreifer unbegrenzt Login-Versuche senden und Passwörter per Brute-Force erraten. 10 Versuche/Minute auf /api/login sind ausreichend für legitime User (auch bei "Passwort vergessen"-Loops) und blockieren Automatisierung effektiv.

Output: flask-limiter in requirements.txt, Limiter(app) in app.py, @limiter.limit() auf api_login und api_register.

Multi-Worker-Hinweis: In-Memory-Storage reicht für Single-Worker (aktueller Stand auf VPS mit Gunicorn gthread 1+4). Bei Skalierung auf Multi-Worker (Block M) muss auf Redis-Backend umgestellt werden. Dieser Hinweis ist im Code dokumentiert.

Erstelle `services/rate_limiter.py`:
```python
from flask_limiter import Limiter
from flask_limiter.util import get_remote_address

# Singleton-Instanz — wird in app.py mit init_limiter(app) initialisiert
limiter = Limiter(
    key_func=get_remote_address,
    default_limits=[],
    storage_uri="memory://",
    # Future: bei Multi-Worker (Block M): storage_uri="redis://localhost:6379"
)

def init_limiter(app):
    """Bindet limiter an Flask-App. Aufzurufen in app.py nach app-Initialisierung."""
    limiter.init_app(app)
```
