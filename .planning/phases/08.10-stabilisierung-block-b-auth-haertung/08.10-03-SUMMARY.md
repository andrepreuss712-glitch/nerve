CSRF-Schutz end-to-end implementiert: flask-wtf CSRFProtect(app) im Backend, 3 korrekte csrf.exempt()-Aufrufe, CSRF-Token Meta-Tag in base.html, getCsrfToken()-Helper und X-CSRFToken Header in allen 4 verbleibenden JS-Files mit POST-Calls.

## What Was Built

### Task D — CSRF Backend (dd64f5d)

**requirements.txt:** `flask-wtf>=1.2.0` hinzugefügt.

**app.py:**
- `from flask_wtf.csrf import CSRFProtect` im Import-Block
- `csrf = CSRFProtect(app)` NACH `socketio = SocketIO(app, ...)` — Reihenfolge kritisch für WSGI-Level-Interception (SocketIO Zeile 43, CSRFProtect Zeile 50)
- 3 csrf.exempt()-Aufrufe nach `init_oauth(app)`:
  - `csrf.exempt(stripe_webhook)` — Stripe-Server POST ohne Browser-Cookie, Auth via HMAC
  - `csrf.exempt(google_callback)` — OAuth GET-Callback, kein Browser-POST
  - `csrf.exempt(microsoft_callback)` — OAuth GET-Callback, kein Browser-POST

**templates/base.html:**
- `<meta name="csrf-token" content="{{ csrf_token() }}">` nach `<meta name="viewport">` eingefügt

### Task E — CSRF Frontend (a418878)

**pip-launcher.js:** `getCsrfToken()` helper + `X-CSRFToken: getCsrfToken()` auf 3 POST-Calls:
- `/api/precall/research` (PreCall-Analyse)
- `/api/set_profile` (Profil-Auswahl beim Call-Start)
- `/api/beenden` (Call-Ende)

**profile_editor.js:** `getCsrfToken()` helper + `X-CSRFToken` auf 2 POST-Calls:
- `/profiles/api/profile/*/faqs` (FAQ erstellen)
- `/profiles/api/profile/*/tabu` (Tabu-Begriffe speichern)

**feedback.js:** `getCsrfToken()` helper + `X-CSRFToken` auf FormData-POST `/api/feedback` (nur `X-CSRFToken` Header, kein Content-Type da FormData auto-setzt)

**admin_dashboard.js:** `getCsrfToken()` helper definiert (nur GET-Calls aktuell — Zukunftssicherheit)
