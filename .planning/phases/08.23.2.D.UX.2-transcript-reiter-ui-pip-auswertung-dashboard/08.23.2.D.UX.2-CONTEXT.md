# Phase 08.23.2.D.UX.2: Transcript-Reiter UI im PiP + Auswertung + Dashboard - Context

**Gathered:** 2026-06-03
**Status:** Ready for planning (mit vorgeschaltetem Pflicht-Spike — siehe PT-GATE)

<domain>
## Phase Boundary

Transkript an drei UI-Stellen sichtbar machen, damit der Cold-Caller während des Calls nicht
mehr mitschreiben muss — plus Text-Markieren/Copy + Suche. **Reine UI-Phase** auf bestehender
Daten-Foundation (UX.1: `transcript_segments`-Tabelle existiert bereits).

**Drei UI-Kontexte:**
1. **Live im PiP** während des Calls — Live-Scroll der Segmente, hidden-by-default, per Knopf einblendbar.
2. **PiP-Post-Call-Score-Ansicht** — Transkript direkt nach Outcome-Bestätigen erreichbar.
3. **Große Auswertung** (`session_detail.html`, = Dashboard-Call-Detail-View) — Transkript als Reiter
   neben Score/Outcome/Lernkarten.

**In Scope:** Transkript-Anzeige in den drei Kontexten, wiederverwendbares Reiter-System,
Suche/Highlight (große Auswertung), Text-Markieren + Copy-out, neuer Lese-Endpoint.

**Out of Scope (eigene Phasen):** DB-Schema-Änderungen (steht aus UX.1), Outcome-Korrektur/Termin-
Nachtrag (→ NACHTRAG), Live-Anonymisierung, Anonymisierungs-Tuning (→ D.UX.3).

</domain>

<decisions>
## Implementation Decisions

### Reiter-System-Architektur (Anti-Abrieb mit NACHTRAG)

- **R-01:** Wiederverwendbare **Vanilla-JS-Komponente** (z.B. `n-tabs`) mit deklarativem HTML via
  data-Attributen. `session_detail.html` UND Phase NACHTRAG hängen einen Reiter dran, indem sie
  HTML + data-attr hinzufügen — **kein Logik-Duplikat, kein zweimal-bauen**. Sauberer Vertrag,
  testbar, passt zum Vanilla-JS-Constraint (kein React). Die Komponente ist DAS Deliverable, das
  NACHTRAG mitnutzt (Task 2 dort: "Reiter in der großen Auswertung → Ergebnis korrigieren + Termin nachtragen").
- **R-02:** In **dieser** Phase wird die große Auswertung minimal-invasiv umgebaut: die bestehenden
  gestapelten Sektionen (Score-Hero, Breakdown, Chart, Einwand-Timeline) wandern komplett in einen
  **"Übersicht"-Reiter**; daneben ein neuer **"Transkript"-Reiter**. Etabliert nur den Reiter-Container,
  bestehende Inhalte bleiben unangetastet (geringstes Abrieb-Risiko).
- **R-03:** **Deep-Link via URL-Hash** (z.B. `.../session/42#transkript`) + zuletzt gewählter Reiter
  gemerkt. NACHTRAG + die geplante Dashboard-Erinnerung ("schau nochmal rein") können gezielt auf
  einen bestimmten Reiter verlinken.

### PiP-Transkript (enger Kontext)

- **PT-01:** Ziel-Layout im PiP = **side-by-side**: Coaching rechts, Transkript-Panel links daneben,
  im **automatisch verbreiterten** PiP-Fenster. KEIN Overlay, KEIN Vollflächen-Umschalten. Aktuell
  öffnet der PiP als Document-Picture-in-Picture mit `documentPictureInPicture.requestWindow({width:480,height:900})`
  (`static/pip-launcher.js:1540`).
- **PT-GATE (⚠️ HARTER PFLICHT-SPIKE VOR JEDEM BAU):** Kann das Document-PiP-Fenster nach dem Öffnen
  per JS automatisch verbreitert werden (`window.resizeTo` / `window.resizeBy` auf das Document-PiP-Window,
  Ziel-Browser Chrome)?
  - **JA →** Auto-Aufklappen/Verbreitern bauen (PT-01).
  - **NEIN →** **STOPP, kein Bau** des PiP-Transkripts. An André zurückmelden **mit Alternativen**.
  - **Manuelles Fenster-Ziehen durch den User ist KEIN akzeptierter Fallback** (André-Direktive 2026-06-03).
  - Empfehlung: als eigenständiger `/gsd-spike` VOR `/gsd-ui-phase`/Planung. Spike-Ergebnis entscheidet,
    ob der PiP-Teil dieser Phase überhaupt gebaut wird. Reiter-System (Bereich 1) + Dashboard-Reiter +
    Text-Tools sind vom Spike-Ergebnis unabhängig und können unabhängig geplant werden.
- **PT-02:** Live-Scroll: **Auto-Scroll zum Neuesten, pausiert sobald der User hochscrollt** (älteres
  lesen). Dann erscheint ein "↓ Neueste"-Knopf zum Zurückspringen. Standard-Chat-Pattern.
- **PT-03:** Darstellung im engen PiP = **kompakte Sprecher-Zeilen** (Sprecher-Label Berater/Kunde
  farbcodiert + Text, optional kleiner Timestamp) — maximale Textmenge sichtbar. Die große Auswertung
  darf laut UI-SPEC breiter/anders dargestellt werden.

### Datenquelle Live vs. persistiert

- **DQ-01:** Live WÄHREND des Calls = **roher Echtzeit-Text** aus dem RAM-Puffer (eigener Bildschirm
  des Beraters, eigener Call). Keine Live-Anonymisierung (Latenz + Kosten im Live-Loop vermeiden,
  Constraint "nur Haiku/günstig live"). Anonymisierung passiert erst beim Auflegen für die Persistenz.
- **DQ-02:** Große Auswertung (session_detail/Dashboard) = **neuer Endpoint `GET /api/transcript/<conversation_log_id>`**,
  liefert sortierte Segmente (anonymisiert) aus `transcript_segments`, **org-/owner-scoped** (Zugriffsschutz
  wie bestehende Dashboard-Routes). Reiter lädt daraus. Wiederverwendbar für andere Reiter/PiP.
- **DQ-03:** Post-Call-Score-Ansicht im PiP (direkt nach Auflegen) = **Live-RAM-Puffer weiternutzen**
  (sofort da, kein Warten auf den Call-Ende-DB-Insert, konsistent mit der Live-Ansicht).
- **Bewusste Folge:** PiP (live + post-call) zeigt **rohen** Text, Dashboard zeigt **anonymisierten**
  Text desselben Calls. Das ist gewollt, kein Bug.

### Text-Tools (Suche / Markieren / Copy)

- **TT-01:** Suche/Highlight **nur in der großen Auswertung** (breiter Kontext). PiP bleibt schlank.
  (Roadmap: Suche = "Optional Bonus".)
- **TT-02:** Such-Modus = **Highlight + Durchspringen**: Treffer in Brand-Farbe markieren (KEIN Gelb —
  CLAUDE.md Punkt 8), mit ↑/↓ durch Treffer springen, Treffer-Zähler (z.B. 3/12). Gesprächs-Kontext
  bleibt sichtbar (kein Filtern/Ausblenden).
- **TT-03:** Copy = **native Textauswahl** (Maus-Markieren funktioniert in allen drei Kontexten
  automatisch) + zusätzlich ein **"Ganzes Transkript kopieren"-Knopf**. Kein Pro-Segment-Button.
  Haupt-Use-Case: gute Out-of-Script-Momente / neue Einwände extern speichern.

### Claude's Discretion

- Live-Datenfluss-Mechanismus in den PiP (bestehender SocketIO-Transcript-Stream wiederverwenden vs.
  Polling des RAM-Puffers) — Researcher/Planner wählt anhand des bestehenden pip-launcher.js-Pfads.
- Konkrete Brand-Farbe für Such-Highlight + Sprecher-Farbcodierung (via nerve.css-Tokens) — gehört
  in die UI-SPEC.
- Endpoint-Response-Format-Details (Pagination bei sehr langen Transkripten ja/nein) — Researcher/Planner.

</decisions>
