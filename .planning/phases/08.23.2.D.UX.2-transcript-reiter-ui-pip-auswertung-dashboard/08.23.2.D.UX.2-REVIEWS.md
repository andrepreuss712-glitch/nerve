## Findings — vor Execute einarbeiten

### DUX2-01 — `state.transcriptSegments` nie initialisiert → TypeError 🐛 (LOW sev, ECHTER Crash)
Plan 04 pusht in `state.transcriptSegments`, initialisiert es aber nie → erster `.push()` wirft `TypeError` wenn `undefined`.
**Fix:** `state.transcriptSegments = []` initialisieren (z.B. in `_setupPipWindow` oder bei state-Init) VOR jedem push.

### DUX2-02 — Resize-Messung via fixem `setTimeout(350)` → Race auf langsamen Rechnern ⚙️ MED
Plan 04: nach `resizeTo(960,900)` misst ein statischer 350ms-Timer `innerWidth`. Auf langsamem Rechner, wenn die OS-Resize-Animation >350ms dauert → Check sieht `<900` → Fallback-Overlay rendert → DANN ploppt das Fenster auf 960 = falsches Layout.
**Fix:** 350ms als Notnagel behalten, aber `ResizeObserver` auf `pip.document.body` (oder PiP-`resize`-Event) ergänzen, der zuverlässig auf Side-by-side umspringt sobald `innerWidth >= 900`.

### DUX2-03 — Eager-Load-Verschwendung + fehlendes `hashchange` → n-tabs soll Aktivierungs-Event feuern ⚙️ MED
Plan 03 muss `/api/transcript` bei JEDEM `session_detail`-Load eager fetchen (auch wenn der Transkript-Reiter nie geöffnet wird), weil n-tabs.js (Plan 01) kein Aktivierungs-Event feuert — und Plan 01 keinen `hashchange`-Listener für In-Page-Deep-Link-Navigation hat.
**Fix:** Plan 01 n-tabs feuert ein `CustomEvent` (z.B. `'n-tab:activated'`, detail `{tabId}`) beim Aktivieren + ein `window 'hashchange'`-Listener. Plan 03 lazy-loadet das Transkript dann bei erster Aktivierung von `#transkript` (Deep-Link-Pfad aktiviert → Event feuert → Fetch). Entfernt die Pro-Load-Verschwendung + fixt In-Page-Hash-Navigation. **Bonus:** sauberer Aktivierungs-Hook für NACHTRAG (das n-tabs mitnutzt).

### DUX2-04 — Tab-Buttons fehlt `aria-controls` ♿ LOW
Plan 01 `.n-tab-btn` (role=tab) fehlt `aria-controls="<panel-id>"` — obligatorisch für Screenreader-tab/tabpanel-Paarung; `data-tab-target` allein reicht Screenreadern nicht. **Fix:** `aria-controls` pro Tab-Button ergänzen (deckt auch den früheren Visuals-FLAG zu aria-labels auf den Such-Nav-Buttons ◀/▶ — mit einarbeiten).
