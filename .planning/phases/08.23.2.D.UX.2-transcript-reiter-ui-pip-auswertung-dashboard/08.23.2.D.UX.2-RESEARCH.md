## Summary

Reine Frontend-Phase mit **einem** neuen Backend-Read-Endpoint. Die Daten-Foundation (UX.1) steht und ist produktiv befüllt (76 Segmente in `transcript_segments`). Das `TranscriptSegment`-ORM-Model existiert (models.py:718) und wird bereits in `routes/learning.py` (Z.85, Z.256) gelesen — der neue Endpoint kopiert diesen Query nahezu 1:1 und ergänzt nur owner-Scoping über `conversation_logs.user_id`.

Drei Kontexte mit unterschiedlicher Datenquelle, **bewusst getrennt**: (1) Live-PiP + (2) Post-Call-PiP nutzen den **RAM-Puffer** (roh, kein DB-Roundtrip), (3) große Auswertung nutzt den **DB-Endpoint** (anonymisiert). Die zentrale Landmine: der bestehende SocketIO-`transcript`-Event im PiP rendert **derzeit keine Segment-Liste** — er setzt nur `state.lastTranscript`. Die Live-Segment-Liste im PiP ist also ein **Neubau**, nicht ein Anzapfen einer bestehenden gerenderten Liste.

Das Reiter-System ist genuin neu (kein wiederverwendbarer Vanilla-JS-Tabs-Component existiert). Alle von der UI-SPEC referenzierten nerve.css-Tokens existieren; nur die `--transcript-*`-Sprecher-/Highlight-Tokens müssen neu in `:root` ergänzt werden. PT-GATE ist **JA** (resolved) — der PiP-Teil ist cleared to build mit Measure-and-Fallback-Auflage.

**Primary recommendation:** Endpoint in `routes/learning.py` (`learning_bp`, dort lebt schon der `TranscriptSegment`-Read + die `conv`-Scope-Logik), Query + Scope aus learning.py:66–91 wiederverwenden, JSON `{segments:[{ts_ms,speaker,text}], ...}` ohne Pagination. n-tabs.js neu, in base.html `{% block scripts %}` via session_detail laden. PiP-Live-Segment-Liste als Neubau (eigener Render-Pfad + Hook in den `transcript`-Socket-Handler).

## Architecture Patterns

### n-tabs Komponente (R-01 — generisch, deklarativ)
- **Pattern:** Reines DOM-Scanning auf `[data-tabs]`-Container, `data-tab-target` auf Buttons, Panels per `id` + `hidden`-Attribut. Init scannt alle `.n-tabs` auf der Seite (mehrfach-instanzfähig für NACHTRAG).
- **Deep-Link:** Init liest `location.hash` → aktiviert Match; sonst `localStorage('n-tabs-last-{pageId}')`; sonst erster Tab. Klick → `history.replaceState(null,'', '#'+id)` + `localStorage.setItem`.
- **A11y:** `role="tablist"`/`role="tab"`/`role="tabpanel"`, `aria-selected`, `hidden` (UI-SPEC §Accessibility).
- **Vorbild bewusst NICHT:** `switchTab5`/`fcd-tab` (pip-launcher.js:829–863) ist ein bespoke Precall-Picker mit `onclick`-Inline + ohne deep-link/role — NICHT wiederverwendbar. Admin `_tab_*.html` sind Server-Jinja-Partials — falsches Paradigma. R-01 ist genuin neu.

### PiP Resize-on-Toggle (PT-01, aus Spike-Blueprint)
```js
// Quelle: .claude/skills/spike-findings-salesnerve/references/pip-window-resize.md
transkriptToggleBtn.addEventListener('click', () => {
  const pip = state.pipWindow;             // Document-PiP window
  pip.resizeTo(960, 900);                   // Klick IST die transient activation (gesture-gated)
  setTimeout(() => {
    if (pip.innerWidth >= 900) renderSideBySide(pip);  // Primärpfad
    else                       renderFallbackOverlay(pip);
  }, 350);                                  // async resize + Chrome ~80%-work-area-Clamp
});
```
- **Harte Regeln (Spike):** kein Timer-Resize ohne Klick (gesture-gated, blockiert). Kein `moveTo` (Document-PiP exponiert nur Größe). Manuelles Ziehen ist KEIN Fallback. Chrome 121+.

### Anti-Patterns to Avoid
- **`.n-pill-active` für aktiven Tab** — resolviert zu Teal (#00D4AA, nerve.css:252/660); UI-SPEC verlangt neutralen `.n-tab-btn--active` (transparent bg, dark text, bottom-border `--glass-border`). 60/30/10-Verstoß sonst.
- **Gelb für Such-Highlight** — CLAUDE.md P.8. Brand-Teal-Tokens nutzen (`--transcript-highlight-*`).
- **`requestWindow({width:960})` direkt breit öffnen** — neue PiP-Fenster ohne Cache starten ~20% work-area + Clamp; zwingt Transkript immer offen. Spike-Approach B, verworfen.
- **Umlaut in Identifiern** — `id="transkript"` ASCII (CLAUDE.md). User-Text "Übersicht"/"Transkript" mit echten Umlauten.

## Common Pitfalls / Landmines für den Planner

### Landmine 1: `'system'`-Sprecher rendert nicht in der UI-SPEC
**Was:** CHECK erlaubt `speaker IN ('berater','kunde','system')` (models.py:731, inspect.sh). `_sp_map` mappt unbekannte/None-Speaker auf `'system'` (app_routes.py:69) — d.h. `'system'`-Segmente **existieren real** (Rollen noch nicht bestätigt). UI-SPEC stylt aber NUR berater/kunde (`--transcript-berater-*`/`--transcript-kunde-*`).
**Risiko:** `'system'`-Segmente bekommen keine Farbe/Label → leeres/kaputtes Rendering.
**Empfehlung:** Planner muss `'system'`-Fall explizit definieren: entweder neutral-grau (z.B. `--page-text-muted`, Label "SYSTEM" oder kein Label) oder ausblenden. **An André/UI-SPEC-Owner rückmelden** — ist in UI-SPEC nicht abgedeckt. `[ASSUMED]` bis geklärt.

### Landmine 2: PiP-`transcript`-Event rendert aktuell keine Segment-Liste
**Was:** `state.socket.on('transcript', …)` (pip-launcher.js:2274) setzt **nur** `state.lastTranscript = d.text` — es gibt **keine** gerenderte Live-Segment-Liste im PiP, an die man sich „dranhängen" kann. Die sichtbaren PiP-Slots (`pip_stream_start`/`pip_token`) sind der **Coaching**-Stream, NICHT Transcript.
**Risiko:** Plan, der annimmt „bestehende Transcript-Liste anzapfen", baut auf Luft (genau der Punkt-21-Variablen-Namens-Fehler-Typ).
**Empfehlung:** Live-Segment-Liste ist **Neubau**. Payload-Shape des `transcript`-Events verifizieren — d.type==='final', d.text vorhanden; **prüfen ob `speaker`/`ts_ms` im Event-Payload mitkommen** (UI-SPEC behauptet `{speaker,text,ts_ms}` — im Handler aktuell nur `d.type`/`d.text` gelesen). Planner muss den Server-Emit (`emit('transcript', …)`-Quelle) gegenchecken, bevor er Sprecher-Zeilen im PiP verspricht. `[ASSUMED]` bis Emit-Shape verifiziert.

### Landmine 3: PiP zeigt roh, Dashboard zeigt anonymisiert — gewollt
**Was:** DQ-01/DQ-03 (RAM, roh) vs. DQ-02 (DB, anonymisiert). Derselbe Call sieht im PiP anders aus als im Dashboard.
**Risiko:** Tester/Reviewer meldet „Bug: Texte stimmen nicht überein".
**Empfehlung:** Im Plan + Verify-Sektion explizit als gewolltes Verhalten dokumentieren (CONTEXT.md "Bewusste Folge").

### Landmine 4: Deep-Link-Hash + Chart-Init-Reihenfolge
**Was:** session_detail.html hat inline `<script>` für Chart.js (Z.502–579), das beim Page-Load das Canvas in der (künftig) versteckten Übersicht rendert. Wenn Übersicht initial `hidden` ist und Transkript via `#transkript` aktiv, könnte Chart in `display:none` mit Breite 0 initialisieren.
**Risiko:** Chart bricht bei Deep-Link `#transkript`.
**Empfehlung:** Übersicht-Tab als **Default/erster** Tab (Chart rendert sichtbar); bei Tab-Wechsel zu Übersicht ggf. `chart.resize()`. Planner: Chart-Init-Timing gegen `hidden`-Panel prüfen.

### Landmine 5: D.UX.4-Post-Call-Hook-Lokation
**Was:** D.UX.4 hat den Post-Call-Score-Screen so gebaut, dass ein Transkript-Knopf drangehängt werden kann („Platz gelassen, kein Umbau" — CONTEXT canonical_refs).
**Empfehlung:** Planner muss die exakte Hook-Stelle im Post-Call-Score-Render in pip-launcher.js lokalisieren (Outcome-Confirm-Flow, `_decideModalState`-Umfeld aus D.UX.1) bevor Context-2 geplant wird. Nicht in dieser Research lokalisiert — **offene Stelle für Planner**.
