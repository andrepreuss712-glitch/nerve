## Summary

Phase 08.5 erweitert den NERVE Live-Loop von reiner Keyword-Einwand-Erkennung zu einem 4-Kategorien-Klassifikator (einwand_known / einwand_unknown / frage / smalltalk-none). Das zentrale technische Problem: Claude soll wieder als Live-Klassifikator reaktiviert werden — was in Phase 06.3 bewusst vermieden wurde. Der Forschungs-Kern ist zu verstehen, WARUM Phase 06.3 den analyse_loop entkoppelt hat, damit dieselben Fehler nicht zurueckkehren.

Der analyse_loop bleibt erhalten und wird erweitert: Er klassifiziert Utterances und — wenn keine Keyword-Match vorliegt — generiert via `qa_pipeline.py` Antworten fuer unbekannte Einwaende und FAQ-Matches. Das Dual-Pipeline-Muster (Keyword-Matcher als deterministischer Primary, Claude als semantischer Secondary) ist das korrekte Muster fuer diese Erweiterung.

Training-Pipeline-Umbau auf v2-modular ist der groesste Scope-Block (+8-12h). `training_service.py` nutzt aktuell direkte `claude_client.messages.create`-Calls ohne Prompt-Versioning. Alle drei Training-Prompts (Kunden-Simulation, Scoring, Stimmung) muessen auf `prompt_pipeline` + `ewb_pipeline`-Muster umgestellt werden.

**Primaere Empfehlung:** Neue Datei `services/qa_pipeline.py` analog zu `ewb_pipeline.py`. Classifier-Prompt in `prompt_versions` (module='classifier'). FAQ-Matching via lokale sentence-transformers (Modell `paraphrase-multilingual-MiniLM-L12-v2`) auf dem Hetzner VPS — vollstaendig DSGVO-konform, kein API-Call, <50ms Latenz.

## D-06 PFLICHT-RESEARCH: Phase 06.3 Entkopplungs-Ursache (aufgeklaert)

[VERIFIED: git log + CONTEXT.md 06.3 + git show 00c88db]

### Root Cause (aufgeklaert, KRITISCH fuer Phase 08.5)

**Ursache: Anthropic 529 overloaded_error beim EWB-Vorlesen durch doppelten parallelen Claude-Call-Pfad.**

Phase 06.2 hat den Keyword-Matcher etabliert, der fuer Slot 0 + Slot 1 als Primary dient. Das Problem war, dass nach Phase 06 ZWEI parallele EWB-Erkennungs-Pfade gleichzeitig liefen:

1. **Keyword-Matcher (Phase 06.2):** Slot 0 <1ms (deterministisch), Slot 1 via `streame_auto_variante(trigger='keyword')` — sauber.
2. **analyse_loop (Phase 4.8, alt):** Feuerte bei JEDEM Deepgram Final ZUSAETZLICH Slot 0 via `analysiere_mit_claude_streaming` UND Slot 1 via `streame_auto_variante(trigger='analyse_loop')`.

**Konkretes Problem:** Wenn der Nutzer eine EWB-Antwort vorliest, transkribiert Deepgram den Vorlese-Text als neues Segment → analyse_loop feuert auf den Vorlese-Text → parallele Claude-Calls → Anthropic 529 `overloaded_error`. Der Loop schloss sich selbst.

**Was in Phase 06.3 entfernt wurde (Commit 00c88db):**
- `streame_auto_variante(trigger='analyse_loop')` entfernt (Slot-1-Spawn aus analyse_loop)
- `analysiere_mit_claude_streaming` fuer Slot-0 aus analyse_loop entfernt
- Beide PiP + non-PiP Branches rufen jetzt nur noch `analysiere_mit_claude()` (non-streaming)
- `_last_slot` / `_last_slot_time` entfernt (write-only dead code, D-11 06.3)
- ANALYSE_INTERVALL auf 4s erhoeht (D-10 06.3: Intelligence-only, nicht latenz-sensitiv)

**Was erhalten blieb (unveraendert, BLEIBT auch in 08.5):**
- `_write_ft_assistant_event` (FT-Logging Asset)
- Kaufbereitschafts-Tracking
- Phase-Classifier (every 5th cycle)
- Cold-Call-Inference
- Active-Hint-Orchestration

### Implication fuer Phase 08.5

Phase 08.5 reaktiviert Claude im analyse_loop als Klassifikator. Die Voraussetzung zum Vermeiden des alten Bugs:

**CRITICAL: qa_pipeline darf NIEMALS in Slot 0 oder Slot 1 rendern wenn der Keyword-Matcher bereits gefeuert hat.** Das D-02 Vorrang-Prinzip ist direkt aus diesem Bug abgeleitet. Die Implementierung muss folgendes sicherstellen:

1. Keyword-Matcher pruefen ZUERST (im Deepgram-Callback-Thread, <1ms)
2. Nur wenn Keyword-Matcher NICHT gefeuert hat → Klassifikator-Call
3. `slot1_variant_busy_until` in `ls.state` als Mutex-Guard nutzen (bereits vorhanden, Phase 06.2)
4. qa_pipeline nutzt `analysiere_mit_claude()`-Stil (non-streaming fuer Klassifikation) + Streaming nur fuer Antwort-Generierung in Slot 1
5. Vorlese-Text-Problem: Falls ein User die qa-Antwort vorliest und Deepgram das aufnimmt, muss der Klassifikator `smalltalk/none` zurueckgeben → keine Reaktion. Das geschieht durch guten Klassifikator-Prompt (nicht durch einen separaten Filter).

### Anti-Patterns to Avoid

- **Streaming fuer Klassifikation:** Klassifikator-Call MUSS non-streaming sein (kleines JSON-Output). Streaming nur fuer Antwort-Generierung (Slot 1 render).
- **Embedding-Modell per Request laden:** sentence-transformers Modell EINMAL beim Service-Start in Modul-Global cachen, NICHT per Request neu laden (5-10s Ladezeit).
- **Beide Pfade parallel:** NIEMALS Keyword-Matcher UND Klassifikator fuer denselben Utterance in Slot 0/1 rendern lassen — das war der Phase-06.3-Bug. Sequentiell + Threshold-Skip (D-01, D-02).
- **Tabu-Filter vor FAQ-Match:** Tabu-Filter kommt NACH Antwort-Generierung, NICHT vorher. Erst generieren, dann filtern.
- **profile_faqs ohne Index:** `frage_muster`-Felder werden nur bei FAQ-Match geladen — kein Volltextindex noetig fuer v1 (<50 FAQs per Profil).

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Semantic Embedding/Similarity | Eigenen Embedding-Layer | `sentence-transformers` `paraphrase-multilingual-MiniLM-L12-v2` | Edge-Cases bei Deutsch: Umlaute, Konjugationen, Modalpartikeln |

## Common Pitfalls

### Pitfall 1: Vorlese-Text-Loop (Phase 06.3 Bug Redux)
**What goes wrong:** User liest KI-Antwort aus Slot 1 vor → Deepgram transkribiert → analyse_loop klassifiziert als frage oder einwand_unknown → generiert Antwort auf die eigene Antwort
**Why it happens:** Deepgram trifft keinen Unterschied zwischen Kunden-Utterance und Berater-Utterance im Cold-Call-Modus
**How to avoid:** Klassifikator-Prompt muss explizit erkennen: "Wenn der Sprecher (Berater) einen fertigen Satz vorliest, der wie eine Vertriebs-Antwort klingt, klassifiziere als 'smalltalk_none'." Alternativ: session_mode='cold_call' → Berater-Audio-Abschnitte via Mute-Track erkennbar
**Warning signs:** Logs zeigen `[QA] classify utterance=...gegenargument...` → `kategorie=frage` → zweite Antwort generiert

### Pitfall 2: Embedding-Modell Cold-Start
**What goes wrong:** Erstes FAQ-Match nach Server-Start dauert 10+ Sekunden
**Why it happens:** sentence-transformers laedt Modell (~83MB) beim ersten `SentenceTransformer()` Aufruf
**How to avoid:** Modell beim App-Start in `app.py` pre-loaden (oder lazy-init in `qa_pipeline.py` Modul-Global, wird beim ersten Import getriggert)
**Warning signs:** Erster Live-Call nach Deployment hat 10s Latenz-Spike in Logs

### Pitfall 3: slot1_variant_busy_until Race-Condition
**What goes wrong:** Klassifikator und Keyword-Matcher feuern gleichzeitig fuer denselben Utterance → beide rendern in Slot 1
**Why it happens:** Deepgram-Callback und analyse_loop laufen in verschiedenen Threads
**How to avoid:** Keyword-Matcher schreibt `ls.state['kw_fired_for_line'] = line_id` unter `state_lock`. analyse_loop prueft das Flag ZUERST unter `state_lock`. Wenn Flag gesetzt → skip Klassifikator. Flag reset bei Utterance-Ende.
**Warning signs:** PiP Slot 1 flackert / zeigt zwei Antworten kurz hintereinander

### Pitfall 4: profile_faqs Org-Isolation vergessen
**What goes wrong:** User sieht FAQs eines anderen Profils
**Why it happens:** DB-Query ohne org_id-Filter
**How to avoid:** Alle `profile_faqs`-Queries IMMER mit JOIN auf `profiles.org_id = g.org.id` (analog zu Profil-CRUD-Pattern in `routes/profiles.py`)
**Warning signs:** SQL-Injection via profile_id-Parameter moeglich (ASVS V4)

### Pitfall 5: Anrede-UX Edge-Case: Auto-Select Skript
**What goes wrong:** User hat nur ein Skript im Profil → Skript-Auswahl wird uebersprungen → Anrede-Auswahl auch uebersprungen → `conversation_logs.anrede` bleibt NULL → Profil-Default greift statt Session-Override
**Why it happens:** D-10 definiert diesen Edge-Case explizit aber er ist leicht zu uebersehen
**How to avoid:** Wenn nur ein Skript vorhanden: Skript wird auto-selected, ABER ein expliziter Anrede-Zwischen-Schritt (2-Button-Row) wird trotzdem eingeblendet. Kein Skip erlaubt.
**Warning signs:** `conversation_logs.anrede = NULL` in DB bei Single-Skript-Profilen

### Pitfall 6: Training-Prompt-Umbau bricht bestehende Training-Sessions
**What goes wrong:** `prompt_versions`-Tabelle hat keinen Eintrag fuer `module='training_kunde'` → `_load_prompt_template` faellt auf Fallback → Training-Bot antwortet mit Generic-Prompt ohne Profil-Kontext
**Why it happens:** Vergessen, Seed-SQL fuer neue Training-Module in `_migrate()` zu schreiben
**How to avoid:** `INSERT OR IGNORE` fuer alle neuen `prompt_versions`-Zeilen in `_migrate()` VOR dem ersten Training-Call. Analog Phase 08 Pattern.
**Warning signs:** `[Training] template miss version=v1-training_kunde — using fallback` im Log

### FAQ-Embedding-Match Pattern

```python
# Source: sentence-transformers Dokumentation [CITED: sbert.net]
# Lazy-Init Pattern analog _COMPILED_KEYWORDS in einwand_keyword_matcher.py [VERIFIED: Codebase]

from __future__ import annotations
from typing import Optional
import threading

_MODEL = None
_MODEL_LOCK = threading.Lock()

def _get_model():
    global _MODEL
    if _MODEL is None:
        with _MODEL_LOCK:
            if _MODEL is None:
                from sentence_transformers import SentenceTransformer
                _MODEL = SentenceTransformer('paraphrase-multilingual-MiniLM-L12-v2')
    return _MODEL

def match_faq(utterance: str, faqs: list[dict], threshold: float = 0.75) -> Optional[dict]:
    """
    Semantic FAQ-Match. faqs: [{'id': int, 'frage_muster': str, 'antwort': str}]
    Returns matching faq dict oder None wenn kein Match ueber threshold.
    MUST NOT raise. [ASSUMED: ~50ms Inferenz auf CX22 CPU fuer <100 FAQs]
    """
    if not faqs or not utterance:
        return None
    try:
        model = _get_model()
        from sentence_transformers import util
        q_emb = model.encode(utterance, convert_to_tensor=True)
        faq_texts = [f['frage_muster'] for f in faqs]
        f_embs = model.encode(faq_texts, convert_to_tensor=True)
        scores = util.cos_sim(q_emb, f_embs)[0]
        best_idx = int(scores.argmax())
        if float(scores[best_idx]) >= threshold:
            return faqs[best_idx]
    except Exception as e:
        print(f"[QA] FAQ-Match failed: {e}")
    return None
```

### apply_tabu_filter() v1 Pattern

```python
# Source: eigene Implementierung basierend auf D-16 [ASSUMED: Impl-Detail, Claude's Discretion]
import re

def apply_tabu_filter(text: str, tabu_begriffe: list[str]) -> bool:
    """
    Returns True wenn Text einen Tabu-Begriff enthaelt (→ Antwort verwerfen).
    case-insensitive, Wortgrenzen-tolerant fuer Komposita.
    Fuer v1: einfaches substring-Match reicht.
    """
    if not tabu_begriffe or not text:
        return False
    text_lower = text.lower()
    for begriff in tabu_begriffe:
        if not begriff:
            continue
        if begriff.lower() in text_lower:
            return True
    return False
```
