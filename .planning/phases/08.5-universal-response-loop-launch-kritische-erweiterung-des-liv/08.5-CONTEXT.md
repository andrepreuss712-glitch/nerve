## Implementation Decisions

### Klassifikator-Architektur (aus Discuss 23.04.2026)

- **D-01: Latenz-Strategie — Sequential + Threshold-Skip.**
  Klassifikator läuft als erster Call (Haiku). Wenn Keyword-Matcher bereits in Slot 0 gefeuert hat (`einwand_known`), wird der Klassifikator-Output für diesen Utterance ignoriert — kein zweiter Call. Nur bei `einwand_unknown` oder `frage` folgt der zweite Call (Antwort-Generation). Haiku-only constraint absolut (CLAUDE.md: Sonnet MUSS aus Live-Loop raus).

- **D-02: Slot-Kollision — Keyword-Matcher hat Vorrang.**
  Wenn Keyword-Matcher in Slot 0 feuert → Klassifikator-Output für denselben Utterance wird verworfen. Deterministisch, kein Race-Condition-Risiko. Kein "beide rendern".

- **D-03: Confidence-Schwelle — 0.80 via Env-Var.**
  Default: `CLASSIFIER_CONFIDENCE_THRESHOLD=0.80` (nicht 0.75 wie im Briefing — 0.75 war ohne Live-Daten zu optimistisch). Unter 0.80 → keine Antwort-Generation. Env-Var erlaubt Justierung ohne Code-Deploy. Admin-Panel-UI kommt post-Launch wenn Praxis-Daten vorliegen.

- **D-04: Fallback bei Low-Confidence — Subtiler Soft-Hint.**
  Kein leerer Slot, aber kein aggressiver Warn-Text. Kleiner grauer Text im Slot-Bereich: "Einwand gehört — du selbst" oder "kein sicherer Treffer". Kein Emoji, kein Warn-Gelb. Position: unterhalb Slot oder im leeren Slot-Bereich, dezent.
  **Claude Code soll in Plan-Phase 2-3 Text-Varianten vorschlagen und per AskUserQuestion wählen lassen** (Finalisierung erst dort).
  Optionaler Post-Call-Bonus (v1 nicht zwingend): Liste unsicher klassifizierter Einwände im Session-Detail (/session/<id>).

### Quality-Gates (LOCKED aus Briefing)

- **D-05: Phase-08-Gate gilt auch für unknown-generierte Antworten.**
  80% sofort-vorlesbar + 3 Sub-Kriterien gelten identisch. Separater Test-Datensatz in Wave 7 nötig: 20 Fragen × 3 Branchen (SaaS, Maschinen, Vermögen) = 60 Q&A-Paare. André erstellt Content-Grundlage, Claude Code baut Test-Logik.

### Pipeline-Anbindungen

- **D-06: Phase 06.3 Entkopplungs-Grund — PFLICHT-RESEARCH für Researcher-Agent.**
  Der Code-Kommentar in `services/claude_service.py:1066` lautet: "Phase 06.3: analyse_loop no longer renders into PiP slots. - **D-07: Training-Pipeline — Komplett-Umbau (nicht minimaler Patch).**
  `training_service.py` wird vollständig auf v2-modular umgestellt. Scope:
  - Nutzt `prompt_pipeline` + `ewb_pipeline` (nicht nur EWB-Aufruf)
  - Kunden-Simulations-Prompts in `prompt_versions` versioniert
  - Scoring-Prompts in `prompt_versions` versioniert
  - Stimmungs-Prompts in `prompt_versions` versioniert
  - Alle Training-Events mit `prompt_version`-Tags in FT-Tabellen (analog `ft_assistant_events`)
  - A/B-Test-Fähigkeit für Kunden-Personas und Kritiker-Prompts
  **Begründung:** Phase 4.7.1 hat `prompt_versions`-Tabelle für Milestone 7.2 (eigene fine-tuned NERVE-KI) eingeführt. Minimaler Patch (Option 1) würde nur EWB-Antworten versioniert speichern — Kunden-Simulation, Scoring, Stimmung blieben ohne Version-Tag. Alt-Training-Sessions wären für Fine-Tuning wertlos (nicht rückwirkend analysierbar). Zusatz-Aufwand: +8-12h.

### Anrede-UX-Umzug (LOCKED aus Briefing — 5 konkrete Änderungen)

- **D-09:** PreCall-Anrede-Button entfernen aus `templates/pip-launcher` (oder wo die 2-Button-Row sitzt).
- **D-10:** Skript-Auswahl-UI erweitern: 2-Button-Row "Du / Sie" als Pflichtfeld im Skript-Wahl-Modal. Vorbelegt mit letztem Call-Wert als stärkerem Default, Profil-Default als Fallback.

- **D-11:** `conversation_logs.anrede` bleibt als Session-Feld — Quelle wechselt von PreCall-Button auf Skript-Auswahl.

### FAQ-Feld + Exclusion-Liste + Tabu-Filter (LOCKED aus Briefing)

- **D-13: Neue DB-Tabelle `profile_faqs`.**
  Felder: `id`, `profile_id`, `frage_muster` (Freitext), `antwort` (Freitext), `kategorie` (Technik/Preis/Referenzen/DSGVO/Produkt/...), `created_at`, `used_count`.

- **D-14: Matching-Strategie v1 — Semantic Similarity, Schwelle 0.75.**
  Embedding-Provider: Noch offen — DSGVO-Argument spricht für Claude-API via AWS Bedrock Frankfurt (eu-central-1), nicht OpenAI ada-002 (US-Server). **Researcher-Agent soll DSGVO-Konformität + Cost-Vergleich aufstellen** und Empfehlung liefern.

- **D-15: Neues Profil-Feld `profile.tabu_begriffe`.**
  Liste von Begriffen/Themen die KI nie erwähnen darf (Konkurrenz, Preis vor Demo, rechtlich riskante Claims). UI: einfache Tag-Liste im Profil-Editor.

- **D-16: `apply_tabu_filter()` als Post-Processing-Step.**
  Auf generierte Antwort (sowohl für frage- als auch einwand_unknown-Pfad). Enthält Antwort einen Tabu-Begriff (case-insensitive, stem-tolerant): Antwort verwerfen, Fallback ausgeben (still oder Soft-Hint per D-04).
