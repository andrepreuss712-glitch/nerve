## Summary

Review covers the Phase 08.5 Universal Response Loop additions: the QA pipeline (`qa_pipeline.py`), the classifier confidence threshold (`config.py`), the FAQ CRUD routes (`routes/profiles.py`), and the `EinwandKeywordMatcher` dedup guard (`einwand_keyword_matcher.py`), along with supporting infrastructure across `claude_service.py`, `live_session.py`, and the test suites.

Six warnings cover missing `_qa_pipeline_dispatch` function referenced in tests, the embedding model's `False`-sentinel conflation, an `OR`-precedence edge case in `_require_own_profile`, a static file pattern not used for CSS, an unreachable branch in `analyse_loop`, and reset logic missing new Phase 08.5 state keys. Four info-level findings cover dead imports, a redundant `import json` inside a loop, repeated `_json` re-imports in a single function, and a magic number in `qa_pipeline.py`.

## Critical Issues

### CR-01: `_parse_json` raises `ValueError` / `IndexError` on empty or malformed Claude output

**File:** `services/claude_service.py:463`
**Issue:** `_parse_json` slices with `raw[start:end]` where `start = raw.find('{')` and `end = raw.rfind('}') + 1`. When Claude returns an empty string or a response that contains no JSON object (e.g., a refusal, an apology, or a 529-overloaded error message that leaked through), `find` returns `-1` and `rfind` returns `-1`, so the slice becomes `raw[-1:0]` (empty string) and `json.loads('')` raises `json.JSONDecodeError`. This exception is NOT caught in `analysiere_mit_claude` — it propagates up through `analyse_loop` and kills the background analysis thread permanently. The `analysiere_coaching` call has the same exposure. Once the thread dies it never restarts, silently breaking the entire live loop for the remainder of the session.

**Fix:**
```python
def _parse_json(raw: str) -> dict:
    if not raw:
        return {}
    start = raw.find('{')
    end   = raw.rfind('}') + 1
    if start == -1 or end == 0 or start >= end:
        return {}
    try:
        return json.loads(raw[start:end])
    except json.JSONDecodeError:
        return {}
```
Callers (`analysiere_mit_claude`, `analysiere_coaching`, `classify_phase`) already handle `{}` gracefully.

### CR-02: `_letzte_gemeldete_version` dict grows unbounded — potential memory leak / state pollution across users

**File:** `routes/app_routes.py:13`
**Issue:** `_letzte_gemeldete_version: dict = {}` maps `user_id -> last_version` and is written on every `/api/ergebnis` poll (every ~500 ms per connected user). The dict is never pruned. On a long-running server with many users cycling through the app, this accumulates one entry per unique `user_id` permanently. More importantly, because this is a module-level mutable global shared across all requests, stale version numbers from previous sessions persist. If user A stops their session (version resets to 0 in `reset_session`), but `_letzte_gemeldete_version[A]` still holds the old high-water mark, the first API poll after session reset returns `version=0 <= stale_last_v` and the "Neues Ergebnis" log line is never printed until the version counter exceeds the stale value. This is a correctness bug in single-server deployments.

**Fix:**
```python
# In reset_session() in live_session.py, broadcast a signal so app_routes can clear the entry.
# Simplest fix: clear on session start (api_beenden triggers reset_session; complement with
# a clear in the reset path or on the /live route):

# In api_beenden (app_routes.py), after reset_session():
uid = getattr(g, 'user', None) and g.user.id
if uid and uid in _letzte_gemeldete_version:
    _letzte_gemeldete_version.pop(uid, None)

# Also cap dict size as a safety net:
MAX_VERSION_CACHE = 500
if len(_letzte_gemeldete_version) > MAX_VERSION_CACHE:
    _letzte_gemeldete_version.clear()
```

### WR-02: Embedding model sentinel `False` is truthy-checked inconsistently — model load failure may not be detected

**File:** `services/qa_pipeline.py:78`
**Issue:** When `SentenceTransformer` initialization fails, `_MODEL` is set to `False` as a sentinel to prevent retry. The getter returns `_MODEL if _MODEL else None` — this works, but the docstring says "MUST NOT raise" and the sentinel pattern is fragile: any future refactor that does `if _MODEL is not None` (common Python idiom) instead of `if _MODEL` would treat `False` as "model loaded but falsy", causing a `TypeError` when `.encode()` is called on `False`. Additionally, `_MODEL` starts as `None` (missing), becomes a `SentenceTransformer` instance (loaded), or `False` (failed). The three-state distinction is meaningful but relies on implicit truthiness rather than an explicit type guard.

**Fix:**
```python
_MODEL_LOAD_FAILED = object()  # explicit sentinel, distinct from None

def _get_embedding_model():
    global _MODEL
    if _MODEL is _MODEL_LOAD_FAILED:
        return None
    if _MODEL is None:
        with _MODEL_LOCK:
            if _MODEL is None:
                try:
                    from sentence_transformers import SentenceTransformer
                    _MODEL = SentenceTransformer('paraphrase-multilingual-MiniLM-L12-v2')
                except Exception as e:
                    print(f"[QA] embedding model load failed: {e}")
                    _MODEL = _MODEL_LOAD_FAILED
                    return None
    return _MODEL if _MODEL is not _MODEL_LOAD_FAILED else None
```

### WR-03: `_require_own_profile` — org isolation check can return wrong result when `g.org` attribute is checked but `g.org.id` is 0 (falsy)

**File:** `routes/profiles.py:408`
**Issue:** The check `if not hasattr(g, 'org') or g.org is None or p.org_id != g.org.id` is correct for `None`, but `g.org.id` could theoretically be `0` (integer zero) on a corrupt DB row. `p.org_id != g.org.id` would evaluate correctly in that edge case, but the broader pattern of using `is None` as the only guard means if `g.org` is set but `g.org.id` is `0`, the comparison still works. The actual risk here is lower priority, but the function is called in all five FAQ/tabu mutation endpoints — a silent wrong-org access would be a security regression. The function also opens a DB session but does not close it on the `None` return path from `filter_by().first()` (line 405-406): the session `db` is returned to the caller, who is expected to call `db.close()` in the `finally` block. This is only safe if all callers actually do so — confirmed they do — but `db` leaks if the caller forgets to use the returned session in a try/finally. The pattern is fragile.

**Fix:** Document the contract clearly and add an assertion or rename to `_require_own_profile_or_none` to make the dual-return pattern explicit. Low risk in practice given current callers are all correct.

### WR-05: `match_faq` — `faqs[best_idx]` index may be wrong when some FAQ entries lack `frage_muster`

**File:** `services/qa_pipeline.py:264`
**Issue:** `faq_texts` is built by filtering `faqs` to only entries that have a non-empty `frage_muster` key. But `best_idx` is then used to index `faqs` (the unfiltered list) instead of the filtered subset. If any entry in `faqs` is missing `frage_muster` and appears before the best match in the original list, the index will return the wrong FAQ entry or raise `IndexError`.

```python
# Bug:
faq_texts = [f.get('frage_muster', '') for f in faqs if f.get('frage_muster')]
# ...
best_idx = int(scores.argmax())
return faqs[best_idx]  # wrong — best_idx is relative to filtered faq_texts, not faqs
```

**Fix:**
```python
# Build a parallel filtered list and index into it:
filtered_faqs = [f for f in faqs if f.get('frage_muster')]
if not filtered_faqs:
    return None
faq_texts = [f['frage_muster'] for f in filtered_faqs]
# ... (embeddings + cos_sim as before)
best_idx = int(scores.argmax())
best_score = float(scores[best_idx])
if best_score >= threshold:
    return filtered_faqs[best_idx]  # index into filtered list
```

### IN-02: `_ACTIVE_PROMPT_CACHE` in `claude_service.py` is never invalidated — stale after prompt updates

**File:** `services/claude_service.py:104`
**Issue:** `_ACTIVE_PROMPT_CACHE: dict = {}` caches `module -> version` lookups from `PromptVersion`. The cache is populated on first call and never cleared. If a prompt version is activated in the DB while the server is running, the cache continues to serve the stale version until the server restarts. For a solo-founder production system this is acceptable, but it makes the "activate new prompt" workflow require a restart, which is undocumented. The `PROMPT_EWB_VERSION_OVERRIDE` env var in `.env.example` is a separate mechanism that bypasses the DB entirely, so the cache issue only affects the non-override path.

**Fix:** Either document the "restart required after prompt update" limitation, or add a TTL-based expiry: `_ACTIVE_PROMPT_CACHE_TTL = {}  # module -> expiry time.monotonic()`.

### IN-04: `apply_tabu_filter` does substring match — short tabu terms may produce false positives

**File:** `services/qa_pipeline.py:281`
**Issue:** `apply_tabu_filter` uses plain substring match (`begriff.lower() in text_lower`). A tabu term like `"SAP"` would trigger on `"SAPPHIRE"` or `"Ich habe keine Kapazität"` if "ap" happened to appear. For single-character or very short tabu terms, false positives will silently discard valid responses without the user knowing why. The docstring notes "v1 (D-16)" indicating this is a known simplification, but it could cause confusing behavior in production with poorly configured tabu lists.

**Fix:** Add a warning log when a term is shorter than 3 characters, or use word-boundary matching for short terms:
```python
def apply_tabu_filter(text: str, tabu_begriffe: list) -> bool:
    if not tabu_begriffe or not text:
        return False
    text_lower = text.lower()
    for begriff in tabu_begriffe:
        if not begriff or not isinstance(begriff, str):
            continue
        s = begriff.strip()
        if not s:
            continue
        if len(s) < 3:
            # short terms: only match as whole word
            import re
            if re.search(r'\b' + re.escape(s.lower()) + r'\b', text_lower):
                return True
        elif s.lower() in text_lower:
            return True
    return False
```
