## Konflikt-Aufloesung

**D-05 vs. Req-4 — was gibt anonymize() bei Art-9-Treffer zurueck?**

Entscheidung: **D-05 Tuple-Interface gewaehlt.**
- `anonymize()` gibt bei Art-9-Treffer `('[ART9_REDACTED]', 'C')` zurueck (niemals None)
- Caller-Code prueft: `if not should_persist(anon_text): skip_insert()`
- Alternativ: `if anon_text == '[ART9_REDACTED]': skip_insert()`
- Begruendung: Tuple-Kontrakt ist konsistenter — kein `None`-Unpack-Fehler bei Caller-Seite (Pitfall 2 aus RESEARCH.md vermieden)

## Finding 1 Fix: ART9_KEYWORDS Modul-Level-Import

```python
# Korrekt (Modul-Ebene, Zeile ~14 in anonymization.py):
from services.art9_keywords import ART9_KEYWORDS

# _check_art9() verwendet ART9_KEYWORDS direkt ohne eigenes import-Statement:
def _check_art9(text: str) -> bool:
    text_lower = text.lower()
    for keywords in ART9_KEYWORDS.values():  # direkter Zugriff, kein import hier
        for kw in keywords:
            if kw in text_lower:
                return True
    return False
```
