### CR-02: Double-counting in error-rate — `_register_error()` and `_record_snippet_error()` both append to `_error_timestamps`

**Files modified:** `services/anonymization.py`
**Commit:** `89e10c1`
**Applied fix:** Removed all three `_record_snippet_error()` calls from the `except` blocks in `anonymize()` (Art-9, Regex, and NER steps). Only `_register_error()` is now called in each error path — it already does the full append-prune-threshold-check including setting `is_pipeline_healthy = False`. This restores the circuit breaker to its intended 5-error threshold instead of tripping at 3.

### WR-01: `anonymize_output()` not called on auto-variant streamed result in `streame_auto_variante`

**Files modified:** `services/claude_service.py`
**Commit:** `b0b8f6d`
**Applied fix:** Added an `anonymize_output()` call on `cleaned` (the final assembled AI text) in `streame_auto_variante` after streaming completes and before the `pip_token_done` emit. Uses `ls.get_anonymisierer(sid)` to retrieve the per-SID cache. Wrapped in try/except so a failure is non-fatal and logged. The anonymized `cleaned` is then used in both the `result` dict and the `pip_token_done` event.

### WR-02: `_apply_regex_filter` mutates `text` while `_parse_phone_de` runs on already-tokenized text

**Files modified:** `services/anonymization.py`
**Commit:** `c77a2dd`
**Applied fix:** Hoisted `_parse_phone_de(text)` to run on the original `text` at the top of `_apply_regex_filter`, before any IBAN or email substitutions. The result is stored in `_phone_vals`. The phone-replacement loop now iterates over `_phone_vals` instead of calling `_parse_phone_de(text)` mid-function on the already-mutated text.

### WR-03: `init_anonymisierer()` never called in session-start path — anonymizer always `None`

**Files modified:** `services/deepgram_service.py`
**Commit:** `9dcc871`
**Applied fix:** Added `ls.init_anonymisierer(_sid)` immediately after `ls.init_session_state(...)` closes in `handle_start_live_session`. This creates the `AnrufAnonymisierer` instance for the SID so that `ls.get_anonymisierer(sid)` returns a real cache object for all subsequent transcript and output anonymization calls.

---

### WR-04: Thread-safety documentation gap in `anonymize_output()`

**Files modified:** `services/anonymization.py`
**Commit:** `d0e7d8e`
**Applied fix:** Added a documentation block to the `anonymize_output()` docstring explaining the known snapshot-outside-lock design: the lock is held only for the mapping snapshot; the replacement loop runs outside the lock (correct because tokens are write-once). Documents the known limitation that entries added concurrently after the snapshot are missed for the current pass, and notes the risk is low for the current single-session-per-SID usage (D-08, WR-04).

---

### WR-05: `[ART9_REDACTED]` sentinel check does not guard `_merge_pending` queue — raw Art-9 text flows into analysis buffers

**Files modified:** `services/deepgram_service.py`
**Commit:** `a64dc45`
**Applied fix:** Introduced `_text_for_analysis` variable (initialized to raw `text` as a safe fallback) that is set to the anonymized text on success, or `None` on Art-9 hit, pipeline error, or any exception. The entire `_merge_pending` block is now guarded by `if _text_for_analysis is not None:`, and both the append-to-existing and create-new paths use `_text_for_analysis` instead of raw `text`. Art-9 and error cases also set `_text_for_analysis = None` in their respective branches so the analysis buffers (`_per_sid_transcript`, `_per_sid_coaching_buffer` via `_flush_segment`) never receive Art-9 content.
