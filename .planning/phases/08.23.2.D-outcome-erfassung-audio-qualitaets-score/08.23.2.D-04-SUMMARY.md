## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] SQLite BIGINT NOT NULL autoincrement-Konflikt in CallEvent-Tests**

- **Found during:** Task 4.2 Test-Ausfuehrung (test_audio_health_bg_writes_score_and_callevent_with_buffer)
- **Issue:** SQLite erkennt AUTOINCREMENT nur fuer `INTEGER PRIMARY KEY`, nicht fuer `BIGINT PRIMARY KEY`. call_events.id ist `BIGINT NOT NULL` -> INSERT ohne explizite id schlaegt fehl mit `NOT NULL constraint failed: call_events.id`.
- **Fix:** `itertools.count()` mit time-basiertem Start als Test-Counter fuer event_id. Explizite `id=next(_event_id_counter)` bei jedem CallEvent-Insert im Test. Kein Produktionscode-Aenderung.
- **Kein Rule 4:** Das ist ein Test-only-Fix, kein Architektur-Aenderung. Der Produktionscode in api_beenden nutzt denselben CallEvent-INSERT-Pattern — dort funktioniert er weil das ORM `autoincrement=True` hat und bei echten Engines (PostgreSQL) korrekt autoincrement nutzt. Fuer SQLite-Tests ist explizite ID erforderlich.
- **Files modified:** tests/test_api_beenden_calls_update.py
- **Commit:** c7afd2b

**2. [Rule 1 - Minor] UUID als str() fuer SQLite-Compat in _make_test_call()**

- **Found during:** Task 4.2 erster Test-Lauf
- **Issue:** `uuid.uuid4()` gibt UUID-Objekt zurueck. SQLite unterstuezt keinen nativen UUID-Typ -> `ProgrammingError: type 'UUID' is not supported`.
- **Fix:** `call_id = str(uuid.uuid4())` in `_make_test_call()`.
- **Files modified:** tests/test_api_beenden_calls_update.py
- **Commit:** c7afd2b

**3. [Rule 1 - Minor] Import-Alias fuer Call im UPDATE-Block**

- **Found during:** Task 4.1 Implementation
- **Issue:** Der Plan-Vorschlag `from database.models import Call, CallEvent` im UPDATE-Block wuerde mit dem `Call`-Namen im Thread-Scope kollidieren.
- **Fix:** `_CallModel` im UPDATE-Block, `_CallAH`/`_CallEventAH` im Thread-Body als Aliase.
- **Files modified:** routes/app_routes.py
- **Commit:** 10c3b3b
