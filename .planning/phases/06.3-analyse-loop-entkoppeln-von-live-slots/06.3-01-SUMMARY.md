# Phase 06.3 Plan 01: analyse_loop Slot-Entkopplung Summary

**One-liner:** Removed all Claude streaming/slot render paths from analyse_loop; Keyword-Matcher (06.2) is now sole PiP-slot primary, eliminating the parallel-call cascade that caused Anthropic 529 errors during EWB-Vorlesen.

## What Was Done

### Task 1 — Surgical removal of all slot render paths from analyse_loop

In `services/claude_service.py`, the `if active_sid:` branch of `analyse_loop` previously:
1. Spawned `streame_auto_variante(..., trigger="analyse_loop")` via `sio.start_background_task` — feeding Slot 1
2. Called `analysiere_mit_claude_streaming(neuer_text, kontext, active_sid, slot_id)` — feeding Slot 0 via pip_token events

Both paths are now replaced with a single non-streaming `analysiere_mit_claude(neuer_text, kontext)` call — the same function the non-PiP `else:` branch already used.

Removed code:
- `slot_id = 0`, `analyse_loop._last_slot`, `analyse_loop._last_slot_time` (D-11: write-only)
- `slot1_variant_busy_until` busy-guard block
- `sio.start_background_task(streame_auto_variante, ..., "analyse_loop")` call
- `analysiere_mit_claude_streaming(...)` call
- Stale Phase-06 D-08/D-09 slot-assignment comments

Preserved untouched:
- `_write_ft_assistant_event` (FT-Trainingsdaten, lines 118 + 733 + 1074 + 1358)
- Kaufbereitschafts-Tracking (lines ~1033-1068)
- Phase-Classifier (runs every 5th cycle, lines ~1097-1120)
- Cold-Call-Inference (lines ~1120-1140)
- Active-Hint-Orchestration (lines ~1140-1200) — emits coaching hints to separate UI channel, not Slot 0/1

### Task 2 — ANALYSE_INTERVALL 2s → 4s

`config.py` line 34: `ANALYSE_INTERVALL = 4` with comment explaining the rationale. Halves Claude API call volume from the analyse_loop background thread. All analyse_loop consumers (FT-events, Kaufbereitschaft, Phase-Classifier, Cold-Call-Inference, Active-Hint-Orchestration) are non-latency-sensitive intelligence functions — 4s interval has zero user-visible impact.
