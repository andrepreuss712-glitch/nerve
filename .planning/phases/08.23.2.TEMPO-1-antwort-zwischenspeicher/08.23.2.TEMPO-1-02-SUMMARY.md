# Phase 08.23.2.TEMPO-1 Plan 02: Antwort-Zwischenspeicher — Marker setzen Summary

Der `cache_control`-Marker sitzt jetzt wert-basiert (`_layer=='stable'`) auf dem stabilen
Antwort-Prefix in `answer_system_content()`, geschaltet über `config.CACHE_ANTWORT`, abgesichert
durch 5 Marker-Tests plus einen E3-Byte-Gleichheits-Test des Anti-Cache-Poison-Filters.

## Was gebaut wurde

### Task 1 — Der Marker (Commit `2437fd3`)
- `answer_system_content()` (`services/prompt_pipeline.py`): die verwerfende List-Comprehension
  (`content = [{'type':'text','text':b['text']} for b in blocks if b.get('text')]`) ersetzt durch
  eine `for`-Schleife, die den Marker über den **`_layer`-Wert** setzt:
  `if _cache_an and not _cache_gesetzt and b.get('_layer') == 'stable': _block['cache_control'] = {'type': 'ephemeral'}`.
- Zuordnung ist **wertbasiert, nicht Index-basiert** — belegt: `grep -c "content[0]"` == 0.
- Genau 1 Breakpoint pro Request via `_cache_gesetzt`-Deckel (A4). Volatil-Block trägt nie `cache_control`.
- Schalter `config.CACHE_ANTWORT` via lazy `import config as _cfg` in der Funktion (Modul bleibt
  side-effect-free beim Import); fail-open (nie raise, ohne Config -> an).
- Fallback (`'Verstehen und helfen, nie druecken.'`) ohne Marker (A6).
- Docstring von „PHASE 1: PLAIN ... OHNE cache_control" auf den aktivierten Zustand ersetzt.
- `wc -l`: 686 (vor Task 1, Anker bestätigt) -> 717 (nach dem Marker-Einbau).
