# Cross-AI Plan Review — Phase 08.23.2.TAXO3 Scheibe (b) — ROUND 2

## Gemini Review (gemini-3.1-pro-preview)

### 1. Summary
The plans are meticulously detailed and correctly enforce the architectural mandates (RAM vs. DB,
explicit event shapes). The strict adherence to `_session_state` as the data source and the creation
of a dedicated `_continuation_fallback_until` are excellent structural choices. However, there are two
critical execution flaws that will break the live experience: a race condition between the audio
transcription and the button click, and a fundamental contradiction between forcing JSON output and
requiring low-latency token streaming.

### 2. Strengths
- **Persistence Layer Verification (b-01):** The explicit `inspect.sh` + writers-vs-readers table
  satisfies Punkt 26 and guarantees the Continuation button won't read stale batch data.
- **Circuit Breaker Isolation (b-03):** Excellent catch and design — a fully isolated
  `_continuation_ttft_history` / `_continuation_fallback_until` avoids EWB Haiku cross-contamination.
- **Fail-open & Graceful Degradation (b-02, b-03):** Fallback to the generic "Frag nach" instead of
  hanging, plus fail-open for the volatile context block, keep the live loop robust.
- **Event Contract (b-01):** `payload_jsonb` + schema version for the mirrored marker is the correct,
  pragmatic choice — no migration, retains queryability.

### 3. Concerns
- **🔴 HIGH — Audio/Click Race Condition (b-03):** The advisor speaks the echo and *immediately*
  presses the button. The Socket.IO click travels almost instantly; Deepgram STT takes ~300–500ms to
  arrive and append to `_session_state[sid]['analysiert_bisher']`. If the click handler reads RAM
  immediately, the mirrored echo is likely **not there yet** → the LLM continues from the *previous*
  turn. This is a Punkt-26 async-readiness case that RV-1 did NOT close: RV-1 proved RAM-vs-DB, but
  assumed RAM is *already filled* at click time. The reverse race (reader outruns the STT writer) is open.
- **🔴 HIGH — Streaming JSON Contradiction (b-03):** b-03 demands forced JSON
  (`{"action":"continue","text":"..."}`) AND streams output to the FE for TTFT. Streaming raw JSON
  sends literal brackets (`{"action...`) to the UI/TTS, breaking rendering. You cannot stream text out
  of a still-generating JSON envelope without a specialized buffering parser. RV-4's forced-JSON bailout
  directly conflicts with the Punkt-25 streaming/TTFT requirement.
- **🟡 MEDIUM — Python Scope Trap in Circuit Breaker (b-03):** Setting `_continuation_fallback_until`
  inside `streame_continuation_antwort` without `global _continuation_fallback_until` creates a local
  var → the breaker silently never trips globally.
- **🟡 MEDIUM — Punctuation in Burned Openers (b-02):** `derive_burned_openers` extracting the first
  word without stripping punctuation treats "Verstehe," and "Verstehe." as different openers →
  dedup defeated, tic persists.
- **🟢 LOW — Empty Context Handling (b-03):** Button pressed at call start (before any speech) →
  `analysiert_bisher` empty → strong model may hallucinate an opening.

### 4. Suggestions
- **Fix the Audio Race (b-03):** Add a short debounce/delay (~500ms) in `pip-launcher.js` before
  emitting `freie_antwort`, OR have the backend handler briefly wait/check for STT quiescence, giving
  Deepgram time to append the echo to RAM. (Consider a readiness-seam check rather than a fixed sleep.)
- **Simplify the Bailout Format (b-03):** Drop forced JSON. Use a **text-prefix contract**: instruct
  the LLM *"If unclear, start your response exactly with 'ASK_CLARIFICATION: '. Otherwise stream the
  continuation text normally."* The backend buffers the first few tokens; if it sees the prefix, it
  aborts and emits the generic fallback. Preserves TTFT streaming, no JSON parsing acrobatics.
- **Enforce `global` (b-03):** Explicitly require `global _continuation_fallback_until` in b-03 Task 1.
- **Normalize Openers (b-02):** Explicitly require punctuation stripping (regex `[^\w\s]`) + lowercasing
  for comparison in `derive_burned_openers`.
- **Empty Context Guard (b-03):** In `handle_freie_antwort`, if context is empty/too short, return the
  generic "Frag nach" immediately without calling the LLM.

### 5. Risk Assessment
**Overall Risk: HIGH. Go/No-Go: NO-GO for Execute.**
The plans model the architecture correctly, but b-03 will fundamentally fail in production: the race
guarantees the model won't see the echo, and the JSON-streaming contradiction outputs literal JSON to
the FE. Both HIGH risks must be patched into the plans first. Fixes are straightforward (prefix instead
of JSON, click delay/readiness-check) but must be explicitly detailed before execution.
