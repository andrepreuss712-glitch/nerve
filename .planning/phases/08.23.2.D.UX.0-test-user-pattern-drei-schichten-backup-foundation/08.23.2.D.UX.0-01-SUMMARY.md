### Email-Guard Smoke-Test (Production-REPL, beide Formen)

```
# (a) to als LISTE:

[EMAIL] test-user recipient ['andre-test@nerve.local'], skip
RESULT: False

# (b) to als BARE STRING (G-1 kritischer Bypass-Beleg):
$ python -c "from services.email_service import _send; print(_send({'to': 'andre-test@nerve.local', ...}))"

RESULT: False
```

Beide Formen blockiert. Der bare-String-Fall (b) belegt dass G-1 (isinstance-Normalisierung) korrekt funktioniert — ohne diese Normalisierung wuerde `any(... for r in recipients)` bei einem String ueber einzelne Zeichen iterieren und der endswith-Check wuerde nie matchen.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] alembic upgrade als postgres-User (nicht nerve_app)**
- **Gefunden bei:** Task 2 Produktion-Upgrade
- **Problem:** `nerve_app` hat kein `CREATE SCHEMA`-Recht → `alembic upgrade head` schlaegt fehl mit `permission denied for database nerve`
- **Fix:** Migration als `sudo -u postgres DATABASE_URL=postgresql:///nerve alembic upgrade head` ausgefuehrt
- **Erklaerung:** Dieses Verhalten ist KORREKT und sicherheitsmaessig beabsichtigt. nerve_app ist kein DDL-User. Aenderung nur in Ausfuehrungs-Methode, nicht in der Migration selbst.
- **Commit:** kein separater Commit (Deployment-Schritt)

**2. [Rule 3 - Blocking] seed_test_user.py braucht DATABASE_URL Env-Variable**
- **Gefunden bei:** Task 3 Seed-Ausfuehrung auf Production
- **Problem:** Skript ohne DATABASE_URL laedt SQLite (Default), nicht Postgres. `sudo -u nerve_app` mit Peer-Auth funktioniert.
- **Fix:** `sudo -u nerve_app bash -c 'DATABASE_URL=postgresql://nerve_app@/nerve ... python scripts/seed_test_user.py'`
- **Erklaerung:** Korrekt — seed_test_user.py-Doku im Docstring beschreibt dies als Ausfuehrungs-Pattern

**3. [Rule 1 - Bug] seed_test_user.py market-Wert korrigiert**
- **Gefunden bei:** Task 3 Code-Review vor Commit
- **Problem:** Plan-Vorlage hatte `market='de'`, aber models.py hat `default='dach'` und NOT NULL
- **Fix:** `market='dach'` im Seed-Skript (Spalte ist NOT NULL, falscher Default wuerde Fehler vermeiden aber falschen Wert setzen)
