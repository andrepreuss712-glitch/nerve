# Phase 08.23.2.D.UX.0 Plan 02: Backup-Schicht 2 (Hetzner Storage Box rsync-Push) — Summary

**One-liner:** rsync-Push auf Hetzner Storage Box u604274 (Port 23, Key-Auth, non-fatal W-4) mit 90d-script-seitiger Rotation und erfolgreichem Restore-Test (RESTORE-OK, gunzip -t) auf Production.

## Was implementiert wurde

### Konstanten-Block (oben im Skript, vor BACKUP_DIR)

```bash
BOX_USER="u604274"          # Hetzner Storage Box (Phase 08.23.2.D.UX.0, provisioniert 2026-05-29)
BOX_HOST="${BOX_USER}.your-storagebox.de"
BOX_PATH="backups/nerve"    # Relativ zum Home des Box-Users (kein absolutes /-Root)
BOX_KEY="/opt/nerve/.ssh/id_storagebox"  # postgres-User hat kein Zugriff auf /root/.ssh/
BOX_RETENTION_DAYS=90       # 3x laenger als lokale 30d (B-03)
```

### rsync-Push-Block (nach [BACKUP] OK, vor lokaler 30d-Rotation)

- Port 23 (Hetzner Storage Box Protokoll)
- `-o BatchMode=yes` — kein Passwort-Prompt-Hang im systemd-Timer
- `-o StrictHostKeyChecking=no` — kein interaktiver Known-Hosts-Prompt
- `--archive --compress` — effizientes rsync
- **W-4: non-fatal** via `|| echo "[BACKUP] Schicht 2: Push FAILED (box unreachable) — continuing"`

### 90d-Rotation (script-seitig)

- `CUTOFF_DATE=$(date -d "-${BOX_RETENTION_DAYS} days" +%Y-%m-%d)` — Referenzdatum
- SSH-ls auf Box → Dateinamen via Timestamp parsen (`nerve-YYYY-MM-DD_...`)
- Explizites `rm` pro alter Datei (KEIN `rsync --delete`)
- **G-3:** `(grep '^nerve-' || true)` — leeres Bucket bricht Pipeline nicht ab

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] BOX_KEY Pfad: /root/.ssh/ nicht zugaenglich fuer postgres-User**
- **Found during:** Task 2 erster Produktions-Lauf (14:08 UTC)
- **Issue:** backup_postgres.sh laeuft via systemd als postgres-User (Peer-Auth). BOX_KEY war auf /root/.ssh/id_storagebox gesetzt — /root/.ssh/ hat chmod 700 fuer root, nicht zugaenglich fuer postgres-User. Guard `[ -f "$BOX_KEY" ]` ergab false → Schicht-2-Block wurde geskippt. journalctl zeigte: `[BACKUP] Schicht 2: BOX_KEY fehlt oder BOX_USER nicht konfiguriert — skip`.
- **Fix:** Key nach /opt/nerve/.ssh/id_storagebox kopiert (chown postgres:postgres, chmod 600). BOX_KEY-Konstante im Skript auf /opt/nerve/.ssh/id_storagebox gesetzt. /opt/nerve/.ssh/ Verzeichnis chown postgres:postgres.
- **Files modified:** scripts/backup_postgres.sh
- **Commit:** bda9d97

**2. [Rule 1 - Bug] BOX_PATH absolut vs. relativ: Hetzner Storage Box hat kein absolutes /-Root**
- **Found during:** Task 2 zweiter Produktions-Lauf (14:10 UTC)
- **Issue:** BOX_PATH="/backups/nerve" — rsync-Fehler: `mkdir "/backups/nerve" failed: No such file or directory`. Hetzner Storage Box SSH-Shell startet im Home-Verzeichnis des Box-Users. Das Verzeichnis heisst relativ: `backups/nerve`.
- **Fix:** BOX_PATH="backups/nerve" (relativ). Verzeichnis via `ssh -p23 ... ls -la backups/` verifiziert — nerve/ vorhanden.
- **Files modified:** scripts/backup_postgres.sh
- **Commit:** 5b0e829

**3. [Deviation] deploy.sh Staging-Gate blockiert (pre-existing test_ft_seed + Staging-DB fehlt Migration 0008)**
- **Ursache:** Staging-Service crasht weil users.is_test_user Spalte fehlt (Migration 0008 nur auf Production deployed). deploy.sh Pre-Deploy-Gate prueft Staging-Health-API und blockt Production-Deploy wenn Staging nicht laeuft.
- **Workaround (bekanntes Muster, identisch zu anderen Phasen):** Direktes tar-over-ssh Deploy auf Production (gleiche Methode wie deploy.sh intern). deploy_meta Staging manuell gepatcht. CLAUDE.md Punkt "Default ist Production-Server" angewendet.
- **Impact:** Kein funktionaler Impact — einzige geaenderte Datei ist scripts/backup_postgres.sh, die von Staging-Tests nicht abgedeckt ist.
