## What Was Built

### DB Models (Task 1)
- `ProfileSkript` model — table `profile_skripte` with `profile_id` FK, `name`, `inhalt`, `sortierung`, `created_at`
- `ProfileOpener` model — table `profile_opener` with identical structure
- Both auto-created via existing `init_db()` / `Base.metadata.create_all()`

### Profile Editor CRUD (Task 2)
- 8 new Blueprint endpoints under `/profiles/<pid>/skripte` and `/profiles/<pid>/opener`
- GET (list), POST (create), PUT (update by id), DELETE (delete by id)
- org_id guard on all read endpoints; owner/admin check on write endpoints
- CSS `.crud-card` and `.btn-add` classes added to `{% block extra_style %}`
- `crudList(containerId, endpoint, label)` JS helper: loads on page open, blur-saves name/inhalt, deletes with confirm
- `PROFILE_ID` template variable set from `{{ profile.id if profile else 'null' }}`
- Two new sections in Gespraechsleitfaden: "Skripte" and "Opener-Sammlung" with add buttons

### Launcher API Extension (Task 3)
- `api_launcher_init`: queries ProfileSkript/ProfileOpener for active profile, adds `skripte[]` and `opener[]` to response
- `api_launcher_profile/<pid>`: same — adds `skripte[]` and `opener[]` alongside `daten`

### PiP Launcher Step 5 (Task 4)
- State extended with `skripte[]`, `openerItems[]`, `selectedSkriptId`, `selectedOpenerId`
- Init fetch assigns `state.skripte` and `state.openerItems` from API response
- `renderStep5()` rebuilt: Profil label+dropdown → Skript label+dropdown+preview → Opener label+dropdown+preview → action buttons
- Profile change re-fetches skripte/opener, resets selections, re-renders step
- Skript/Opener `onchange` updates inline preview text immediately
- Legacy opener from `state.profileDaten.opener` shown as fallback when no ProfileOpener items exist
