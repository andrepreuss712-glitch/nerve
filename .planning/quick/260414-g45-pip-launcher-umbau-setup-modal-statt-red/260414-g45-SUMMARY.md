# Quick g45: PiP Launcher Umbau — Setup Modal statt Redirect

Setup-Flow laeuft jetzt als Modal ueber der aktuellen Seite (kein /live-Redirect), PiP enthaelt nur Live-Coaching, beide Systeme (pip-launcher.js und app.js /live) koexistieren konfliktfrei.

## What Was Built

### Task 1 — API endpoints + base.html modal shell + sidebar change

**routes/app_routes.py:**
- Added `GET /api/launcher/init` — returns `{ profiles, active_profile_id, precall_verfuegbar, profile_daten }`. Protected by `@login_required`, org_id filtered.
- Added `GET /api/launcher/profile/<int:pid>` — returns profile with parsed daten. Protected by `@login_required` + org_id filter (T-g45-02 mitigated).

**templates/base.html:**
- Sidebar "Live-Assistent" link changed from `href="/live"` to `onclick="window.NerveLauncher && window.NerveLauncher.open()"` — no page navigation.
- Replaced `#navLiveOverlay` + `#navConsentOverlay` + their inline script block with `#launcherModal` shell (pip-launcher.js populates `#launcherContent`).
- Added `#pip-live-window` hidden div with live coaching HTML (tabs, EWB row, beenden button, postcall section) using `nlp-*` IDs.
- Added full PiP CSS block (`.pip-*`, `.launcher-*` classes).
- Added `<script src="pip-launcher.js">` for logged-in users, before `{% block scripts %}`.

### Task 2 — static/pip-launcher.js (self-contained IIFE, ~900 lines)

6-step modal flow managed entirely in pip-launcher.js:
- **Step 1:** Mode selection (Cold Call / Meeting) with SVG cards
- **Consent (1.5):** Inline consent script for Meeting mode; rejection falls back to Cold Call
- **Step 2:** PreCall option (skipped if `precall_verfuegbar=false`)
- **Step 3:** PreCall research form (Firmenname, Ansprechpartner, Branche, Optionale Infos) with loading bar
- **Step 4:** PreCall result — read-only briefing with edit / new analysis / accept actions
- **Step 5:** Skript & Opener selection — profile dropdown with live opener preview, profile fetch on change

Call start (`startCall()`):
- Closes modal, sets profile server-side (fire-and-forget)
- Loads Socket.IO from CDN if not present
- Opens `documentPictureInPicture.requestWindow` + `getUserMedia` in same click handler (user gesture)
- Starts AudioWorklet at 16kHz, streams audio_chunk via own socket
- Moves `#pip-live-window` into PiP document, copies stylesheets, wires button events
- Starts timer, renders EWB buttons from profileDaten.einwaende

PostCall:
- `endCall()` stops mic, POSTs `/api/beenden`, calculates score (replicated calcPipScore logic) + tags (replicated buildHighlightTags)
- Shows score + tags in PiP; hides header/tabs/content/ewb-row/beenden button
- "Naechster Call" closes PiP + reopens setup modal
- "Details" navigates to `/logs/<conv_id>`

### Task 3 — app.html cleanup + app.js guards

## Deviations from Plan

### Auto-fixed / Implementation decisions

**1. nlp-* ID prefix for pip-live-window elements**
- Found during Task 1: the plan said to reuse existing pip-section-live HTML with existing IDs (pip-panel-opener, pip-timer, etc.)
- Issue: those same IDs exist in app.html's #pip-window — having both in the same document would cause getElementById conflicts when the /live page loads
- Fix: Used `nlp-` prefix for all pip-live-window element IDs (nlp-timer, nlp-mode-badge, nlp-panel-opener, etc.) and updated pip-launcher.js accordingly
- Files modified: templates/base.html, static/pip-launcher.js

**2. Meeting consent as inline step (not separate step number)**
- Plan described a 6-step flow; meeting consent was described as step within startCall()
- Implementation renders consent inline within the modal content area right after mode selection, before precall/skript steps
- Cleaner UX: no jump in step numbering, back button returns to mode selection
