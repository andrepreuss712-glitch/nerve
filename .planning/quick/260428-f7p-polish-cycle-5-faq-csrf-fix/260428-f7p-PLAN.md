Exakte Zeilenpositionen (aus Datei gelesen):

**Bug 1 — persistFaq() PUT-Branch, Z.160–165:**
```js
// VORHER (Z.160-165):
fetch('/profiles/api/profile/faqs/' + id, {
  method: 'PUT',
  credentials: 'same-origin',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(payload),
}).catch(function (e) { console.warn('[FAQ] update failed', e); });
```
Fix: Header um `'X-CSRFToken': getCsrfToken()` ergänzen. `.catch` durch `.then(function(r){ if(!r.ok) console.warn('[FAQ] update failed', r.status); }).catch(...)` ersetzen (kein DOM-Eingriff nötig, da kein row.remove() hier).

**Bug 2 — deleteFaq(), Z.187–194:**
```js
// VORHER (Z.187-194):
fetch('/profiles/api/profile/faqs/' + id, {
  method: 'DELETE',
  credentials: 'same-origin',
})
  .then(function () { row.remove(); })
  .catch(function (e) { console.warn('[FAQ] delete failed', e); });
```
Fix: X-CSRFToken-Header ergänzen. `.then` nur `row.remove()` aufrufen wenn `r.ok` — sonst Fehlermeldung loggen UND row NICHT entfernen:
```js
fetch('/profiles/api/profile/faqs/' + id, {
  method: 'DELETE',
  credentials: 'same-origin',
  headers: { 'X-CSRFToken': getCsrfToken() },
})
  .then(function (r) {
    if (r.ok) { row.remove(); }
    else { console.warn('[FAQ] delete failed', r.status); }
  })
  .catch(function (e) { console.warn('[FAQ] delete error', e); });
```

**Anti-Drift-Check (restliche fetch()-Calls in profile_editor.js):**
- Z.120 `loadFaqs` GET → kein CSRF nötig (read-only), kein DOM-remove → OK
- Z.169–181 `persistFaq` POST (create) → hat X-CSRFToken + r.ok-Check (Z.175) → OK
- Z.449–461 `saveTabuToServer` POST → hat X-CSRFToken (Z.452) — ABER: `.then(r.json())` ohne r.ok-Check davor. Fix: Wrap mit `r.ok ? r.json() : Promise.reject(r.status)` wie beim FAQ-POST-Create-Pattern.
